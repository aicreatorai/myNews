## 🚀 双阶段执行流程（质量保障核心机制）

> **⚠️ 严格遵守**：先搜索→记笔记→再写作。严禁搜索过程中插写知识点，严禁搜索完立即写作而不整理笔记。

### 第一阶段：搜索记录（专注搜索，不写作）
1. 按搜索优先级 P0→P1→P2 顺序，逐条执行每个子领域的全部关键词搜索
2. **每搜完一个关键词**，立即将结果摘要写入 scratchpad（固定格式）：
   ```
   [子领域] [关键词] → 来源: [URL] | 核心信息: [议题名称+讨论热度+关键讲解点]
   ```
3. 全部搜完前，**不得开始写作**

### 第二阶段：写作输出（专注写作，不再搜索）
1. 基于 scratchpad 笔记选择最热的 6-10 个知识点方向，按轮换分配（聚焦子领域 4-6 条，其余合选 1-3 条），逐条撰写
2. 每条必须引用 scratchpad 中的来源，按"是什么→解决问题→原理三层→代码→对比→场景"格式
3. 写完一条再写下一条，保证每条质量一致

**① 它是什么？（核心概念，200-300字）**

- 一句话定义：用最直白的话说清楚
- 常见误区：大多数人理解错的地方
- 适用边界：什么场景下有用、什么场景下不适用
- 历史脉络：这个技术/概念是怎么发展来的（有助于理解为什么长这样）

**② 它解决了什么问题？（Before → After，200-300字）**

- **Before**：没有这个技术之前，大家怎么做？有什么痛点？
- **After**：有了这个技术之后，改变了什么？
- **量化对比**：用具体数据说话（如"之前需要 10 秒，现在只要 100ms"）
- **真实案例**：最近哪个知名项目/产品用了这个技术，效果如何

**③ 原理深度拆解（400-600字，重点！全文的核心价值）**

三层递进讲解，让不同层次的读者都能学到东西：

**第一层：直觉理解（类比）**
用生活中的例子做类比，让零基础的人也能想象。

**第二层：技术拆解（流程图式讲解）**
用"输入 → 步骤1 → 步骤2 → ... → 输出"的方式描述完整流程。
每一步说明：发生了什么、为什么这样设计、关键参数/数据。

```
输入: [描述输入是什么]
  ↓
步骤 1: [做什么]
  → [关键细节/参数]
  ↓
步骤 2: [做什么]
  → [关键细节/参数]
  ↓
输出: [描述输出是什么]
```

每一步用自然语言描述，配合关键的技术细节和量化数据。

**第三层：公式与核心机制（选填，但推荐）**
如果有数学公式，不直接堆公式，而是用自然语言翻译公式在做什么、为什么是这样。
- 如果没有公式，给出该技术最核心的 1-2 个关键概念或设计决策的解释

**④ 动手验证（代码实战，300-400字）**

不是粘贴大段框架代码，而是**从零开始搭建一个最小可运行示例**：

```python
# 完整的可运行代码，从 import 到结果输出
# 注释说明每段代码在做什么

# 1. 安装/导入
from xxx import yyy

# 2. 准备数据/配置
data = ...
config = {...}  # 关键参数说明

# 3. 核心调用
result = yyy.run(data, **config)

# 4. 输出结果
print(result)
```

- 每行关键代码旁加注释，说明**为什么这么写**
- 如果运行时可能踩坑，在代码前后标注注意事项
- 预期输出：运行后应该看到什么结果

**⑤ 技术对比与选型决策（必填，对比表格）**

如果这个知识点是解决某个问题的一种技术方案，它和类似方案比有什么不同：

**⑥ 思考题与延伸（必填）**

让读者检验是否真正理解：

- **自测题**：1-2 个问题，读者回答后能验证自己是否理解了核心概念

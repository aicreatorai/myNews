## 📝 输出格式

> ⚠️ **每条必须 ≥1000 字**（优先 1200-1500 字）。每条需让读者看完真正理解这个项目的核心价值。

```markdown
### 1. 【项目名+一句话核心价值】（⭐⭐ Star数）

> 📍 **导语**（100-150字）: 用2-3段交代这个项目解决什么开发痛点、比旧方案好在哪里、Star增长趋势（如"过去一周Star翻倍"）、为什么今天值得关注。

---

**⭐ 深度项目解析**

**▌ 它解决了什么真实痛点？**（200-300字）
什么开发场景下会遇到这个问题？没有这个项目之前开发者怎么做？有什么痛苦（举具体例子）？有了之后改变了什么（用数据说话：时间/成本/效率）？这个痛点的普遍性：多少开发者/团队在受这个问题困扰？

**▌ 核心原理与架构**（200-300字）
不要空谈"基于先进技术"，要说清楚：输入→处理→输出的完整流程、关键设计决策（为什么这样设计而不是那样）、各模块的职责分工、数据怎么流转。可以配流程图描述：

```
输入: [描述输入]
  ↓
模块A: [做什么] → [关键机制]
  ↓
模块B: [做什么] → [关键机制]
  ↓
输出: [描述输出]
```

**▌ 5分钟快速上手**（200-300字）
从零开始的完整操作流程，包含可运行的命令/代码：
```bash
# 1. 安装
pip install xxx
# 2. 最小配置
cat > config.yaml << 'EOF'
key1: value1
key2: value2
EOF
# 3. 运行并验证
xxx run --config config.yaml
```

**▌ 真实场景实战**
选一个最贴近真实开发的场景，完整走一遍。传统做法怎么做、耗时多少？现在做法怎么改、效果如何？注意事项和最佳实践。

**▌ 学习路线**

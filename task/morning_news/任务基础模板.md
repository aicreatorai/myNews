# 早间新闻生成任务基础模板

> 本文件为所有 12 个任务文件的通用规范，每个任务文件仅需包含差异化内容（搜索关键词、条数、去重要求等）。

---

## ⚡ 核心约束

1. **必须联网搜索后才能写**，严禁凭训练数据记忆生成
2. **全量搜索原则**：每个子领域的所有关键词必须逐一执行，不得跳跃
3. **核实关键数据**：数字类信息必须通过第二次搜索确认
4. **信息来源必填**：每条末尾标注真实来源（媒体名称 + 报道日期）
5. **禁止套话**：不使用"具有重要意义"等空洞表述，用事实和数据说话

---

## 🔄 搜索缓存机制（P0优化 - 节省30-40%搜索开销）

> **核心思路**：多个Agent可能搜索相同或相似的关键词（如"中美关系"同时出现在01/03）。先进先查缓存，相同关键词只搜一次。

### 搜索前
```bash
# 先检查缓存是否已有该关键词的搜索结果
python3 scripts/search-cache.py has "<关键词>"

# 如果有缓存，直接读取
python3 scripts/search-cache.py get "<关键词>"  # 返回上次搜索结果

# 如果没有缓存，联网搜索后存入
```

### 搜索后
```bash
# 将搜索结果存入缓存（供后续Agent复用）
python3 scripts/search-cache.py search "<关键词>" "<搜索结果摘要>"
```

### 手动维护
```bash
python3 scripts/search-cache.py stats  # 查看缓存统计
python3 scripts/search-cache.py clean 7  # 清理7天前的缓存
```

---

## 🚀 双阶段执行流程

### 第一阶段：搜索记录（优先查缓存，没有再搜索）
1. 对每个关键词，先执行 `search-cache.py has "<关键词>"` 检查缓存
2. 缓存命中 → 直接读取结果，跳过联网搜索
3. 缓存未命中 → 联网搜索，然后将结果写入缓存
4. 每条搜索结果写入 scratchpad：
```
[关键词] → 核心信息: [时间+主体+关键数据] | 来源: [URL]
```

### 第二阶段：写作输出
基于 scratchpad 笔记逐条撰写，每条必须引用真实来源

## 🗂️ 知识类模块去重（必读）

> 以下规则适用于 **07/08/09/10/12/13/14/15** 知识/工具/成长类模块。其余模块无需阅读此节。

### 问题背景

知识类内容（AI知识点、工具使用、创业方法等）具有**知识稳定性**——RAG原理不会每天变、时间管理方法不会每天变。如果每天只换角度讲同样的知识点，对读者就是重复阅读。

### 核心方案：知识索引 + 层级递进

系统维护 `task/knowledge-index-{模块编号}.json`（按模块拆分），记录每个知识类模块已覆盖的主题及层级。

**层级定义**：
| 层级 | 说明 | 示例 |
|------|------|------|
| L1 概念层 | 是什么、解决什么问题 | "RAG的原理与入门" |
| L2 技术层 | 内部机制、关键参数、优化 | "RAG的分块策略与重排序" |
| L3 实践层 | 生产级方案、踩坑经验 | "百万级文档RAG系统的6个坑" |
| L4 前沿层 | 最新演进、融合创新 | "GraphRAG+传统RAG双通道方案" |

### 执行前必做：查询知识索引

写作前，执行以下步骤：

1. **确定候选主题**：从搜索结果中确定你想写的3-5个候选主题
2. **查询索引**：对每个候选主题，运行：
   ```bash
   python3 scripts/manage-knowledge.py check <模块编号> "<主题关键词>"
   ```
3. **判断结果**：
   - `🔴 已达L4` → 彻底跳过该主题
   - `🔴 近期已覆盖` → 换方向或等30天后再写
   - `🟢 可写，建议层级: LX` → 按建议层级写，标题加注`[LX]`前缀

4. **写作后追加记录**：每条写完后，运行：
   ```bash
   python3 scripts/manage-knowledge.py add <模块编号> '{"topic":"主题名","title":"标题","level":"LX","depth":"层级名","angle":"切入角度","keywords_snippet":"关键词片段"}'
   ```

### 非重复判断标准

| 情况 | 是否重复 | 示例 |
|------|---------|------|
| 同主题+同级 | ❌ 重复，跳过 |
| 同主题+不同级 | ✅ 不重复，用递进层级 |
| 同主题+同级+不同切入角度 | ✅ 不重复（如"API用法"vs"性能优化"） |
| 不同主题 | ✅ 不重复 |

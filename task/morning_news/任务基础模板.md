# 早间新闻生成任务基础模板

> 本文件为所有 12 个任务文件的通用规范，每个任务文件仅需包含差异化内容（搜索关键词、条数、去重要求等）。

---

## ⚡ 核心约束

1. **必须联网搜索后才能写**，严禁凭训练数据记忆生成
2. **全量搜索原则**：每个子领域的所有关键词必须逐一执行，不得跳跃
3. **核实关键数据**：数字类信息必须通过第二次搜索确认
4. **信息来源必填**：每条末尾标注真实来源（媒体名称 + 报道日期）
5. **禁止套话**：不使用"具有重要意义"等空洞表述，用事实和数据说话

---

## 🔄 搜索缓存机制（P0优化 - 节省30-40%搜索开销）

> **核心思路**：多个Agent可能搜索相同或相似的关键词（如"中美关系"同时出现在01/03）。先进先查缓存，相同关键词只搜一次。

### 搜索前
```bash
# 先检查缓存是否已有该关键词的搜索结果
python3 scripts/search-cache.py has "<关键词>"

# 如果有缓存，直接读取
python3 scripts/search-cache.py get "<关键词>"  # 返回上次搜索结果

# 如果没有缓存，联网搜索后存入
```

### 搜索后
```bash
# 将搜索结果存入缓存（供后续Agent复用）
python3 scripts/search-cache.py search "<关键词>" "<搜索结果摘要>"
```

### 手动维护
```bash
python3 scripts/search-cache.py stats  # 查看缓存统计
python3 scripts/search-cache.py clean 7  # 清理7天前的缓存
```

## 🚀 双阶段执行流程

### 第一阶段：搜索记录（优先查缓存，没有再搜索）
1. 对每个关键词，先执行 `search-cache.py has "<关键词>"` 检查缓存
2. 缓存命中 → 直接读取结果，跳过联网搜索
3. 缓存未命中 → 联网搜索，然后将结果写入缓存
4. 每条搜索结果写入 scratchpad：
```
[关键词] → 核心信息: [时间+主体+关键数据] | 来源: [URL]
```

### 第二阶段：逐条写作 + 即时保存（防丢策略）

> ⚠️ **核心原则：写一条、存一条**。严禁等全部写完再一次性写入文件，防止中途中断导致已写内容丢失。

**写作流程（逐条循环）：**

```
1. 基于 scratchpad，撰写第 1 条新闻
2. 写入输出文件（首次 write_to_file 写入文件头部 + 第1条）
3. 撰写第 2 条新闻
4. 追加到输出文件（用 replace_in_file 在尾部拼接第2条）
5. 重复上述步骤，直到所有新闻写完
```

**具体操作方式：**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 第1条 | `write_to_file` | 写入完整文件（头部元信息 + 第1条全文） |
| 第2条起 | `replace_in_file` | 在文件末尾追加新条目（搜索 `---` 分隔符定位） |
| 每条写完 | 立即执行追加 | 不积累、不等待 |

**好处：**
- 写入第8条时崩溃 → 前7条已保存 ✅
- 节省 token（不用重复生成前面内容）
- 每条独立可验证（写完即可检查字数/格式/来源）

**错误恢复：**
```
如果中断，检查输出文件已有内容：
□ 已有 N 条 → 从第 N+1 条继续写
□ 文件不存在 → 从第1条重新开始
```

## 📊 内容深度分层（L1-L4 · 知识类模块强制执行）

> **核心原则**：每周 7 篇文章必须有深浅搭配，避免全是入门概念或全是踩坑经验。

| 层级 | 定位 | 典型标题句式 | 适用范围 |
|:--:|------|------|------|
| **L1 概念层** | 是什么、解决什么问题 | "XXX 的原理与入门"、"一文搞懂 XXX" | 新概念/新技术刚火时需要 |
| **L2 技术层** | 内部机制、关键参数、优化 | "XXX 的分块策略与重排序"、核心参数详解 | 读者已了解基础，需要深入 |
| **L3 实践层** | 生产级方案、踩坑经验 | "百万级文档 XXX 系统的 6 个坑"、生产环境实测 | 有实战数据、有失败案例 |
| **L4 前沿层** | 最新演进、融合创新 | "XXX+YYY 双通道方案"、论文精读与复现 | 本周刚出的论文/新方案 |

**每周不少于 2 个层级**：L1+L4（入门+前沿），或 L2+L3（技术+实践），或 L1+L2+L3（梯度）。

**选主题时对应层级**：从主题池选 7 个主题后，为每个主题标注建议层级（L1-L4），确保本周 7 篇覆盖 ≥2 个层级。

### 层级自检清单

| 问题 | 对应层级 |
|------|:--:|
| 本周有没有一篇能让新手看懂的？（纯概念讲解，不含复杂术语） | L1 |
| 本周有没有一篇深入讲原理机制的？（有参数对比/公式/架构图） | L2 |
| 本周有没有一篇带真实数据的？（生产数据/踩坑/量化效果） | L3 |
| 本周有没有一篇讲最新突破的？（本周论文/刚发布模型/新方案） | L4 |
> 每篇至少对应 1 个层级，全部 4 个都覆盖更好但**不强求**。

## 🔗 跨日期主题关联（知识类模块强制执行）

> **核心原则**：同一主题的 L1→L2→L3→L4 文章散落在不同日期，需要能被读者串联阅读。

### 关联方法

**写作时**：
1. 写完一篇文章后，搜索 `news/` 目录中**同一模块、同一主题**的历史文章（查 `news-index.json` 或文件名匹配）
2. 如果存在相关历史文章，在文末 `🔗 信息来源` 后追加：

```markdown
**📚 系列阅读**（同主题深度递进）
- [L1 入门] {YYYYMMDD} - [标题] → 适合新手了解概念
- [L2 技术] {YYYYMMDD} - [标题] → 深入讲参数和机制
- [L3 实践] {YYYYMMDD} - [标题] → 本篇，聚焦踩坑经验
```

**搜索历史文章的具体方式**：
- 按主题关键词搜 `news-index.json`：`python3 scripts/manage-knowledge.py search "<主题关键词>"`
- 按模块编号过滤，只关联同一模块（07 不关联 12）
- 优先选层级互补的（本篇 L3 → 优先关联历史 L1/L2）
- 上限 3 篇，按日期倒序

### 主题标识（选填但推荐）

在每篇文章头部添加主题标签，便于后续检索：

```markdown
> 🏷 主题：RAG与知识检索 | 层级：L3 实践层 | 模块：07
```

长期效果：读者搜索"RAG"时，可找到一条从 L1 到 L4 的完整学习路径。

### 标题格式
- 不超过 35 字
- 必须包含核心信息（主体+动作+数据）

## 🗂️ 知识类模块去重（必读 · 强制执行）

> ⚠️ **强制性要求**：以下规则对本模块**硬性约束**，不遵循会导致生成内容被判定为重复而废弃。
>
> 以下规则适用于 **07/08/09/10/12/13/14/15** 知识/工具/成长类模块，其余模块无需阅读此节。

### 问题背景

知识类内容（AI知识点、工具使用、创业方法等）具有**知识稳定性**——RAG原理不会每天变、时间管理方法不会每天变。如果每天只换角度讲同样的知识点，对读者就是重复阅读。

### 核心方案：知识索引 + 层级递进

系统维护 `task/knowledge-index-{模块编号}.json`（按模块拆分），记录每个知识类模块已覆盖的主题及层级。

**层级定义**：
| 层级 | 说明 | 示例 |
|------|------|------|
| L1 概念层 | 是什么、解决什么问题 | "RAG的原理与入门" |
| L2 技术层 | 内部机制、关键参数、优化 | "RAG的分块策略与重排序" |
| L3 实践层 | 生产级方案、踩坑经验 | "百万级文档RAG系统的6个坑" |
| L4 前沿层 | 最新演进、融合创新 | "GraphRAG+传统RAG双通道方案" |

### ⚠️ 强制执行流程

> 💡 **核心原则**：去重的是「相同内容」，不是「相关话题」。
> 同一技术有不同版本更新 → 不同内容 ✅ 保留
> 同一事件有全新进展 → 不同内容 ✅ 保留
> 完全相同的内容再次出现 → 重复 ❌ 跳过

#### 第一步：内容级去重检测（必做）

对每条候选新闻，**必须**执行：

```bash
python3 scripts/check-dedup.py check "<标题>"
```

**判断规则**（3种结果）：
| 检测结果 | 含义 | 操作 |
|----------|------|------|
| 🔴 与历史内容重复 | 完全相同的内容已经写过 | **跳过** |
| 🟡 相似主题但版本不同 | 同一技术有版本更新 | **保留，标题注明版本演进** |
| 🟢 无历史重复 | 全新内容 | **正常写作** |

> ⚠️ 版本更新不算重复。例如 "TypeScript 7.0" 和 "TypeScript 7.1" 是不同的内容。
> ⚠️ 同一事件有全新进展也不重复，例如"中美谈判第二天有新进展"不等同于"中美谈判第一天"。

#### 第二步：查知识索引（必做）

对知识类模块的候选主题，必须执行：

```bash
python3 scripts/manage-knowledge.py check <模块编号> "<主题关键词>"
```

**判断规则**：
| 检测结果 | 操作 |
|----------|------|
| 🔴 已达L4 | **彻底跳过**该主题 |
| 🔴 近期已覆盖 | **换方向**或等30天后再写 |
| 🟢 可写，建议层级: LX | **必须**按建议层级写，标题加注 `[LX]` 前缀 |

#### 第三步：写作前自查清单（必答）

```
□ check-dedup.py check 返回 🔴 重复？           → 跳过
□ check-dedup.py check 返回 🟡 版本更新？        → 保留，标注版本演进
□ check-dedup.py check 返回 🟢 可写？            → 继续
□ manage-knowledge.py check 是否已达 L4？        → 跳过

结论：□ 通过 □ 跳过
```

#### 第四步：写作后追加记录

每条写完后，**必须**执行：

```bash
python3 scripts/manage-knowledge.py add <模块编号> '{"topic":"主题名","title":"标题","level":"LX","depth":"层级名","angle":"切入角度","keywords_snippet":"关键词片段"}'
```

### 非重复判断标准

| 情况 | 是否重复 | 示例 |
|------|---------|------|
| 同主题+同级 | ❌ 重复，跳过 | |
| 同主题+不同级 | ✅ 不重复，用递进层级 | |
| 同主题+同级+不同切入角度 | ✅ 不重复（如"API用法"vs"性能优化"） | |
| 不同主题 | ✅ 不重复 | |

## 📊 表格生成规范

> 生成的表格需要在手机端正常显示。过宽/过密的表格在手机上无法阅读。

### 核心原则
1. **对比表格 ≤4 列**（含首列）：超过4列拆成多个小表或改为分点描述
2. **每列文字 ≤20 字**：单元格内容精简，长文本改为要点或缩写
3. **优先用分点列表替代表格**：如果只有2-3行对比数据，用 `- **维度**: 内容` 格式比表格更清晰
4. **数据表格 ≤6 行**：超过6行的大表改为"Top 3 + 其余见下文"的分段结构

### 正确示例（≤4列、短文本）
```
| 维度 | 本产品 | 竞品A | 竞品B |
|------|--------|-------|-------|
| 价格 | ¥99/月 | ¥199  | 免费  |
| 速度 | 2秒   | 5秒   | 8秒   |
```

### 错误示例（5列、长文本—手机上无法阅读）
```
| 对比维度 | 本产品 | 竞品A | 竞品B | 竞品C |
|---------|--------|-------|-------|-------|
| 在大量数据场景下的内存占用表现 | 极优，仅占用200MB... | ... | ... | ... |
```

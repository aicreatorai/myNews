# 内容级精确去重方案

> **分析日期**：2026-05-19 | **更新日期**：2026-05-19
> **核心原则**：去除"相同内容"，保留"相关话题"——同一技术不同版本更新不算重复

---

## 一、什么是重复？

### ❌ 应该去除
| 情况 | 示例 |
|------|------|
| 同一标题在多模块出现 | "中美经贸磋商达成五项成果"在01和05同时出现 |
| 同一内容隔天又写一次 | "独立开发者MakeLanding月入45万"连续两天出现 |
| 完全相同的导语和判断 | 同一来源同一事件同一数据 |

### ✅ 保留（不算重复）
| 情况 | 示例 |
|------|------|
| 同一技术不同版本更新 | TypeScript 7.0 Beta → TypeScript 7.1 功能不同 |
| 同一技术不同角度讨论 | 科技前沿谈技术原理，科技动态谈市场影响 |
| 同一话题不同进展 | "中美谈判"每天都有新进展 |

## 二、技术方案：内容指纹索引

### 核心原理

```
标题文本 → 标准化（去前缀/去标点/去版本号）→ 取前40字
导语文本 → 取前60字
         ↓ 拼接 + MD5
     内容指纹（唯一标识）
```

### 版本号感知

系统内置版本号模式识别，自动判断两个标题是否指向不同版本：
- `\d+\.\d+(?:\.\d+)?` — 3.27, 7.0
- `Beta|Alpha|RC|Preview` — 版本后缀
- `v?\d+` — v2, 第3版

如果检测到**同一技术 + 不同版本号** → 不算重复，标注"版本更新"。

## 三、工具使用

### 3.1 写作前查重（Agent 用）

```bash
python3 scripts/check-dedup.py check "<标题>"
```

输出三种结果：

| 输出 | 含义 | 操作 |
|------|------|------|
| 🟢 无历史重复，可写 | 全新内容 | 正常写作 |
| 🟡 相似主题但版本不同，可写 | 同一技术版本更新 | 保留，注明版本演进 |
| 🔴 与历史内容重复，建议跳过 | 完全相同内容 | **跳过** |

### 3.2 全量检测（后置用）

```bash
# 检测同天跨模块重复 + 跨天重复
python3 scripts/check-dedup.py scan 2026-05-19

# 构建/更新内容指纹索引
python3 scripts/check-dedup.py build-index 2026-05-19
```

### 3.3 每日完整流程

```bash
# 1. 生成提示（已嵌入去重黑名单）
python3 scripts/run-morning-news.py --date 2026-05-20

# 2. 执行 Agent 时，直接对照提示中的黑名单：
#    📅 昨日同模块已有 → 跳过
#    📚 历史已覆盖(近60天) → 需查知识索引
#    📋 本日已有报道(同批次) → 跳过

# 3. 全部完成后：
python3 scripts/run-morning-news.py --only-post --date 2026-05-20
```

### 指纹索引存储

- 数据库：`task/content-fingerprint.db`（SQLite，非 JSON）
- 表结构：`fingerprint(主键), module, date, headline, lead, normalized`
- 索引：主键索引(O(1)查询) + (module, date)复合索引 + date 索引
- 自动 WAL 模式：并发读写无锁

### 性能保障

| 操作 | 当前(773条) | 1年(3万条) | 5年(15万条) |
|------|:----------:|:----------:|:----------:|
| 精确指纹查询 | <0.1ms | <0.1ms | <0.1ms |
| 范围查询(LIMIT 200) | <0.1ms | <0.5ms | ~1ms |
| 增量插入100条 | <0.5ms | ~1ms | ~1ms |
| 数据库大小 | 16KB | ~1.6MB | ~8MB |

> 注：模糊相似度比对限定在最近 **60 天**内（配置 `SIMILARITY_LOOKBACK_DAYS`），不会随历史累积而变慢。
> 旧 JSON 索引已自动迁移到 SQLite，原文件备份为 `content-fingerprint-index.json.bak`。

## 🔴 发现的问题

### 问题 1：verify_files 只检查文件数量，不检查内容质量

`run-morning-news.py` 的 `verify_files()`（line 148-189）仅检查：
- 文件数量是否为 12 个
- 文件大小是否 > 0

**风险**：如果 Agent 输出内容含占位符（如未替换的 `{DATE}`）或生成失败，不会被检测到。

**修复建议**：
```python
def verify_files(date_params):
    # ... 现有逻辑 ...
    # 新增内容检查
    for f in files:
        content = open(os.path.join(out_dir, f)).read()
        warnings = []
        if '{DATE' in content:
            warnings.append('含未替换的日期占位符')
        if len(content) < 200:
            warnings.append('文件内容过短')
        if '生成失败' in content or 'error' in content.lower():
            warnings.append('可能生成失败')
        if warnings:
            print(f'  ⚠️ {f}: {", ".join(warnings)}')
```

### 问题 4：前端 Markdown 渲染器存在解析缺陷

`js/app.js` 的 `renderMarkdown()` 函数有以下问题：

**① 代码块内的标记会被二次解析**（line 591-593 vs 606-618）

代码块内容中的 `**bold**`、`*italic*`、`###` 等标记，在代码块被识别后，仍会经过后续的加粗/斜体/标题正则，导致代码块内容被错误渲染。

示例输入：
```markdown
```
**这不是粗体**
```
```
渲染结果：代码块内的 `**` 被误转为 `<strong>`。

**② 表格渲染过于粗放**（line 628-632）

```javascript
html = html.replace(/\|(.+)\|/g, (match) => {
```

所有 `|` 都被当作表格处理，包括行内代码中的 `|` 和普通文本中的 `|`。

**③ 没有转义正则特殊字符**

行内代码 `` `code` `` 替换后，里面的 `*`、`_`、`` ` `` 等仍会被后续规则匹配。

### 问题 5：搜索缓存关键词归一化丢失窗口信息

`search-cache.py` 的 `_normalize_key()` 会将不同时间窗口的搜索词映射到同一缓存键：

```python
# 两个不同的搜索词：
"AI 工具 {DATE-1}至{DATE}"  → 归一化: "ai 工具"
"AI 工具 {DATE-30}至{DATE}" → 归一化: "ai 工具"  ← 相同！
```

`run-morning-news.py` line 119：

### 问题 7：gen-news-index.py 扫描目录过多

从 `news/` 根目录扫描，但根目录下可能有其他非日期文件。当前通过 `re.match(r'\d{8}', entry)` 过滤。但在 `_date_to_dir` 和 `parse_date_from_filename` 中没有对无效日期做容错。

### 去重机制改造说明

**之前（写后检测）**：
```
Agent写 → scan检测重复 → 发现重复 → 废弃重写 ❌
```

**现在（写前阻断）**：
```
run-morning-news.py 生成提示
  ↓ 自动查询 SQLite 指纹索引
  ↓ 提取昨日同模块 + 近60天历史
  ↓ 注入 → Agent 提示中已有黑名单
Agent写作 → 对照黑名单 → 已覆盖就跳过 ✅
```

**改造效果**：
- Blacklist 直接嵌入提示词，Agent 写作前即可判断
- 无需 Agent 执行外部脚本
- 第一批输出自动注入第二批提示，跨批去重
- 后置 scan 作为"安全检查"而非"主要防线"

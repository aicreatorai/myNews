### 问题 2：搜索缓存关键词归一化可能跨日期混淆

`search-cache.py` 的 `_normalize_key()` 会剥离关键词中的日期范围：
- `"AI 工具 {DATE-1}至{DATE}"` → 归一化为 `"ai 工具"`
- `"AI 工具 {DATE-30}至{DATE}"` → 也归一化为 `"ai 工具"`

**后果**：不同时间窗口的搜索会返回同一个缓存结果。例如 30 天窗口的关键词拿到 24 小时的缓存。

**建议**：
```python
# 保留窗口信息到归一化键中
def _normalize_key(keyword):
    # 提取日期窗口信息
    window_match = re.search(r'\{DATE-(\d+)\}.*?\{DATE\}', keyword)
    window = f'w{window_match.group(1)}' if window_match else 'w1'
    # 归一化主体
    kw = re.sub(r'\s*\{date[^}]*\}', '', keyword.strip().lower())
    return f'{kw}__{window}'
```

## 二、整体流程评估

```
任务文件(.md)
  └→ run-morning-news.py 生成提示
       └→ 人工复制提示给 AI (Claude/ChatGPT)
            └→ AI 读取任务文件，替换 {DATE} 占位符
                 ├→ 搜索前: search-cache.py has/get (查缓存)
                 ├→ 未命中: 联网搜索并 search-cache.py search (存缓存)
                 ├→ 写入 scratchpad
                 └→ 基于 scratchpad 写新闻文件
                      └→ run-morning-news.py --only-post (验证+索引+提交)
```

**风险评估**：
- ⚠️ **无法强制 AI 执行搜索** — 配置要求"必须联网搜索"，但无法验证
- ⚠️ **日期占位符依赖 AI 手动替换** — `{DATE}` 替换靠 AI 理解，可能出错
- ⚠️ **无搜索结果质量门禁** — 无法验证搜索是否返回了时效正确的新闻

# 12 子 Agent 并行新闻生成配置

> **说明**：本配置文件定义如何通过 12 个子 Agent，并行执行 `task/morning_news/` 目录下的 12 个新闻板块任务，一次性生成完整早间新闻。

> **更新时间**：2026-05-16（v3.4：合并01-04为新闻早报，12子Agent，自动日期）

---

## 🎯 整体设计

### 执行日期
> **说明**：以下变量由 `run-morning-news.py` 脚本自动替换为当天日期，无需手动修改

| 参数 | 变量 | 说明 |
|------|------|------|
| `{DATE}` | 自动 | 今天日期（如：2026-05-16） |
| `{DATE-1}` | 自动 | 昨天日期 |
| `{DATE-2}` | 自动 | 前天日期 |
| `{YYYYMM}` | 自动 | 年月（如：202605） |
| `{YYYYMMDD}` | 自动 | 年月日（如：20260516） |
| **搜索时段** | 自动 | {DATE-1} 07:00 ~ {DATE} 07:00 |
| **输出根目录** | 自动 | `news/{YYYYMM}/{YYYYMMDD}/` |

### 📦 P0优化工具（v3.3 新增）

| 工具 | 路径 | 作用 |
|:----|:-----|:-----|
| **一键执行脚本** | `scripts/run-morning-news.py` | 自动创建目录、清缓存、生成Agent提示、验证、索引、提交 |
| **搜索缓存** | `scripts/search-cache.py` | 缓存搜索结果，相同关键词只搜一次，节省30-40%搜索开销 |
| **知识索引** | `scripts/manage-knowledge.py` | 知识类模块去重管理 |

> **使用方式**：先运行 `python3 scripts/run-morning-news.py --date {DATE}` 生成执行计划，再将生成的2批Agent提示交给AI依次执行。
> Agent执行搜索前优先查缓存（`search-cache.py has`），有缓存直接复用，无缓存再联网搜索。

### 执行策略（分 2 批，避免 API 限流）

每批内的 Agent **同时启动**，批间 **等待前一批全部完成** 再启动下一批：

1. **第一批（新闻+科技 6 个）**：01、05、06、07、08、09 — 时效性最高的新闻与科技
2. **第二批（知识+工具 6 个）**：10、11、12、13、14、15 — 知识沉淀与开发工具

## 🧩 子 Agent 定义（共 12 个）

### 通用执行规则（所有 Agent 共享）

1. **先加载基础模板**：每个 Agent 必须先读取 `task/morning_news/任务基础模板.md` 获取通用规范（核心约束、输出格式、去重规则等）
2. **再加载模块文件**：然后读取各自模块的差异化文件（如 `01_今日头条.md`），获得搜索关键词、条数要求、特有约束
3. **先搜索，再写作**：完成模板加载后，必须执行联网搜索，严禁凭记忆生成内容
4. **全量搜索原则**：各任务文件中的每个子领域关键词必须逐一执行，不得跳跃
5. **核实关键数据**：所有数字类信息必须通过第二次搜索确认
6. **严格基于搜索结果**：不得在搜索结果之外自行添加细节
7. **信息来源必填**：每条新闻末尾标注真实来源（媒体名称 + 报道日期）
8. **自动填充日期**：将任务文件中的 `{DATE}`、`{DATE-1}`、`{DATE-2}`、`{YYYYMM}`、`{YYYYMMDD}` 替换为实际日期值
9. **分批执行**：12 个子 Agent 分 2 批执行，避免搜索 API 限流

### 通用跨模块去重规则（对所有 Agent 强制）

| 事件类型 | 归属模块（主角度） | 其他模块若涉及则切入角度 |
|---------|------------------|----------------------|
| 商业/公司动态 | 06_科技动态 | 05→只谈技术原理，不谈商业合作/投资 |

| 语言版本发布 | 09_开发语言 | 11→只谈该语言在本生态的影响，不报道版本本身 |
| 移动端开发技术 | 11_移动开发 | 05→只谈底层AI技术，不谈开发框架 |
| AI开源项目 | 10_GitHubSkills | 08→只谈开源项目代码，不谈使用体验 |

## 📋 验证清单

1. **全量搜索验证**：随机抽查 2-3 个关键词，确认搜索结果中有该时间窗口内的真实新闻
2. **文件完整性检查**：检查 12 个文件是否全部存在且非空（01_04合并版输出01_今日头条.md）
3. **内容质量检查**：
   - 每条新闻是否有信息来源标注
   - 每条新闻是否有实质内容（非标题党）
   - 是否存在跨模块重复报道
4. **知识类模块专项检查**：
   - 是否读取了最近 7 天历史文件
   - 是否避免与历史内容重复

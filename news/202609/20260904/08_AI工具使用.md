### 1. 【Cursor AI：用 .cursorrules + 计划模式把陌生代码库改出新功能】

> 📍 **导语**：Cursor 不是套了聊天的编辑器，而是把 AI 嵌进编辑体验的"代码库原生 IDE"。它最大的痛点是新手直接抛需求让 AI 自由生成，导致架构混乱、业务跑偏。今天值得学，是因为官方刚放出一套"理解→计划→构建→测试→复盘"的端到端 SOP，配合 .cursorrules 与模型分流，能把改陌生代码库的效率翻倍，且输出质量稳定可控。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**：Cursor 是构建在 VS Code 之上的 AI 原生 IDE，扩展、快捷键、导航习惯可无缝迁移。它把 AI 当作核心原语，提供内联编辑（Cmd+K）、基于整个代码库的对话、多文件上下文与架构感知补全。免费版可用基础模型与有限请求，Pro 版约 20 美元/月解锁更强模型与更高额度。相比"插件式"助手，Cursor 的 AI 读你读的、看你看的、改你改的，是本质差异，新手开箱即可复用原有 VS Code 肌肉记忆。

**▌ 解决什么（核心功能场景化拆解）**：场景一"接手陌生仓库"——让 Agent 用 Ask 模式先走读结账流程，列出组件、API 与服务，省去人工翻代码；场景二"加功能"——切到 Plan Mode（Shift+Tab）先出计划再构建，避免 400 行错代码；场景三"修偶发 bug"——把失败测试交给 Debug 模式找根因而非改症状；场景四"收尾"——让 Agent 自审 diff、跑边界用例，最后把踩坑经验写进 .cursorrules，形成可复用知识。最让人 WOW 的是：它能在你合并前用云端 Agent 并发测 unicode、超大折扣值、并发用码等你没想到的情况。

**▌ 原理拆解（实战工作流）**：

```
场景：假设你要给一个不熟悉的电商结账流程加"折扣码"功能，周五前要上线。
Step 1: 打开 Cursor → 用 Ask 模式让 Agent 走读 checkout 流程：
  "在加折扣码前，先讲讲 checkout 怎么工作？涉及哪些组件、API、服务？从购物车到支付确认的数据流是什么？"
Step 2: 切 Plan Mode（Shift+Tab）→ 让 Agent 产出 discount-codes.md：
  新增 DiscountService 校验（过期/次数）、改 PricingService.calculateTotal()、加输入框、加 /api/discount/validate、写测试。
Step 3: 构建后一个测试失败——百分比折后再减固定额，结果随顺序变化。把症状交给 Debug 模式：
  "discount stacking 测试失败，同样折扣因顺序不同总额不同，去 DiscountService.ts 找根因并展示每步前后值。"
Step 4: 推送前让 Agent 自审："Review 我所有改动，找 bug、遗漏的错误处理、与现有模式不一致处。"
Step 5: 把"先百分比后固定额"写进 .cursorrules，闭环收尾。
关键心得：从读代码到上线约半天，比纯手写省 60% 时间且风格统一。
```

**▌ 动手验证（进阶技巧）**：① 模型分流——内联补全用 Haiku（200ms 响应），复杂推理用 Sonnet/GPT-4o，会话等待可降 60%；② 写 .cursorrules 放项目根，规定函数式组件、命名导出、interface 优于 type，团队 PR 风格评论可降 25%；③ 把"Fix This Error"映射成单快捷键，每次报错省 2-3 秒；④ 全局 Custom Instructions 写"导出函数带 JSDoc、优先 async/await"，让拿到可用函数所需的提示次数从 2.3 降到 1.7。⑤ 用 Ask 模式先探索再动手，能在改第一行代码前建立代码库心智地图，避免改错层；⑥ 团队把共享 .cursorrules 提交进版本库，新人克隆即继承全部规范，PR 评审成本显著降低，长期看比反复人工纠风格更划算。

### 2. 【n8n：用节点拖拽把"表单→AI→通知"流程全自动跑起来】

> 📍 **导语**：n8n 是开源的工作流自动化编排器，常被叫做 Zapier 的开源平替，但比它强在能直接挂 AI 节点、写 JavaScript/Python、对接 300+ 系统与私有部署。痛点是从零搭自动化要懂节点与表达式。今天值得学，是因为它"表单提交后自动整理并通知"的入门路线 30-60 分钟就能跑通第一版，零代码也能把周报从 3 小时压到几分钟。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**：n8n 是德国团队开发的开源自动化工具，采用节点画布 + 表达式的数据流模型，支持自托管（Docker 一行起）、Webhook/定时触发、AI Agent 节点与 300 多个官方集成（Google Sheets、Notion、飞书、Slack、邮件等）。社区版免费可商用，云版按执行量计费。它的核心差异是"数据怎么在节点间流动"完全可见，且能在代码节点写任意逻辑，适合把 AI 和各种 SaaS 打通，企业也能私有部署保障数据不出域。新手从模板库挑一个相近流程改参数，十分钟就能跑通第一个自动化，学习曲线相当平缓。

**▌ 解决什么（核心功能场景化拆解）**：场景一"表单收集"——用户填表，n8n 接收数据并用 AI 节点分类、摘要、抽关键词；场景二"跨系统同步"——把结果写进 Google Sheets/飞书表格或发邮件给自己；场景三"企业串联"——接 CRM、工单、数据库做自动化；场景四"带 AI 的决策"——AI Agent 节点配 Memory 与 HTTP/数据库工具，用 IF/Switch 做条件分支与人工确认。最 WOW 的是：你设一次，之后每周行业周报自动抓取 10+ 网站、整理、推送，全程无需手动。

**▌ 原理拆解（实战工作流）**：

```
场景：假设你要做一个"表单提交 → AI 总结 → 写表格并邮件通知"的流程。
Step 1: 新建 Workflow，选"表单/Webhook 触发"作为起点，拿到提交内容。
Step 2: 加一个"编辑字段/示例数据"节点模拟输入，方便没真实数据时调试。
Step 3: 加 AI 节点对输入做分类与摘要，重点看它的输出字段长什么样（变量名、结构）。
Step 4: 加"写入"节点——写 Google Sheets/Notion/飞书，或加"邮件"节点发给自己。
Step 5: 手动执行一次，从执行日志看每个节点拿到什么数据，再补错误提示与失败重试。
关键心得：用 Schedule Trigger 定时、Split In Batches 分批避免压垮下游、Error Trigger 做降级，比手动整理省 90% 时间。
```

**▌ 动手验证（进阶技巧）**：① 用 docker run 一行起 n8n 并开 BASIC_AUTH 保护；② 善用"执行日志"逐节点看数据，是排错最快路径；③ 配 Error Trigger + Switch 节点实现模型调用超时自动降级到备用模型；④ 耗时任务（如视频生成）务必进 Redis 队列异步处理，前端轮询进度而非同步阻塞。⑤ 用 Schedule Trigger 定时拉取任务、Split In Batches 分批调用，避免一次性请求压垮下游模型服务；⑥ 把常用流程保存为模板，团队直接复用，新人照模板改参数即可上线第一条自动化，沉淀成本趋近于零。

**▌ 对比选型**

| 决策维度 | 用 n8n | 用 Dify | 用 Coze 扣子 |
|---------|----------|--------|--------|
| 适合什么任务 | 跨系统 SaaS 自动化 | 企业知识库/AI 应用 | 快速发智能体 |
| 不适合什么任务 | 复杂对话编排弱 | 非 AI 纯数据编排 | 深度系统集成 |
| 学习成本 | 中（节点+表达式） | 中低 | 低 |
| 价格 | 社区版免费 | 开源免费/云版计费 | 免费/企业版 |

### 3. 【豆包 AI：语音对话 + 图片识别，把 AI 助手装进日常碎片时间】

> 📍 **导语**：豆包是字节跳动的国产全能 AI 助手，PC、App、微信/抖音小程序全端互通。它最被低估的能力是"国内最自然的语音交互"——开车、做饭、走路时张嘴就能问，且能用语音+文字双向回复；同时支持拍照识图分析。今天值得学，是因为它把"对话、语音、图像"三件套做成零门槛入口，新手用手机号或抖音账号一键登录即可开用。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**：豆包由字节跳动推出，覆盖网页端 doubao.com、iOS/Android App 与抖音内小程序，账号与抖音/字节系互通，登录即用。基础对话、语音对话、图片识别均免费，会员主要提升响应优先级与高级创作模板。它定位"日常全场景"助手，与 Kimi（长文档）、DeepSeek（代码）形成互补。核心差异是语音自然度与多端数据同步，适合不想打字的移动场景，通勤做饭都能连续产出。

**▌ 解决什么（核心功能场景化拆解）**：场景一"语音创作"——点底部麦克风直接说"写一首春天歌词"，豆包语音+文字回；场景二"拍照分析"——拍张食物/文档/物品图发给它即得解析；场景三"文案改写"——左侧"文案创作"选模板，生成后可一键修改；场景四"多端续写"——手机拍图提问，电脑继续同对话深化。最 WOW 的是：它把 AI 从"坐着打字"变成"走着说话"，通勤做饭都能产出内容，且语音识别在国产工具里最自然。

**▌ 原理拆解（实战工作流）**：

```
场景：假设你是运营，通勤路上要产出一条朋友圈预热文案。
Step 1: 打开豆包 App → 点底部中间麦克风图标，直接口述："帮我写一条周末咖啡馆打卡的朋友圈，轻松治愈风，带 emoji，不超 60 字。"
Step 2: 豆包用语音+文字回复。不满意就语音追问："再俏皮一点，加'续命'梗。"
Step 3: 到公司后开 PC 端，同一对话继续："把上面文案扩成公众号开头 150 字，加一个痛点钩子。"
Step 4: 需要配图分析时，拍店内环境图发给豆包："这张图适合配什么色调文案？给三个标题。"
Step 5: 最终复制文案+选定标题，直接进排版工具。
关键心得：语音输入比打字快 3 倍，碎片时间产出初稿，电脑端精修，全流程不卡设备。
```

**▌ 动手验证（进阶技巧）**：① 用"角色设定 + 主题 + 场景 + 输出要求"万能公式提升质量，如"作为职场文案编辑，写客户新春祝福，正式温暖，含'携手共进'，80 字"；② 善用 Shift+Enter 换行不发送、点赞/点踩做多轮优化；③ 右侧"插件"唤起文档问答、PPT 生成、AI 绘画扩能力；④ 把豆包与 Kimi、DeepSeek、即梦组成"日常+长文+代码+视频"工具组合覆盖全场景。⑤ 通勤时用语音产出初稿、到工位用 PC 端精修，是利用豆包多端同步最划算的姿势，碎片时间不再浪费；⑥ 拍照识图不止做分析，还能让它给图片配文案标题，做社媒内容一步到位，省去再开一个工具写文案。

### 4. 【Dify：用可视化工作流把大模型串成可发布的 AI 应用】

> 📍 **导语**：Dify 是当下最火的开源 LLM 应用开发平台，能把 GPT、Claude、通义、文心等模型拖拽成自动化工作流，并一键发布为 Web App、API 或 MCP 服务。痛点是新手容易把提示词写很长却连不通变量。今天值得学，是因为它的"上传内容→AI 总结→页面调用"路线最适合做 AI 应用，本地 Docker 十分钟就能起，企业知识库、合同审查、多步客服都能落地。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**：Dify 由 LangGenius 开源，定位低代码 LLM 应用编排层，支持 Workflow（单轮任务）与 Chatflow（多轮对话）两种形态，可接知识库、HTTP 工具、条件分支与人工审核，并私有化部署保障数据合规。社区版开源免费，云版按用量计费。其核心差异是"变量聚合"节点能把多 LLM 输出整理成统一格式，比单纯写提示词更适合复杂业务，企业也能完全自托管不触外部云。它把"提示词工程"隐藏在可视化节点背后，非算法背景的产品与运营也能上手编排自己的 AI 应用。

**▌ 解决什么（核心功能场景化拆解）**：场景一"企业知识库问答"——喂公司文档做精准检索；场景二"批量文档处理"——合同审查、简历筛选；场景三"多步客服"——意图识别→知识检索→人工审核→回复；场景四"内容生成"——如"短剧分镜生成器"：解析小说→提取角色→生成分镜 JSON。最 WOW 的是：发布为 API 后，可被 n8n、扣子或其他系统直接调用，成为平台里的"AI 能力中台"，一处编排多处复用。

**▌ 原理拆解（实战工作流）**：

```
场景：假设你要做一个"上传文章 → AI 总结 → 页面调用"的小应用。
Step 1: 新建应用时判断形态：单轮处理用 Workflow，多轮对话用 Chatflow。
Step 2: 在开始节点定义输入变量（文章内容/文件/问题/用户角色），变量务必清晰。
Step 3: 加 LLM 节点做摘要或问答，再按需要加分类、提取、条件判断、知识检索节点。
Step 4: 在预览区反复测，观察变量是否正确传递、输出是否稳定可复用。
Step 5: 确认后发布成 Web App / API / MCP 服务，前端或 n8n 直接调用。
关键心得：把"输入变量、节点、知识库、发布方式"连起来，比堆长提示词更可控，迭代快 3 倍。
```

**▌ 动手验证（进阶技巧）**：① 用 git clone + docker compose up -d 十分钟本地起，国内配阿里云镜像加速；② 复杂流程重点处理变量类型、节点失败、最大循环次数、并发与预算；③ 模型可接官方 API 或 OpenAI-compatible 多模型网关，统一管理不同供应商；④ 生产环境配路由降级（如 DeepSeek 超时切通义千问再切 GPT），用 Error Trigger 做重试。⑤ Workflow 与 Chatflow 不要混用，单轮任务坚决用 Workflow，否则变量传递会变复杂难维护；⑥ 发布为 MCP 服务后能被其他 Agent 直接编排，是把它变成"能力中台"的关键一步，企业多系统落地时强烈推荐此路径。

**▌ 对比选型**

| 决策维度 | 用 Dify | 用 Coze 扣子 | 用 n8n |
|---------|----------|--------|--------|
| 适合什么任务 | 企业 AI 应用编排 | 快速发智能体 | 跨系统自动化 |
| 不适合什么任务 | 纯非 AI 数据流转 | 复杂业务编排 | 对话流弱 |
| 学习成本 | 中低 | 低 | 中 |
| 价格 | 开源免费/云计费 | 免费/企业版 | 社区版免费 |

### 5. 【通义千问：通义灵码写代码 + 听悟转写 + 万相出图的一体化提效】

> 📍 **导语**：通义千问是阿里系的大模型助手，真正的提效不在聊天框，而在它衍生的"工具矩阵"：通义灵码（IDE 写代码插件）、通义听悟（语音转写）、通义万相（AI 绘画）。痛点是多数人只把它当聊天工具。今天值得学，是因为这条"代码+会议+设计"组合拳能覆盖开发者一天的高频场景，且深度绑定阿里云生态，企业可私有化部署。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**：通义千问由阿里云推出，主对话框与其他 AI 类似，但核心价值在左侧三大入口：通义灵码（需在 IDE 插件中心安装，专写代码）、通义听悟（语音转文字，单独 App）、通义万相（AI 绘画，左侧菜单）。免费版可用通用对话与基础能力，企业版支持私有化部署与内部系统对接。它的差异是"一个账号打通 coding、会议、设计"，对阿里云用户尤其顺滑，且企业数据可留在自有 VPC 内。

**▌ 解决什么（核心功能场景化拆解）**：场景一"写代码"——在 IDE 装通义灵码，输入需求直接生成带注释的爬虫/接口；场景二"会议转写"——用听悟把录音转文字并出纪要；场景三"出图"——用万相按提示词生成配图；场景四"数学/逻辑"——主对话解題给详细步骤。最 WOW 的是：开发者不必在 ChatGPT、飞书妙记、Midjourney 间来回切，通义一家覆盖开发到产出的链路，上下文不丢失。

**▌ 原理拆解（实战工作流）**：

```
场景：假设你是开发者，要写个"爬豆瓣 Top250 存 Excel"的脚本并顺手出张封面图。
Step 1: 在 IDE 装通义灵码插件，打开新文件，输入：
  "你是 Python 专家，写爬虫爬取豆瓣电影 Top250（名/评分/导演），存 Excel，加详细注释。"
Step 2: 灵码生成代码，你本地跑通；遇到报错把错误信息贴回让它修。
Step 3: 开会后用通义听悟导入录音，自动出文字稿+要点纪要，复制进周报。
Step 4: 用通义万相生成封面："电影胶片风， popcorn 与排行榜，暖色调，4K"。
Step 5: 把脚本、纪要、封面图汇总进交付文档。
关键心得： coding、会议、设计三件事原来要 3 个工具，现在 1 个账号闭环，切换成本归零。
```

**▌ 动手验证（进阶技巧）**：① 写代码用"角色+任务+约束（类型提示/错误处理/注释）"公式提升一次通过率；② 解题用"请解答并给详细步骤"拿可教学过程；③ 企业用户优先通义千问企业版做私有化，数据安全合规更强；④ 把通义与 DeepSeek（代码）、Kimi（长文）组合，按"核心需求精准选型"搭个人工具栈。⑤ 听悟转写后直接出纪要，比人工整理会议省 80% 时间，是开发者最容易忽视的隐藏功能，周会复盘效率立竿见影；⑥ 万相出图可批量生成多版草图，挑优再精修，比一稿定稿成功率高得多，做封面配图尤其明显。

### 6. 【Kimi：拖进 200 万字文档，让 AI 帮你读论文、审合同、画人物关系】

> 📍 **导语**：Kimi 是月之暗面出品的国产长文本 AI，杀手锏是"超长上下文+文档解析"——支持 PDF/Word/Excel/TXT，单次最大约 200 万字，能把 30 万字小说的人物关系、50 页论文的核心论点一次性吃透。痛点是很多人只用它聊天。今天值得学，是因为"上传文档→基于内容提问"这条工作流，让读论文、审合同、做财报分析从几小时压到几分钟，且竞品在文档长度上暂时跟不上。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**：Kimi 由 Moonshot AI 开发，官网 kimi.com，手机号注册（暂不支持第三方登录）。免费版每日约 20-30 次对话、文件上传可用，付费版解锁无限次与更高并发。它最强且独特的用法是"上传文件后基于内容提问"——论文、合同、财报、小说都能喂。核心差异是上下文长度，文心一言、通义千问在支持的文档长度上暂时不及，长文本场景几乎无对手，是科研与法务的刚需入口。

**▌ 解决什么（核心功能场景化拆解）**：场景一"论文精读"——传 50 页 PDF 问"核心论点是什么、第三节实验数据说明什么"；场景二"合同审查"——提取关键条款、风险点；场景三"小说分析"——传 30 万字小说让画人物关系图+性格总结；场景四"财报提炼"——从冗长报告中抽市场规模与增长趋势。最 WOW 的是：它把"人读长文"变成"AI 读后回答"，且输出带结构（要点/表格/关系图），直接可用，不遗漏细节。

**▌ 原理拆解（实战工作流）**：

```
场景：假设你要在一小时内吃透一篇 50 页的英文论文并写文献笔记。
Step 1: 打开 kimi.moonshot.cn，手机号登录，点输入框左侧回形针上传 PDF。
Step 2: 上传后输入结构化提示词（公式：文档需求+输出格式+重点要求）：
  "总结这篇论文的核心论点与研究方法，输出要点式，重点标注实验设置与主要结论，语言简洁。"
Step 3: Kimi 给要点，你追问："第三节的实验数据说明了什么？和第二节假设一致吗？"
Step 4: 让它"提取所有图表结论，按'方法-结果-局限'三栏列表"，形成笔记骨架。
Step 5: 最后说"用一句话给我这篇论文的可用 citation 与一句话贡献"，收尾。
关键心得：原本通读+笔记要 3 小时，现在 1 小时拿可用笔记，且不忘细节。
```

**▌ 动手验证（进阶技巧）**：① 提示词公式"文档需求（总结/分析/提炼）+输出格式+重点要求"稳定产出；② 长文档优先用网页端，避免 App 端次数限制；③ 把合同/论文的关键问答结果导出，再喂给豆包扩写成报告；④ 免费版注意每日次数，批量任务分散到多天或升付费版提并发。⑤ 长文档优先网页端上传，App 端有每日次数限制容易中途断档，影响连续分析体验；⑥ 把 Kimi 的提取结果再喂给豆包扩写成正式报告，是两个国产工具接力提效的典型组合，长文处理到成文一步衔接。

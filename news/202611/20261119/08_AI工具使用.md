### 1. 【Tesseract】一句话交付成品的桌面AI执行器

**▌ 导语**：11月14日，一款叫 Tesseract 的免费桌面应用在 Product Hunt 上线后迅速冲进当周新品榜前列。它的卖点不是"又一个会聊天的 AI"，而是"把话变成文件"——你说一句需求，它交付一个能打开的网站、一份幻灯片、一条视频、一个 logo 或一张调研表格。更特别的是，它自己不训练模型，而是调用你账号里已有的 Claude Code、Codex、Gemini CLI、OpenCode 等编码智能体，用你自己的订阅，不额外收 API 费用。首页摆着 33 个引导式 maker、220 多个模板和 14 套设计主题，几乎没有上手门槛。对长期被"AI 只会给建议、不会干活"折磨的职场人来说，这是值得花一个晚上认真试的工具。

**▌ 它是什么**：Tesseract 是一个跨 Mac、Windows、Linux 的桌面客户端，本质是一层"任务编排外壳"。你选一个切入点或直接从一句话开始，它会先把需求翻译成一份执行计划摆在你面前，确认后才调动底层编码智能体逐步完成。产物是真实文件——网页项目、PPTX、视频片段、SVG 图标或电子表格，而不是一段聊完即散的对话记录。它采用"无订阅、额度可续"的模式：免费额度用完会自动回补，重度使用可按 10 美元起购买预付额度去跑高级模型，没有月费绑定。它把"会配环境的极客工具"包装成"会说人话就能用"的交付器，这是它区别于普通 AI 助手的根本。

**▌ 它解决了什么问题**：普通用户面对 AI 最大的落差是"它说得很热闹，我手里什么都没有"。你要一份竞品对照表，它回你一段文字建议；你要一个演示页，它给你 Markdown 大纲。Tesseract 解决的是从"描述"到"交付物"的最后一公里：它把你已经付费的智能体能力封装成"接活—计划—执行—出文件"的闭环，不需要你自己搭环境、配 API、管依赖。它也解决多智能体来回切换的麻烦——不用记哪个工具擅长网页、哪个擅长幻灯片，统一入口按任务派活。对不想学命令行、又想用上专业编码智能体的人，它把门槛从"会配环境"直接降到"会说人话"，这正是它上线后关注度飙升的原因。

**▌ 核心原理拆解**：理解 Tesseract 的原理，关键是"壳与核分离"这四个字。它本身不做生成，而是把你的需求编译成结构化的任务图：先规划步骤、列出涉及的文件与工具，再以子进程方式调用你本地登录的 Claude Code、Codex 等，把每一步的输出回传成可视化进度条。它之所以能"一句话出成品"，靠的是三层预制：模板库把常见任务（落地页、周报、调研表）固化成骨架，设计主题统一配色与排版，maker 引导你补齐必要参数。安全机制上它采用"计划先行 + 危险步骤二次确认"：凡是涉及删除、发送、覆盖的动作都会单独弹窗要你点头，避免智能体擅自越界。这套机制让它既借力成熟智能体的生成能力，又把最终控制权牢牢留在用户手里，而不是把 agent 当成不可控的黑箱。

**▌ 动手验证**：动手验证建议从一件小而具体的事开始：做一张"本周待办看板"网页。第一步，下载客户端，用你已有的 Claude 或 ChatGPT 账号登录底层智能体，全程不填 API Key。第二步，在首页选"网站"模板，输入一句需求："做一个极简待办看板，三列分别是待办、进行中、已完成，卡片可拖动，奶油底色，圆角，带本地保存。"第三步，先看你给出的计划——重点核对它是否列出了 HTML、CSS、JS 文件和本地存储方案；若发现步骤里夹带"清空 Downloads 目录"这类越界操作，立刻否决并让它重新规划。第四步，确认后观察它逐步写入文件，每完成一步就点开预览验证效果。第五步，若配色不对，追加一句"把阴影改成暖灰、圆角加大到 20px"让它迭代。最终你会得到一个能直接在浏览器打开的完整文件夹。关键心得：它比自己从零搭环境快得多，但"先审计划再放行"这一步绝不能省。

**▌ 对比选型**：把 Tesseract 和同类摆在一起对比会更清楚。与 v0、Bolt.new 这类云端网页生成工具相比，Tesseract 的强项是产物留在本地、覆盖品类多（网页、PPT、视频、logo、表格都做），弱点是依赖你已有的智能体订阅、首次配置稍繁琐。与直接用 Claude Code、Codex 相比，它多了可视化计划和模板，却牺牲了极客的精细控制。与通用 AI 助手相比，它交付的是文件而不是文字。选型建议：想要一个完整成品且已有智能体账号，选 Tesseract；只想快速看个网页原型，用 v0 更省事；要深度定制代码，还是回到 IDE 里的编码智能体更顺手。

### 2. 【DevEco Code】鸿蒙AI编程三模式上手

**▌ 导语**：鸿蒙生态今年在开发者工具上动作不断。11月，华为把一款叫 DevEco Code 的终端 AI 编程 Agent 开源出来，用 npm 一行命令就能装完，内置 GLM-5.1、GLM-5.3 免费额度，单账号每分钟 50 次请求，社区实测口径是"每天 5 亿 Token 用不完"。它最值得学的不是"又一款代码补全插件"，而是把同一件事拆成 Build、Plan+Build、Goal 三种模式，让你按任务复杂度自己选挡位。对做鸿蒙应用、又常被"AI 写一半跑不起来"坑过的开发者，这是一份能直接照抄的上手地图。趁额度免费，很值得先上车试一轮。

**▌ 它是什么**：DevEco Code 是鸿蒙官方开源的命令行 AI 编程 Agent，跑在终端里，登录华为账号即可使用。安装只需一行 `npm install -g @deveco/deveco-code@stable`，启动后输入 `deveco` 进入交互界面。它把大模型、代码读写、语法检查、构建出包、推送模拟器串成一条完整流水线，并能通过 `/models` 切换模型、`/connect` 接入第三方模型。它的定位很明确：从"AI 帮你写代码"进化到"AI 替你把需求干完"。你只管给需求、做验收，中间的编码、查错、打包、部署环节由它自己在流水线里跑，这正是它与普通对话式编程助手的本质区别。

**▌ 它解决了什么问题**：传统 AI 编程助手常卡在三个地方：需求模糊时乱猜、改动范围失控、写完不做验证。DevEco Code 解决的是"任务复杂度与自动化程度匹配"的问题。小修小补时你不想让它先写一份长计划，大特性开发时你又不敢让它直接开干。三种模式把选择权交回给你：Build 直接执行、Plan+Build 先想后做、Goal 全自动迭代。它同时解决鸿蒙开发专属的痛点——构建、推送模拟器这些环节被一并纳入流水线，不用你在 IDE、终端、模拟器之间来回切换。而免费 GLM 额度大幅降低了试错成本，让"让 AI 把需求干完"这件事从口号变成可日常使用的流程。

**▌ 核心原理拆解**：理解 DevEco Code 的原理，关键在于"模式即控制粒度"。Build 模式下，Agent 收到需求直接进入理解—生成—语法检查—修复—出包—推模拟器的循环，你只验收结果。Plan+Build 模式在前面插入一个规划阶段：Agent 结合工程目录、代码文件、依赖关系来理解背景，主动识别需求里的模糊点，用 Question 工具跟你交互补全，最后产出一份可执行的任务列表，再切回 Build 逐项跑。Goal 模式则是完全体：先交互完成需求分析、架构设计和任务拆分并生成结构化文档，随后进入自主迭代——写代码、查语法、编译打包、部署模拟器、自动验证，发现问题自己修，循环往复直到达成你定的目标。三种模式的差异，本质是"人什么时候介入"：任务越复杂，越应该把介入点前移到规划阶段，而不是等代码写歪了再补救。

**▌ 动手验证**：动手验证建议用一个完整的小需求走一遍 Goal 模式。第一步，按 `npm install -g @deveco/deveco-code@stable` 安装，运行 `deveco` 并用华为账号登录，确认 `/models` 里 GLM 模型可用。第二步，准备一个能正常启动的鸿蒙练习工程作为基线，这样后续改动才有可对照的验证标准。第三步，在 Goal 模式输入一句需求："做一个待办清单页，支持新增、删除、列表展示，新增后必须自动列出结果，并保证构建通过。"注意别只说"帮我实现功能"，要给出文件边界、验收标准和禁止事项。第四步，观察它先输出需求分析与任务拆分文档，核对是否合理；若它跳过检查现有代码就大范围重写，先要求它缩小改动并解释依据。第五步，进入自主迭代后紧盯每轮的测试输出——要求它贴出实际命令结果，而不是口头说"已修好"。最终你会得到一个构建通过、能在模拟器打开的页面。关键心得：复杂任务先 Plan 再 Build，比直接甩给 Goal 更可控。

**▌ 对比选型**：把 DevEco Code 和通用编码 Agent 对比，边界很清楚。与 Claude Code、Codex 相比，它的独特价值是鸿蒙工具链原生打通、GLM 额度免费，适合鸿蒙应用开发；但通用性和生态成熟度不如后者。与 Cursor 这类 IDE 内嵌工具相比，它是终端形态，更适合习惯命令行、要跑完整流水线的人。与只写代码不验证的助手相比，它把构建与模拟器推送纳入闭环。选型建议：做鸿蒙、想省 token 成本，选它；做跨平台 Web 项目，Claude Code 或 Cursor 更合适；只是随手改几行小代码，就不必开 Goal 模式这种"重武器"。

### 3. 【Fleeep】免费笔记不拿你数据训练

**▌ 导语**：在 AI 笔记工具动不动"拿你的内容训练模型"的当下，11月7日冲上 Product Hunt 日榜第一的 Fleeep 走了一条反方向的路：免费，把截图、书签、语音笔记收进一个安静的地方，并明确承诺不用你的数据训练。它不追求"帮你生成内容"，而是先把你散落各处的原始素材归拢好、找得回。上线首日它就被评价为"解决了一个真实问题，而不是给聊天机器人套个壳"。对既想用 AI 整理资料、又担心隐私泄露的记者、学生和素材工作者，这款小工具值得认真认识。

**▌ 它是什么**：Fleeep 是一款免费的笔记聚合应用，核心动作是"收"——把网页截图、收藏的书签、随手录的语音笔记统一丢进一个时间线式的收纳盒，再提供检索与整理。它与主流笔记工具最大的不同是数据立场：公开声明不将用户内容用于模型训练，这在以"AI 能力"为卖点的同类产品里相当少见。它上线首日即在 Product Hunt 拿下当日第一，被媒体列为本月"最低风险的试水选择"：免费、无训练、解决真问题。免费是它的重要标签，没有强制订阅门槛，你可以零成本判断它是否适合自己的资料习惯。

**▌ 它解决了什么问题**：很多人的资料散落在微信收藏、浏览器书签、相册截图、录音机里，要用时怎么也找不回来。Fleeep 解决的是"碎片素材的统一入口"问题：先把它们收进一个地方，再谈 AI 整理。它还解决一个更隐秘的焦虑——当你把私人笔记喂给 AI 时，这些内容会不会变成别人模型的训练数据。Fleeep 用"不训练你的数据"把这条顾虑直接划掉，让你敢把真实素材放进来。对内容创作者而言，它把"收集—沉淀—调用"的第一步变得没有负担：免费又克制，意味着你不必在"效率"和"隐私"之间做痛苦取舍。

**▌ 核心原理拆解**：Fleeep 的原理可以拆成"采集归一化 + 本地优先存储 + 检索增强"三层。采集层把不同来源——截图、链接、音频——转成统一记录的元数据，打上时间与来源标签，让异构素材进入同一条时间线。存储层强调对用户数据的克制：不训练、不外泄，把隐私边界写进产品承诺，这也是它敢让人放心收素材的底气。检索层则让你可以按关键词、时间或来源把旧素材重新翻出来，必要时再借模型做摘要。它并不是靠"生成能力"取胜，而是把"记得住、找得到、不越界"这三件事做扎实。理解这层原理，你就不会拿它去和写作 AI 比谁更会写，而会把它当成整个资料流的素材底座。

**▌ 动手验证**：动手验证可以从一次"资料归拢"开始。第一步，下载 Fleeep，用最轻量的方式建一个收纳空间，先别急着分类。第二步，把手头三类素材各丢两条进去：一张网页截图、两个收藏书签、一段手机录的语音备忘，观察它是否自动打上时间和来源标签。第三步，用关键词搜索其中一条内容，验证它能否在几秒内定位——这是判断"找得回"是否成立的关键一步。第四步，专门检查它的隐私设置，确认"不用于训练"的选项处于开启状态，再决定要不要放入更敏感的素材。第五步，试着把一周的零散素材连续收进来，看看时间线是否帮你补上了原本会遗忘的脉络。关键心得：它最值钱的地方不是替你写，而是让你敢于把原始素材交出去；先养成为期一周的"随手收"习惯，再谈用 AI 做二次整理。

**▌ 对比选型**：把 Fleeep 和同类对比，定位差异很明显。与 Notion AI 相比，Notion 强在结构化协作与工作区问答，Fleeep 强在"收得快、不训练数据"的轻量与隐私。与印象笔记这类老牌笔记相比，它更聚焦多模态碎片的聚合，而不是长文编辑。与各类"AI 写作笔记"相比，它主动放弃生成能力，换取数据克制，这是一种清晰的取舍而非功能缺失。选型建议：重视隐私、只要一个安静的素材收纳盒，选 Fleeep；需要团队协作和复杂知识库，用 Notion；要长文档编辑，传统笔记工具更顺手。

### 4. 【墨刀】自然语言生成可交互原型上手

**▌ 导语**：做产品原型最耗时的往往不是画图，而是把"预约流程""提交表单"这些环节串成能点、能走通的东西。国产工具墨刀近年在原型环节加入了 AI 能力，可以用自然语言先搭出页面骨架和基础交互，再在可视化画布里继续修改。它的定位很清楚：先验证流程是否成立，再打磨视觉。对没时间学专业设计工具的产品经理、运营和创业者，这是一条能快速把点子变成可点击原型的捷径，而且全程在中文语境里完成，协作和交付也更贴合国内团队习惯。

**▌ 它是什么**：墨刀是一款国产的在线原型与界面设计协作工具，提供界面设计、原型、协作与交付能力，并引入 AI 辅助设计创作。它支持通过自然语言辅助生成原型，再结合组件、交互和预览继续修改。和纯代码生成工具不同，墨刀产出的是可点击的原型稿，重点是"流程走得通"——用户能否完成预约、提交表单、修改订单。它把 AI 生成放在流程验证这一段：你先用一句话拿到初稿，再用组件库和交互面板补齐空状态、错误提示和返回操作，让原型从"能看"变成"能走"。

**▌ 它解决了什么问题**：传统原型要先学工具、拖组件、连交互，门槛并不低；而很多点子在验证阶段根本不值得投入这么多精力。墨刀解决的是"想法到可点击验证之间的成本"问题——用自然语言生成把第一步压缩到几句话，让你把精力放在"流程对不对"而不是"组件摆得齐不齐"。它还解决团队协作中的交付问题：原型、组件和反馈留在同一项目里，减少设计与开发之间的来回确认。对国产团队而言，本地化的协作链路和交付格式也是它相较海外工具的实用优势，不必再为语言和网络折腾。

**▌ 核心原理拆解**：墨刀 AI 原型的核心原理是"模板化布局 + 组件的语义绑定 + 交互状态机"。当你输入一句自然语言需求，系统先把它映射到预设的页面模式库——列表页、表单页、详情页等，生成带占位内容的页面骨架；接着把按钮、输入框等元素绑定到组件库中的真实组件，使它们能被后续编辑；再为页面挂上跳转、弹窗等交互状态，形成可点击的流程。这里的关键认知是：AI 给的是"能走的流程稿"，不是"能上线的产品"。所以第一次生成后，要用一个具体任务把路径完整走一遍，补齐空状态、错误提示和返回操作，验证流程是否真的闭环。理解这一层，你就不会把初稿当终稿，也不会因为细节缺失而误判工具能力。

**▌ 动手验证**：动手验证建议用一个"预约改版"的小流程起步。第一步，打开墨刀新建项目，在 AI 辅助入口输入："做一个门店预约流程：选择日期、选择时段、填写手机号、确认提交，提交后显示成功页。"第二步，拿到初稿后先别急着美化，用一个具体任务把路径完整走一遍——从选日期一路点到成功页，记录哪里卡住。第三步，补齐 AI 容易漏掉的细节：空状态（无可选时段）、错误提示（手机号格式错误）、返回操作（从上一步退回）。第四步，把这些页面和已有的设计规范对齐，让新页面沿用项目里的组件和状态定义，减少生成稿与现有产品之间的差异。第五步，把原型分享给同事点一遍，收集反馈后再决定是否进入视觉打磨。关键心得：AI 帮你跳过的是画第一张图的时间，跳不过的是"用真实任务把流程走通"的验证。

**▌ 对比选型**：把墨刀放进原型工具里对比会更清楚。与 Figma、Framer 这类偏设计与发布的工具相比，墨刀的强项是中文语境、流程验证和快速交付，弱项是高阶视觉设计与生态扩展。与 v0、Lovable 这类直接出代码的网页生成工具相比，墨刀交付的是可点击原型而非可部署代码，更适合验证阶段。与国产同类 Pixso 相比，墨刀更偏流程原型，Pixso 更偏界面设计与协作交付。选型建议：想快速验证流程、又要国产协作，选墨刀；要精致视觉或前端代码，分别用 Figma 或 v0。

### 5. 【PasteGuard】剪贴板密钥本地打码不上云

**▌ 导语**：把一段包含 API Key 的配置贴进 AI 聊天窗口问问报错，是很多开发者的日常，也是最容易泄密的瞬间。11月4日上线的 macOS 小工具 PasteGuard 就是为这一刻准备的：当你复制的内容里含有密钥或个人敏感信息，它会在剪贴板层面自动打码，贴进对话的是掩码而不是真值；需要时一个"Restore"动作又能把真实值还原回来。全程不需要账号、不申请额外权限、数据不离开你的 Mac。它解决的不是"生成什么"，而是"别把秘密交出去"——对几乎每周都会把凭证贴进对话框的开发者，这是刚需级的防护。

**▌ 它是什么**：PasteGuard 是一款面向 Mac 的剪贴板隐私保护工具。它常驻后台"看守"剪贴板，一旦检测到符合规则的内容——如 API Key、令牌、身份证号等，就用掩码替换后再供你粘贴。你可以添加自定义规则、导入 CSV 词表、维护忽略列表，还能在误判时用 Restore 把原值放回。它的设计哲学是"最小权限 + 本地处理"：无账号、无云同步、不申请系统辅助权限，所有判断都在本机完成。它特别适合"经常把凭证或个人数据复制粘贴到 AI 对话"的人——这几乎包括每个开发者，以及每周至少干一次这种事的普通用户。

**▌ 它解决了什么问题**：AI 助手越用越深，人们习惯把报错日志、配置片段整段贴进对话框，里面往往夹着密钥、Token 甚至客户数据。一旦这些内容进入第三方对话，就可能留在日志里或被用于改进模型。PasteGuard 解决的是"复制粘贴这一秒的泄密"：在你无意识地粘贴之前，先替你把秘密遮住。它也解决"知道该小心却总忘"的人性问题——不需要你每次手动检查，而是把保护变成默认动作。配合"永远不手动输入秘密进对话"的习惯，它把最危险的泄密路径堵上，让你在享受 AI 便利的同时不必时刻提心吊胆。

**▌ 核心原理拆解**：PasteGuard 的原理是"剪贴板钩子 + 规则匹配 + 可逆掩码"。它在系统剪贴板层注册监听，当你执行复制动作时读取内容，用正则、自定义规则和导入的词表进行模式匹配；命中后不是删除，而是用掩码字符串替换剪贴板内容，这样你粘贴出去的是无害的假值。可逆性是关键设计：真实值被暂存在本机，点击 Restore 时把剪贴板还原成原值，方便你贴进真正需要的地方，比如代码编辑器或密钥管理后台。整个过程不联网、不申请辅助权限，靠 macOS 提供的剪贴板访问能力完成。理解这个原理你就明白它的边界：只有秘密正处在剪贴板里（也就是你确实复制了它）才可能被遮住；如果你是手打进对话，它无能为力。

**▌ 动手验证**：动手验证要从"确认规则是否覆盖你的秘密格式"开始。第一步，安装 PasteGuard 并确认它常驻后台，先用自己的一段假密钥测试：复制一个形如 `sk-xxxx` 的字符串，再粘贴到备忘录，看它是否变成掩码。第二步，进入设置添加你们公司的密钥前缀规则，或导入一份 CSV 词表，把你常用的凭证格式都列进去。第三步，维护忽略列表——把那些你确信不敏感、但总被误判的内容加进去，避免影响正常复制。第四步，测试 Restore 功能：确认打码后能把真实值原样还原到剪贴板。第五步，找一段真实工作场景的报错日志（含假密钥）贴进 AI 对话，确认秘密没有以明文出现。关键心得：掩码只在"你复制了秘密"时生效，所以配合"永远不手输秘密"的习惯才完整；免费版已经够用，但规则覆盖一定要自己验证过才算数。

**▌ 对比选型**：把 PasteGuard 和其他隐私方案对比，边界清晰。与密码管理器自带的"复制后自动清空剪贴板"相比，PasteGuard 专注"AI 对话输入"这一高危场景，且可逆还原更灵活，不会让你贴到一半发现值没了。与企业级 DLP（数据防泄漏）系统相比，它是面向个人的轻量本地工具，无需部署、即装即用。与手动检查再粘贴相比，它把保护变成自动动作，不依赖你的自制力。选型建议：个人开发者、经常把配置贴进 AI，选它；企业统一管控的数据防泄漏，需要专业 DLP 方案；偶尔用 AI、内容不敏感的人，保持手动警惕就够。

### 6. 【CodeBuddy子代理】给AI编程配一支虚拟团队

**▌ 导语**：当编码 Agent 能读代码、改文件、跑命令，单线程作战的瓶颈就从"写得不够快"变成"上下文被污染、任务互相干扰"。CodeBuddy Code 提供的"子代理（Subagents）"功能，正是为这个问题而来：你可以预配置一批有专门身份、专属工具和独立上下文窗口的 AI 助手，遇到匹配的任务就委派出去，它们独立干完再把结论交回主对话。到 11月，这套能力的文档与使用方式已经相当完整。对想把 AI 从"一个通才"升级成"一支分工团队"的开发者来说，这是值得花十分钟上手的一招。

**▌ 它是什么**：子代理是 CodeBuddy Code 中预配置的专门 AI 人格，可被主对话按任务领域调用。每个子代理都有明确的目的、独立的上下文窗口、可配置的工具权限和自定义系统提示。当你遇到与某个子代理专业领域匹配的任务，CodeBuddy Code 会把任务委派给它，子代理在自己的上下文里独立工作，完成后把结果返回主对话。这样一来，代码审查的来回、测试的报错都不会挤占你的主工作区。子代理创建后可以跨项目复用，也能在团队之间共享，形成一致的工作流——它本质上是一套"委派 + 隔离"的工程化机制，而不是多开几个聊天窗口。

**▌ 它解决了什么问题**：单 Agent 处理复杂项目有三大痛点：上下文越滚越长导致失焦、不同任务需要不同工具权限却难以隔离、专业能力难以复用。子代理解决的是"上下文保留与专业化"：每个子代理在自己的上下文里运行，主对话保持干净；审查、安全、测试等不同领域可各配一个子代理，各自带领域提示，提高专业任务的成功率；权限上可以给只读子代理放行、给危险操作单独审批，把强大工具限制在可信范围。它还解决"可重用性"——一次创建、多个项目复用、团队共享一致流程。对需要"审查—编码—测试"流水线的人，这相当于凭空配了一支各司其职的虚拟团队。

**▌ 核心原理拆解**：子代理的原理是"委派 + 上下文隔离 + 权限分级"。主对话遇到任务时，依据子代理的描述判断是否匹配，匹配则把任务连同一份独立上下文交给它；子代理按自己的系统提示和可用工具执行，全过程不写回主对话历史，只在结束时回传结论，从而避免污染主上下文。配置上，子代理以带 YAML 前置的 Markdown 文件存储：项目级放在 `.codebuddy/agents/`，用户级放在 `~/.codebuddy/agents/`，同名时项目级优先。文件里定义名称、描述、工具白名单和系统提示，你可以让 AI 先生成草稿再自己改。关键设计点是"工具权限可按子代理分配"——把高能工具限制在特定类型，是控制风险的核心。理解这层，你就明白子代理不是噱头，而是有隔离、有权限、有复用的正经委派机制。

**▌ 动手验证**：动手验证可以从创建一个"代码审查子代理"开始。第一步，在 CodeBuddy Code 中运行 `/agents`，选择"创建新代理"，并决定放项目级还是用户级——想团队共享就放用户级。第二步，详细描述它的职责，例如："你是一名资深代码审查者，只在被要求时审查最近改动，重点看权限、密钥、依赖和边界条件，只报告风险，不改代码。"第三步，选择授予的工具：审查类只需只读工具，千万别给写权限。第四步，保存后显式调用："使用 code-reviewer 子代理检查我最近的更改"，观察它独立返回一份风险清单，而主对话上下文保持干净。第五步，迭代优化：若它返回无关内容，就回去收紧系统提示的工具白名单与职责边界。最后把它共享给团队，统一审查标准。关键心得：子代理的价值在"隔离与复用"，别把所有工具都塞给同一个子代理，那等于没隔离。

**▌ 对比选型**：把子代理和其他方案对比，差异明确。与在主对话里切换话题相比，子代理提供真正的上下文隔离，不会把审查噪音带进主任务。与多开几个 AI 会话相比，它可配置、可共享、可复用，适合团队长期沉淀。与通用的"多智能体框架"相比，它内置在编码工具里、开箱即用，但生态扩展性不如独立框架。选型建议：想在一个项目里分工做审查、编码、测试，用子代理；只是偶尔换个话题，主对话切换即可；要复杂的跨工具编排，再考虑独立多智能体框架。

### 1. 【MoE专家路由：无辅助损失的Sigmoid偏置均衡成主流】（L1）

> 📍 **导语**：2026 年开源前沿模型几乎集体转向 MoE：DeepSeek-V4-Pro 用 384 个专家、Kimi K2、Qwen3.6、GLM-4.5 都是稀疏激活架构。但真正决定这类模型服务成本和质量的，并不是专家数量，而是“路由”——每个词元该交给哪几个专家处理。本周多项研究（arXiv:2611.09252、DeepSeek-V3 技术报告）集中指向一个结论：用无辅助损失的 Sigmoid 偏置均衡，正在取代传统带辅助损失的 Softmax Top-K，成为 2026 年主流做法。理解路由，才能看懂大模型为什么“总参数巨大、显存却不大”。

---

**🧠 深度解析**

**▌ 它是什么？**
MoE（混合专家）路由是一套轻量的“门控网络”，它对每个输入的词元打分，只激活少数几个专家子网络，其余参数休眠。常见误区是以为“路由＝选最好的专家”，其实它同时承担负载均衡的职责：如果所有词元都涌向同一批专家，就会形成“路由坍缩”，其余专家永远学不会东西。历史上从 Switch Transformer 的 Top-1、GShard/Mixtral 的 Top-2，到 DeepSeek-V3 的“共享专家＋路由专家”组合，路由策略一直在算力和均衡之间找平衡。它与当下热点直接相关：本周美团 LongCat-2.5（1.6T MoE）、Kimi K3.1 Pro（2.8T MoE）、百度 ERNIE 5.5 Flash（280B MoE）的密集发布，背后都是路由技术的成熟。

**▌ 它解决了什么问题？**
Before——早期 MoE 必须加一个“辅助负载均衡损失”，强迫词元均匀分流到各专家，但这个损失会和主任务目标打架，且常带来质量损失；同时 Softmax Top-K 对超大规模（上百专家）的通信和显存不友好。After——Sigmoid 打分＋无损失偏置均衡：给每个专家加一个不参与梯度的偏置项，训练时哪边过载就把偏置调低、空闲的调高，既消灭了干扰性梯度，又把负载失衡指标 MaxVio 从 0.72 降到 0.04（1B 规模实测）。量化收益：同样质量下，省掉辅助损失带来的训练不稳定；在 384 专家规模上仍能保持均衡，使单卡/单节点能服务更大的有效参数量。近期 DeepSeek-V4、GLM-4.5 都采用该方案。

**▌ 核心原理拆解**

**第一层：直觉理解**——把 MoE 想象成一家大公司，接到任务（词元）后，不是全员上阵，而是由前台（路由器）判断该派哪两三个专家小组处理。问题在于如果前台总把活派给同一批“明星员工”，其他人就废了——所以需要一套调度机制让工作量大致公平。

**第二层：技术流程拆解**——输入 → 路由器对全部 E 个专家线性打分 s＝x·R → Sigmoid/Softmax 得到分数 → 取 Top-k → 用原始分数做权重加权求和专家输出 → 只激活这 k 个专家。关键在于：无损失偏置是在“选 Top-k”这一步才把偏置加上（偏置不进梯度），选完再用无偏的原始分数算混合权重。训练每步后，按各专家实际负载更新偏置：过载专家偏置－δ，空闲专家偏置＋δ。

**第三层：公式与核心机制**——为什么偏置“无梯度”很重要？传统辅助损失 LBL 把“各专家选中频率×平均路由权重”作为惩罚项加进总损失，它会引入与任务无关的梯度，干扰主目标；而无损失偏置只是一个外部控制量，像 PID 控制器里的积分项（arXiv:2611.09252 把这类方法统一为“积分控制器”），只根据实测负载误差做修正，不影响主损失。这样在保持质量的同时消除失衡。

**▌ 动手验证**

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch
# DeepSeek-V3 风格的 MoE，router_logits 可观察每个专家得分
model = AutoModelForCausalLM.from_pretrained(
    "deepseek-ai/...", torch_dtype=torch.bfloat16, device_map="auto")
tok = AutoTokenizer.from_pretrained("deepseek-ai/...")
inp = tok("请解释混合专家模型", return_tensors="pt").to(model.device)
out = model(**inp, output_router_logits=True)   # 需模型支持该参数
logits = out.router_logits[0]            # 形状 [层, 词元, 专家数]
topk = logits.topk(2, dim=-1)            # 每个词元选 Top-2 专家
print("每词元激活的专家:", topk.indices[0].tolist())
```

注意：并非所有开源 MoE 都暴露 router_logits；若报错可改用 `model.config.num_experts` 查看专家数，或加载 DeepSeek-V2/V3 的建模文件。预期输出显示每个词元被分到 2 个专家。

**▌ 对比选型**

| 维度 | Sigmoid无损失偏置 | Softmax+辅助损失 | Expert-Choice |
|------|------|------|------|
| 核心思想 | 偏置控均衡,原始分定权重 | 辅助损失逼均匀 | 专家反选token |
| 适用场景 | 大规模前沿MoE | 中小规模MoE | 非因果任务 |
| 负载均衡 | MaxVio 0.72→0.04 | 需调损失权重 | 天然均衡 |
| 学习成本 | 低(无额外损失) | 中(调系数) | 高(泄漏风险) |

### 2. 【GRPO组相对策略优化：去掉Critic让RL训练省一半显存】（L2）

> 📍 **导语**：本周多模态与推理模型竞赛进入“强化学习深水区”：马斯克称 Grok4.8 进入 RL 阶段，XAI、DeepSeek、阿里 Qwen、Kimi 都靠 RL 把推理能力拉满。而支撑这一波后训练的主流算法正是 GRPO（组相对策略优化）——DeepSeek-R1 背后的关键技术。相比老牌 PPO，GRPO 最大的卖点是“不要价值网络（Critic）”，显存直接砍掉约一半。最新研究还把 GRPO 延伸到“接地引导 GRPO（GD-GRPO）”用于视觉智能体（arXiv:2611.12886）。理解 GRPO，等于理解 2025-2026 年几乎所有开源推理模型的训练引擎。

---

**🧠 深度解析**

**▌ 它是什么？**
GRPO 是一种面向 LLM 的强化学习算法，由 DeepSeek 在训练 DeepSeekMath 时提出，后被 DeepSeek-R1 推到聚光灯下。它的核心定义是：对同一道题目（prompt）采样一组 G 个回答，用这组回答奖励的均值和标准差做“组内归一化”，得到每个回答的相对优势，再拿这个优势去更新策略。它最常见的误区是“GRPO 就是更简单的 PPO”——其实本质改变是优势估计方式：PPO 靠一个和策略同规模的价值网络估值，GRPO 直接拿“同组其它样本”当基线。它天然契合可校验奖励（数学对错、代码能否跑通）。历史脉络：从 PPO（需 Critic）→ GRPO（去 Critic）→ 衍生 DAPO、GSPO、Dr.GRPO、GDPO 等改进。本周 Reframe 论文的 GD-GRPO 就是其中之一。

**▌ 它解决了什么问题？**
Before——PPO 在大模型上要维护一个与策略模型几乎同规模的 Critic 网络，带来巨大显存与算力开销，这是很多团队跑不起 RL 的主因（7B 模型上相当于“8 张 H100 跑得起来 vs 16 张才跑得起来”的差别）。After——GRPO 去掉 Critic，显存约省一半；组归一化还顺手消解了大部分 reward scale 的麻烦。量化收益：典型组大小 G＝8~64，二值奖励（对/错）下，组内白化在同一 prompt 的成功/失败回答间产生干净对比信号；在 MATH-500 上，相关无标签 RL 方法让 Qwen2.5-Math-7B 从 56% 提升到 79.5%。近期 DeepSeek-R1、Qwen、OLMo 3 等大量推理模型都采用 GRPO 或其变体。

**▌ 核心原理拆解**

**第一层：直觉理解**——考试时你不知道一道题的标准分是多少，但能横向比：同一道题让同学做 G 份，大家平均得分当“及格线”，高于平均的回答被鼓励、低于的被抑制。GRPO 就是用“组内相对论”替代“绝对评分”。

**第二层：技术流程拆解**——对 prompt x：①从当前策略采样 G 个 rollout y1..yG（典型 G＝8~32）；②用验证器对每个打分 ri（常是 0/1 或可校验分数）；③算组内均值 μ 和标准差 σ；④优势 Ai＝(ri－μ)/σ（全零/全一组要加 ε 或过滤，否则除零）；⑤代入 PPO 式 clipped 目标，并加对参考策略的 KL 惩罚（β 常 0.001~0.04）。整批更新只靠组内相对差异。

**第三层：公式与核心机制**——为什么去 Critic 还能稳定？因为同一 prompt 的多个 rollout 共享同一基线 μ，方差主要由“组内差异”贡献，而 reward scale 被 σ 白化掉，因此不需额外网络估值。但代价是：依赖单一标量奖励，难联合优化多属性；且全成功/全失败组（标准差 0）会导致优势爆炸或消失，需过滤退化 prompt。GRPO-Guard 等变体专门处理视觉生成流中的过优化。

**▌ 动手验证**

```python
from trl import GRPOConfig, GRPOTrainer

cfg = GRPOConfig(
    num_generations=8,        # 组大小 G
    max_completion_length=512,
    beta=0.04,                # KL 惩罚系数
    learning_rate=1e-6,
    output_dir="grpo-math",
)

def reward_correct(completions, **kw):
    # 验证器：答案正确给 1，否则 0
    return [1.0 if is_correct(c) else 0.0 for c in completions]

trainer = GRPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    reward_funcs=reward_correct,
    args=cfg, train_dataset=math_ds,
)
trainer.train()   # 同一 prompt 采样 8 份，组内归一化更新
```

注意：GRPO 对奖励形态极敏感，0/1 奖励与稠密奖励训出差异很大；组大小 G 越大方差越低但 rollout 数线性增加。

**▌ 对比选型**

| 维度 | GRPO | PPO | DPO |
|------|------|------|------|
| 核心思想 | 组内相对优势,无Critic | 需价值网络估优势 | 直接偏好对比 |
| 适用场景 | 可校验奖励的推理/代码 | 通用RLHF | 离线偏好数据 |
| 显存开销 | 约省一半 | 高(同规模Critic) | 低 |
| 学习成本 | 中(调G/β/奖励) | 高(调Critic/GAE) | 低 |

### 3. 【扩散模型蒸馏：把50步生成压到1-4步的少步采样】（L3）

> 📍 **导语**：视频生成正从“等几分钟”走向“实时可交互”。NVIDIA Cosmos Lab 本月开源的 rCM/Causal rCM，把原本 50-100 步的扩散采样压到 1-2 步，在 14B 参数视频模型上提速 15-50 倍，VBench-T2V 仍达 84.63；同时 Pika H3 Flex 把采样从 50 步压到 6 步、Qwen-Image 2.1 做到 4 步出图。这些背后是“扩散蒸馏”这一工程主线：用一个小模型去学会大模型多步去噪的“终点”，跳过中间过程。理解它，就理解了为什么 2026 年的 AI 视频能塞进手机、能边生成边播放。

---

**🧠 深度解析**

**▌ 它是什么？**
扩散模型蒸馏，是一类把“多步迭代去噪”压缩成“少步甚至单步生成”的训练技术。常见误区是把它等同于“更简单的小模型”——其实蒸馏是让一个学生模型去逼近教师扩散模型的输出分布，质量来自对教师轨迹的学习。它的适用边界：少步采样在图像/视频生成上最成熟，但在需要极高保真或复杂结构的场景仍有质量损失，常需配合对抗或分数正则。历史脉络：从渐进式蒸馏（Progressive Distillation）→ 一致性模型（Consistency Models/LCM）→ 分布匹配蒸馏（DMD）→ 2026 年的分数正则连续时间一致性模型（rCM）。本周 Causal rCM 还加入“因果流式”模式，支持逐帧实时输出。

**▌ 它解决了什么问题？**
Before——标准视频扩散每个片段要做 50-100 次完整前向，单片段动辄秒到分钟级，根本无法做直播、手机创作或实时游戏交互。After——蒸馏把采样降到 1-4 步。量化收益：传统扩散单帧 100 步×120 帧＝12000 次运算，一致性扩散单帧 7 步×120 帧＝840 次，提速约 14 倍；rCM 在 Wan2.1（1.3B 学生）上 1-2 步达 VBench 84.63，比需 4-8 步的同类蒸馏更省；MobileI2V 更在 iPhone 16 Pro Max 上 2.24 秒生成 720p 视频。近期 Pika H3 Flex（6 步）、Qwen-Image 2.1（4 步）、Runway/Seedream 等都受益于该路线。

**▌ 核心原理拆解**

**第一层：直觉理解**——扩散像“慢慢把模糊照片一点点变清晰”，要走 100 小步；蒸馏相当于训练一个人“无论看到多模糊的初稿，都能直接猜出最终清晰图”，于是一步到位。

**第二层：技术流程拆解**——教师扩散模型定义从噪声到数据的轨迹；①训练学生网络 f，使其对任意噪声水平 x_t 都映射到同一“干净终点” x_0（一致性约束）；②用教师模型的 score 函数做分数正则，避免小步数下的误差累积与模式覆盖偏差（rCM 的关键）；③推理时从纯噪声出发，只跑 1-4 次 f 即可出图/视频。Causal 变体改为逐帧生成，每帧以已生成帧为条件，并用 KV 缓存保持时序一致。

**第三层：公式与核心机制**——为什么需要“分数正则”？标准一致性模型（sCM）在细节生成上有质量瓶颈，源于其前向散度目标的“模式覆盖”特性会累积误差；rCM 引入反向散度（score distillation）作长跳跃正则，补齐“模式寻求”能力，在提质同时保持多样性，无需 GAN 调参。连续时间训练让学生从完整噪声水平分布学习，而非离散子集，这也是激进降步后质量不崩的原因。

**▌ 动手验证**

```python
from diffusers import DiffusionPipeline
import torch
# 以 LCM（潜空间一致性模型）为例，4 步出图
pipe = DiffusionPipeline.from_pretrained(
    "latent-consistency/lcm-sdxl", torch_dtype=torch.float16)
pipe.to("cuda")
img = pipe(
    prompt="一只戴墨镜的猫在霓虹街头",
    num_inference_steps=4,   # 普通 SD 要 20-50 步，LCM 只要 4 步
    guidance_scale=8.0,
).images[0]
img.save("cat.png")
print("4 步生成完成")
```

注意：少步模型对 guidance_scale 敏感，步数过低易出现模糊/结构错误；生产可用 rCM 类权重做视频。预期：4 步即可得到可用图像。

**▌ 对比选型**

| 维度 | 一致性蒸馏(rCM) | 渐进式蒸馏 | GAN对抗蒸馏 |
|------|------|------|------|
| 核心思想 | 分数正则一致性,连续时间 | 逐步减半步数 | 判别器逼真实 |
| 适用场景 | 大参数视频/图像 | 通用扩散 | 追求锐利细节 |
| 步数 | 1-4步 | 4-8步 | 1-4步 |
| 多样性 | 高(保多样) | 中 | 易模式崩塌 |

### 4. 【解耦视觉编码：专用视觉容量比预训练先验更重要】（L4）

> 📍 **导语**：多模态大模型怎么“看”图，一直是个被含糊处理的问题：大多数模型挂一个预训练好的视觉编码器（如 CLIP），再接语言模型；新一些的配方则从头训编码器，甚至干脆去掉编码器让主干直接吃图像块。本周 NYU 与 Meta FAIR 的论文《Unbundling Multimodal Vision Encoding》（arXiv:2611.17334，2026-11-12）用严格控制实验把这团乱麻拆开，结论反直觉：独立的视觉预训练先验并非必需，真正重要的是“专用视觉容量”，而且它可以放在主干早期层内（in-fusion），在保持质量的同时降低首字延迟（TTFT）。这对想自己训 VLM 的团队是降本增效的直接指南。

---

**🧠 深度解析**

**▌ 它是什么？**
视觉编码“解耦”指的是把视觉编码器这一组件里捆绑的三项设计决策拆开单独评估：①视觉先验（是否用上游预训练的知识）、②专用容量（是否保留只服务图像的参数）、③放置位置（在融合前还是融合内）。常见误区是“去掉编码器＝模型更轻”——论文证明，即便把主干放大到等同编码器的参数量，无编码器的模型在视觉理解上仍落后，说明缺的是“专用容量”而非“参数总量”。它适用边界：结论在 1.7B~6.4B 主干规模成立，超大前沿规模（70B+）是否一致仍待验证。历史脉络：从 CLIP 式预训练编码器 → 联合从头训编码器 → encoder-free → 本周提出的 in-fusion 早期层内放置。

**▌ 它解决了什么问题？**
Before——业界比较 VLM 配方时，数据、架构、算力都不同，一个模型赢了，你根本说不清是预训练赢了、容量赢了还是融合设计赢了；而且保留独立预训练编码器意味着多一段训练流程和高昂上游算力。After——论文在“终身算力（lifetime compute，含上游预训练）”对齐下比较：从头联合训的编码器与预训练编码器表现持平（先验非必需）；而把专用视觉容量放进主干最早几层（in-fusion），质量与预融合编码器相当，还能降低首字延迟（TTFT）。量化收益：跳过独立编码器预训练阶段，训练管线大幅简化；in-fusion 设计减少跨模块通信，TTFT 更低。近期趋势（如原生多模态 Ling-3.2-flash、Qwen3.8-VL）正呼应“专用容量＋早期融合”的方向。

**▌ 核心原理拆解**

**第一层：直觉理解**——好比一个通用团队要处理图像，传统做法是先请一位“有经验的专家”（预训练编码器）单独预处理；论文发现，专家带来的“经验”未必关键，关键是为图像工作预留“专职人手”（专用容量），而且这些专职人手坐在团队内部早期工位（早期层）比坐在团队门口（预融合）更高效。

**第二层：技术流程拆解**——输入 224×224 图像切成 14×14＝256 个图像块 → 线性嵌入成视觉 token → 三种配方对比：①预训练编码器：独立上游训好的编码器＋投影；②从头编码器：同架构但与主干联合从零训；③无编码器：图像块直接进主干；④in-fusion：在主干最早几层插入只处理图像的视觉模块。所有配方在同一数据（Nemotron-CC 文本＋MetaCLIP 图文）、同一主干（Qwen3 式 dense）、同一终身算力下训练，再在 VQA 与语言基准上比。

**第三层：公式与核心机制**——关键发现用控制变量表达：在匹配终身算力时，Scratch 编码器≈预训练编码器（先验不必需）；但 Encoder-free 即使主干放大到“吃掉”编码器参数量，视觉理解仍掉队（专用容量必需）；而 in-fusion 把专用容量放在早期主干层，靠缓存已算特征避免重复跨模块通信，既保质量又降 TTFT。注意评估分辨率升到 448×448（1024 视觉 token），细节任务更受益。

### 5. 【激活引导：不改权重在推理时微调模型行为】（L1）

> 📍 **导语**：想让模型更“安全”、更“礼貌”或改变某种风格，不一定非要重新训练。本周 ICLR 2026 与 EMNLP 2026 连续出现多篇“激活引导（Activation Steering）”工作：它直接在推理时往模型内部激活值上加/减一个方向向量，就能改变拒绝、安全或风格表现，成本低、可解释。Apple 还提出“动态缩放引导”按上下文调强度。但它也有脆弱的一面：《The Sharp Directions Are Against You》（arXiv:2610.16084）指出标准 CAA 方法在不少输入上会“反向引导”。理解这项技术，是从“调权重”转向“调机制”的关键一步。

---

**🧠 深度解析**

**▌ 它是什么？**
激活引导是一种推理时行为控制技术：找到模型中代表某种概念（如“拒绝”“有害”“礼貌”）的激活方向向量，在生成时把这个向量加到指定层的激活上，从而在不训练、不微调的前提下改变模型行为。常见误区是以为它“和提示词一样但更便宜”——其实它改的是内部表征，比提示更底层，但也更脆弱、副作用更难评估。适用边界：适合轻量、可逆的行为干预；不适合需要精确、稳定控制的严肃安全场景。历史脉络：从对比激活加法（CAA）→ 模仿提示的 PSR 模型（ICML 2026）→ 带反馈控制的 PID Steering（ICLR 2026）→ 动态缩放（Apple）。

**▌ 它解决了什么问题？**
Before——要改变模型行为，传统做法是收集数据做 SFT 或 RLHF，周期长、成本高、且不可逆（改了权重）。After——激活引导零训练、秒级生效、随时可撤。量化收益：相比全参数微调，它不占训练算力；相比提示词，它在内部表征层面干预，对“模型本就会但不愿表达”的行为更有效。近期 Apple 动态缩放让引导在不同任务上更稳定；PID Steering 把引导建模为比例-积分-导数控制器，跨多模型、多基准比传统常数系数引导更鲁棒；EMNLP 2026 的“属性引导”还能针对特定人群生成定制解释。

**▌ 核心原理拆解**

**第一层：直觉理解**——把模型内部每个位置想象成一个有许多旋钮的仪表盘，某个旋钮拧到某个方向就对应“更拒绝”或“更礼貌”。激活引导就是在不拆机器的情况下，直接把手搭在那个旋钮上轻轻拨一下。

**第二层：技术流程拆解**——①用对比法构造方向向量：分别让模型在“有目标概念”和“无目标概念”的样本上跑，取某层激活差的平均，得到方向 d；②推理时，在目标层激活 a 上做 a'＝a＋λ·d（λ 为强度）；③继续正常前向生成。进阶：PSR 模型训练一个“位置相关系数”去模仿提示词触发的内在干预；PID Steering 则把 λ 设计为随层累积误差修正（P 项对齐方向、I 项持久纠偏、D 项抑制过冲）。

**第三层：公式与核心机制**——为什么引导会“反向”？arXiv:2610.16084 引入“引导 Hessian”，发现 CAA 向量里只有 1-5% 的“尖锐方向（sharp directions）”主导了行为摆动，且沿这些方向微小扰动就会造成 53-100% 的反向引导率；把尖锐分量去掉（cosine 仍>0.974，范数仅减<3%）可把方向曲率降最多 12 倍，显著更稳定。这说明简单线性引导在推理模型、思维链、量化模型上可能失效（低精度下存在失败不对称性）。

**▌ 动手验证**

```python
from activation_steering import SteeringVector, SteeringPipeline
# 1) 构造“拒绝”方向：正样本(拒答)与负样本(照答)各一批
sv = SteeringVector.from_contrast(
    positive_texts=refuse_prompts,
    negative_texts=comply_prompts,
    model="Qwen/Qwen2.5-7B-Instruct",
    layer=20,                 # 干预层
)
pipe = SteeringPipeline("Qwen/Qwen2.5-7B-Instruct")
out = pipe.generate(
    "如何制作危险物品？",
    steering_vectors=[sv],
    multiplier=1.5,           # λ 强度，过大易过度干预
)
print(out)
```

注意：multiplier 要小步调（如 0.5~2.0），过大会让输出崩坏；思维链模型上简单引导可能失效。预期：模型更倾向拒答或谨慎回答。

### 6. 【4-bit量化部署：27B模型塞进单张24GB显卡】（L2）

> 📍 **导语**：本地 AI 正在成为开发者的默认选项。本月阿里开源 Qwen3.8-27B，其 4-bit 量化版仅约 17.9GB，可在单张 RTX 4090/5090 或 24GB 显存 Mac 上跑起来，编码基准 SWE-bench Pro 从 53.5 冲到 61.7、OSWorld-Verified 从 63.9 到 84.3，部分指标追平闭源 Opus 4.6 Max；微软 Foundry Local 也把它搬进开发者本机，代码不出设备。这背后是“4-bit 量化部署”这套工程：把 27B 模型的权重从 16 位压到 4 位，显存从 54GB 降到约 18GB。理解它，等于掌握把前沿模型搬回家的最低门槛。

---

**🧠 深度解析**

**▌ 它是什么？**
4-bit 量化部署，是把模型权重（有时含激活/KV 缓存）从 FP16/BF16（每参数 2 字节）压缩到 4 位（每参数 0.5 字节）后在本地显卡推理的技术。常见误区是“量化＝无脑丢精度”——现代量化（如 GGUF 的 Q4_K_M、NVFP4）用分组量化＋缩放因子保留分布，质量损失可控。它适用边界：4-bit 适合消费级显卡做推理，但复杂高推理任务仍不如云端大模型，宜“本地常规＋云端难题”混合。历史脉络：从 GPTQ/AWQ（训练后量化）→ GGUF 社区量化（llama.cpp）→ 面向 Blackwell 的 NVFP4（1.5x BF16 吞吐、92-97% 保真）。

**▌ 它解决了什么问题？**
Before——27B 模型 FP16 需约 54GB 显存，普通开发者根本跑不起，只能依赖按 token 计费的云端 API，代码与上下文还要上传。After——4-bit 仅需约 13.5GB 权重（实测 Q4_K_M 文件 16.8GB、运行时 20-24GB），塞进 24GB 显卡。量化收益：免去持续 API 账单、数据不出本机（合规友好）、断网可用。实测 Foundry Local 在 RTX 5090 上长上下文（>131K token）持续吞吐优于 llama.cpp；NVFP4 在 Blackwell 上达 1.5x BF16 速度、92-97% top-1 保真。近期 Qwen3.8-27B、Microsoft Foundry Local、Unsloth 动态量化都把“单卡跑前沿”变成现实。

**▌ 核心原理拆解**

**第一层：直觉理解**——模型权重像一本超厚的说明书，原来每个字用 2 字节记；量化相当于把相邻一段字合起来只记一个“大概值＋比例”，整本书变薄到 1/4，翻起来快得多，只要比例选得好，意思基本不丢。

**第二层：技术流程拆解**——①校准：用一小批样本跑模型，统计每组的激活分布；②分组量化：把权重按小块（如 block）分成组，每组算一个缩放因子 scale 和零点，把 FP 值映射到 4 位整数（0-15）；③推理时反量化回近似 FP 参与计算（或硬件原生低精度计算）；④配合 KV-cache 量化、embedding 共享、CPU 卸载进一步省显存；⑤推理框架（llama.cpp/vLLM/ONNX Runtime）加载 GGUF 或 NVFP4 权重跑生成。

**第三层：公式与核心机制**——为什么 4-bit 还能保质量？因为权重分布有结构性，分组 scale 能捕捉每组的范围，把量化误差局限在组内；NVFP4 更进一步用硬件级 FP4 张量核心，配合稀疏与缩放，在 Blackwell 上既快又保真。但代价：精度敏感任务（如 GPQA Diamond、HLE）仍落后全精度；低精度还会削弱“激活引导”等内部干预的效果（存在失败不对称性）。因此部署要按任务选精度（Q3_K_M 给 16GB 卡、Q4_K_M 给 24GB 卡、Q5_K_M 求最高保真）。

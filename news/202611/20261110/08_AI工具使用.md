### 1. 【WorkBuddy 5.11 三模式实战：让AI真正动手干活】

> 📍 **导语**：WorkBuddy 是腾讯 CodeBuddy 团队出品的桌面 AI 智能体工作台，2026 年 11 月 3 日更新到 5.11.0，最大特点是"真的动手"而不只是聊天。它通过 Ask/Plan/Craft 三种模式，把会议录音整理成表格、把发票按月份归档、把周报推到你手机。本文拆解三种模式怎么选、怎么用，帮普通人把重复劳动交给 AI。

---

▌ 它是什么

WorkBuddy 是腾讯云 CodeBuddy 团队于 2026 年 3 月上线、11 月 3 日迭代至 5.11.0 的桌面 AI 智能体工作台。它和普通聊天 AI 最大的区别是：你看到的是"任务"而不是"聊天记录"。界面只有三块——左侧导航区（新建任务、Claw、插件、定时任务、资料库、专家·技能·连接器）、中间任务对话区（下指令、看拆解步骤、看执行进度）、右侧结果区（工作空间文件、浏览器、变更记录、产物预览）。它兼容 OpenClaw 技能生态，内置 20 多个技能包，支持混元、DeepSeek、GLM、Kimi、MiniMax 多模型切换，还能通过微信、企微、QQ、飞书、钉钉远程遥控你的电脑。一句话定义：它是一个能"看着你的文件、替你的电脑动手"的桌面智能体。

▌ 它解决了什么问题

多数 AI 工具的真实情况是——你打开对话框问两句，然后关掉，活还是自己干。WorkBuddy 想改变的是"描述需求后等一段文字建议、剩下的活自己干"这件事。具体场景包括：第一，文件苦力——扫描下载文件夹、按文档/图片/视频/压缩包分类归档、批量重命名、生成清单；第二，数据处理——上传 Excel 自动清洗、透视、生成柱状图和折线图、输出带图表的分析文件；第三，文档产出——会议纪要、周报、汇报 PPT、调研报告，不是给建议而是直接交付可验收的成品；第四，重复劳动——每日资讯早报、周五自动周报、月度费用报销台账，配置一次长期运行。它把"你叫它帮我查一下"变成"你叫它帮我做一下"。

▌ 核心原理拆解

WorkBuddy 的核心在于三种交互模式的设计哲学。Ask（问答）模式类似普通大模型对话，只给建议不动手，适合问概念、问写法、问思路；Plan（规划）模式先出方案让你确认、不动手，适合复杂任务开工前对方向；Craft（执行）模式才真正去读文件、操作电脑、交付成果，是日常最常用模式。官方建议"复杂任务先用 Plan 敲定方向，再用 Craft 执行"，因为直接用 Craft 干复杂任务，可能做到一半才发现方向错了，前面全废。它的三大能力组件是：专家（封装好的垂直 Agent，支持专家团协作，由"团长"自动拆解任务、多角色并行执行、最后整合结果）、技能（把你的经验固化成可复用工作流）、连接器（基于 MCP 协议打通 Notion、GitHub、Google Drive、Slack 及企业微信、飞书、腾讯文档、邮箱、网盘）。简单说：专家给方法，技能给流程，连接器给通道，三者凑齐才是一个完整的数字员工。

▌ 动手验证

上手分三步。第一步：装（3 分钟），在 codebuddy.cn/work 下载安装包，双击安装，手机端扫码登录，历史对话跟着账号走，务必走官网而非第三方下载站。第二步：三个必做设置——划定工作空间，只授权要动的文件夹，绝不开系统盘和隐私目录；选对模型，面板显示倍率，倍率越低越省，日常问答用低倍率模型，多步骤分析换能力更强的模型，识别图片用带视觉能力的模型；设置个性化指令，相当于给 AI 写长期工作规范，永久生效，还可以在 .workbuddy/ 下的 IDENTITY.md 定义 AI 身份、USER.md 记录你的偏好。第三步：说第一句话，用 Craft 模式交办一件真事，例如"读取 D 盘会议纪要文件夹里的产品评审文档，整理成包含议题结论、责任人和截止日期的表格，标记争议事项"。最标准的指令格式是"做什么 + 在哪 + 要什么格式"，这一句对所有 AI 工具通用。

▌ 对比选型

| 维度 | WorkBuddy | 普通聊天AI | 纯自动化脚本 |
| --- | --- | --- | --- |
| 是否动手操作文件 | ✅ 能读本地文件并改动 | ❌ 只给文字建议 | ✅ 但需写代码 |
| 上手门槛 | 低，图形界面+中文 | 低 | 高，需编程 |
| 远程/定时能力 | 微信企微等远程+定时任务 | 不支持 | 需自行搭建 |
| 模型灵活性 | 多模型可切换 | 单一 | 不涉及 |

### 2. 【Claude Code+Cursor 双工具AI编程工作流实战】

> 📍 **导语**：Claude Code 与 Cursor 是当前最受欢迎的两款 AI 编程助手，但单独用任一个都只能覆盖开发环节的一部分。本文基于多篇实战指南，拆解"Claude Code 规划+构建测试、Cursor 打磨审阅"的双工具协作流，并给出建立项目记忆文件、编辑前先规划、做小而带测试的提交等工程习惯，帮开发者把 AI 从"补全工具"升级为"协作者"。

---

▌ 它是什么

Claude Code 是 Anthropic 出品的终端型 AI 编程代理，擅长跨文件批量改动、依赖升级、根据测试报错自动修复等"步骤多、涉及文件多、需要验证"的任务；Cursor 是基于 VS Code 的 AI 原生编辑器，Tab 补全、Chat 对话、Composer/Agent 跨文件修改都很顺手，且能完美继承 VS Code 快捷键。两者定位不同：Claude Code 解决"看得全、改得稳"，Cursor 解决"写得快、改得准"。实战中常见做法是写新功能用 Cursor 的补全与 Chat，重构或跨文件修改切到 Cursor 的 Composer，批量任务与自动化则交给 Claude Code。

▌ 它解决了什么问题

单一 AI 编程工具容易遇到三类瓶颈：第一，补全幻觉——在不熟悉的库上，补全的代码"看起来越合理越危险"，方法签名或参数顺序和实际版本不一致，肉眼难发现；第二，上下文陈旧——长会话里 token 消耗随轮次快速累积，无关信息干扰模型判断；第三，冲突与遗漏——两个代理同时编辑同一文件会产生冲突，忽略测试"就这一次"正是 bug 溜进来的时刻。双工具分工本质是让每个工具只做它最不可替代的事，再用工程纪律（规划—执行—审阅）兜住质量。

▌ 核心原理拆解

这套工作流的灵魂是"建立项目记忆文件 + 编辑前先规划 + 做小而带测试的提交"。Claude Code 提供 init 命令创建 claude.md 记忆文件、clear 命令在切换任务时重置上下文、Plan 模式在不编辑任何内容的情况下研究并提方案、自定义斜杠命令复用提示、hook 在每次编辑后自动跑格式化。经济学原因很直接：Agent 每轮循环都要重新发送对话历史、读取的文件内容和命令输出，长会话 token 消耗非线性增长；与其携带大量陈旧上下文，不如用一份精炼的 claude.md 重新开局，既省钱又减少干扰。每日节奏建议：早晨回顾待办挑 1 到 3 个任务，每个先用 Claude Code 规划再构建测试，通过后提交，用 Cursor 打磨审阅，收工时把新信息更新进 claude.md。

▌ 动手验证

实操从"干净工作区"开始。用 Cursor 打开项目时必须"打开文件夹"而非单个文件，这样它才能建立完整项目索引；启动 Claude Code 要在项目根目录，否则看不到完整结构。权限配置上，只读操作（读文件、列目录）可放开自动执行，删除文件、执行危险命令保持手动确认，陌生或生产代码保持严格确认。一个可复制的流程：在 Cursor 中用 Chat 让 AI 阅读 README 理解背景 → 用 Claude Code 分析代码库、列出涉及文件和影响面 → 用 Agent 执行批量修改 → 通过 git diff 审查是否改了无关文件 → 运行测试和构建验证 → 让 AI 生成提交说明、人工确认后提交。建议用 Git 先提交一次 baseline，AI 改乱了也能回滚。

▌ 对比选型

| 维度 | Claude Code | Cursor | GitHub Copilot |
| --- | --- | --- | --- |
| 擅长 | 跨文件批量、自动修复 | 补全快、跨文件重构 | 行内补全、API 问答 |
| 交互形态 | 终端代理 | 编辑器内 | 编辑器插件 |
| 上手成本 | 中（需命令行） | 低（VS Code 用户） | 低 |

### 3. 【AI写作四段流：用DeepSeek豆包Kimi跑通成稿】

> 📍 **导语**：AI 写作最大的误区是"帮我写一段"，结果空泛还要返工。本文基于多篇 2026 实测攻略，拆解"选题—提纲—初稿—润色"四段流程，并以 DeepSeek、豆包、Kimi 三款中文友好工具为例，演示如何用结构化提示词把模糊想法变成可发布文章，同时守住"人补经验、查数字、按发布"的安全底线。

---

▌ 它是什么

这里的"四段流"不是某个单一工具，而是一套适配多数聊天式 AI 的写作流程方法论。第一步选题：让 AI 给 10 个方向，你挑最有感觉的；第二步提纲：让 AI 生成多级大纲，你确认结构；第三步初稿：按提纲逐段扩写；第四步润色：让它改口语化、缩短字数、校对逻辑。搭配的三款工具各有侧重——DeepSeek 中文长文本处理强、免费，适合写长文和整理资料；豆包接地气、懂中文互联网梗，适合小红书、公众号、朋友圈文案；Kimi 能读 PDF/Word、长文本总结强，适合写报告、总结文档。三者都有免费额度，可先都试再定。

▌ 它解决了什么问题

写作痛点是"没文采写不出、半天憋一句、不知怎么开头、写完像流水账"。四段流把 AI 从"替你写"变成"陪你写"：没思路让 AI 出选题；知道写什么但不知开头让它写三个不同风格开头你选；卡文把前文发给它问接下来怎么写；写完让它润色、改口语化、缩字数；交稿前让它校对错别字与逻辑。它解决的是"从 0 到 1 启动难"和"从草稿到成稿打磨慢"两件事，而非取代人的判断。

▌ 核心原理拆解

四段流成立的关键是"结构化提示词"。低效指令如"写一篇关于健康的文章"必然空洞；高效指令需包含角色设定（"扮演有 10 年经验的新媒体爆款写手"）、任务描述（"适合小红书的护肤精华推广"）、具体要求（"3 个核心卖点、使用场景、呼吁互动、亲切口语化"）、格式限制（"不超过 5 段、300 字内"）。更稳的做法是把你重复讲的规则写成一份提示词模板，长期复用。其底层逻辑是：AI 负责加速生成与多角度供给，人负责补经验、查数字、定发布——Google 看的是内容有没有用，这个分工刚好对上；发布前必须人工查证所有 AI 生成内容，尤其是价格、政策、合同、医疗、财务类。

▌ 动手验证

以 DeepSeek V4 写一篇"职场效率"公众号文章为例。第一步（5 分钟）输入："我想写职场效率公众号文章，面向 25-35 岁上班族，给 10 个选题方向，每个一句话说吸引点"，挑一个。第二步（3 分钟）输入："我选《上班总是忙到死？这 5 个方法让你准时下班》，请生成包含引言、3 个方法、结语的多级提纲"。第三步让它按提纲逐段扩写，每段指定字数。第四步润色："把语言改得更口语化，删掉'总之'这类套话，控制在 1200 字"。发布前务必：把你的真实经历补进去、用搜索引擎核对文中所有数据和案例、通读一遍改掉机器腔。免费版即可跑通整条流程，不必急着付费。

▌ 对比选型

| 工具 | 强项 | 适合场景 | 免费额度 |
| --- | --- | --- | --- |
| DeepSeek | 中文长文、整理资料 | 长文、资料综述 | 免费 |
| 豆包 | 接地气、口语化 | 小红书/公众号文案 | 免费 |
| Kimi | 读文件、长文总结 | 报告、文档总结 | 免费 |

### 4. 【n8n自托管搭建自动日报Agent工作流实战】

> 📍 **导语**：每天花 20 分钟刷十几个网站凑行业简报，是很多人的隐形时间黑洞。本文基于 n8n 与 Coze/Dify 实测对比，手把手教你在 n8n 上用 5 个节点搭一个"定时抓取—AI 总结—推送手机"的自动日报 Agent，并讲清自托管与云部署在数据安全上的取舍，让重复劳动一次性买断。

---

▌ 它是什么

n8n 是一款开源的可视化工作流自动化工具，用"节点+连线"的方式把不同应用串起来，无需写代码也能搭复杂流程。搭建自动日报 Agent 的核心链路是：定时触发（Schedule Trigger）→ 数据抓取（HTTP Request 请求搜索 API 取行业新闻）→ AI 总结（AI Agent 节点，System Prompt 写清"输出核心热点+一句话点评+可信度提示"）→ 结果推送（Webhook/邮件/飞书节点发到手机）。n8n 的一大优势是每个节点都能单独执行、单独查看输入输出，调试极友好。它还支持 RAG 知识库（接 Qdrant/Pinecone/Weaviate 向量库）、多 Agent 协作、人工审核节点与错误重试。

▌ 它解决了什么问题

它解决的是"高频、规则明确、却反复占用注意力"的信息收集类劳动。以前每天早上手动刷网站、复制粘贴、写简报，现在 9 点手机准时收到"热点+点评+链接"成品，通勤路上扫两眼即可。更进一步，它把"邮件分类、发票录入、会议纪要做待办"这类机械活也自动化：AI 读取邮件附件抽取供应商、金额、到期日填入表格；粘贴会议转录，AI 抽取行动项并按上下文指派负责人创建任务。其价值不在于一步到位的"全能助理"，而在于先用 5 节点以内小闭环拿到正反馈，再迭代扩展。

▌ 核心原理拆解

自动日报的本质是"触发器—获取—思考—分发"四段管道。触发用 Cron 设每天 9:00；获取用 HTTP Request 拉取新闻列表，注意截图扔给模型比纯文本烧得多，可用精简 mini 模型省 90% 成本；思考环节把 System Prompt 写死输出结构，避免 AI 自由发挥；分发用 Webhook 或飞书/邮件节点。数据安全上，n8n 可自托管，数据留在自己 NAS 或服务器，而 Coze 等跑在厂商云上、数据经过第三方。关键工程纪律：第一，先跑通 5 节点内小闭环再扩展；第二，算 Token 成本，国产 DeepSeek 等性价比 API 个人场景月成本可忽略；第三，敏感数据（客户资料、公司文档）别轻易喂公域 SaaS。

▌ 动手验证

实测 3 小时可搭出能跑的日报 Agent。Step1 新建工作流，加 Schedule Trigger 设 Cron 每天 9:00。Step2 加 HTTP Request 节点请求搜索 API 取行业新闻列表。Step3 加 AI Agent 节点，System Prompt 写明"输出核心热点+一句话点评+可信度提示"。Step4 加 Webhook/邮件/飞书节点把简报发到手机。Step5 手动点几次 Execute Workflow，逐节点看输入输出，提示词不满意就改 Prompt 重跑。进阶可把节点换成多 Agent 协同（一个抓取、一个写稿、一个审稿），或用本地知识库让日报只讲你关注的赛道。嫌 n8n 太极客，Coze 零代码版 10 分钟也能跑同样效果。

▌ 对比选型

| 维度 | n8n | Coze 扣子 | Dify |
| --- | --- | --- | --- |
| 部署 | 可自托管，数据自主 | 字节云，零代码 | 可自托管，偏应用 |
| 上手 | 中，节点编排 | 低，拖拽 | 中 |
| 适用 | 复杂编排、长期跑 | 快速原型 | 知识库应用 |

### 5. 【扣子Coze零代码搭建知识库客服Bot实战】

> 📍 **导语**：企业要一个"能答产品问题、不乱编、可多轮对话"的客服 Bot，不一定非要技术团队。本文基于北京市计算中心 Coze 实战课与扣子官方文档，拆解如何在扣子平台零代码创建知识库客服 Bot：配置人设与 Prompt、上传文档建知识库、开通开场白与预设问题、测试发布，让非技术人员也能搭出落地智能体。

---

▌ 它是什么

扣子是字节跳动旗下的一站式 AI 开发平台，提供"低代码应用 + 智能体（Bot）+ 工作流"能力。搭建知识库客服 Bot 的核心对象是 Bot 和工作流节点：Bot 由人设（设定角色与回复边界）、插件（搜索、计算器、天气等工具）、知识库（上传文档做检索增强）、变量记忆（跨轮记住用户上下文）组成。平台还提供应用 IDE，内置大模型、代码、意图识别、知识库写入与检索等节点，满足复杂业务编排。对团队，扣子有团队版（共享项目、Agent 与资产）和企业版（统一权限与安全治理）。

▌ 它解决了什么问题

它解决的是"非技术团队也想用 AI，但请不起开发"的落地门槛。过去搭一个客服 Bot 要写代码、接模型、管向量库；在扣子上，业务人员拖拽即可：创建 Bot 并写人设 Prompt → 上传产品手册 PDF 建知识库 → 配置知识库检索让回答有出处 → 开通对话开场白与预设问题提升首轮体验 → 多轮对话测试后一键发布到飞书机器人或微信。它把"AI 能力安全带进组织"这件事，从研发项目压缩成半天的配置工作，特别适合 FAQ 客服、内部制度问答、销售话术助手等场景。

▌ 核心原理拆解

知识库客服 Bot 的可靠性来自"检索增强生成（RAG）"。原理是：先把企业文档切分（Chunking）并做 Embedding 存入向量库；用户提问时，先检索最相关的片段，再把片段作为上下文注入大模型提示词，让模型"基于给定资料回答"而非凭记忆编造。这正对应实战课里的"上传知识文档、配置知识库检索"两步。人设 Prompt 则设定对话边界（哪些问题不接受），工作流的"条件分支"可处理如时间冲突等异常。进阶还能把 Coze 调用 n8n 的 Webhook 触发更复杂的工作流，实现"快速原型（Coze）"与"复杂编排（n8n）"衔接。

▌ 动手验证

按官方文档与实战课，实操分四步。第一步创建 Bot：进入扣子，新建 Bot，在"人设与回复逻辑"里写清角色（如"你是某产品售后助手"）、职责边界和可接受的提问范围。第二步建知识库：上传产品手册、FAQ 文档，平台自动切分建索引，测试时提问应优先命中文档内容。第三步配置交互：开通对话开场白与 3 到 5 个预设问题（如"怎么退款""保修多久"），降低用户首轮成本。第四步测试与发布：做多轮对话测试，故意问文档外的问题看它是否老实说"不清楚"，确认无误后发布到飞书或微信。实战课还演示了"会议安排 Workflow Agent"：请求→查日历→创建→通知，并用条件分支处理时间冲突，可作为扩展练习。

| --- | --- | --- | --- |

### 6. 【把模糊任务拆成清单：AI协作四步法】

> 📍 **导语**：很多人用 AI 第一句话就是"帮我写一份方案"，结果空泛还得返工。本文基于今日头条与 ONES 的方法论，拆解"先交代背景—让 AI 提问—拆成可执行动作—人工核验"四步法，附一套可复用的提示词骨架，帮你在任何聊天式 AI 上把模糊需求变成可勾选的任务表。

---

▌ 它是什么

这套方法不是某个工具，而是一套"与 AI 协作拆任务"的通用流程，核心是把"一次生成一大段文字"改成"先问清楚、再拆任务、再辅助执行、最后人工核验"。四步为：第一步交代背景，说清要完成什么、给谁看、何时交、有何限制；第二步让 AI 先提问再动笔，把未知项标"待确认"而非自行编造；第三步把结果拆成今天能做的动作，每项写明具体动作、耗时、资料、完成标准、先后顺序；第四步让 AI 检查事实依据与推测，但不让它自己给自己盖章。ONES 进一步把拆解固化为五步：整理输入、设定拆分维度、生成候选、人工校验、落入工作项。

▌ 它解决了什么问题

它解决的是 AI 输出"看起来完整、做起来空泛"的通病——目标不清、步骤笼统、缺时间与检查标准。直接丢一句"帮我做产品推广"，AI 会编出看似合理却无法落地的方案；而结构化输入（"面向零售商的产品介绍，读者是采购，今天先完成初稿，不得编造材质、认证、交货期"）能逼出可验证的产出。它把写作、整理资料、准备会议、做产品介绍、安排日常这些场景，从"漂亮但空泛的文字"变成"可逐项打勾的任务表"，让人专注判断而非重复劳动。

▌ 核心原理拆解

方法成立的底层是"结构化提示词 + 人机分工边界"。角色（Role）、背景（Context）、约束（Constraints，明确禁止项与必守项）、任务（Task，拆成 Step-by-Step）、输出格式（Output Format，用 Markdown/JSON 定义）五要素，让 AI 从"随机抽奖"变"精准执行"。ONES 提出的字段模板（标题、背景/目标、验收标准、优先级、负责人角色五项必填）保证产出结构一致；结构化输入保证 AI 有足够信息生成可验证内容；人工审核负责处理不确定项与依赖关系。落库前还有质量核对清单：字段完整性、验收标准可验证、颗粒度合适、依赖明确、负责人明确、不确定项已处理、时间口径一致——任何一项不通过就退回。

▌ 动手验证

拿一件小事试做。先写结构化需求："我要为一款产品准备面向零售商的产品介绍，读者是采购人员，今天先完成初稿，不能编造材质、认证和交货期。"再复制这段提示让 AI 先提问："你现在是我的工作助理，先不要给答案，找出目标、受众、截止时间、已有资料和限制，缺少的信息最多提 5 个关键问题，无法回答的标'待确认'不编造。"信息补齐后输入："请把任务拆成可执行清单，每项写明具体动作、预计耗时、需要的资料、完成标准、先后顺序，优先今天能完成的 3 项，有依赖标出来，不要把'认真研究'当步骤。"初稿后让它检查："逐项指出哪些有事实依据、哪些是推测、哪些缺来源，数字日期名称勿补写。"涉及价格政策合同务必回原始文件核对，敏感信息别贴公域 AI。

| --- | --- | --- |

| 四步拆清单 | 可落地、可验证 | 前期多花几分钟 |
| 纯人工拆解 | 最可控 | 慢、费脑力 |

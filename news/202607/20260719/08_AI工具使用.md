### 1. 【Cursor+Claude Code+Codex 三角分工：一个写、一个审、一个收尾】

> 📍 **导语**（约 110 字）: 单靠一个 AI 编程工具既写又审，很容易“自己骗自己”——它生成的代码它自己说没问题。2026 年 7 月社区里流行起一套更稳的分工法：用 Cursor 看代码画地图、Claude Code 动手改、Codex 只读审查。三者各管一段，把“写”和“审”拆开，bug 率和返工率明显更低，复杂任务也不再卡死在单人模式。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**（约 130 字）
Cursor 是带 AI 的 IDE，擅长读整个代码库、画调用关系图、做最终的 diff 审查和本地微调；Claude Code 是命令行里的自主编程 Agent，能自己读文件、改多文件、跑测试、修失败；Codex（OpenAI）则更适合作只读的“独立评审员”。三者都基于大模型，收费上 Cursor 与 Claude Code 有订阅档、Codex 按 token 计费。一句话：别让一个工具既当运动员又当裁判，分工后才稳。

**▌ 它解决了什么问题（核心功能场景化拆解）**（约 180 字）
场景一「定位问题」：遇到线上 bug，先让 Cursor 找相关函数和附近日志，输出“入口在哪、涉及哪些文件”，人能直观看到地图。场景二「实现功能」：把 Cursor 圈定的范围交给 Claude Code，要求“先给计划再改代码”，它自己跑测试、修失败、汇报真实改动。场景三「独立审查」：Claude Code 改完后，让 Codex 以只读方式审查 diff，重点查金额精度、边界条件、权限边界、测试缺口，且不修改文件——它的价值是“挑刺”而非“写代码”，能挡住 80% 的回归风险。

**▌ 原理拆解（实战工作流）**（约 320 字）
```
场景：假设你要修复一个“订单金额计算错误”的线上 bug
Step 1（Cursor 定位）: 打开 Cursor，选中疑似模块，输入：
  “这个订单金额计算错误的入口在哪里？相关测试和计算函数在哪？先不要改代码。”
  Cursor 会列出 src/order/calc.ts 与对应测试，画出调用链。
Step 2（Claude Code 实现）: 把范围贴给 Claude Code：
  “请只围绕订单金额计算错误排查，先找相关测试和函数，不要重构无关模块，修复后运行最小相关测试。”
  它给出计划→改代码→跑 pnpm test→报告实际改动。
Step 3（Codex 审查）: 改完后让 Codex 只读审查：
  “请审查当前 diff，重点看金额精度、边界条件、旧订单兼容和测试覆盖，不要修改文件。”
  Codex 返回具体风险点，无高风险会明确说“安全”。
Step 4（人工收尾）: 回到 Cursor 看 diff，调整命名、删多余注释、决定是否提交；发现改崩可用 /rewind 回退检查点。
Step 5（成果）: 一个经过“写—审—收尾”三道关的修复，比单人改完直接合入更稳，回归概率显著下降。
关键心得：同一时间只让一个工具拥有写权限，避免并发改同一批文件互相覆盖。
```

**▌ 进阶技巧**（约 100 字）
维护一份 AGENTS.md 写在项目根目录，记录语言、框架、测试命令、代码风格与已知问题，三个工具都会读它，能消除 80% 的“AI 不懂我项目”抱怨；大任务用 git worktree 给 Claude Code 和 Codex 隔离工作区；关键节点让 Claude Code 提交 git commit 当存档点，改崩直接 /rewind 回退。新手建议先单独用 Claude Code 跑通一个小功能，再引入 Codex 做独立审查，逐步过渡到三角分工，避免一开始就三个工具并行写同一批文件导致互相覆盖、难以排查。

**▌ 选型对比**
| 决策维度 | Cursor | Claude Code | Codex |
|---------|--------|-------------|-------|
| 适合任务 | 定位/审查/收尾 | 多文件实现 | 只读评审 |
| 不适合任务 | 大段自主写 | 独立质量把关 | 写代码 |
| 学习成本 | 低 | 中 | 低 |
| 价格 | 订阅制 | 订阅/按量 | 按 token |

### 2. 【n8n 自托管搭 AI 自动化工作流：RSS 抓取到 Slack 推送零代码实战】

> 📍 **导语**（约 110 字）: 每天手动刷新闻、整理简报、再发到群里，是最典型的“重复劳动”。n8n 是一款开源的自动化编排工具，用拖拽节点把 RSS、邮件、Slack、数据库和 AI 串成流水线，自己架在便宜的云主机上就能永久免费用。2026 年它的 AI Agent 节点成熟后，连“判断新闻是否相关并写摘要”都能交给模型，个人和小团队用周末就能搭起一套“永不掉线”的自动化中枢。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**（约 130 字）
n8n 是 fair-code 许可的开源自动化平台，支持 400+ 集成节点（官方称 500+），能连接各种外部服务，AI 只是其中一种节点。自托管版用 `docker compose up -d` 一行命令起在 5 美元/月的小主机上，执行次数不限、完全免费；云端版按用量计费。它不像 Zapier 那样贵，也不像纯脚本那样难维护——工作流可导出 JSON 进 Git 版本管理。适合想把多个系统“粘”起来的技术团队与个人玩家。

**▌ 它解决了什么问题（核心功能场景化拆解）**（约 180 字）
场景一「定时聚合」：每天 9 点抓取多个 RSS 源，按关键词过滤，把相关新闻推到 Slack，省去人工刷资讯。场景二「AI 判断」：把“关键词过滤”换成 AI Agent 节点，让模型判断新闻是否与你的行业相关并写一句话摘要，模糊语义判断交给模型、确定的流程交给节点，两者结合最稳。场景三「跨系统打通」：把表单、数据库、邮件、飞书等串成审批流，比如线索进来自动打分打标签再推给销售。最让人 WOW 的是：AI 节点不额外收费，只有模型 API 的 token 账单，且原生支持 Pinecone、Qdrant、pgvector 做 RAG 知识库问答。

**▌ 原理拆解（实战工作流）**（约 320 字）
```
场景：假设你要每天 9 点把“AI 编程”相关新闻摘要推到团队 Slack
Step 1（部署）: 在云主机执行 docker run -d -p 5678:5678 n8nio/n8n，
  浏览器打开 5678 端口即进入画布。
Step 2（基础流）: 拖入 Schedule Trigger（每天 9:00）→ RSS Read（订阅几个科技源）
  → Filter（关键词含 AI/编程）→ Slack（发消息），四节点连线，逐节点 Execute 测试，10 分钟跑通。
Step 3（加 AI）: 把 Filter 换成 AI Agent 节点，填入模型 API Key，
  提示词：“判断这条新闻是否与 AI 编程相关，相关则写 30 字中文摘要，无关输出空。”
  体验一次“模型模糊判断 + 节点确定流程”的组合。
Step 4（兜底）: 上线前设 Error Workflow（失败就通知你）给关键节点加 Retry，
  自动化最怕“失败了不知道”，而非失败本身。
Step 5（成果）: 每天准时收到一份 AI 筛选+摘要的行业简报，团队成员无需任何操作。
关键心得：工作流导出 JSON 存进 Git，出错随时回滚；高流量场景开 Queue 模式多 worker 扛量。
```

**▌ 进阶技巧**（约 100 字）
把公共逻辑抽成 Sub-workflow 复用，维护大流程必备；工作流导出 JSON 进 Git 做版本控制，改崩能一键回滚；自托管务必管好证书与密钥——n8n 存着你所有服务的 key，主机被攻破等于全线失守；模型节点记得设用量上限，避免跑飞账单。新手建议从官方模板库挑一个相近的现成工作流改，而不是从空白画布画，能省掉大半踩坑时间；遇到节点报错优先看 Execution 日志里的输入与输出，比盲猜快得多，也能顺便理清数据在节点间是怎么流转的。

**▌ 选型对比**
| 决策维度 | n8n | Zapier | Make |
|---------|-----|--------|------|
| 适合任务 | 跨系统+AI | 开箱即用 | 可视化流 |
| 不适合任务 | 纯小白零配置 | 高频自定义 | 重度自托管 |
| 学习成本 | 中 | 低 | 中 |
| 价格 | 自托管免费 | 订阅较贵 | 按操作计费 |

### 3. 【Dify+DeepSeek 零代码搭公众号写作流水线：从找方向到自动成文】

> 📍 **导语**（约 110 字）: 做公众号最耗时的不是写，而是选题、排版、盯发布这些重复活。2026 年一套被反复验证的组合是：Dify 管选题研究、DeepSeek 管长文输出、n8n 管发布调度。三者零代码拼起来，单篇文章生产从 3 小时压到 20 分钟，月成本才 50 出头。新手不用写一行代码，就能让“今天写什么—写成什么样—何时发出”全程自动跑。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**（约 130 字）
Dify 是开源的 LLM 应用开发平台，可私有化部署、数据自己掌控，适合搭工作流、管提示词和知识库；DeepSeek 是国产大模型，中文性价比极高，每百万 token 不到 2 元，一篇 1500 字文章 API 成本约 0.03 元；n8n 负责把前面两步编排进定时发布。三者组合对技术小白友好：Dify 和 n8n 都是拖拽画布，DeepSeek 只需要在节点里填 API Key。适合想做内容副业、又不想雇人的个人与小微团队。

**▌ 它解决了什么问题（核心功能场景化拆解）**（约 180 字）
场景一「选题」：在 Dify 搭一个 4 节点 Chatflow——知识库导入过往高阅读文章做风格锚定、HTTP 节点拉取领域热榜、LLM 节点调用 DeepSeek 生成 5 个选题、代码节点加权打分输出 TOP2，整条 40 秒跑完，还带热点匹配度/风格适配度/差异化三维评分。场景二「写作」：DeepSeek-R1 按结构化提示词出 1200 字初稿，实测可用率 85%，平均只需 2 处人工修改。场景三「发布」：n8n 用 Cron 早 7:30 触发，串起 Dify 取题→DeepSeek 成文→格式清洗→公众号草稿 API 推送→飞书通知，你只需点“发布”。

**▌ 原理拆解（实战工作流）**（约 330 字）
```
场景：假设你要日更一个职场类公众号
Step 1（Dify 选题）: 在 dify.ai 新建 Chatflow，依次拖入：
  知识库节点（导入 30 篇高阅读旧文）→ HTTP 节点（拉取新榜/Feedly 热榜）
  → LLM 节点（DeepSeek API，生成 5 个选题）→ 代码节点（按三维打分输出 TOP2）。
  跑完得到今日两个候选方向，带评分。
Step 2（DeepSeek 写作）: 给 DeepSeek 的提示词：
  “你是资深公众号写手。按选题生成 1200 字文章，H2 分 3-4 章，每章含可复现步骤，
  列出 3 个以上真实工具名和至少 1 个实测数据，禁用空洞口号。”
  初稿约 8 分钟出炉。
Step 3（n8n 调度）: 搭六节点 Workflow：
  Cron(7:30) → Dify API → DeepSeek API → JS 清洗格式 → 公众号草稿推送 → 飞书通知。
Step 4（避坑）: 在 DeepSeek 提示词加“不确定时标注待验证”，防它编工具名；
  n8n 的 JS 节点随机替换 10% 形容词保留“人味”，躲过平台 AI 内容检测。
Step 5（成果）: 早上看飞书通知→打开草稿箱→预览→点发布，全程 3 分钟。
关键心得：成本 Dify+n8n 共用 2 核 4G 云主机 50 元/月 + DeepSeek 约 3 元/月，比兼职便宜约 40 倍。
```

**▌ 进阶技巧**（约 100 字）
Dify 知识库导入历史爆文做“风格锚定”，新文调性更稳；DeepSeek 偶尔编造工具名，加“不确定时标注待验证”即可规避；n8n 的 JS 节点随机替换 10% 形容词保留人味，运营至今零 AI 内容警告；Coze 用户可用插件商店的“新榜数据”插件替代 Dify 选题节点，更开箱即用。若担心内容同质化，可把知识库换成你自己的行业资料，让每篇初稿都带你的独特视角，而非泛泛而谈的通用稿；同时保留人工终审环节，AI 负责提速、人负责把关调性。

|---------|------|------|------|
| 适合任务 | 私有化AI应用 | 零代码机器人 | 跨系统调度 |
| 不适合任务 | 极简不懂部署 | 深度定制 | 纯对话Agent |
| 学习成本 | 中 | 低 | 中 |
| 价格 | 开源免费 | 免费+增值 | 自托管免费 |

### 4. 【国产AI分工使用手册：豆包写文案、Kimi读长文、通义做PPT的组合心法】

> 📍 **导语**（约 110 字）: 很多人把同一个 AI 当万能工，结果写文章、做 PPT、读合同全塞给它，样样都不精。2026 年一批重度用户总结出更高效的“AI 管理”心法：像排兵布阵一样给国产大模型分工——豆包专写中文文案、Kimi 专读长文档、通义千问专做 PPT 和表格、剪映专剪视频。一个 AI 只干一件事，产出质量比“什么都问同一个”高三倍不止。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**（约 130 字）
豆包（字节）中文文案与润色强、语气自然；Kimi（月之暗面）长上下文读论文/合同/报告稳；通义千问（阿里）做 PPT、表格、数据分析顺手；剪映（字节）一键成片与字幕效率高。四者均为国产、免费或低门槛会员，本地数据可控性优于部分海外工具。一句话：别追“最强单个模型”，而追“最顺手的组合”——熟练用一个免费国产工具，比拥有十个高级账号都实在。

**▌ 它解决了什么问题（核心功能场景化拆解）**（约 180 字）
场景一「写文案」：把头条稿、小红书文案、产品描述交给豆包，给它明确受众与风格，润色和标题优化最省力。场景二「读长文」：上百页 PDF、合同、研报丢给 Kimi，让它提取要点、列风险、做对比，长文本消化远超人眼。场景三「做汇报」：把提纲或数据交给通义千问，一键生成 PPT 与思维导图，从“一句话”到“可演示”。场景四「剪视频」：成片素材交给剪映 AI 成片，自动配字幕、转场、节奏，短视频生产从小时级降到分钟级。核心心法：每个工具固定分工，别混着用。

**▌ 原理拆解（实战工作流）**（约 320 字）
```
场景：假设你要做一份“行业分析”并产出图文+短视频
Step 1（豆包写初稿）: 给豆包：
  “写一份面向 30-45 岁职场人的行业分析短文，1200 字，口语化，用小标题分段，
  每段一个真实案例，别用‘首先其次最后’。”
  得到结构清晰的文案底稿。
Step 2（Kimi 读资料）: 把 5 份行业 PDF 上传 Kimi：
  “提取这 5 份报告的核心数据、趋势与风险点，用表格对比，并标注来源页码。”
  Kimi 输出可引用的要点，补足数据。
Step 3（通义做 PPT）: 把要点贴给通义千问：
  “基于这些要点生成 12 页汇报 PPT，含目录、数据页、结论页，配思维导图。”
  一键拿到可演示文稿。
Step 4（剪映成片）: 把文案与 PPT 导入剪映“图文成片”，
  选配音音色、自动字幕与转场，生成 1 分钟短视频。
Step 5（成果）: 同一主题同时产出长文、PPT、短视频三种形态，分发不同平台。
关键心得：任务指令模板 = 任务类型+目标受众+具体格式+字数限制+风格要求+反面案例，越具体产出越准。
```

**▌ 进阶技巧**（约 100 字）
用“任务指令模板”替代模糊提问：任务类型+受众+格式+字数+风格+反面案例，1 分钟写清指令省下 10 分钟返工；AI 第一次不对就“反悔纠正”，像教新人一样告诉它哪句数据错、哪段太生硬；只盯一个工具用到烂，比天天换模型更出活；把常用分工写成一份“AI 岗位表”贴桌面，避免今天一套明天一套。每周复盘一次哪个工具在哪类任务上翻车，动态调整分工，比如发现通义做复杂图表不稳就改回人工或用其他工具补位，让组合始终贴着你的真实工作流进化。

**▌ 选型对比**

**▌ 它是什么（工具速览）**（约 130 字）

**▌ 它解决了什么问题（核心功能场景化拆解）**（约 180 字）
场景一「短剧」：选“爆款女频短剧创作大师”Skill，它按风格与爆款元素自动分人物、写分集大纲、写首集剧本、做分镜、写 Seedance 提示词，一条龙。场景二「TVC/电影」：Agent 询问画幅、字幕、对白语言（多语种），先生成角色/产品/场景三视图再开拍，情绪化大片也能跑。场景三「口播」：上传脚本或主题，自动生成镜头、字幕、配音节奏。最 WOW 的是“角色一致性”——过去生视频角色老变，现在 Skill 固定三视图，多镜头里人物不串脸。

**▌ 原理拆解（实战工作流）**（约 320 字）
```

### 6. 【Kimi Goal Mode 目标模式：把复杂任务交给 AI 自主多轮驱动直到完成】

> 📍 **导语**（约 110 字）: 普通对话式 AI 要你一步一步喂指令，复杂任务容易半途而废。2026 年 7 月 Kimi 推出 Goal Mode（目标模式）与 Kimi Desktop，你只需给一个终态目标，它就自主拆步骤、多轮调用搜索与本地文件、反复迭代直到任务完成，还能并行跑多个 Agent 当“AI 同事”。对要做竞品分析、长调研、资料整理的人，等于雇了个会自己干活的助理。

---

**🛠 深度实操指南**

**▌ 它是什么（工具速览）**（约 130 字）
Kimi（月之暗面）的 Goal Mode 是面向“复杂目标”的执行模式：你描述想要的结果，它自己规划子任务、连续多轮搜索/读写、逐步逼近完成，而非一问一答。Kimi Desktop 进一步支持并行 agents、读取本地文件，把 Kimi 变成能操作你电脑资料的 AI 队友。与此前已熟的“200 万字超长上下文”不同，Goal Mode 强在“自主驱动过程”而非“单次读得多”。免费与会员档均可体验，适合研究、运营、咨询等需要反复查证的任务。

**▌ 它解决了什么问题（核心功能场景化拆解）**（约 180 字）
场景一「竞品调研」：给目标“对比国内前 3 家 AI 视频工具的功能与定价”，Goal Mode 自主搜资料、读你本地的竞品清单、产出带来源的对比表。场景二「长文整理」：丢进一堆会议录音转写与文档，让它提炼行动项、风险与待办，多轮迭代不出错。场景三「并行研究」：Kimi Desktop 里开多个 Agent 分别盯不同主题，像小组分头干活。最 WOW 的是“直到完成”——它会自己判断是否还需补一步，而不是答完一句就停，真正把任务闭环。

**▌ 原理拆解（实战工作流）**（约 320 字）
```
场景：假设你要做一份“国内 AI 视频工具竞品分析”交周五例会

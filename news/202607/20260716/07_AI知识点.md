### 1. 【模型结构化剪枝：删掉冗余通道，标准硬件上真提速】

> 📍 **导语**（80-100字）：大模型动辄数百亿参数，显存与延迟成为落地最大门槛。非结构化剪枝虽能减参却因稀疏模式不规则需专用硬件才能加速。结构化剪枝直接移除整个通道或注意力头，让压缩后的稠密模型在普通GPU上跑得更快，是今年ACL/EACL多篇论文的落地热点。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
模型结构化剪枝（Structured Pruning）是一类在大语言模型上"做减法"的压缩技术：它不修改单个权重，而是成块地删除整个冗余结构单元，例如FFN中的神经元通道、注意力模块中的KV头，或整个网络层。与非结构化剪枝（只把零散权重置零、留下不规则稀疏矩阵）不同，结构化剪枝产出的是形状规整、可直接用标准张量运算执行的"稠密小模型"。一个常见误区是认为"剪得越多越好"——过度剪枝会塌缩性能。它适用于显存受限、追求低延迟推理的场景，但不适合需要保留全部长尾能力的超大规模基座。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：此前部署一个LLaMA-2-7B，需把全部参数载入显存，推理受内存带宽限制逐token缓慢生成。剪枝后，例如GRASPrune在LLaMA-2-7B上实现50%参数压缩，WikiText-2困惑度仅12.18，同时保持主流zero-shot任务性能，整个优化仅需512条无标注样本、单张A100上6分钟完成。SoBP在OPT-66B上将吞吐量提升至接近密集模型的两倍；SlimQwen把800亿参数MoE压缩到约四分之一（23B），显存节省超70%而智商几乎不掉。量化对比：显存占用从156GB降至约40GB级，推理吞吐翻倍。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——把大模型想成一家大厨房，每个厨师（通道/专家）各管一道工序。结构化剪枝就是盘点后发现某些厨师长期闲置或职能重叠，于是把他们整体请离，厨房布局不变、动线更短，出餐更快，而招牌菜的味道基本不受影响。

**第二层：技术流程拆解**——典型流程为：① 准备一个轻量"校准集"（多领域文本，如Multi-Domain Calibration）；② 用可学习门控变量或重要性评分（如范数、Hessian近似）给每个结构单元打分；③ 按全局预算（如"最多删50%"）一次性或迭代地移除低分单元；④ 因删层会改变后续输入分布，需做误差补偿/缩放校准（如SoBP用Cholesky稳定更新修正下一层输入，GRASPrune用少量无标注数据修复尺度偏移）；⑤ 导出可直接部署的稠密权重。

**第三层：公式与核心机制**——以RMSNorm式通道重要性为例，结构化剪枝求解带预算约束的优化：min‖W·M − W*‖，s.t. ‖M‖₀ ≤ B，其中M为0/1门控、B为预算。GRASPrune的巧思是把FFN channel与KV head group纳入统一优化空间，训练中用投影算子持续把解拉回可行集，从而使"评分目标"与"最终剪枝目标"一致，避免传统"先评分再剪枝"的目标错位。

**▌ 动手验证**（100-150字）
用torch内置结构化剪枝快速体验通道级移除：
```python
import torch.nn as nn
from torch.nn.utils import prune
linear = nn.Linear(768, 768)
# 按L1范数对输出通道剪枝30%
prune.ln_structured(linear, name="weight", amount=0.3, n=1, dim=0)
print("剩余非零输出通道:", int((linear.weight != 0).sum(0).any(0).sum()))
# 真实大模型可用 peft/transformers 的 prune 流程或 ncompress 库
```
注意：移除后需`prune.remove`固化掩码，并做少量校准微调恢复精度。

### 2. 【大模型可解释性XAI：从黑箱事后解释走向内建可解释】

> 📍 **导语**（80-100字）：当大模型进入信贷、医疗、司法等高风险决策，光有准确率不够，还得说清"为什么"。2026年ACL综述提出从"事后解释"转向"内生可解释"——把玻璃箱设计直接写进架构，这正成为可信AI与合规部署的关键方向。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
可解释性（XAI）是研究"让模型决策可被人类理解"的方法集合。对大模型，它分两条路线：事后解释（Post-hoc）在不改模型的前提下分析已训练好的黑箱，如SHAP、LIME、注意力可视化、概念激活向量TCAV；内生可解释（Intrinsic）则从设计之初就让计算可读，如功能透明模型GAM/KAN、概念瓶颈模型CBM。一个常见误区是"注意力高=模型真的依赖它"——研究已证明高注意力权重并不总对应真实决策。适用边界：事后解释灵活但可能不忠实，内生解释更可信却牺牲表达能力。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：过去模型输出"拒贷"，用户与监管都不知道原因，无法满足GDPR第22条"获得解释权"。引入XAI后，SHAP可指出"负债收入比使通过概率降22分、就业史加8分"；医疗影像用Grad-CAM标出肺区焦点，医生一眼验证依据。2026年ACL综述系统归纳五类内生范式：功能透明、概念对齐、表征可分解、显式模块化、潜在稀疏性诱导，让模型从"黑箱"走向"玻璃箱"。量化收益：在金融/医疗等受监管场景，可审计性从"无"提升到可提供逐决策依据，合规风险显著下降。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——把模型想成一位只给结论不写过程的医生。事后解释像事后请他补写"我为什么这么诊断"；内生可解释则要求他看病时就把推理步骤写在病历上，每一步都可查。前者可能编得头头是道却不忠实，后者天然可信但写起来受限。

**第二层：技术流程拆解**——① 特征归因（SHAP/LIME）：扰动输入、观察输出变化，给每个特征分配贡献分；② 概念归因（TCAV）：定义" sarcasm"等概念的正负样本，学习其在激活空间的方向并量化影响；③ 注意力/显著图：把注意力权重或梯度映射成文本高亮或图像热力；④ 机制可解释（Mechanistic）：用归纳头、稀疏自编码器SAE定位内部"电路"；⑤ 内生设计：用KAN把每层换成可解释基函数，或CBM先预测概念再决策。

**第三层：公式与核心机制**——SHAP基于合作博弈论的Shapley值：φᵢ=Σ_{S} (|S|!(n−|S|−1)!/n!)(v(S∪{i})−v(S))，把每个特征视为"贡献者"公平分摊预测增量，理论严谨但计算贵。新版评估范式（华盛顿大学/哥大）更进一步，主张用"决策效用"（Theoretic Value）而非抽象质量评判解释，即解释是否真改善了下游决策。

**▌ 动手验证**（100-150字）
用captum给一句文本做归因：
```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer
from captum.attr import IntegratedGradients

inputs = tok("这笔贷款风险很高", return_tensors="pt")
attr = ig.attribute(inputs.input_ids, target=1)
print("各token归因得分:", attr.sum(-1).squeeze().tolist())
```

### 3. 【知识蒸馏新变体：自蒸馏与特权幻觉破解让小模型学真本事】

> 📍 **导语**（80-100字）：把大模型"老师"的能力教给小模型，是端侧AI落地核心路径。2026年蒸馏研究接连突破：On-Policy自蒸馏让模型用"后见之明"教自己，DOPD则破解了"给老师开小抄反而害了学生"的特权幻觉，学生平均得分提升7.5分、弥合89.8%能力差距。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
知识蒸馏（Knowledge Distillation）是让小"学生"模型模仿大"教师"模型的输出分布，从而以极少参数逼近大模型能力。经典做法是Hinton的soft targets+温度蒸馏。2026年的新变体主要分两支：自蒸馏（Self-Distillation）让模型在推理时构造更强的"自我"当老师（如SDFT/SDPO/OPSD），把推理算力转化为训练信号；以及针对"特权信息"的DOPD（双重在线策略蒸馏），识别并剔除老师依赖"小抄"的假能力。误区：蒸馏不是单纯"抄答案"——只给最终概率分布会让学生学不到解题思路，需传递过程性知识。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：以往在线策略蒸馏（OPD）让学生照抄老师每个词的概率，但老师只喊答案、不暴露思考过程，且单次采样噪声大，训练后期准确率震荡无法提升。浙江大学与蚂蚁集团2026年6月研究指出该缺陷并提出传递"内心世界"。更严重的是"特权幻觉"：给老师注入视觉标注等特权信息后，学生模仿的是老师"翻答案"的捷径而非真能力，导致熵崩塌、泛化失效。DOPD用"特权优势差"区分真假差距，让学生平均得分提升7.5、弥合89.8%师生差距。OPSD在Qwen3-8B上数学准确率达52.2%，优于GRPO(51.3%)与SFT(50.0%)。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——经典蒸馏像学生背老师给的"标准答案"，自蒸馏像学生考完试后，对照正确答案（带解析）自己改卷、把"为什么"内化；DOPD则像班主任发现：有些题老师是因为"看了答案"才做对，这种"假本事"不值得学生学，于是只在老师真比学生强的地方重点教。

**第二层：技术流程拆解**——① 构造教师：SDFT用旧任务示例作上下文构造Demonstration-Conditioned Teacher，OPSD让Teacher看着Ground Truth答案生成CoT；② 学生（Base）在自己的采样轨迹上用KL散度拟合教师分布；③ DOPD额外让师生都带"小抄"公平前向，算逐token"特权优势差"（PAG），将场景分为关键知识/共识/不确定/探索四类，分别用深度全词蒸馏、轻量教师蒸馏、弱自蒸馏、轻量自蒸馏；④ 在线更新，师生同步训练。

**第三层：公式与核心机制**——蒸馏损失本质是最小化师生输出分布的KL散度：L=Σ_q KL(p_T(·|q) ‖ p_S(·|q))。DOPD的核心指标PAG = Δ(teacher‖student)在带/不带特权信息下的差异；OPSD优化的是per-token散度而非GRPO式的标量奖励，使密集信号直接指导每个token。d-OPSD进一步把该范式推广到扩散语言模型，仅数百步即收敛，远少于RL的上千步。

**▌ 动手验证**（100-150字）
用transformers的最小蒸馏损失示意：
```python
import torch, torch.nn as nn
def distill_loss(student_logits, teacher_logits, T=4.0):
    s = torch.log_softmax(student_logits/T, -1)
    t = torch.softmax(teacher_logits/T, -1)
    return nn.KLDivLoss(reduction="batchmean")(s, t) * T * T
# 实战可加载HF上DOPD/OPSD开源权重做微调
```

### 4. 【世界模型World Model：让AI在内部先模拟一遍再行动】

> 📍 **导语**（80-100字）：大语言模型像"文科生"，世界模型像"理科生"——它关心空间、时间、运动与因果，让AI在行动前"先想一想后果"。从自动驾驶到机器人，再到视频生成，世界模型正成为生成式AI与决策式AI的交汇点，是2026年最热的赛道之一。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
世界模型（World Model）是AI对"外部世界如何变化"的内部预测器：观察当前状态，预测若采取某动作未来会发生什么。它不同于只处理语言的大语言模型，而关注空间、时间、物体、运动、因果与动作反馈。一个常见误区是"能生成逼真视频=理解物理"——Sora类模型仍可能穿模、流体异常，画面漂亮不等于物理正确。它适用于自动驾驶、机器人、工业仿真等需预测后果的场景；纯文本问答场景则LLM更合适。其思想源于2018年Ha与Schmidhuber的World Models，2025年DreamerV3已能在150+控制任务"想象"未来改进行为。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：过去很多AI是"训练有素的反应机器"，看到输入直接输出，几乎不预判。世界模型让自动驾驶看到前车减速、旁车贴近车道线时，推测对方可能急刹或变道并提前反应；让机器人在真实操作前于内部"梦境"多次练习，提升学习效率。2026年4月阿里发布HappyOyster世界模拟器（支持1分钟连续实时位移），腾讯开源混元3D世界模型2.0（生成可编辑3D资产）。量化上，Stanford HAI 2026报告指出仿真操控成功率89.4%，而真实家庭任务仅约12%，正说明世界模型+仿真能大幅降低真实试错成本。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——你站在桌边看到水杯在桌沿，不必真推倒就知道它大概率会摔碎。世界模型就是给AI装上这种"脑补"能力：行动前在内部模拟多种可能结果，选风险最小、效率最高的方案，而非盲目出手。

**第二层：技术流程拆解**——主流有三条路线：① 模型化强化学习（Dreamer）：学环境的压缩时空表示（VAE+RNN/SSM），在latent space里训练策略再迁移真机；② 视频生成派（Sora/Genie 3/HappyOyster）：扩大视频生成规模模拟世界演化，可交互导航；③ 潜空间预测派（LeCun的JEPA/V-JEPA 2）：不在像素空间逐帧生成，而在抽象表征空间预测未来，更接近人类物理直觉。具身方向如ω-EVA把世界模型塞进动作生成闭环：policy先出动作草稿，世界模型在latent预演后果，refiner据此修正。

**第三层：公式与核心机制**——Dreamer式世界模型学习转移函数ẑ_{t+1}=f_θ(z_t,a_t)与奖励r_t=g_θ(z_t,a_t)，在latent空间用"想象"rollout优化策略；JEPA则用能量/对比方式在表示空间预测y=Encoder(x')约Encoder(f(x))，避免逐像素重建。评价成熟度的六指标：时间一致性、空间一致性、物理一致性、动作可控性、多模态一致性、可迁移性（WorldScore/PhysBench/PhyWorldBench）。

**▌ 动手验证**（100-150字）
用dreamer风格的latent预测伪代码理解思想：
```python
import torch
# z: 当前状态 latent, a: 动作, f: 学习到的世界动态
z_next_pred = world_model.transition(z, a)   # 预测下一状态
reward_pred  = world_model.reward(z, a)        # 预测奖励
# 在 latent 中滚动多步即"内部想象"，再选收益最高的动作
```

### 5. 【归一化层技术：RMSNorm如何稳住深层Transformer训练】

> 📍 **导语**（80-100字）：激活函数决定模型"能表达什么"，归一化决定优化器"能否活过几十层"。从Post-LN到Pre-LN，再到RMSNorm，归一化层默默撑起千亿模型的训练稳定。Llama、Qwen、DeepSeek全系采用RMSNorm，比LayerNorm快约7-20%。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
归一化（Normalization）是Transformer块中的"稳压器"，把每个token的特征向量保持在稳定数值尺度，防止深层堆叠时激活爆炸或梯度消失。主流有LayerNorm（2016，原始Transformer用，按token特征维算均值方差再标准化）与RMSNorm（2019，去掉均值中心化，只用均方根缩放）。一个常见误区是"归一化提升表达能力"——它不增加新信息，只是让已有信息在深度上更易优化。适用边界：语言模型用LayerNorm/RMSNorm而非BatchNorm，因为序列长度可变、batch统计量噪声大；Pre-LN（归一化放子层前）是现代标配。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：原始Transformer用Post-LN（归一化放残差之后），超过12-24层就需复杂学习率warmup，否则梯度在层间被压缩而消失或爆炸。改为Pre-LN后，残差路径保持"干净"，梯度以恒等路径回传，100+层模型用简单优化配方即可训练。RMSNorm进一步省去均值计算与β偏置，在每block调用两次的累积下，整体前向/反向快约7-20%，Llama/Qwen/DeepSeek/Mistral/Gemma全部采用。量化：RMSNorm相比LayerNorm约快7-10%（部分实现10-20%），参数更少，训练稳定性与最终质量基本持平，是千亿级模型省显存提速的关键。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——深层网络像传话游戏，每传一层声音可能越来越大或越来越小，传到第60层可能放大到300倍（1.1⁶⁰≈304）而爆掉。归一化就是每层之间加个"音量校准器"，把信号重新拉回正常区间，保证信息不被扭曲。

**第二层：技术流程拆解**——现代decoder块流程：RMSNorm→多头注意力→加回残差流；RMSNorm→SwiGLU FFN→加回残差流。每block两次归一化，但残差流本身不归一化，只有"增量"经过归一化输入。关键设计：Pre-LN让残差路径无归一化阻断，梯度dy/dx=(df/dx)+1中的"+1"恒等项保证即使df/dx趋零，上游梯度仍原样回传。

**第三层：公式与核心机制**——LayerNorm：LN(x)=γ·(x−μ)/√(σ²+ε)+β，μ、σ²为token内特征均值方差，γ、β为可学逐维缩放偏移。RMSNorm：rms=√(mean(x²))，RMSNorm(x)=γ·x/rms，省去均值减法与β。深层训练中还可能出现"RMSNorm gamma爆炸"——可学γ在深层变得过大反而抵消归一化，现代训练用L2裁剪或权重衰减显式约束γ的范数以防发散。

**▌ 动手验证**（100-150字）
手写RMSNorm感受其简洁：
```python
import torch, torch.nn as nn
class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__(); self.gamma = nn.Parameter(torch.ones(d)); self.eps = eps
    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).sqrt()
        return self.gamma * x / (rms + self.eps)
# 对比 nn.LayerNorm(d) 可见 RMSNorm 少一次均值减法
```

**▌ 对比与选型**（必填表格）
| 对比维度 | RMSNorm | LayerNorm | BatchNorm |
|---------|--------|---------|----------|
| 中心化 | 否 | 是 | 是(跨batch) |
| 速度 | 快(7-20%) | 基准 | 慢/不稳 |
| 适用序列 | 是 | 是 | 否(变长) |
| 参数 | γ | γ,β | 运行统计 |
| 主流采用 | Llama/Qwen | BERT/GPT2 | CNN |

### 6. 【激活函数演进：从ReLU到SwiGLU为何大模型偏爱它】

> 📍 **导语**（80-100字）：注意力是Transformer的灵魂，激活函数却是决定模型能否叠几十层、长文本不混乱的底层组件。ReLU易"死神经元"，GELU平滑但表达有限，SwiGLU以双支路门控全面适配大模型痛点，成为2026年几乎所有前沿模型的标配。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
激活函数是插入线性变换之间的非线性函数，给神经网络引入表达能力，否则多层堆叠等价于单层线性变换。大模型FFN（前馈网络，承载大部分参数与知识存储）的激活函数经历了ReLU→GELU→Gated GELU→SwiGLU的演进。SwiGLU不是单一函数，而是"双支路FFN+门控非线性"：SwiGLU(x)=(xW₁)⊙SiLU(xW₂)再经W₃降维。误区：以为激活只是"开关"——门控本质是让模型自己决定哪些语义保留、哪些过滤，类似可学习的注意力开关。适用边界：CNN/MLP仍多用ReLU，而Decoder大模型几乎全用SwiGLU/GeGLU。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：ReLU(x)=max(0,x)简单快速，但负数区梯度恒为0导致"神经元死亡"、无法表达否定/转折等负向语义、深层梯度消失，早已被大语言模型淘汰。GELU平滑无死区，却是单支路、非线性上限低、与MoE稀疏架构不兼容、量化损失大。SwiGLU用双支路门控：W₁出内容、W₂经SiLU出0~1权重，逐元素相乘实现自适应筛选。效果上，Shazeer论文显示SwiGLU比非门控变体困惑度低0.5-1.0点；Qwen-7B用SwiGLU长文本逻辑连贯，而ChatGLM2(GELU)超长上下文易梯度衰减、前言不搭后语；DeepSeek-V4还加了输出clamp(L=10)防极端值爆炸。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——普通激活像家里总闸：所有信息一视同仁地通过。门控激活像每个房间独立调光开关：重要信息全亮通过，次要信息调暗，噪声几乎关闭。SwiGLU就是给FFN装了两套独立线路——一条传内容、一条调亮度，二者相乘完成"智能筛选"。

**第二层：技术流程拆解**——① 输入x分别过W₁、W₂两个线性投影，得到内容支路与门控支路；② 门控支路经SiLU(z·σ(z))平滑激活成0~1系数（SiLU处处有梯度、无死区）；③ 内容⊙门控权重逐元素相乘，实现自适应加权；④ 经W₃降维还原维度送入下一层。相比原ReLU FFN（d_ff=4×d），SwiGLU常用d_ff≈8/3×d（如Llama 4096→11008），同等参数预算下困惑度更优。

**第三层：公式与核心机制**——SiLU(z)=z·σ(z)融合线性与sigmoid门，正负区间均有饱满平滑响应，无梯度饱和、无不激活死区；门控乘积引入高阶复合非线性，知识存储密度更高。DeepSeek-V4的clamp变体：SwiGLU_clamped=clamp(SwiGLU(x),−10,10)，在FP8/FP4混合精度下防止罕见大值溢出，几乎不触发却兜住灾难性离群。

**▌ 动手验证**（100-150字）
用PyTorch实现SwiGLU FFN：
```python
import torch, torch.nn as nn
import torch.nn.functional as F
class SwiGLUFFN(nn.Module):
    def __init__(self, d, ffn=11008):
        super().__init__()
        self.w1, self.w2 = nn.Linear(d, ffn, bias=False), nn.Linear(d, ffn, bias=False)
        self.w3 = nn.Linear(ffn, d, bias=False)
    def forward(self, x):
        return self.w3(F.silu(self.w1(x)) * self.w2(x))  # 门控⊙内容
```

**▌ 对比与选型**（必填表格）
| 对比维度 | SwiGLU | GELU | ReLU |
|---------|--------|------|------|
| 结构 | 双支路门控 | 单支路 | 单支路 |
| 死神经元 | 无 | 无 | 有 |
| 非线性强度 | 高 | 中 | 低 |
| MoE适配 | 优 | 差 | 差 |
| 量化友好 | 优 | 中 | 差 |

### 7. 【预训练数据课程：用难度编排让模型学得更稳更快】

> 📍 **导语**（80-100字）：大模型训练不止"数据越多越好"，更要"按顺序喂对数据"。课程学习（Curriculum Learning）按难度递增编排训练数据，让模型先打语言基础再啃推理硬骨头。2026年ICML上华为EDCO用推理熵做动态课程，把"从易到难"升级为"当前最该学"。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
课程学习（Curriculum Learning）借鉴人类"先易后难"的学习规律，按难度递增顺序向模型呈现训练数据。在大模型预训练中，它体现为数据混合比例的阶段调整：早期多喂网页/书籍等通用易数据建立语言基础，后期逐步增加代码、数学等困难推理数据。2026年的前沿从"静态课表"走向"动态课程"——如华为EDCO用模型推理熵实时判断"当前最该学什么"。误区：课程不是"越难越好"——过早喂困难数据会导致训练不稳定；也不是"有课程就一定比随机好"，排序信号须适配模型当前能力。

**▌ 它解决了什么问题？**（120-180字）
**Before → After**：传统随机混洗数据，模型在已掌握样本上浪费预算、在困难样本上early collapse。课程学习让7B模型最终损失降0.1、GSM8K推理准确率从35%升至42%（+7%）；Meta 2026研究显示课程学习可减少18-45%训练步数，推理任务甚至减少60%训练token。但LR衰减会与"由易到难"冲突（OpenReview研究：恒定LR下课程优势明显，标准LR decay使其失效，需用模型权重平均缓解，平均提升1.64%）。华为EDCO在通信领域RLFT上达46.96%，高于随机40.43%与PPL课程44.78%，且前缀熵估计把单样本成本从2.24秒降到0.37秒（降83.5%）。

**▌ 核心原理三阶拆解**（350-500字）
**第一层：直觉理解**——训练领域大模型像备考：题库贵、时间紧，你不能随机刷题，而应让模型每一步都做"当前最该做"的题。静态课程是训练前写好的固定课表；动态课程则像私教每节课根据学生状态调整——已经会的跳过，仍在犹豫的重点练。

**第二层：技术流程拆解**——① 定义难度信号：长度、困惑度PPL、可读性、压缩比，或更先进的推理熵；② 静态编排：热身阶段(0-10%步)用儿童读物/简单新闻，进阶(10-30%)用普通书籍百科，高级(30%-100%)转标准随机混合；GPT-4.5三阶段动态混合使MMLU+8.7%、GSM8K+12.3%；③ 动态编排（EDCO）：估计训练池样本对当前模型的推理熵，选最高熵（最不确定）的一批组成下一阶段课程，训练后重算、样本动态进出；④ 用quick-answer prompting+前缀熵估计把评估成本压到可在线使用。

**第三层：公式与核心机制**——EDCO以推理熵H(q|a₁..ᵢ₋₁)衡量样本挑战性，选top-N高熵样本；训练重评估曲线TREC（ICML另一工作）用最终模型权重回顾性评估"数据在何时被遇见保留最好"，并可由AdamW隐式EMA系数提前预测，从而把高质量数据对齐到TREC低谷以提效。核心思想：样本价值=数据本身质量×模型当前是否仍不确定。

**▌ 动手验证**（100-150字）
简易课程混合器示意：
```python
import numpy as np
stages = [{"web":0.8,"code":0.2}, {"web":0.5,"code":0.5}]  # 易->难
def get_mix(step, total):
    p = step/total
    i = min(len(stages)-1, int(p*len(stages)))
    return stages[i]   # 训练进度越深，困难数据占比越高
print(get_mix(100, 200))  # 后期偏向代码等推理数据
```

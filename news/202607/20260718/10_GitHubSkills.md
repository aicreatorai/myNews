### 1. 【Caveman：用"穴居人语言"写 Prompt 给 Claude Code，省 65% Token 的 AI 编程技能】（⭐ 86.8k）

> 📍 **导语**：随着 Claude Code、Cursor 等编程 Agent 成为日常，Token 消耗正悄悄变成团队最贵的隐性成本——你写给模型的客套话、背景解释、过渡句，绝大部分对"把活干对"毫无帮助，却牢牢占着上下文窗口。Caveman 是一个专为 Claude Code 设计的 skill（技能包），它反直觉地主张：把自然语言 prompt 压成"穴居人式"的极简指令（主谓宾堆叠、去掉连接词与修饰），据说能省下约 65% 的 Token。截至 2026-07-10，它在 GitHub 已收获 86,848 颗星，是当月 AI 编程工具里增长最猛的"反套路"项目之一。今天值得关注，是因为它戳中了一个被所有人忽略的真相：AI 编程的成本优化，可能不靠换更便宜的模型，而靠把话"说短"。

---

**⭐ 深度项目解析**

**▌ 它是什么**
Caveman（仓库 `JuliusBrussee/caveman`）本质上是一个 Claude Code 的"提示词风格约束技能"，而不是一个新模型或新框架。它定义了一套写作约定：用最原始、最直接、最接近"穴居人说话"的方式下达指令——只保留动词、对象、约束，删掉所有解释、铺垫、礼貌用语。开发者把这套约定加载进 Claude Code 后，原本几行的需求描述会被自己和 Agent 共同压缩成关键词式指令，模型照此执行。它不改变 Agent 的能力边界，只改变"你喂给它的语言密度"。

**▌ 解决什么痛点**
在用 AI 编程助手时，开发者常不自觉地写大段背景："你好，我正在做一个 React 项目，里面有个按钮组件，我希望你帮我稍微改一下它的样式，让它……"。这类话术对模型理解帮助有限，却大量占用上下文与 Token。一个中等规模项目里，prompt 本身可能占整体消耗的 30%–50%。更糟的是，冗长 prompt 还容易引入歧义，让模型"过度发挥"。没有 Caveman 之前，你只能手动精简；有了它之后，团队把"写短"变成可复用、可校验的规范，单次编码会话的 Token 账单直接下降约三分之二，长会话里尤为明显。对按量计费的 API 用户和需要反复多轮迭代的重构场景，这是实打实的钱。

**▌ 原理拆解**
Caveman 的原理并不神秘，它是一套"提示词重写约定 + skill 加载钩子"。其原理结构可以看作：
```
输入: 开发者用自然语言写的啰嗦需求
  ↓
约束层: 强制删连接词/客套话/重复解释，只留 动作+对象+约束
  ↓
压缩层: 把长句拆成穴居人式短语（如 "fix: btn color red, hover dark"）
  ↓
执行层: Claude Code 以高压缩指令运行，上下文噪声显著降低
  ↓
输出: 同样的代码改动，但 Token 消耗下降约 65%
```
关键在于，它不重训模型，也不替换推理后端，而是利用 Claude Code 的 skill 机制，在每次会话开场注入一段"写作纪律"。模型在更少语义噪声下更快锁定意图，减少了为"理解废话"而浪费的推理步数。这是典型的"提示工程即优化"思路。

**▌ 动手验证**
把技能克隆到 Claude Code 的技能目录即可启用：
```bash
# 1. 克隆技能到本地 Claude 技能目录
git clone https://github.com/JuliusBrussee/caveman ~/.claude/skills/caveman
# 2. 启动 Claude Code 并查看已加载技能
claude
# 在会话中输入 /skills 即可看到 caveman，启用后按"穴居人"风格写指令
# 3. 验证：对比改写前后同一任务的消耗
# 普通写法: "请帮我把这个按钮改成红色，鼠标悬停时变深一点，谢谢"
# Caveman 写法: "btn: color red, hover darker"
```
启用后，建议你拿一个真实的重构任务做 A/B：同一需求分别用长 prompt 与穴居人写法跑两次，观察 Claude Code 状态栏的 Token 计数差异。

**▌ 对比选型**
| 维度 | Caveman | 手写精简 prompt | 换更便宜的小模型 |
|------|---------|----------------|------------------|
| 节省幅度 | ~65% Token | 不稳定，靠自觉 | 单价降但质量波动 |
| 上手成本 | 低（装个 skill） | 零工具但难坚持 | 需改架构与评测 |
| 质量影响 | 基本不变 | 易误删约束 | 可能下降 |
| 适用场景 | 长会话/高频编码 | 偶尔使用 | 预算极敏感 |

**▌ 真实场景实战**
假设你在一个 200 文件的 TypeScript 项目里批量把 `any` 改成具体类型。传统写法你会写一大段说明背景；用 Caveman 你只需：`refactor: replace any with inferred types, file by file, keep tests green`。Agent 直接动手，省下的 Token 在多文件迭代里累加非常可观。最佳实践：把团队常用的"穴居人模板"沉淀进 `AGENTS.md`，让格式约定自动生效。

**▌ 学习路线**
前置只需会用 Claude Code。入门：读仓库 README 的示例对照表，照抄 10 个改写案例。进阶：把 Caveman 风格与项目的 `AGENTS.md`、CI 检查结合，形成团队规范。今日行动：装好 skill，挑一个正在做的任务用穴居人写法重跑一次，看 Token 计数。

### 2. 【OpenCode：住在终端里的开源 AI 编程 Agent，双代理模式兼顾效率与安全】（⭐ 42k）

> 📍 **导语**：开发者的典型工作流是：在 IDE 写代码，遇到问题切到浏览器问网页版 AI，拿到建议再切回 IDE 改——频繁的上下文切换不断打断"心流"。OpenCode 由 SST 团队打造、采用宽松的 MIT 协议，是一个专为终端设计的开源 AI 编码代理，让强大的编程能力直接留在你最熟悉的黑框里。截至 2026-07，它已在 GitHub 收获超过 4.2 万星标。它最巧妙的设计是"双代理"：默认 `build` 代理有完全权限可改文件、跑命令；`plan` 代理只读、且执行命令前必须确认。按 Tab 即可切换。今天值得关注，是因为它代表了"AI 编程助手终端化、开源化"的明确趋势。

---

**⭐ 深度项目解析**

**▌ 它是什么**
OpenCode（仓库 `sst/opencode`）是一个运行在命令行里的 AI 编码代理，定位是"终端里的结对编程伙伴"。你不必离开命令行，就能让 AI 分析代码、解释逻辑、修 Bug、重构，甚至直接执行修改。它兼容多种模型后端（OpenAI、Anthropic、本地 Ollama 等），核心价值是把分散在 IDE 插件、网页聊天、终端之间的编程动作收拢到一处。

**▌ 解决什么痛点**
过去 AI 编程能力被锁在各自封闭的环境里：网页版要开浏览器，IDE 插件绑定特定编辑器，且大多"只聊天不改文件"。开发者在多个窗口间反复横跳，上下文一旦丢失就要重新解释项目背景，效率折损严重。OpenCode 把全流程放进终端：分析、修改、运行、测试一气呵成，且通过 `/init` 命令扫描项目生成 `AGENTS.md`，让后续所有对话都基于项目整体理解，回答更具针对性。对习惯 Vim/tmux、常年泡在 SSH 远程机器上的开发者，这是刚需。

**▌ 原理拆解**
OpenCode 的原理是"代理 + 工具调用 + 项目上下文"的闭环：
```
输入: 用户在终端输入自然语言任务
  ↓
上下文层: /init 生成 AGENTS.md，记录项目结构与约定
  ↓
代理调度: build(可写) / plan(只读) 双模式，Tab 切换
  ↓
工具层: 调用文件读写、Shell 执行、测试运行等工具
  ↓
输出: 直接落盘的代改 + 终端可验证的结果
```
其关键设计决策是"权限分级"——build 模式拥有完全访问适合实干，plan 模式默认禁写、跑命令前请求确认适合安全审查。这把"效率"与"安全"从互斥变成了可随时切换的两档。

**▌ 动手验证**
OpenCode 安装轻量，Node.js 环境即可：
```bash
# 1. 通过 npm 全局安装
npm install -g opencode
# 2. 进入项目目录并初始化上下文
cd your-project && opencode init
# 3. 启动交互式代理（默认 build 模式）
opencode
# 需要安全审查时按 Tab 切到 plan 模式，只读不改
```

**▌ 对比选型**
| 维度 | OpenCode | Claude Code | Aider(已报道) |
|------|----------|-------------|---------------|
| 部署 | 开源 MIT | 闭源商业 | 开源 |
| 环境 | 纯终端 | 终端 | 终端 |
| 权限模式 | 双代理可切 | 单一 | 单一 |
| 模型绑定 | 多后端 | 偏 Claude | 多后端 |

**▌ 真实场景实战**
设想你在远程 VPS 上维护一个服务，本地没装 IDE。直接 `ssh` 进去跑 `opencode`，用 plan 模式先让它读一遍异常日志相关代码并给出修复思路（不改动），确认无误后切 build 模式让它改文件、跑测试。全程不离开终端，也不需要把代码拉回本地。最佳实践：把常用约束写进 `AGENTS.md`，让代理少问多干。

**▌ 学习路线**
前置：会用终端与 Git。入门：装好 OpenCode，用 `/init` 初始化一个练手项目。进阶：配置多模型后端，让简单任务走本地 Ollama、复杂任务走云端。今日行动：在本机项目里跑一次 `opencode`，用 plan 模式审一段陌生代码。

### 3. 【AI Website Cloner：给个网址，多 Agent 协作几分钟还原整套可运行前端代码的网站克隆工具】（⭐ 26k）

> 📍 **导语**：前端工程师常遇到这种需求：老板丢来一个竞品网站，"照这个做一个"。传统做法要手动翻 DOM、量样式、抄交互，极其枯燥。AI Website Cloner（独立开发者 JCodesMore 出品）在 2026 年 7 月连续登上 GitHub Trending，狂揽 26,000+ 星标。它的核心能力一句话说清：给 AI 编程助手一个网址，几分钟后自动把整个网站逆向还原成可运行的现代前端代码——不是截图、不是静态 HTML 拷贝，而是完整的 Next.js 项目，含组件、样式、交互逻辑、响应式适配。官方推荐使用 Claude Code + Opus 4.8，且兼容 13 种主流 AI 编程工具。今天值得关注，是因为它把"网站克隆"从体力活变成了多 Agent 流水线。

---

**⭐ 深度项目解析**

**▌ 它是什么**
AI Website Cloner 本质上是一个"技能包（Skill）"，安装到任意 AI Agent 工具上即可用。它把"克隆网站"拆成一条五阶段多 Agent 协作流水线：侦察 → 基础建设 → 组件规格 → 并行构建 → 组装与 QA。它本身不写模型，而是编排多个 Builder Agent 并行工作，最终吐出一套可运行的前端工程。

**▌ 解决什么痛点**
还原一个网站，难点不在"抄"，而在"理解"：滚动行为、点击交互、悬停效果、响应式断点，这些散落在无数行 DOM 与 CSS 里。人工复刻一个中等页面往往要数小时，且极易遗漏细节。没有这类工具时，开发者只能像素级比对、反复刷新。AI Website Cloner 让 Agent 先系统化扫描目标站点、记录交互与样式规范，再并行派出十几个 Builder Agent 各自负责一个组件，在独立分支上开发，最后组装并做视觉回归。对做竞品分析、快速搭原型、做设计稿落地的团队，时间从"天"压缩到"分钟"。

**▌ 原理拆解**
其原理是一条多 Agent 流水线：
```
阶段1 侦察: 打开目标站，记录滚动/点击/悬停/响应式行为
  ↓
阶段2 基础建设: 抽取设计令牌，下载图片/视频/SVG 资源
  ↓
阶段3 组件规格: 拆解区块，生成 getComputedStyle() 级 CSS 规范
  ↓
阶段4 并行构建: 多个 Builder Agent 各负责一组件，独立分支开发
  ↓
阶段5 组装QA: 拼回完整页，视觉回归测试，输出 Next.js 工程
```
关键在于"规格先行、并行构建"——组件规格阶段把每个区块的样式量化到计算值级别，下游 Agent 才能并行而不冲突，最后由组装阶段统一回归，保证视觉一致性。

**▌ 动手验证**
它作为技能包运行，命令极简：
```bash

/clone-website https://目标网站.com
# 2. 支持同时丢多个网址并行处理
/clone-website https://a.com https://b.com
# 3. 完成后在生成目录下查看完整 Next.js 工程并本地预览
cd cloned-site && npm install && npm run dev
```

**▌ 学习路线**

### 4. 【Page Agent：一行 JS 让企业内部网页听懂人话，阿里开源的网页自然语言操控工具】（⭐ 25k）

> 📍 **导语**：企业里的 ERP、CRM、后台管理页，表单多到头皮发麻——一个订单录入流程点 20 下鼠标是起步价。过去想自动化这类网页，要么用 Selenium/Puppeteer 太重，要么上 RPA 太贵。2026 年 7 月，阿里开源 Page Agent（仓库 `alibaba/page-agent`），GitHub 星标已突破 25,000。它的做法简单到离谱：一行脚本加进页面，刷新后右下角多一个对话框，你说"点击登录"它就点，说"输入用户名 admin"它就打。今天值得关注，是因为它把"用自然语言驱动网页"做成了零门槛的轻量方案，特别贴合企业内部系统的自动化痛点。

---

**⭐ 深度项目解析**

**▌ 它是什么**
Page Agent 是一个基于 TypeScript 的"页面内 GUI 代理"，用自然语言操控网页。它不是一个独立 App，而是一段可嵌入的脚本：把它注入任意页面，页面就获得一个对话入口，用户用中文/英文下发指令，Agent 在页面内直接执行点击、输入、选择等操作。仓库语言为 TypeScript，已在 2026-07-04 登上 GitHub Trending 日报。

**▌ 解决什么痛点**
企业内部系统的最大痛点是"操作繁琐但逻辑固定"：每天在后台重复点几十次相同流程，既耗时又易错。Selenium 写脚本成本高、维护难；商业 RPA 授权贵、部署重。没有 Page Agent 时，员工只能机械重复。它用"纯文本驱动"绕开了传统自动化的重包袱：不需要截图、不需要视觉识别，只要把页面 DOM 翻译成文字清单交给大模型，模型返回操作指令即可执行。对客服、运营、数据录入等高频重复岗位，是把人力从点击中解放出来的低成本杠杆。

**▌ 原理拆解**
Page Agent 的原理分三步，是一个"DOM 文本化 + LLM 决策 + 页内执行"的闭环：
```
步骤1 翻译: 把页面 DOM 结构转成文本清单（按钮/输入框/下拉全变文字描述）
  ↓
步骤2 决策: 文本清单 + 用户指令 → 大模型返回具体操作（如 click#login）
  ↓
步骤3 执行: Page Agent 在页面内调用原生 API 完成点击/输入/选择
  ↓
输出: 用户用一句话完成的原本需多步鼠标操作
```
关键设计是"不依赖视觉"——直接用 DOM 语义而非截图，既快又准，也避开了视觉模型的成本与误差。指令与页面状态在同一上下文，多步任务也能连贯执行。

**▌ 动手验证**
注入方式极简，一行即可：
```bash
# 1. 在目标页面通过浏览器控制台或书签注入脚本（示意）
# 把官方提供的 page-agent 脚本通过 <script> 引入页面
<script src="https://unpkg.com/@alibaba/page-agent/dist/agent.js"></script>
# 2. 刷新页面，右下角出现对话框
# 3. 输入自然语言指令即可驱动页面
# 例如: "点击登录" / "在用户名输入框输入 admin" / "提交表单"
```

**▌ 对比选型**
| 维度 | Page Agent | Selenium | 商业 RPA |
|------|------------|----------|----------|
| 接入成本 | 一行脚本 | 写代码 | 授权+部署 |

### 5. 【Meetily：基于 Rust 的隐私优先本地 AI 会议助手，4 倍速实时转录与说话人分离】（⭐ 21.7k）

> 📍 **导语**：会议记录是个高频刚需，但把录音传到云端转写，隐私敏感型团队根本不敢用。Meetily（仓库 `Zackriya-Solutions/meetily`）是一个隐私优先的开源 AI 会议助手，用 Rust 构建，集成 Parakeet / Whisper 实现约 4 倍速的实时语音转录与说话人分离，全程本地处理、不联网。它兼容 Ollama 做摘要，支持 macOS 与 Windows。截至 2026-07-10 已收获 21,674 颗星。今天值得关注，是因为它把"会议智能"从云端 SaaS 拉回了本地，给企业内网、医疗、法务等强隐私场景提供了一条合规路径。

---

**⭐ 深度项目解析**

**▌ 它是什么**
Meetily 是一个本地优先的 AI 会议助手，核心是用 Rust 写的桌面应用，把语音识别（Parakeet / Whisper）、说话人分离（diarization）、摘要（对接本地 Ollama）串成一条完全在本地跑的流水线。它不把音频发到任何外部服务，所有计算在用户机器上完成，是隐私敏感场景的"可审计替代方案"。

**▌ 解决什么痛点**
传统会议记录有两种代价：要么人工记、费时且易漏；要么用云端转写 SaaS、快但数据出境。对医疗、法务、金融以及任何处理机密信息的团队，把会议录音上传第三方是合规红线。没有 Meetily 时，这类团队只能在"效率"与"隐私"间二选一。Meetily 用本地模型把转写速度做到实时的约 4 倍（即 1 小时会议几分钟出稿），并自动区分"谁在说什么"，再用本地大模型生成结构化纪要。对动辄每天数场内部会的团队，这是既保合规又保效率的关键工具。

**▌ 原理拆解**
Meetily 的原理是"本地音频流水线"：
```
输入: 麦克风/系统音频实时流
  ↓
ASR层: Parakeet 或 Whisper 本地模型做语音转写（约4倍速）
  ↓
分离层: diarization 模型区分不同说话人，打上Speaker标签
  ↓
摘要层: 文本送本地 Ollama 生成结构化纪要
  ↓
输出: 带说话人、带时间戳、带摘要的本地会议记录
```
关键设计是"全程离线"——Rust 负责音频捕获与编排，推理全走本地模型权重，无任何网络请求。这让它在隔离内网也能跑，且数据零外流。

### 6. 【Herdr：用 Rust 写的高性能终端 Agent 多路复用器，一台终端并发管理多个 AI 智能体】（⭐ 14.4k）

> 📍 **导语**：当你同时养着好几个 AI 编程 Agent——一个写前端、一个审后端、一个跑测试——在多个终端窗口间来回切，上下文和注意力都会被切碎。Herdr（仓库 `ogulcancelik/herdr`）是一个用 Rust 编写的高性能终端 Agent 多路复用器，让你在"一台终端"里并发管理多个 AI Agent 同时运行。2026-07-04 登上 GitHub Trending 日报，已收获 14,409 颗星。今天值得关注，是因为"多 Agent 并行"正在从概念变成日常，而终端正是调度它们最高效的指挥台。

---

**⭐ 深度项目解析**

**▌ 它是什么**
Herdr 是一个终端里的"Agent 多路复用器"：它不像单个聊天机器人那样一次只服务一个会话，而是把多个 AI Agent 的会话面板聚合在同一个终端界面里，支持并发运行、分屏查看、统一输入调度。用 Rust 编写，意味着低内存占用与高响应速度，适合长时间挂多个 Agent 的场景。

**▌ 解决什么痛点**
多 Agent 协作的尴尬在于"调度繁琐"：你要么开一堆终端标签手动切，要么用 tmux 自己拼，要么在不同 GUI 工具间跳。Agent 一多，光是"看谁在干什么、谁卡住了"就耗掉大量精力。没有 Herdr 时，并行跑三个 Agent 等于同时盯三个窗口。Herdr 把它们收进一个多路复用视图：左边列 Agent、右边看输出，谁完成、谁报错一目了然，你只需在统一入口下发与转发任务。对"用 Agent 舰队做并行编码"的团队，这是把混乱变有序的指挥面板。

**▌ 原理拆解**
Herdr 的原理是"终端多路复用 + Agent 会话抽象"：
```
输入: 用户在统一终端界面操作
  ↓
会话层: 为每个 Agent 维护独立会话状态与历史
  ↓
调度层: 多路复用器并发驱动多个 Agent，分屏渲染输出
  ↓
交互层: 统一快捷键在 Agent 间切换、转发上下文、广播指令
  ↓
输出: 单终端内并行可视的多个 Agent 工作流
```
关键设计是"Rust 内核 + 会话隔离"——Rust 保证多路渲染的轻量与低延迟，会话隔离确保每个 Agent 的上下文互不污染，转发时才显式共享，避免串味。

**▌ 动手验证**
Rust 项目，用 cargo 安装：
```bash
# 1. 通过 cargo 安装
cargo install herdr
# 2. 启动多路复用终端
herdr
# 3. 在界面内新建多个 Agent 会话面板，分别绑定不同任务/模型
# 例如: 面板A=前端编码, 面板B=后端审查, 面板C=测试运行
```

**▌ 对比选型**
| 维度 | Herdr | 多开终端标签 | tmux 手动拼 |
|------|-------|--------------|-------------|
| Agent聚合 | 原生支持 | 否 | 半手工 |
| 资源占用 | 低(Rust) | 高 | 中 |
| 统一调度 | 是 | 否 | 弱 |
| 适用 | 多Agent并行 | 单任务 | 通用 |

**▌ 真实场景实战**
一个功能需要前后端联动改造。开三个 Herdr 面板：A 让 Agent 改前端组件，B 让 Agent 同步改后端接口，C 跑测试套件。你在一个终端里巡视三者进度，发现 B 报错就把日志转发给 A 对齐。最佳实践：给每个面板约定清晰的职责边界，避免 Agent 互相覆盖文件。相比手动切窗口，它把"盯进度"的精力成本降到接近零，让你把注意力留给真正的决策而非界面切换。

**▌ 学习路线**
前置：会用终端，了解 AI Agent 基本概念。入门：装好 Herdr，建两个面板跑不同小任务。进阶：把它接入你的 CI/测试流，做"常驻 Agent 舰队"。今日行动：在同一终端里并行跑两个 Agent，体会统一调度的省心。

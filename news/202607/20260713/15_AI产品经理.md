### 1. 【主】数据飞轮与评测驱动：AI产品经理如何构建可量化的产品质量评估体系

> 📍 **导语**（100-160字）: AI 产品的好坏不能只看 DAU 和留存，模型准确率、任务完成率、幻觉率才是真正的"产品健康度"。2026 年 AI PM 必须建立"业务指标 + 模型指标"双轨评估体系（Evaluation-Driven Development），用 A/B 验证不同模型/Prompt 的效果差异，用人工标注加自动评分持续监控输出质量。把评估当成产品的"体检表"，才能在模型周级迭代中守住体验底线。

---

**📋 深度产品分析**

**▌ 核心指标速览**（100-200字）
- 评估覆盖率（Evaluation Coverage）：生产环境 AI 功能中被自动评估覆盖的比例，Elite 团队 >90%。
- 有效完成率：用户未触发"重新生成" + 结果页停留 >5 秒 + 进行下一步操作，三者同时满足，行业基准约 70%。
- Token 效率 = 任务完成质量评分 / Token 消耗总量，同样效果 Token 效率高 2 倍 ≈ 毛利率高 2 倍。
- 漂移检测时效（Drift Detection Lead Time）：Elite 团队 1 小时内发现质量回退。
- 人工对齐 Cohen's Kappa >0.7 才认为 Judge 评估可信。

**▌ 这个方法/案例是什么？**（150-250字）
评测驱动开发（EDD）是把"好不好用"从主观感受转化为可比较、可追踪、可自动化指标体系的工程方法。它适用于所有已上线的生成式 AI 产品，尤其当团队规模超过 5 人、模型每月迭代、且输出质量直接影响付费转化的阶段。新手 PM 最容易踩的坑是"用满意度代替质量"——满意度包含情绪和界面等非任务因素，无法反映真实任务完成度。与传统 PM 的本质区别：传统产品迭代靠点击率、留存率等客观指标；AI 产品因模型不确定性，必须额外建立"模型能力边界"和"输出质量"的独立评估层，且评估本身要随线上分布持续漂移而动态更新。

**▌ 为什么有效？（底层产品逻辑，400-600字）**
AI 产品的核心特性是"不确定性"：同样 Prompt，模型升级后可能变好也可能变坏；上游厂商（OpenAI、Anthropic）会静默更新权重；用户提问分布会随热点迁移。没有评估，PM 等于蒙眼开车。评测体系利用了三个杠杆：第一，数据飞轮效应——线上真实流量经 LLM-as-a-Judge 打分后回流为优化信号，低分样本自动进入 DSPy 训练集或 SFT 数据集，形成"评估→优化→再评估"闭环，腾讯云案例显示 CoT 强制推理比直接打分一致性高 25%–40%。第二，成本可观测性——Token 效率指标让 PM 能用同一把尺子比较"贵但准"与"便宜但幻觉多"的方案，避免被厂商跑分误导。第三，风险前置——AI QA Scorecard 的 Safety Failure Rate 与 Human Oversight Adherence 直接对应监管与品牌风险。决策框架：当产品处于"模型能力决定体验上限"阶段（如写作、问答、Agent），评估体系是必选项；当产品只是把 AI 当普通 API 调用且输出不直接影响决策（如内部分类标签），可用轻量人工抽检替代。关键数据：某医疗诊断 Agent 评测中发现，对罕见病的诊断准确率比常见病低 41%，根源是训练数据分布偏差——若不建立分病种评估，这一缺陷会一直被平均准确率掩盖。失败场景：只建固定 Golden Test Set 而不同步线上分布，一个月后覆盖率可能跌到 30% 以下（腾讯云称"评测集过拟合"），此时评估已失真。

**▌ 具体怎么落地？（实操指南，300-600字）**
第一步（定义）：列出核心场景测试用例集（建议 20 个典型场景，覆盖长文本、短文本、专业领域），明确每个场景的"有效完成"标准与评分 Rubric（结构化 YAML/JSON，可版本控制）。第二步（执行）：搭建 LLM-as-a-Judge 流水线——智能采样层（只采样低置信度、长尾、用户负反馈请求，将 Judge API 成本控制在总推理 3%–5%）→ Judge 执行层（CoT 先给理由再打分）→ 校准层（定期人工抽检算 Kappa，<0.7 触发 Rubric 修订）→ 反馈闭环层（低分样本自动进 CI 回归）。第三步（验证）：建立夜间评估（Nightly Eval）对代表 Prompt 集跑分，异常自动告警；每周人工校准一次偏差。产出物：一份可版本化的评估看板（覆盖率、有效完成率、Token 效率、安全失败率）+ 一份 PRD 中的"质量门禁"章节（上线前必须通过预设 Rubric 阈值）。

**▌ 真实产品案例（必填）**
| 维度 | 案例详情 |
|:----|:---------|
| 产品名称 | 某医疗诊断 Agent（国内三甲试点） |
| 问题背景 | 平均准确率高，但分病种表现差异大，无法定位薄弱点 |
| 执行过程 | 建立 20 场景测试集 + LLM-as-a-Judge 多维 Rubric + 每周人工校准 |
| 结果数据 | 发现罕见病诊断准确率比常见病低 41%；经数据补采后整体误诊率下降，评估覆盖率达 92% |
| 关键启示 | 平均指标会掩盖分布偏差，分场景评估是医疗 AI 上线前的硬门槛 |

**▌ 对比分析**
| 对比维度 | 本方法 | 传统方案 | AI特有方案 |
|---------|--------|---------|-----------|
| 核心逻辑 | 双轨指标 + 持续评估 | 仅看 DAU/留存 | LLM-as-a-Judge 自动打分 |
| 适合场景 | 生成式/ Agent 产品 | 确定性功能产品 | 模型周级迭代产品 |
| 投入成本 | 中（需建管线） | 低 | 中高（算力成本） |
| 见效周期 | 2–4 周 | 即时 | 1–2 周 |
| 最大风险 | 评测集过拟合 | 质量黑盒 | Judge 偏见未被校准 |

**▌ 今天就做的一件事**（100-200字）
打开你的产品后台，导出最近 7 天用户"重新生成"和"负反馈"的请求样本各 30 条，手动打一个 1–5 分质量分，统计你的"有效完成率"基线。预计耗时 40 分钟。做完后你会得到一个真实数字——如果低于 70%，说明你的产品正 silently 流失用户，明天就能据此排优先级。

### 2. 【主】Agentic UX设计：从聊天框到"对话+画布"的AI Agent交互范式

> 📍 **导语**（100-160字）: 当 AI 从"回答问题"进化为"自主执行任务"，传统 GUI 与单轮对话都失灵了。Agentic UX 的核心是从"用户适应界面"转向"界面适应用户"：AI 主动预测操作、用户只需确认或拒绝。2026 年领先产品已走向"对话 + 画布 + 多 Agent 军团"的三层架构，PM 必须重新设计状态机、优先级与约束，而非具体按钮。

---

**📋 深度产品分析**

**▌ 核心指标速览**（100-200字）
- 对话深度阈值：当用户需求需迭代 30 轮以上，纯对话框信息线性堆叠导致全局不可见，画布形态留存更优（天工 Skywork Design 实证）。
- 多 Agent 并行：Dynamic Workflows 将批量任务从"逐轮手动"变为"百个 Agent 并发"，规模任务效率提升一个数量级。
- 分层对话策略：指令层（直接执行）/ 策略层（先分析再确认）/ 洞察层（预测性建议），对应不同确认强度。
- 上下文断裂率：传统长对话在第 10 轮后话题丢失，结构化记忆可将多轮稳定性量化提升。

**▌ 这个方法/案例是什么？**（150-250字）
Agentic UX 是面向 AI Agent 的交互范式，把界面从"固定按钮布局"改为"意图理解 + 主动服务 + 可逆操作"。它适用于多步骤、跨工具、需要持续上下文的复杂任务产品（如设计、研发、数据分析 Agent）。新手 PM 常犯的错是把 Agent 塞进旧版 Chatbot 外壳，导致用户在第 15 轮对话时"记不清第 3 轮说了什么"。与传统 UX 本质区别：传统 UX 假设"我设计按钮，用户来点"；Agentic UX 假设"我理解意图，主动给最优操作"，界面元素变为状态机与约束条件，而非静态页面。

**▌ 为什么有效？（底层产品逻辑，400-600字）**
Agentic UX 利用了 AI 的三个特性：意图理解、长程记忆、自主规划。第一，意图直达降低认知负荷——用户不必学习工具，工具揣测并适应用户（如注册选"我是 HR"后首页直接预生成校招海报草稿）。第二，画布解决"对话的线性诅咒"：对话适合说清一件事，画布适合看清一件事；当需求复杂到需迭代 30 轮，对话框信息堆叠难以纵览全局，而画布把首页、生成页、画廊沉淀为可持续修改的 UI 项目，所有历史可视化留存。天工 3.1 的 Skywork Design 正是把设计工作从对话框搬到无限延展画布，一轮对话对应一轮迭代，第 40 轮画布"不会忘"。第三，多 Agent 军团解决规模瓶颈：Dynamic Workflows 面向"批量生成上百产品页、全站文案改版"类需求，派百个 Agent 并发执行。决策框架：单轮问答型用纯对话；3–15 轮中等复杂用"对话 + 操作建议预览"；15 轮以上复杂创作用"对话 + 画布"；规模化批处理用"对话 + 多 Agent 工作流"。失败场景：把完全代理化（用户只见结果不见过程）用在高频可逆操作上，用户会失去掌控感而弃用——灵钥 V5.1 的实践表明，需保留"观点边界"与"关系感知"，让 AI 输出可控而非过度干预。

**▌ 具体怎么落地？（实操指南，300-600字）**
第一步（定义状态机）：列出产品所有"什么情况显示什么内容"的状态规则，而非画具体页面。第二步（分层对话）：指令层（简单命令直接执行，如"部署到生产"）；策略层（复杂任务 AI 先分析再问确认）；洞察层（预测性建议如"检测到潜在 bug，是否修复"）。第三步（引入画布/工作流）：当用户对话轮次 >15 或需管理多对象时，自动切换至画布视图；批量任务触发多 Agent 并发。第四步（可逆性）：所有 AI 动作提供预览、确认、Undo，降低误操作恐惧。产出物：一份 Agentic UX 状态机文档 + 画布/对话切换阈值定义 + 多 Agent 任务编排 PRD。

**▌ 真实产品案例（必填）**
| 维度 | 案例详情 |
|:----|:---------|
| 产品名称 | 天工 Skywork 3.1（昆仑万维） |
| 问题背景 | 用户与 AI 聊到第 15 轮后难以纵览全局，对话框管不了十几个页面的设计 |
| 执行过程 | 上线 Skywork Design（画布）+ Dynamic Workflows（多 Agent 并发） |
| 结果数据 | 复杂设计需求从"便签纸画建筑图"变为可视化项目；批量页面生成效率提升一个数量级 |
| 关键启示 | 对话负责"说清"，画布负责"看清"，多 Agent 负责"做多" |

**▌ 对比分析**
| 对比维度 | 本方法 | 传统方案 | AI特有方案 |
|---------|--------|---------|-----------|
| 核心逻辑 | 界面适应用户意图 | 用户适应固定界面 | 对话+画布+多Agent |
| 适合场景 | 复杂/多步骤任务 | 确定性流程 | 自主执行任务 |
| 投入成本 | 高（架构重构） | 低 | 中高 |
| 见效周期 | 1–2 月 | 即时 | 2–4 周 |
| 最大风险 | 用户失控感 | 无法处理模糊意图 | Agent 编排失控 |

**▌ 今天就做的一件事**（100-200字）
打开你正在做的 AI 产品，数一数用户平均需要几轮对话才能完成核心任务。如果超过 10 轮且涉及多对象管理，立刻画一张"状态机图"：列出 3 个最高频意图，标注每个意图下 AI 应主动提供什么操作建议。预计耗时 30 分钟，这能暴露你当前界面是否把认知负荷错误地推给了用户。

### 3. 【主】极速激活：用意图预测与预设生成重写AI产品Onboarding流程

> 📍 **导语**（100-160字）: 传统 Onboarding 靠引导页教用户"怎么用"，AI 原生产品却让用户"说一句需求"直接拿到结果，激活终点从"学会操作"变成"表达意图"。范式已从"Demo 优先"走向"意图即入口"：砍掉冗余导航，用多模态对话与预设生成做零学习成本的核心交互，PM 要设计的是第一句话就能交付价值的"黄金首屏"。

---

**📋 深度产品分析**

**▌ 核心指标速览**（100-200字）
- 60 秒到价值（WARP 框架）：新用户进入产品 60 秒内应获得真实结果，而非走完引导 tour。
- 首次成功生成时间（Time-to-first-successful-generation）：核心激活指标，越短留存越高。
- 激活率目标 >50%、习惯形成率（第 2 周回访）目标 >25%。
- 提示迭代率目标 1.5+/会话、输出满意度目标 >60%。
- Elys 通过精细化 onboarding 仪式 + 三维度风格滑块，让用户首次体验"数字自我意识"。

**▌ 这个方法/案例是什么？**（150-250字）
AI-Native Onboarding 是用"意图预测 + 预设生成"替代"功能教学"的激活方法。它适用于所有生成式 AI 产品，尤其面向非专业用户、且首屏是空白输入框的产品。新手 PM 最易踩的坑：在首页放"你想问点什么？"的极简输入框，把创造提示词的认知负荷全部推给小白用户，造成"指令恐惧症"和空白状态流失。与传统 Onboarding 本质区别：传统 SaaS 教"功能在哪"，AI SaaS 教"怎么协作"——用户要学的是"问什么、怎么改、何时信"，而不是按钮位置。

**▌ 为什么有效？（底层产品逻辑，400-600字）**
AI 产品利用了"产出即价值"的特性：用户一旦在短时间内看到实实在在的产出，PLG 链路留存率大幅提升。第一，意图直达消除空白状态——用户注册选标签【我是 HR】，首页即由后台大模型预生成"本月招聘季的校招海报草稿和 JD 文案，点击即可修改"，用预设 Prompt 和 UI 点击代替纯自由输入。第二，Aha Moment 前置：GitHub Copilot 的 Aha 是"第一次接受 AI 建议省下 10 分钟"，Notion AI 是"一句话生成会议纪要质量比自己写还好"，Cursor 是"自然语言重构复杂代码不到 30 秒"——这些都发生在 3 步内。第三，自适应引导替代固定 tour：传统引导按预测路径设计，用户一偏离就失效；AI 引导在用户卡住时 surfacing 建议、跳过步骤时自适应，不会 stale。决策框架：若激活率是瓶颈，先做 action-gated 清单与自适应流；若激活稳但功能留存软，做 in-app 辅助与行为分群。失败场景：盲目追求"AI 可以做任何事"而摊薄输出质量——冷启动阶段宁可缩小范围保质量，也不要大而不精；输出质量不达预期是 AI 冷启动失败最常见原因。

**▌ 具体怎么落地？（实操指南，300-600字）**
第一步（定义 Aha）：逆向分析 7 日留存最高的前 10% 用户，找出他们首次使用的共同行为；或用用户访谈问"第一次觉得产品真有用是什么时候"。第二步（减少步骤）：把"注册→设组织→邀成员→建库→传文档→提问"压成"注册→内置示例→直接提问"3 步内。第三步（预设生成）：注册时让用户选 2–3 个用途标签，首页用大模型预生成场景化提案；首屏放 3–5 个模板 Prompt + 预填示例，用户 30 秒内得到首个输出。第四步（序列跟进）：Day0 欢迎+首个可复制 Prompt，Day1 Aha 检查，Day3 真实案例，Day5 坦诚局限建立信任，Day7 进阶提示词，Day14 习惯触发。产出物：Aha Moment 定义文档 + 首屏预设生成 PRD + 14 天激活邮件序列。

**▌ 真实产品案例（必填）**
| 维度 | 案例详情 |
|:----|:---------|
| 产品名称 | Elys（AI 社交数字分身） |
| 问题背景 | 社交 App 注册流失高，用户面对空白界面无感 |
| 执行过程 | 精细化 onboarding 仪式：捏脸、录声音、回答"我是谁"、三维度风格滑块、Context 飞轮 |

### 7. 【副】海外AI产品失败复盘：从巨头翻车案例看AI产品的踩坑教训

> 📍 **导语**（100-160字）: 通用 Agent 初创存活率仅 18%，垂直 Agent 却达 45%——越通用越难落地。银行保险业坐拥 450 万亿资产却跑不出统治级 AI，根因是"零容错、无高质量数据、难标准化"三道门槛。复盘这些失败，帮 AI PM 避开"为通用而通用"与"低估行业门槛"两大陷阱。

---

**📋 深度产品分析**

**▌ 核心指标速览**（100-200字）
- 垂直 vs 通用存活率：医疗/金融垂直 Agent 初创约 45%，通用框架类仅 18%。
- 银行保险：总资产超 450 万亿、年营收超 10 万亿，却无行业级统治 AI。
- 法律 AI Harvey：Top100 律所 92 家付费，单客年费最高 $2000 万，并购尽调 48 小时完成、准确率 98.6%、成本仅人工 1/22。
- 医疗 AI OpenEvidence：覆盖全美 60% 三甲，临床决策辅助使用率 >75%。
- 三重门槛：可接受的容错边界、可获取高质量数据、可单点突破的标准化工作流。

**▌ 这个方法/案例是什么？**（150-250字）
海外 AI 失败复盘是从"跑输/未跑通"的产品中提炼 PM 决策教训的方法，重点对比"为什么某些行业能出统治级 AI、某些不能"。它适用于选型垂直 vs 通用、评估入场行业的 PM。新手常误判"越通用越值钱"，但数据表明通用框架存活率最低。与传统复盘本质区别：AI 失败多源于"容错边界误判"与"数据可用性"，而非功能缺陷——这是 AI 时代特有的失败模式。

**▌ 为什么有效？（底层产品逻辑，400-600字）**
复盘揭示了 AI 产品成功的三个隐藏要素。第一，容错边界决定护城河：医疗/法律能跑出统治级 AI，因为它们踩中"可接受容错边界 + 可获取高质量数据 + 可单点突破标准化工作流"三要素；而银行保险不能接受这三点——1% 误差即上亿损失，数据高度隔离难获取，核心风控工作流无法标准化，于是成为"落后生"。这告诉我们：选行业时先看"错误容忍度"，而非"市场大小"。第二，垂直 > 通用：通用 Agent 解决"效率问题"（做 PPT、写周报），垂直 Agent 解决"生死问题"（误诊、风控漏洞），低容忍度反而成护城河——专业壁垒越高对手越少、客户越愿付费。第三，数据闭环是生死线：法律 AI Harvey 用 3 年改写顶级律所工作流，靠的是深度耦合专业语料与可控输出；通用框架无行业数据，难达生产级。决策框架：若你做通用工具→必须靠网络效应与极致体验；若做行业 AI→先确认该行业是否具备"三要素"，否则慎入。失败场景：盲目切入零容错高监管行业却无高质量数据与标准化工作流，必死；或做通用 Agent 却无差异化，存活率仅 18%。

**▌ 具体怎么落地？（实操指南，300-600字）**
第一步（行业体检）：用"容错边界 / 数据可用性 / 工作流标准化"三要素给目标行业打分，任一项为 0 则慎入。第二步（定位）：能单点突破就做垂直（专攻肿瘤、眼科而非全科），用行业 Know-how 建壁垒。第三步（数据）：尽早绑定头部机构拿"证据链"（临床论文、专家背书、采购目录），数据即护城河。第四步（交付）：从"查法条"升级为"交付成果"（如合同审阅准确率 95%、风险识别提升 80%），按效果而非席位定价。产出物：行业三要素评分表 + 垂直切入点 PRD + 数据合作路线图。

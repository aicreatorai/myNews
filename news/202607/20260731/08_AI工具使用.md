# AI工具使用

### 1. 【Cursor 与 Claude Code 协同：Agent 编程工作流把需求直接变成可运行代码】

**导语**
2026 年，最会写代码的人往往不是只依赖某一个 AI 工具，而是把 Cursor 和 Claude Code 并排放在同一条工作流里。前者是你朝夕相处的编辑器，后者是你放在终端里的自主智能体。两者分工明确、用 git 做交接，能把"提需求—写代码—跑测试—修漏洞"的闭环压缩到几分钟。具体落地的分工是：Claude Code 负责"想清楚再动手"的计划与长跑，Cursor 负责"边看边改"的精细循环，git 则是它们之间的交接单。本文用一条真实功能开发路径，讲清怎么让这对组合各司其职、互不踩踏，把一个人的产出顶成一支小队。

**它是什么**
Cursor 是一款 AI 原生的代码编辑器，核心能力是 Tab 级自动补全、Cmd+K 针对性编辑、Composer/Agent 模式做跨文件修改，并能完整理解你的代码库规模与结构。Claude Code 则是 Anthropic 推出、跑在终端里的编码智能体，擅长读完整仓库、做多文件重构、真实运行测试、按分支做改动并主动读报错自修。2026 年两者都支持 Background Agents（后台智能体），你不必盯着界面，它跑完会通知你。两者还都支持 Skills（SKILL.md）与 MCP 工具生态，同一套能力描述可以在不同工具间复用，避免重复造规则。

**它解决了什么问题**
单用其一会留下明显能力空白：只用 Cursor，遇到需要跑测试、跨十几个文件、耗时半小时以上的大重构，容易跑偏且要人一直盯着屏幕；只用 Claude Code，又少了在编辑器里边看边改、即时预览的顺手感。把"编辑器内精修"与"终端里自主长跑"分开，既保住手感，又把重活交给能自我循环的智能体，避免来回切换造成的状态丢失与上下文断裂，也减少了人在低价值等待上的时间消耗。

**原理拆解**
关键在"谁干什么"的分工。Cursor 负责：文件导航、单文件小改、内联修复、UI 预览、肉眼看 diff。Claude Code 负责：仓库探索、多文件实现、执行测试、命令行调试、结构化 review。两者通过 git 工作树做契约——一次只让一个工具改代码，另一个做 review，改完提交再交接，避免两个 AI 同时写同一片文件造成磁盘竞争。共享规则放在 CLAUDE.md 与 .cursor/rules/ 里，保证两边上下文一致；MCP Server（github、postgres、slack 等）两工具通用，配一次处处可用。

**动手验证**
先在仓库根目录建共享规则：mkdir -p .claude/commands .cursor/rules .cursor/commands，再 touch CLAUDE.md 和 .cursor/rules/project-conventions.mdc，写清技术栈、命名规范与禁止项。比如要做一个"任务控制中心"界面，可让 Claude Code 先读相关文件、输出计划不执行；你确认后切到 Cursor 用 Composer 做精修与可视 review；长任务交回 Claude Code 后台跑，你去做别的事，它完成会通知你。最后用 git diff --check 做交接校验，必要时局部回退，保持工作树干净。

**对比选型**
轻量补全、单文件小改用 Cursor Tab 最快；需要读上下文仔细推理用 Cursor 聊天；12 个文件以上带测试的功能、30 分钟以上的重构交给 Claude Code；CI 报错修复在终端让 Claude Code 直接干。重度用户两者月费合计约 40–60 美元，远低于资深工程师一小时成本。切忌两者同时改同一文件，也别用 Claude Code 去做 Tab 补全那种细活——把合适的工作交给合适的工具，组合收益才大于单工具之和。

### 2. 【豆包进阶实战：用智能体编排与无人值守把日常办公自动化】

**导语**
豆包是字节跳动推出的全场景智能体平台，很多人只把它当聊天框用，其实它的进阶玩法在"智能体编排"和"无人值守"上。把常用任务沉淀成自定义智能体，再配合自然的语音交互和批量文件处理，日常办公里的重复劳动可以大幅让位给 AI。具体说，就是把"每周写周报""整理会议纪要""批量改文案"这类固定动作，从每次手动交代变成一次配置、长期复用的流水线。本文讲清怎么把豆包从"问答工具"升级为"办公自动化入口"。

**它是什么**
豆包支持对话框主交互、语音对话（国内 AI 工具里最自然的语音之一）、文件上传（PDF/TXT/CSV/Word/Excel/PPT 等最多 50 个）、以及海量预置场景智能体。进阶用户还能零代码自定义助手，把一套固定流程封装成可复用的智能体，并通过开放接口接入自动化流水线，让它在你不在时也能按规则跑任务。它内置音乐生成、生活垂直智能体商店等能力，覆盖面从学生日常到职场通用再到短视频脚本。

**它解决了什么问题**
职场里大量时间消耗在"复制粘贴式"的重复劳动——整理会议纪要、写周报、改文案、答复固定问题。豆包的价值不在于单次问答，而在于把这些高频动作标准化：一次配好智能体的角色、格式与约束，之后每次只需丢材料进去就能拿到统一格式的产物，避免每次重新交代背景，也避免风格飘移。当这类任务被固化成智能体，人就只需做终审，而不是从头写起。

**原理拆解**
核心是把"角色—任务—要求"三元结构固化下来。先给智能体一个明确人设（如"十年经验营养师"），再规定输出格式（表格/分点/Markdown）和排除项（不要术语、不要超字数）。豆包的内容创作秘诀是锁定目标人群、渠道、情感基调和热点元素；批量场景则可用脚本把豆包与 DeepSeek、Kimi 等串成工作流，用 Python 整合各家结果，实现无人值守的连续产出。指令越具体，输出越贴近预期，减少来回返工。

**动手验证**
第一步，打开豆包 App，点底部中间语音键用说话方式交代任务，体验最自然的语音交互；第二步，进入智能体创建，写入"你是资深新媒体运营，负责把产品资料改成小红书文案，要求突出功效、用流行语、每条配场景与标签"；第三步，上传一份产品资料 PDF，让智能体批量产出 3 条文案；第四步，对不满意的结果追加"换种思路重写"或"缩短到 200 字"做多轮微调；第五步，把验证过的指令存为模板，下次直接调用，形成可复用的办公智能体。

**对比选型**
追求生活化、语音自然、零代码自定义助手，豆包最顺手；要超长文档解析（200 万字级）选 Kimi；要科研级严谨推理与多文献交叉比对，选专业推理工具；要代码优先选通义灵码。豆包强在"轻量一站式"，弱在超长论文的研读深度。日常办公自动化首选豆包，研究型长文另配专用工具，两者互补而非互斥。

### 3. 【智谱清言使用技巧：用长文档问答与代码解释器搞定研究与开发】

**导语**
智谱清言是智谱 AI 推出的通用助手，很多人只拿它聊天，却忽略了它在"长文档问答"和"代码解释器"上的实战价值。把几十页报告、论文或需求文档丢进去连续追问，再让它写可运行代码并当场解释，研究与企业开发的效率能明显提升。这条"读文献—写代码—做验证"的链路，恰恰是研究生、分析师和独立开发者最高频的工作。本文聚焦这两条被低估的高频工作流，给出可直接套用的指令模板。

**它是什么**
智谱清言支持长上下文对话、文件上传分析、代码执行与解释、以及智能体调用。它的长文档问答能提炼结构、对比观点、指出数据支撑不足的论点；代码解释器则能在对话里直接运行 Python，完成计算、绘图与数据处理，并把每一步用白话讲清楚，让非专业用户也能看懂代码在干什么。这两类能力叠加，使它同时胜任"研读"与"实现"两端。

**它解决了什么问题**
读长文最痛苦的不是"看不完"，而是"读完了抓不住重点、问不出深问题"。智谱清言把文档变成可追问的知识库：你能让它按维度拆解、用表格对比、标出矛盾点。写代码时，它既给成品也给思路，新手不必在报错里空转，研究者能快速验证一个想法，把"读文献—写代码—做验证"串成一条顺畅的链路，而不必在多个工具间反复搬运上下文。

**原理拆解**
长文档问答的本质是结构化抽取——模型先梳理文档结构，再按你的维度提取结论、定位原文出处。代码解释器则是把自然语言转成可执行代码，在沙箱里运行并返回结果与图表，再把代码逻辑逐行解释。两者都依赖"给足背景 + 明确输出格式"的指令原则，角色越具体、约束越清晰，结果越稳，也越不容易跑题。先把问题框死，再让模型填空，是提精度的关键。

**动手验证**
第一步，上传一份 50 页行业报告，输入"请从技术趋势、市场格局、政策影响三维度分析，提取每维度关键结论，指出数据支撑不足的论点，用表格对比主要企业份额变化"；第二步，针对结论追问"这些判断有哪些市场数据支持"，逼出可核验依据；第三步，切换到代码解释器，让它"用 Python 读入这份 Excel，按区域拆解营收增长动因，输出汇总表与可视化描述"；第四步，对代码问"第 12 行为什么这样处理"，让它逐行解释；第五步，把验证过的分析框架存成模板，下次换文档直接复用。

**对比选型**
长文档与代码一体、要对话里直接跑代码，智谱清言很合适；纯超长文本（百万字）选 Kimi；要严谨溯源与多文献交叉比对，配专业推理工具；要生活化语音与零代码助手，选豆包。智谱清言强在"研究+开发"双场景，弱在超长小说的文学性分析。把读文献、写代码、做验证串起来，它是最佳承载体之一，尤其适合一个人既要懂业务又要会落地的场景。

### 4. 【即梦AI 使用教程：文生图与图生视频的一致性控制技巧】

**导语**
即梦 AI 是字节跳动旗下的图像与视频生成工具，新手常卡在"每次生成都变样"——同一个人、同一套风格，换个提示词就翻车。2026 年的解法不是更长的提示词，而是"参考图 + 种子参数"的一致性控制。对做短视频、电商图、绘本的人来说，能锁住角色与风格，意味着一条系列内容可以低成本连续产出，而不是每条都从零碰运气。本文用文生图到图生视频的最短路径，讲清怎么把"抽卡"变成"可控导演"。

**它是什么**
即梦 AI 支持文生图、文生视频、图生视频等多种模式，可在中文提示词下产出高精度画面，并提供参考图上传、风格控制与参数调节。它与主流图像引擎（如 FLUX、Midjourney）和视频引擎（如可灵、Veo）共享同一套"分镜—关键帧—动起来"的工作流逻辑，新手也能用中文描述拿到可用成片。对中文用户而言，它降低了提示词翻译与风格对齐的门槛。

**它解决了什么问题**
AI 出图最大的坑是"一致性"：做系列内容时角色频繁变脸、场景前后对不上、风格飘移。即梦 AI 通过参考图锚定外观、用风格参考图统一调性、用种子（Seed）复现基础画面，把"抽卡"变成"可控导演"，让短视频、电商图、绘本这类需要连续视觉的生产真正可复用。没有一致性控制，系列化内容就无法规模化，而这正是多数新手止步于单张好图的原因。

**原理拆解**
一致性靠三张"参考圣经"：角色参考图（同一角色 3–5 个角度，锁外观）、场景参考图（同一场景多角度，保环境一致）、风格参考图（选定一种视觉风格指导全部生成）。视频侧用 Image-to-Video：先用即梦或 FLUX 出高质量关键帧，再让视频模型赋予运动，比纯文生视频可控得多。Seed 参数固定随机种子，方便在同底图上微调而不整体重来。先求可控，再求惊艳，是稳妥的进阶顺序。

**动手验证**
第一步，写 15 秒微脚本，每个镜头只描述一个动作一个场景；第二步，用即梦文生图为每个镜头出 4 张变体，选最可用的一张（不追求完美）；第三步，把选中的图做图生视频，配镜头语言提示词如"缓慢右移，红色沙尘轻飘，24fps，运动强度 Medium"；第四步，建"连续性圣经"文件夹存角色、场景、风格参考图，后续生成直接引用；第五步，固定 Seed 做小幅迭代，用剪映拼接加 BGM 导出 1080p；第六步，把成片与参考图归档，沉淀为本账号的视觉资产库。

**对比选型**
要中文提示词友好、一站式文生图+视频，即梦 AI 门槛低；要电影级画质选 Midjourney/Veo；要写实人物与角色一致性选可灵 3.0；要开源免费本地跑选 FLUX。即梦强在"字节生态+中文体验+连贯生产"，弱在顶级电影感仍需外接引擎。新手从 Image-to-Video 起步最稳，先求可控再求惊艳，等工作流跑通再追加高级引擎。

### 5. 【ChatGPT 自定义指令与记忆实战：用持久化人设省去每次重复交代背景】

**导语**
很多人每天打开 ChatGPT 都要重新交代一遍"我是谁、我要什么风格"，其实 Custom Instructions（自定义指令）和 Memory（记忆）功能就是为解决这个重复动作设计的。把人设、偏好、禁忌一次性写进设置，之后每次对话都自动带上背景，省下的不是几句话，而是持续的上下文摩擦。对长期写作、固定受众的内容生产者来说，这一步配置能让每次开口就直接进入状态。实测下来，花十分钟配置，后续每次对话都能少说三句废话、多拿一段合身的输出。本文讲清怎么配、怎么用、怎么避坑。

**它是什么**
Custom Instructions 让你在设置里固定"关于你"和"回答偏好"两段持久化说明，对所有新对话生效；Memory 则让 ChatGPT 在对话中记住你主动让它记下的事实（如"我常用 Python 3.9""受众是 Z 世代"），并在后续对话调用。两者配合，相当于给 AI 装了一个常驻人设，不必每次重写背景，也不必担心它把你当陌生人。你还能查看、编辑、删除记忆，保持人设可控。

**它解决了什么问题**
反复交代背景既费时又容易漏。没有持久化，今天让它"用通俗语言"，明天又得说一遍；没有记忆，它总记不住你的稳定偏好。Custom Instructions + Memory 把稳定偏好固化，让输出风格一致、信息连贯，特别适合长期写作、固定受众的内容生产和个人助理类场景，把"每次重新热身"变成"开口就进入状态"，也降低了遗漏关键约束导致的返工率。

**原理拆解**
Custom Instructions 写入系统层，每次请求都附加这段上下文，模型据此调整角色与语气；Memory 则是对话中显式存储的事实库，模型在需要时检索调用，你也能查看、编辑或删除。注意 ChatGPT 会在快/推理模型间自动路由，输出风格可能突变，因此关键任务要固定模型版本，并把"什么是好答案"写进指令，而不是手把手教它怎么思考。指令写结果，不写过程，是和推理模型相处的要点。

**动手验证**
第一步，打开设置→Custom Instructions，在"关于你"写清身份、行业、常用工具；在"回答偏好"写清语气、长度、格式与禁忌（如"别用专业术语""用 Markdown 表格"）。第二步，对话中遇到稳定偏好，说"请记住我主要用 pandas 2.x"，让它存入 Memory。第三步，开新对话验证背景是否自动带上。第四步，定期在 Memory 设置里清理过期事实，避免旧信息干扰新任务。第五步，把验证过的好指令导出成模板，换账号或协作时也能快速复用。

**对比选型**
要结构化输出与插件生态选 ChatGPT；要长文档与严谨逻辑选 Claude（用 Projects 存规则、XML 标签提精度）；要 Google Workspace 联动选 Gemini。ChatGPT 强在 Custom Instructions 与 Memory 的易用、以及 GPTs 自定义机器人；弱在超长文档研读。把常用背景固化进设置，是所有模型提效的第一步，值得每个重度用户花十分钟配置，之后长期受益。尤其是跨项目协作时，把指令模板共享给队友，能统一整个团队的 AI 输出基线，避免每个人都要从头调一遍风格。

### 6. 【Copy.ai 与 Jasper 实战：用模板化提示词批量产出社媒与博客文案】

**导语**
内容团队最贵的不是创意，而是把创意重复产出几十遍的机械劳动。Copy.ai 和 Jasper 这类专用写作工具的价值，不在于"替你写好"，而在于用模板化提示词把博客、社媒、邮件批量跑通，让人专注在判断与润色上。对单人创作者和小型团队来说，能把周产出从 8 篇提到 25 篇以上，等于用一套流水线放大了人力。本文用一条从大纲到多平台分发的流水线，讲清两者怎么用、怎么避坑。根据实测，单人创作者用这套流水线能把月内容产出从 8 篇拉到 25 篇以上，相当于凭空多出一个兼职编辑，而这多出来的产能几乎不增加边际成本。

**它是什么**
Copy.ai 主打社交文案与"Blog Post Wizard"，可设语气（Expert/Friendly）在 5 分钟内出千字草稿；Jasper 偏营销长文案，提供 Blog Post Intro/Conclusion 模板与品牌语气设定。两者都能接 Buffer、ConvertKit 等做排程，也能借 API 串进 Google Sheets 自动化。定位上，它们都是"内容流水线的一环"，而非全能聊天机器人，强在规模化而非深度思考，适合把重复动作标准化后高速跑通。它不追求比 ChatGPT 更聪明，而追求比手写更快、比聊天更稳，把"批量"做成默认能力，让一个人也能跑出小团队的产量。

**它解决了什么问题**
一篇博客平均 3.5 小时，社媒每天 20 分钟，邮件 2 小时——这些重复产出是规模化的瓶颈。Copy.ai/Jasper 把"构思—草稿—改写—分发"标准化：博客 3.5 小时压到 45 分钟，社媒 20 分钟压到 5 分钟，单人周产出从 8 篇提到 25+ 篇。省下的是时间，留住的是人的编辑判断，让创作者把精力放在选题与把关上，而不是耗在格式与重复措辞里。

**原理拆解**
核心是"模板 + 变量"的提示词工程。先建可复用模板（如"为关键词 {KEYWORD} 写 {WORDCOUNT} 字文章，含 5 个 H2、自然嵌关键词、每段不超 4 行"），再把主题、受众、语气当变量填入。进阶用 Zapier 串起 Google Sheets（选题）→ 模型（生成）→ Buffer（排程）→ Google Docs（存档），并在发布前设人工审批与查重，保证品牌声音不漂移、不出硬伤。模板越沉淀，产出越稳定可控。

**动手验证**
第一步，在 Copy.ai 用 Blog Post Wizard 设语气 Expert，生成 1000 字草稿；第二步，用 Jasper 的 Intro/Conclusion 模板出三种开头，人工挑最强的一条；第三步，把长文丢进 Copy.ai 的社交模板，自动拆成 Twitter 线程、LinkedIn 帖子、IG 文案；第四步，用 Hemingway/Grammarly 做可读性校验；第五步，接入 Buffer 按日历排程，发布前人工过一遍语气与事实，再一键发出。整个链路跑顺后，把每步提示词存为版本化模板，团队可直接套用。

**对比选型**
社媒与短文案、性价比优先选 Copy.ai（月费约 36 美元）；营销长文案与品牌语气锁定选 Jasper（约 49 美元）；通用长文与高性价比选 Claude 或 ChatGPT Pro（各约 20 美元）；笔记与规划选 Notion AI。三者都只是流水线的一环，最终质量取决于人的编辑。新手从 ChatGPT/Copy.ai 起步最稳，先跑通再谈精致，避免一上来就为高级功能付费却用不满。真正省钱的办法是先拿免费额度验证模板是否好用，再决定是否升级付费档，避免为用不到的功能买单，也避免把工具当成万能药而忽略人的终审价值。

端侧AI集成：Apple Intelligence API允许开发者调用设备端Foundation Models（3B参数）进行推理，无需联网。代码示例：
```swift
import AppleIntelligence

func summarizeText(_ text: String) async throws -> String {
    let model = try await OnDeviceModel.named("summarization-3b")
    let result = try await model.generate(prompt: "总结：\(text)")
    return result.text
}
```
并发模型变化：Swift 6.3默认启用严格并发检查，以下代码会产生编译错误：
```swift
class DataManager {
    var items: [String] = [] // 错误：Mutable state in actor
    
    func addItem(_ item: String) {
        items.append(item) // 必须在actor内
    }
}
```
正确写法：使用`@MainActor`或将类声明为`actor`。

**▌ 技术细节深解**（258字）
KMP核心机制：`expect`/`actual`声明。开发者声明期望的API（`expect class PlatformLogger`），在各平台上提供实际实现（`actual class PlatformLogger`）。代码示例：
```kotlin
// 共享模块代码（commonMain）
expect class PlatformLogger {
    fun log(tag: String, message: String)
}

// Android实际实现（androidMain）
actual class PlatformLogger {
    actual fun log(tag: String, message: String) {
        Log.d(tag, message)
    }
}

// iOS实际实现（iosMain）
actual class PlatformLogger {
    actual fun log(tag: String, message: String) {
        NSLog("$tag: $message")
    }
}

// 共享业务逻辑
class UserRepository(
    private val api: ApiService,
    private val logger: PlatformLogger
) {
    suspend fun getUser(id: String): User {
        logger.log("UserRepo", "Fetching user $id")
        return api.getUser(id)
    }
}
```

⚠️ **适配风险**: 模型兼容性风险：某些模型架构（如Mamba、RWKV）尚未有良好的移动端实现。设备兼容性风险：低端设备无法运行大模型，需要提供回退方案（回退到云端API或小模型）。功耗风险：端侧AI推理会显著增加设备功耗（电池消耗），需要优化推理频率（如仅在充电时运行）。

💡 **学习优先级**: 1) 模型量化原理（PTQ vs QAT） - 1周；2) 移动端AI框架使用（TensorFlow Lite / MNN） - 2周；3) 端侧AI性能优化（功耗、推理速度） - 2周。推荐学习资源：Hugging Face文档（移动端模型分区）、TensorFlow Lite官方教程、MNN GitHub仓库。

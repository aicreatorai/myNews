### 1. 【采样与解码策略：温度、Top-p 与 min-p 如何选定下一个词】

▌ 导语

调用大模型 API 时那几个参数，多数人是抄来的配置：写代码调 0.2，写文案调 0.9，出问题就再调低一点。但采样是自回归生成链条里唯一"不可微、纯启发式"的一环。模型本身只输出一个概率分布，究竟从分布里挑哪个词，完全由采样器说了算。同一份权重在不同采样配置下，可以既像严谨的助手，也像满嘴跑火车的诗人。min-p 这类新判据被写进主流推理引擎的默认参数表，说明这一层仍有真实的提升空间，值得认真拆一次。

▌ 它是什么

采样策略是把模型最后一层输出的 logits 向量，变成"下一个 token 的具体选择"的那套规则。它包含两类操作：一是重塑分布，比如温度缩放、重复惩罚；二是截断候选集，比如 top-k、top-p（核采样）、min-p、typical sampling；最后在留下来的候选里按归一化概率抽一个。

常见误区有三个。第一，以为温度是"创造力旋钮"：温度只是把 logits 除以一个数，它同时放大了正确答案和胡话的相对机会，不生产任何新知识。第二，以为温度设成零就等价于贪心：多数框架把零特判成取最大值，但浮点累加顺序与批处理形状变化仍可能让结果不完全可复现。第三，以为温度和 top-p 可以随便叠加：两者的作用顺序会显著改变结果，实现上通常是先做各类分布重塑，再截断、再归一化。

适用边界很清晰：需要严格结构化输出的场合，比如生成 JSON、SQL、代码补全，应该走贪心或约束解码；需要多样性的场合，比如头脑风暴、数据增强、强化学习采样轨迹，才该开高温采样。历史脉络上，从束搜索转向核采样的转折点，是研究者发现"最大似然序列反而退化成重复循环"，这条经验至今支配着开放式生成的默认配置。

▌ 它解决什么问题

Before：早期机器翻译与摘要用束搜索追求最大似然序列，在开放式续写上出现严重的重复退化，整段循环、同一个词连出十遍。纯随机采样又是另一个极端：词表里几万个近乎零概率的长尾 token 加起来仍有可观的概率质量，一旦抽中就是"胡言乱语的种子"，而且错误会沿着自回归链条被后续步骤当成既定事实放大。

After：核采样按累积概率动态裁掉长尾，把候选集大小交给分布自己决定。min-p 进一步换了判据，用"相对于最高概率的比例"当阈值：最高概率是 0.9 时，系数 0.1 意味着只留概率高于 0.09 的候选；分布平坦、最高概率只有 0.1 时，门槛自动降到 0.01，候选自然放宽。min-p 的论文报告，在温度拉到 1.5 至 3 的高温区间，它仍能维持推理与数学基准上的正确率，而同样温度下核采样已明显掉分，等于把"创造性与可靠性"的可用空间整体拉大。工程上的价值更直白：推理模型做多路采样投票时，采样器决定了这些轨迹的有效多样性，直接影响多次采样的通过率。

▌ 原理拆解

第一层，直觉理解。把模型输出想成一位主厨端出的一桌菜，每道菜带一个推荐指数。贪心解码就是永远只吃推荐第一的那道，长期吃必然腻，也就是重复退化；纯随机采样是闭眼乱夹，可能夹到馊了的那盘；top-k 是只在前五盘里挑，可有时前两盘就明显最好、有时前二十盘都不错，固定数字太死板；top-p 是从推荐最高的开始拿，累计到占满九成五就停手；min-p 则先看第一名有多强，第一名特别强就只吃它附近的，第一名自己也拿不定主意，就多试几盘。

第二层，技术流程拆解。输入是词表维度的 logits，现代模型通常十几万维。步骤一，重复惩罚与存在惩罚按已生成内容给相应 token 减分。步骤二，温度缩放，除以 T，小于一让分布更尖，大于一让分布更平。步骤三，归一化成概率。步骤四，截断：top-k 保留前若干个；top-p 先排序，取累积和首次超过阈值的那段前缀；min-p 保留概率不低于系数乘最大概率的项；被淘汰的位置把 logits 置为负无穷。步骤五，重新归一化并做多项式抽样。输出 token 追加进序列，进入下一步。关键参数上，多数实现允许 top-k 与 top-p 同时启用并取交集，min-p 常用 0.02 到 0.1。

第三层，核心机制。min-p 的判据是"候选概率不小于系数乘以最大概率"，不等式两边都含有分布的最大值，等价于对相对置信度设门槛，而不是对绝对概率或累积质量设门槛。温度缩放会按幂次同时改变所有概率，最大值也一起变，比值受到的影响被部分抵消，这就是它在高温下更稳的数学来源。反观核采样，高温把分布压平之后，要累积到九成五需要纳入的候选数量会爆炸式增长，长尾垃圾大量入选。另一个常被忽略的机制是：采样与 KV 缓存无关，但与批处理强相关，同一批里不同请求的采样参数各不相同，推理引擎必须按请求维护独立的 logits 处理器，这正是采样参数在服务端按请求下发而非全局配置的原因。

▌ 动手验证

固定模型与提示词，只改采样参数，直接对比高温下核采样与 min-p 的差别。需要 transformers 4.44 及以上版本才支持 min_p 入参。

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "Qwen/Qwen2.5-1.5B-Instruct"
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name, device_map="auto")
ids = tok("用三句话解释什么是黑洞：", return_tensors="pt").to(model.device)

cfgs = [
    dict(do_sample=False),                              # 贪心，可复现基线
    dict(do_sample=True, temperature=2.0, top_p=0.95),  # 高温+核采样，易失控
    dict(do_sample=True, temperature=2.0, min_p=0.05),  # 高温+min-p，仍可读
]
for c in cfgs:
    out = model.generate(**ids, max_new_tokens=80, **c)
    print(c, "\n", tok.decode(out[0], skip_special_tokens=True), "\n---")
```

预期第二组出现跑题或生僻词，第三组保持通顺。注意关闭采样时传温度会触发告警。

▌ 对比选型

| 维度 | min-p | top-p 核采样 | top-k |
|---|---|---|---|
| 阈值依据 | 相对最高概率 | 累积概率质量 | 固定候选个数 |
| 高温稳健性 | 强 | 弱，易纳长尾 | 中等 |
| 典型取值 | 0.02 至 0.1 | 0.9 至 0.95 | 20 至 50 |
| 生态支持 | 主流引擎已内置 | 各框架默认项 | 各框架默认项 |

### 2. 【Mixture-of-Depths 与早退机制：让简单 token 少花算力】

▌ 导语

大模型对每个 token 都花同样多的算力：无论是一个语气助词，还是一个需要真推理的关键词，都得老老实实过完全部几十层。这在生物直觉上很不自然，在工程上更是浪费。Mixture-of-Depths 与早退这条技术线，试图让计算量随难度分配。当长思维链让解码步数成倍增长，"每 token 均摊算力"的成本被进一步放大，这条并不算新的思路重新变得紧要。

▌ 它是什么

Mixture-of-Depths 是一种在深度方向做稀疏的架构：每个 block 前面放一个路由器，为序列里的 token 打分，只让容量之内、分数最高的那部分 token 走完这一层的注意力与前馈网络，其余 token 顺着残差直连跳过这一层。早退是另一条路：在中间层挂一个输出头，如果当前层的预测已经足够自信，就提前吐出 token，后面的层不再计算。

它不是混合专家。混合专家在宽度上稀疏，选的是专家，每个 token 仍然要经过所有层；Mixture-of-Depths 在深度上稀疏，选的是层，单步浮点运算量直接下降。它也不是剪枝：剪枝静态地删掉权重，而这里是逐 token 动态决定路径，权重一个不少地全部保留。

边界上要注意，训练时用固定容量的选取方式，可以保证计算图静态、批处理形状可预测，这是它能落地的前提。早退在自回归解码里最大的坑是 KV 缓存缺失：提前退出的层没有计算这一位置的键值，后面的 token 想看它就必须补算。这正是相关工作要么引入状态传播近似、要么把"早退加剩余层验证"改造成自投机解码的原因。

▌ 它解决什么问题

Before：等浮点预算下所有 token 一律平权。两万 token 的上下文里，大量结构性内容，标点、模板、格式符号，与真正承载推理的关键词消耗完全相同的算力。想省算力只能整体换小模型或整体量化，粒度粗到无法针对"这句话很简单"这种事实做优化。

After：Mixture-of-Depths 的论文给出的设置里，每层只让约八分之一的 token 参与计算，在同等训练浮点预算下取得更低的损失，或在等效效果下把单步计算量显著压低，单步推理提速可以过半。早退这一侧，置信自适应语言建模在摘要与翻译任务上报告了数倍级别的加速；把早退与剩余层验证组合成自投机的方案，在开源模型上取得一点三到两倍出头的端到端加速，且不需要额外的草稿模型，比标准投机解码更省显存。这类方法的共同价值是：把"难度差异"这一直觉，第一次变成了可训练、可调度的计算分配策略。

▌ 原理拆解

第一层，直觉理解。读一段文字时，你不会逐字精读，虚词一扫而过，公式和结论会反复看。Mixture-of-Depths 就是给每一层配一个判断，决定这一层要不要认真处理这个词。早退更像考试：这道题我第三步就有答案了，剩下的验算跳过。

第二层，技术流程拆解。Mixture-of-Depths 的流程是：输入 token 表示，路由器做一次线性打分，按分数排序取前若干比例，也就是容量因子决定的名额；被选中的 token 进入注意力与前馈网络，输出乘上路由权重后加回残差；未被选中的原样穿过；下一层重新打分，每层挑中的 token 集合各不相同。因为自回归推理时不能"看着未来的 token 排序"，还要额外训练一个辅助预测器，把排序里的名额判断转成逐 token 的二分类。早退的流程是：每层之后接一个共享的输出头与置信度估计，可以用最大概率、熵，也可以用专门训练的分类器，超过阈值即停；阈值通常随生成位置衰减，越靠后越宽松。

第三层，核心机制。最关键的设计决策是"按容量而不是按阈值"。若用阈值决定谁参与计算，每个批次的实际计算量随数据波动，kernel 无法在编译期确定形状，显存峰值也不可控；改用固定名额，每层计算量在编译期就是常数，这是把动态稀疏塞进现代训练栈的核心工程妥协。第二个机制是残差直连保证跳过路径依然可微，梯度能够回流；路由权重以相乘的形式作用在输出上，而不只是硬性选择，这让路由器本身获得梯度信号，与混合专家的门控相乘是同一套思路。早退这一侧的核心难点是置信度校准：模型在中间层往往过度自信，直接拿最大概率当阈值会掉点，所以要引入一致性约束来给出统计意义上的质量保证。

▌ 动手验证

不必自己训一个新架构，用 logit lens 观察"有多少 token 其实早就定型了"，这就是早退收益的直接证据。

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

name = "Qwen/Qwen2.5-0.5B"
tok = AutoTokenizer.from_pretrained(name)
m = AutoModelForCausalLM.from_pretrained(name, torch_dtype=torch.float32).eval()

ids = tok("The capital city of France is", return_tensors="pt")
with torch.no_grad():
    hs = m(**ids, output_hidden_states=True).hidden_states  # 每层输出
for i, h in enumerate(hs):
    p = m.lm_head(m.model.norm(h[:, -1])).softmax(-1)       # 借用最终头做探针
    print(i, repr(tok.decode(p.argmax(-1))), round(p.max().item(), 3))
```

预期看到中间某层起预测就锁定为"Paris"且置信度持续上升，后续层只是加固，这正是可跳过的部分。

▌ 对比选型

| 维度 | Mixture-of-Depths | 早退 | 混合专家 |
|---|---|---|---|
| 稀疏方向 | 深度，选层 | 深度，提前停 | 宽度，选专家 |
| 是否省单步算力 | 是 | 是 | 是，但层数不变 |
| 主要难点 | 推理期路由预测 | 缓存缺失与校准 | 负载均衡 |
| 训练改造成本 | 需重新预训练 | 可后接头微调 | 需重新预训练 |

### 3. 【Triton 与算子融合：用 Python 写出接近手工 CUDA 的 GPU 内核】

▌ 导语

模型跑得慢，八成不是因为算得多，而是因为数据搬得多。算子融合就是把多次显存读写压成一次的手段，过去这活儿只有会写 CUDA 的人能干。Triton 让"用 Python 写 GPU 内核"变成日常操作，而 PyTorch 编译栈背后自动生成的正是 Triton 代码。理解这一层，等于理解现代深度学习框架的性能到底从哪儿来。

▌ 它是什么

Triton 是一门嵌在 Python 里的领域专用语言，加上一个编译器。你只需要描述"按数据块处理一批元素"的逻辑，编译器负责线程分配、寄存器与共享内存调度、访存合并与向量化。算子融合则是把一串逐元素运算或归约运算合并进同一个内核，避免中间张量落回全局显存再读回来。

它不是要取代 CUDA C++。极致优化的矩阵乘、需要特定张量核心数据排布或 warp 级原语的场景，成熟数学库和模板库仍然更强。它也不是万能加速器：融合省下来的是访存带宽，如果算子本身受算力限制，比如大规模矩阵乘，融合的收益就很有限。

脉络上，Triton 最早以"面向分块神经网络计算的中间语言与编译器"的形式在编程语言会议上提出，随后开源；PyTorch 2 之后的编译后端默认生成 Triton 内核，这让它从小众工具变成事实标准。而 FlashAttention 的核心思想，也就是分块加不物化完整注意力矩阵，正是融合思路最著名的教科书案例。

▌ 它解决什么问题

Before：一条"线性层加激活加 dropout 加残差加归一化"的链条，在逐算子执行模式下会启动五到八个内核，每个内核都把整块张量从显存读进计算单元、算完再写回。以数据中心级 GPU 为例，半精度算力在数百万亿次浮点每秒量级，而显存带宽只有每秒几个 TB，逐元素算子的算术强度只有个位数，被带宽死死卡住，实际算力利用率常常只有一两成。

After：融合成一个内核后，只读一次、写一次，典型逐元素链条能拿到两到四倍加速。注意力这类复合算子的收益更夸张：把分块计算与在线归约融合起来，显存占用从随序列长度平方增长变成线性增长，长序列训练既提速数倍又省下大量显存。这也是编译式执行普遍能带来一点三到两倍提速的主要来源，收益并非来自更聪明的数学，而是少跑了几趟仓库。

▌ 原理拆解

第一层，直觉理解。把 GPU 想成一间工厂：显存是厂外仓库，计算单元旁的共享内存是车间货架。搬一趟货很慢，加工很快。不融合就是每道工序都专门跑一趟仓库取料、送回；融合就是一次把料搬进车间，三道工序连着做完再送回去。工厂产能没变，省的全是路上时间。

第二层，技术流程拆解。写一个带即时编译装饰器的函数；用程序号拿到当前数据块负责的行或列索引；用区间生成块内偏移；带掩码从显存加载一块数据到片上；在片上完成求最大值、指数、求和这类计算；再带掩码写回；最后在主机侧以网格配置启动内核，网格决定并行块数。块大小通常要求是二的幂，实践中用工具函数向上取整；再用自动调优在 warp 数、流水级数、块大小的组合里搜索最优配置。整个过程你不写一行线程索引计算，但必须自己想清楚数据怎么切块。

第三层，核心机制。核心概念是算术强度与分块。算术强度等于浮点运算次数除以访存字节数，只要它低于硬件的算力带宽比，内核就是带宽受限的，优化方向必须是减少访存而不是减少计算，这一条判断决定了要不要做融合。分块则是把大问题切成能塞进片上内存的小块，块内反复复用已加载的数据。softmax 的在线算法之所以关键，是因为它把"求最大值、求和、归一化"三趟遍历合成一趟，无需先把整行结果物化出来。这两点合起来，也解释了为什么注意力的高效实现宁愿在反向传播时重算一遍，也不愿把中间矩阵存下来：重算花的是充裕的算力，存下来花的是紧缺的带宽和显存。

▌ 动手验证

写一个最小的融合 softmax 内核，与框架实现对齐结果。需要一张可用的 GPU 与安装了 triton 的 PyTorch 环境。

```python
import torch, triton, triton.language as tl

@triton.jit
def softmax_kernel(x_ptr, y_ptr, n_cols, BLOCK: tl.constexpr):
    row = tl.program_id(0)                      # 一个程序处理一行
    offs = tl.arange(0, BLOCK)
    mask = offs < n_cols
    x = tl.load(x_ptr + row * n_cols + offs, mask=mask, other=-float("inf"))
    x = x - tl.max(x, axis=0)                   # 数值稳定，全程在片上
    e = tl.exp(x)
    tl.store(y_ptr + row * n_cols + offs, e / tl.sum(e, axis=0), mask=mask)

x = torch.randn(1823, 781, device="cuda")
y = torch.empty_like(x)
softmax_kernel[(x.shape[0],)](x, y, x.shape[1],
                              BLOCK=triton.next_power_of_2(x.shape[1]))
print(torch.allclose(y, torch.softmax(x, dim=-1), atol=1e-5))
```

预期输出为真。若列数超过块上限需改写成多块循环版本。

### 4. 【梯度检查点与激活重计算：用重算换显存把大模型训起来】

▌ 导语

微调时爆显存，第一反应通常是降批量大小或换更小的模型。但很多时候真正吃掉显存的，既不是权重也不是优化器状态，而是为反向传播存下来的一大堆中间激活。梯度检查点用"重算一遍前向"换掉这块显存，是单卡微调最划算的一招，也是低秩微调、量化微调、全参微调背后共同的默认开关。

▌ 它是什么

梯度检查点，也叫激活重计算或重物化，是训练期的显存优化技术：前向传播时只保留少量检查点处的激活，其余中间结果算完立刻丢弃；反向传播需要它们时，从最近的检查点重新做一次局部前向，把这些中间量现算出来。

它不是量化，不改数值精度，数学上与不开检查点完全等价，前提是模型里的随机性被正确处理。它也不是显存卸载：卸载是把激活搬到主机内存，省显存但吃总线带宽；重计算花的是算力。二者可以叠加，但代价性质不同。

边界上，推理阶段不需要它，因为无需保存激活。当模型本身已经算力受限、GPU 利用率接近饱和时，重算的时间代价会更明显；反过来，批量小、序列长、显存紧张的场景收益极大。脉络上，这一思路来自把 n 层网络的激活显存从线性降到根号量级的经典工作，如今在主流训练框架、分布式训练库与模型库里都只是一行开关，但很多人并不清楚它到底换掉了什么。

▌ 它解决什么问题

Before：训练时的显存分成四大块，权重、梯度、优化器状态、激活。以常用的自适应优化器为例，一阶与二阶动量以单精度保存时，光优化器状态就约等于参数量的八倍字节。而激活量与批量、序列长度、层数、隐藏维度四者相乘成正比，一个七十亿参数的模型在四千长序列、批量为四时，激活可以轻松超过三四十 GB，远远超过权重本身以半精度存放时的十几 GB。于是显存曲线常常是"权重装得下，第一个反向就炸"。

After：开启逐层检查点后，激活显存通常降到原来的三分之一到五分之一，代价是前向被多做一次。注意总时长并不会翻倍：反向传播本身的开销大约是前向的两倍，多做一趟前向摊到整步里，实测训练时间增加通常在两三成。落到实践上，这个开关能把二十四 GB 的消费级显卡上"必然爆显存"的全参微调变成"能跑"，或者在同样显存下把训练序列长度从两千拉到八千，后者对长文档任务的效果影响往往比多训几个 epoch 更大。

▌ 原理拆解

第一层，直觉理解。像做一道很长的手算除法：为了事后核对每一步，你可以把所有草稿纸都留着，占地方；也可以只留几个关键中间结果，需要核对时从最近的中间结果往下重推一遍，省纸但多花笔墨。梯度检查点选的就是第二条路，而"关键中间结果每隔多远留一个"就是这项技术唯一真正需要调的东西。

第二层，技术流程拆解。先把网络切成若干段，Transformer 里通常一层一段。前向时，每段入口的输入张量被记录为检查点；段内的中间激活在关闭梯度记录的模式下计算，用完立刻释放，因此不进入计算图。反向传播推进到某一段时，取出保存的输入，重新前向这一段并这次建图，得到段内激活，算出该段参数与输入的梯度，随后释放，继续往前一段。关键参数是分段粒度，每层一段还是每若干层一段，决定了显存与时间的权衡点。另一个必须显式关注的参数是重入式实现与非重入式实现的选择，新实现对输入不需要梯度、与分布式数据并行配合等场景兼容性更好，官方建议显式指定而不是依赖默认值。

第三层，核心机制。这本质是一道经典的时间空间权衡题。把 n 层均分成 k 段，需要保存 k 个检查点，段内重算的峰值是 n 除以 k，总显存量级是 k 加 n 除以 k，用均值不等式可知在 k 取根号 n 时最小，得到根号量级的显存，额外时间恰好是一趟前向。工程上的坑几乎全部集中在"重算必须与首次前向逐位一致"：dropout 的掩码、随机深度的抽样、归一化层的运行统计都必须被正确复现，所以实现会在检查点里保存并恢复随机数生成器状态。此外，与已经内部做了重算的高效注意力实现同时使用时，要注意别让两套重算逻辑叠加，否则算力开销翻倍而显存收益并不叠加。

▌ 动手验证

直接量出显存差距，比读文档更有说服力。

```python
import torch
from transformers import AutoModelForCausalLM

def peak(ckpt: bool):
    m = AutoModelForCausalLM.from_pretrained(
        "Qwen/Qwen2.5-0.5B", torch_dtype=torch.bfloat16).cuda()
    if ckpt:
        m.gradient_checkpointing_enable(
            gradient_checkpointing_kwargs={"use_reentrant": False})
    m.train(); m.config.use_cache = False        # 缓存与检查点互斥
    torch.cuda.reset_peak_memory_stats()
    ids = torch.randint(0, 10000, (2, 2048), device="cuda")
    m(input_ids=ids, labels=ids).loss.backward()
    return round(torch.cuda.max_memory_allocated() / 2**30, 2)

print("关闭:", peak(False), "GB / 开启:", peak(True), "GB")
```

预期开启后峰值明显下降，单步耗时上升约两三成。若不关缓存会收到告警。

### 5. 【生成内容水印 SynthID：把不可见标记嵌进模型输出的采样过程】

▌ 导语

判卷、审稿、平台风控都想回答同一个问题：这段文字是模型写的吗。事后分类器早已被证明不可靠，对非母语写作的误判尤其严重，代价直接落在具体的人身上。另一条路是在生成的时候就埋暗记：把水印做进采样环节，让输出在人看不出差别的前提下携带可统计检验的信号。这一路线已经从论文走进生产系统与开源模型库，是内容标识从合规口号变成可调用接口的关键一步。

▌ 它是什么

生成式文本水印，是在解码阶段按密钥有偏地调整 token 选择，使输出携带一种统计信号，持有密钥的一方可以用假设检验判断这段文字是否来自被水印的模型。SynthID 文本方案用的是锦标赛式采样：以密钥与前若干个 token 为种子生成伪随机打分函数，让候选 token 两两比赛，胜者出线成为下一个 token。

它不是隐写术式的可读密文，也不是不可移除的指纹。它是概率信号，改写、翻译、大幅编辑都会让信号衰减；短文本，比如只有几十个 token 时，检测能力很弱。它也不是"判断是否 AI 写的"的通用方案，只能回答"是否由部署了这套水印与这把密钥的模型生成"，换个模型或换把密钥就检不出来。

脉络上，红绿名单方案是起点：按密钥把词表分成绿名单与红名单，对绿名单的 logits 统一加一个偏置，检测时数绿词比例做显著性检验；缺点是改变了输出分布，会影响生成质量。后续方案的卖点是保真变体在期望上保持原分布，并且已经在大规模在线服务里做过对照验证，这类工程证据比基准分数更能说明可用性。

▌ 它解决什么问题

Before：只能靠事后检测。基于困惑度或分类器的检测器在跨领域、跨模型迁移时准确率骤降，且误报有明确的伤害对象；平台侧只能依赖人工抽查与上传元数据，而元数据在复制粘贴的一瞬间就消失了。这种局面下"AI 内容标识"这类监管要求缺乏可落地的技术抓手。

After：生成侧水印把成本前移到解码环节。计算开销近乎为零，只是在 logits 处理器里多做几次伪随机比较，不增加任何模型前向；检测侧只需要文本本身与密钥。在足够长的文本上，检出率可以做到九成以上而把误报率控制在百分之一量级，具体取决于文本长度、模型输出的熵与检测器形式。更实际的进展是它已经被开源实现覆盖：主流模型库提供水印配置类，任何本地模型都能加一个参数开启，检测侧则可用配套的贝叶斯检测器提升低熵文本的判别力。这让"先标识、再治理"的路径第一次具备了工程可行性。

▌ 原理拆解

第一层，直觉理解。想象每次选词都要抛一枚硬币来当裁判，而这枚硬币的偏向由一把只有你知道的密钥决定。旁人读你的文章语句完全正常，但如果统计整篇文章里裁判"猜中"的次数，会显著高于随机水平，这就是水印。把文章改写一遍，相当于换掉大量比赛记录，信号随之变弱，这也解释了为什么水印的抗改写能力有上限。

第二层，技术流程拆解。生成侧：logits 先经过常规的温度与截断处理得到分布；从分布中抽出若干候选，作为锦标赛的参赛者；用密钥与前若干个 token 的哈希生成打分函数，为每个候选给出零或一的分数；按预设层数做单淘汰赛，多轮之后的胜者作为真正输出的 token。检测侧：对给定文本重算每个位置的打分值，用统计量做检验；简单实现取均值，进阶实现用训练过的贝叶斯检测器替代均值。关键参数有三个：上下文窗口长度决定水印的重复性与抗改写性，密钥列表长度对应比赛层数也就是水印强度，以及是否启用保真模式。

第三层，核心机制。核心矛盾是可检测性与分布保真的权衡。若强行给部分 token 加分，水印强度大，但生成质量与多样性同时受损；锦标赛采样在候选本身来自原分布的前提下选出胜者，可以在期望上保持边缘分布不变，代价是水印强度受熵约束。当模型几乎确定下一个词，比如生成代码、固定句式、事实性短答，可供偏置的自由度趋近于零，水印就嵌不进去。这直接推出两个现实结论：低熵文本水印弱，高温长文本水印强。另一个细节是上下文窗口过短会让重复文本反复触发同一场比赛，给攻击者提供分析密钥痕迹的入口，所以窗口长度不能一味调小去换强度。

▌ 动手验证

### 6. 【muP 最大更新参数化：小模型上调好的超参直接迁到大模型】

▌ 导语

训一个几百亿参数的模型之前，你不可能在同样规模上试两百组学习率。行业惯例是抄前人的配方，在小模型上粗调，放大时把学习率手动砍半，炸了再回头改。这套流程接近玄学。最大更新参数化给出一套缩放规则，让最优学习率在宽度变化时基本不漂移，于是可以在几千万参数的代理模型上做完超参搜索，零样本迁移到目标规模。这是把预训练从"赌"变成"可外推工程"的关键一块。

▌ 它是什么

muP，全称最大更新参数化，核心是按网络宽度对三类东西做特定缩放：参数的初始化方差、每类参数的学习率，以及输出层的前向乘子。目标是让网络在宽度趋于无穷时，每一层的激活尺度与每一步的更新引起的激活变化量都保持常数量级，从而超参数的最优点不随宽度移动。

它不是自动调参器，也不保证深度方向的迁移。宽度迁移是它的强项，深度迁移属于后续工作，且仍有额外条件。它也不是免费的性能提升：它保证的是"可迁移"，不是"更强"；只不过实践中因为终于能用上真正搜出来的最优学习率，结果常常确实更好。

脉络上，标准参数化，也就是常见的默认初始化加统一学习率，在宽度增大时最优学习率会系统性变小，这正是"模型越大学习率要调越小"这条经验的来源。muP 把这条经验从口口相传变成了公式。多家芯片与训练框架厂商已经把它接入自家预训练栈，其中单位缩放变体进一步与八位浮点低精度训练结合，解决了原始方案下张量数值范围不便量化的问题。

▌ 它解决什么问题

Before：超参搜索成本与目标模型规模成正比。训一次数百亿参数模型要消耗数十万加速卡小时，没人敢做网格搜索，工程上只能沿用公开论文里的超参表格。一旦换了架构组件，比如换激活函数、换归一化位置、加上稀疏专家层，那张表格的适用性就无从判断，只能再赌一次，往往训到几千步损失曲线发散才发现问题，而这时算力已经烧掉了。

After：在代理模型上把学习率、预热步数、初始化尺度全部搜完，再按规则放大。原始论文报告，在编码器模型与数十亿参数生成模型上，用小代理迁移得到的超参优于原论文手工调出的配置，而调参开销只相当于一次目标规模预训练的个位数百分比。更实用的副产品是坐标检查这套诊断工具：只训几步，把各层激活的统计量随宽度画出来，就能看出缩放实现是否正确，把"训到一千步炸掉"提前到"十步内发现异常"。对小团队来说，后者的现金价值可能比论文里的损失曲线更高。

▌ 原理拆解

第一层，直觉理解。把加宽网络想象成把一支十人团队扩成一千人。如果每个人发言音量不变，一千人一起说话会震耳欲聋，对应激活爆炸；如果按人数把音量压到千分之一，又会谁都听不见，对应更新消失。muP 就是那套"人数变了、音量和发言步长该怎么跟着调"的规则，让团队规模变化时会议节奏保持一致。

第二层，技术流程拆解。先指定一个小模型的宽度作为基准形状。然后把参数分成三类分别处理：嵌入与输入类参数，初始化方差与学习率都不随宽度缩放；隐藏层参数，输入输出维度都随宽度增长，初始化方差按输入维度的倒数缩放，自适应优化器的学习率同样按输入维度的倒数缩放；输出层参数，初始化方差按输入维度平方的倒数缩放，并在前向乘上输入维度倒数的乘子。此外注意力打分的缩放要从常见的根号维度倒数改成维度倒数。工程实现上，库会在每个参数上打好"哪一维是无穷宽度维"的标记，再由配套优化器在参数组层面施加不同学习率，使用者只需替换输出层类型并调用一次形状设置。

第三层，核心机制。关键量是"一步更新引起的预激活变化量"。在标准参数化下，隐藏层的一次更新会让预激活变化按宽度的平方根增长，宽度越大越容易发散，所以必须手动调小学习率来补偿。muP 选的缩放让这个变化量恒为常数量级，既不爆炸也不消失，这就是"最大更新"的含义：在保持稳定的前提下取尽可能大的更新尺度。注意力打分改用维度倒数，来自同一套分析：训练之后 query 与 key 不再是彼此独立的随机向量，其内积按维度线性增长而不是按根号增长，沿用根号缩放会让打分随宽度膨胀，softmax 迅速饱和。坐标检查正是把这些理论量直接画出来，横轴是宽度、纵轴是各层激活坐标的均方值，正确实现应得到近似水平的曲线，而错误实现会给出明显的上升或下降趋势。

▌ 动手验证

用官方库把一个多层感知机改造成 muP 版本，跑一次坐标检查。

```python
import torch.nn as nn
from mup import MuReadout, set_base_shapes, MuAdam

def make(width):                       # 输出层必须换成 MuReadout
    return nn.Sequential(nn.Linear(64, width), nn.ReLU(),
                         nn.Linear(width, width), nn.ReLU(),
                         MuReadout(width, 10))

base, delta = make(64), make(128)      # 基准与增量形状，用于推断无穷维
model = make(1024)
set_base_shapes(model, base, delta=delta)   # 打标记，必须在建优化器之前
for p in model.parameters():                # muP 规定的初始化
    if p.dim() >= 2: nn.init.normal_(p, std=0.02)
opt = MuAdam(model.parameters(), lr=1e-2)   # 按标记分组施加不同学习率
```

配合 mup.coord_check 的 get_coord_data 与 plot_coord_data，对多个宽度各训几步作图，曲线应基本持平。忘记调用形状设置会静默退化成标准参数化，这是最常见的坑。

▌ 对比选型

| 维度 | muP | 标准参数化 | 经验缩放表 |
|---|---|---|---|
| 超参可迁移性 | 宽度方向可迁移 | 不可迁移 | 仅同架构可参考 |
| 调参成本 | 小模型上搜索 | 目标规模上赌 | 近似为零 |
| 实现改造量 | 换输出层加标记 | 无 | 无 |
| 主要局限 | 深度迁移待完善 | 放大即失效 | 换架构即失效 |

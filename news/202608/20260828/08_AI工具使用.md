### 1. 【Claude Code：在终端里派一个会自己跑任务的编程搭档】

> 📍 **导语**：写代码最痛的不是“写新功能”，而是“把一个完整需求从设计一路推到验证”——读代码、跑命令、改文件、过测试，常常要在编辑器、终端、浏览器之间反复横跳。Claude Code（Anthropic 出品）把这件事收进终端：你扔一句话，它把整个工作目录当成工位，自己读仓库、规划方案、执行命令、操作 Git、调用 MCP 工具，甚至能在手机上远程接管。2026 年它又补齐了 Skills、Subagents、Hooks、Plan Mode、跨会话 Memory 与桌面/IDE 插件，从“终端助手”进化成“可编排的自主 Agent 团队”。今天花十分钟学会，复杂任务能甩手交给它。

**它是什么**（工具速览）
Claude Code 是 Anthropic 推出的终端优先（terminal-first）编程 Agent，2026 年已不再是单纯“在终端里聊天的 AI”，而是把你的工作目录当成一个可操作的工位：它能递归读取代码库、执行 shell 命令、运行测试、提交 Git、调用 MCP 外部工具。相较 Cursor 这种“编辑器里的人和 AI 你一句我一句”的协作型工具，Claude Code 的哲学是“委派”——你说清要什么，剩下的从设计到验证全交给它。2026 年新增的关键能力包括：Skills（可复用的技能包，像给 Agent 装插件）、Subagents（派生子 Agent 并行做研究与审查）、Hooks（在特定事件自动触发命令，如提交前跑 lint）、Plan Mode（先出方案再动手，避免一头扎进去）、Memory（跨会话记住你的偏好与项目上下文）、VS Code / JetBrains 插件与 Web 版（claude.ai/code），以及 Fast Mode（Opus 4.6 提速 2.5 倍）。价格上 Pro 约 20 美元/月、Max 100 美元/月、Ultra 200 美元/月；独立测试显示它在相同任务上比 Cursor 少用约 5.5 倍 token，复杂任务单位成本反而更低。

**解决什么**（场景化拆解）
· 加一个完整功能模块：Plan 一次、执行一次，端到端搞定，连测试都自己跑。
· 调试玄学问题：自己翻日志、grep、跑测试复现，而不是你手动排查半小时。
· 大范围重构（20+ 文件）：1M token 上下文配合 Opus 4.7 的推理，能全局理解整个中型代码库并做连贯跨文件改动，上下文上限远优于多数 IDE 工具。
· 复杂 CI/DevOps 脚本：终端原生优势，天然适合写流水线、脚本与服务器运维。
· 多仓库联动：直接切换目录操作，或把多个子 Agent 派到不同 git worktree 分支并行干活。最让人 WOW 的是“Agent Teams”——多个 Claude 实例像一支小队，一个主导、其余并行执行，彼此在独立上下文窗口里协作，把“一个人写代码”变成“带团队交付”。

**原理拆解**（实战工作流）
Claude Code 的工作分四步：先用语义检索与 1M 上下文把整个代码库装进“工作记忆”，再把你的自然语言指令拆成“读—改—跑—验”的动作序列，调用模型生成代码并就地写入文件，最后用命令执行与测试反馈形成闭环。它之所以能跨文件不乱，是因为在提示词里注入了项目结构、相关文件内容与 Memory 约束；Skills 把常用流程固化为可调用模块，Hooks 把“提交前 lint”“跑完测试再回复”这类规则自动化。Plan Mode 则强制它先产出修改清单供你确认，再动手，显著降低误操作。注意：它倾向“大块交付”，逐行微调不如 Cursor 顺手，因此社区建议“把大任务拆成原子子任务、用 Plan Mode 先对齐再执行”，成功率才高。

**动手验证**
场景：给一个 Express 项目加一套带 JWT 的用户鉴权模块。
Step 1：在终端进入项目目录，运行 `claude` 启动，输入“为项目添加 JWT 鉴权：①建 auth 中间件与 /login、/register 路由 ②用 bcrypt 加密密码 ③接入已有 User 模型 ④补单元测试”。
Step 2：它先进入 Plan Mode 列出改动文件清单（routes、middleware、test），确认无误后说“执行”。
Step 3：观察它读代码、写文件、跑 `npm test`；若测试报错，它自己读报错、改代码、再跑，直到通过。
Step 4：用 `/memory` 让它记住“本项目用 ESLint + 单测覆盖率须 >80%”，下次自动遵循；用 Hooks 配置“提交前自动 lint”。
Step 5：本地 `git diff` 审查后提交，或手机开 claude.ai/code 远程确认。关键心得：先 Plan 再执行 + 让它自跑测试，比手写快数倍且不易漏改。

| 适合 | 大重构/自主任务 | 行内协作编码 | 云端异步批处理 |
| 不适合 | 逐行微调 | 纯终端脚本 | 本地实时交互 |
| 学习成本 | 中 | 低 | 中 |
| 价格 | 20刀月起 | 20刀月起 | API计费 |

### 2. 【Sora：用一句话生成电影级连贯短视频】

> 📍 **导语**：想做一条有“时长感”和“连贯叙事”的 AI 视频，多数工具卡在两点：一是单镜头几秒就切，长场景接不起来；二是人物与物体运动容易抖动、穿帮。OpenAI 的 Sora 恰好长在这两块——它以真实感与物理一致性著称，擅长生成时长更长、镜头更连贯的短片，尤其适合做“一气呵成的电影感片段”。2026 年 Sora 的提示词方法论也成熟了：把一段视频拆成“角色 + 视觉风格 + 情绪基调 + 时长”四要素，再自下而上搭概念层、叙事层、感官层。今天值得用它的 Web 版跑通一次“文字 → 成片”的闭环。

**它是什么**（工具速览）
Sora 是 OpenAI 推出的文生视频模型，核心卖点是“真实感、物理一致性与长镜头连贯性”。与 Runway（运动控制强）、Kling（角色/物理一致性好）相比，Sora 最擅长的是长而 cohesive 的场景——人物不崩、物体不乱飞、镜头衔接自然。创作方法论上，资深工作流主张“先概念后画面”：先用一句话定下观众带走的价值（概念层），再排叙事结构（钩子→推进→落点），最后才落到每一镜的感官设计。每镜提示词必须含四个要素——角色分配、视觉风格、情绪基调、时长，缺一个质量就掉档。价格与开放程度上，Sora 早期为受限访问，2026 年已通过 ChatGPT 内置与 Web 端向更多用户开放，按生成分辨率与时长计费。一句话区分：Runway 强在运动控制、Kling 强在角色物理、Sora 强在长镜头叙事。

**解决什么**（场景化拆解）
· 长镜头叙事：写“一位老人沿河岸漫步，黄昏暖光，镜头缓慢横移”，Sora 能把十几秒的连贯运动做得很顺，不像短镜头工具那样频繁跳切。
· 真实感场景：产品、街景、自然风光类题材，物理规律（重力、光照、反射）更可信，少出现“反重力水杯”。
· 概念片/预告：先用概念层定调，再让多镜围绕同一价值展开，成片有起承转合而非堆特效。
· 角色一致性：锁定一张参考图 + 一句话描述，跨镜头复用，身份不漂移。
· 混剪前素材：先出高质量主镜头，再用剪映/CapCut 补实拍与配音。最 WOW 的是“四要素提示词公式”——把导演意图拆成角色/风格/情绪/时长，AI 视频从此有章法，告别“又酷但没故事”。

**原理拆解**（实战工作流）
Sora 的实战逻辑是“自下而上三层 + 每镜四要素”。先搭概念层：用一句话写下观众看完会怎么向朋友描述这段视频，若只能说“看起来很酷”说明概念空洞，要先重写。再搭叙事层：钩子（前 1–3 秒开环）→ 推进（张力）→ 落点（交付价值），给每拍标时间戳。最后搭感官层：为每拍定义“抓眼画面 + 运动”。写提示词时严格包含角色、视觉风格、情绪基调、时长四要素，缺一不可。稳定性靠三点：一是锁定跨镜角色参考，不让身份漂移；二是前 3 秒用强钩子机制留住观众；三是用“开放循环”把悬念留到结尾才揭晓。工具选择上，长连贯场景用 Sora，运动控制用 Runway，角色物理用 Kling。

**动手验证**
场景：做一段 15 秒“清晨咖啡馆慢慢苏醒”的电影感短片。
Step 1：开 Sora Web 版，先写概念层一句话：“一座空咖啡馆在晨光中慢慢醒来，让人想坐下来发呆”。
Step 2：拆成三镜——镜1 空镜推近门面（钩子）、镜2 蒸汽升腾特写（推进）、镜3 窗外人流虚化（落点），各标 5 秒。
Step 3：每镜写四要素提示词，如镜2“特写(角色) 一杯手冲咖啡(风格) 宁静治愈(情绪) 5秒(时长)，蒸汽缓缓上升，暖侧光”。
Step 4：上传一张咖啡馆参考图锁风格，逐镜生成 3–5 个候选，挑稳定不抖的。
Step 5：下载 MP4 进剪辑软件加字幕与 BGM。关键心得：先定概念再写画面、每镜四要素齐全，比堆形容词稳得多。

**对比选型**
| 维度 | Sora | Runway Gen-4.5 | Kling 3.0 |
|------|------|------|------|
| 适合 | 长连贯叙事 | 运动控制 | 角色物理一致 |
| 不适合 | 极短特效 | 长镜头弱 | 超长成片 |
| 学习成本 | 中 | 低 | 低 |
| 价格 | 订阅内 | 订阅制 | 免费/低价 |

### 3. 【即梦 AI：字节出品的国产文生图与图生视频一体机】

> 📍 **导语**：做国风海报、短视频素材，过去要么学 PS/PR，要么翻墙用海外工具——中文语义常理解偏，汉服纹样、江南水乡、网络热梗容易出戏。即梦 AI（字节跳动旗下，入口 jimeng.jianying.com）把“出图 + 出视频”收进一个国产平台：你用中文写一句，它既能生成图像，也能把静图变成动态短视频，且对中文语境、国风审美与抖音生态的理解明显更贴国内创作者。2026 年它已是很多自媒体“先用即梦出初稿、再进剪映精剪”的标准起手式。今天值得用免费额度跑通一次“中文提示词 → 图 → 视频”的流水线。

**它是什么**（工具速览）
即梦 AI 是字节跳动推出的多模态生成平台，同时覆盖文生图、图生图、文生视频与图生视频，与剪映、抖音生态深度打通。它的差异化在于“中文原生”——中文提示词理解准、国风审美到位、对本土热梗与场景（汉服、古镇、国潮）还原度高，且生成结果能一键进剪映做二次剪辑。功能上支持垫图（以图定风格）、多种艺术风格预设、视频运镜与时长控制，免费额度对日常创作者友好，进阶按生成量计费。一句话区分：Midjourney 偏艺术统一、即梦偏“中文好懂、出片快、能直接进短视频流水线”。

**解决什么**（场景化拆解）
· 国风海报：写“水墨风山居图，留白，远山淡墨”，即梦对国风构图与笔触的理解优于多数海外工具，少出“四不像”混搭。
· 图文成片起手：先出一组风格统一的配图，再进剪映配文案做短视频，风格零漂移。
· 图生视频：上传产品静图写“镜头缓慢推近，柔光”，几秒得可在详情页循环的展示片。
· 社媒矩阵：同一中文主题批量出不同构图，适配抖音/小红书多尺寸。
· 创意探索：用垫图锁定一种画风，快速试不同主题。最 WOW 的是“中文提示词即生产力”——你用大白话描述国风场景，它比需要翻译英文 prompt 的工具更省心，新手零门槛。

**原理拆解**（实战工作流）
即梦的工作流是“图在前、视频在后”。先用语义理解解析你的中文指令，在选定风格下生成图像；图生视频则把静图编码为潜空间条件，由视频模型推断运动、深度与连续性，生成带运镜的动态片段。它之所以中文语境更稳，是因为训练语料与本土场景对齐更充分，且和剪映共享审美与模板。稳定性靠三点：一是一次只放一个主运动（避免“又推又环绕”互相打架）；二是用垫图锁定风格，跨图保持一致；三是图生视频前先出一张满意静图，再animate，比直接文生视频更可控。负向提示写“no distortion, no watermark, no text”可排掉畸变与文字水印。

**动手验证**
场景：为一条“国风茶饮”短视频做封面图 + 3 秒动态片头。
Step 1：开 jimeng.jianying.com，文生图输入“国风茶饮海报，青瓷茶杯，水墨远山背景，留白构图，暖色调”。
Step 2：挑一张满意的做垫图，锁定该风格，再出 3 张备选构图统一调性。

Step 4：判断质量看运镜是否平滑、主体是否稳定不畸变；不满意就简化提示词重生成。
Step 5：下载进剪映加字幕与 BGM。关键心得：先定静图再 animate、一次只做一个动作，比堆指令稳得多。

### 4. 【豆包：字节系国产全能 AI 助手，零门槛提效】

> 📍 **导语**：普通人用 AI，最怕两件事：一是英文模型听不懂大白话和方言，二是工具太专、要装一堆。豆包（字节跳动 Seed 系列大模型驱动）恰恰对症——它中文口语理解准、方言识别出错率低，集聊天、写作、绘画、PPT、短视频脚本、语音转写于一身，且与剪映、抖音生态互通，基础功能免费、无广告解锁。对普通上班族、自媒体、学生，它是“装一个顶五个”的国产全能搭子。2026 年 5 月它升级到 2.0 Pro，多模态与修图能力进一步增强。今天值得用免费额度跑通一次“写文案 → 出图 → 剪脚本”的闭环。

**它是什么**（工具速览）
豆包是字节跳动推出的国产全能 AI 助手，底层为自研 Seed 系列大模型，定位“生活化场景适配度拉满”。它支持文本对话、文档解析（上限约 32 万字）、图片识别与生成、语音实时转写、短视频脚本生成，并与剪映、抖音打通，自媒体创作者可直接把生成的脚本与素材推进剪辑流。免费版基础权限充足，无需频繁看广告；短板在于超长文档（几十万字 PDF 全本精读）效率偏弱，硬核数理推导与代码优化不是强项。实测中它对小红书文案、朋友圈段子、带情绪的小短文常给惊喜，那股“人味儿”是真的。一句话区分：DeepSeek 偏推理硬核、豆包偏生活创作，是普通用户零门槛的首选。

**解决什么**（场景化拆解）

· 小红书种草：写“肩颈按摩仪种草文案，口语化带 emoji，结尾引导评论”，一次出多篇备选。
· 短视频脚本：给主题直接出分镜与口播稿，再进剪映成片，自媒体日更不卡壳。
· 修图/配图：内置图像生成与编辑，海报、封面、表情包随手出。

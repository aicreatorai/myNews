### 1. 【终端并行编程实战：Claude Code 多 worktree 与 Skills 复用】

> 📍 **导语**：用 AI 写代码最怕的不是它写不对，而是它把你不同时刻交代的活儿搅成一锅粥——你刚让它修一个跨五个文件的 Bug，改到第三个文件突然想起还有个性能优化要做，于是追加一条消息，结果 Agent 的上下文被打乱，两个任务开始串味，最后谁都没干好。Anthropic 内部团队把这套协作经验总结成一套可复制打法：用多开 worktree 同时跑三到五个独立会话、用 plan mode 先把方案谈清楚再动手、每次纠错后把教训写进 CLAUDE.md、把重复两次以上的操作固化成 Skills 复用库。2026 年这套方法论已经相当成熟，它值得今天就用——配置一次，团队所有人都能像和多个同事并行协作一样和 AI 共事，而不是被一个长会话拖死。

#### 它是什么

Claude Code 是 Anthropic 推出的终端编程智能体，用 `npm install -g @anthropic-ai/claude-code` 一行命令即可安装，之后在任意项目目录输入 `claude` 就能启动。它不是一个聊天框，而是一个能读文件、跑命令、改代码、提 PR 的 agent。核心交互有三层：默认模式需要你确认敏感操作，计划模式（按 Shift+Tab 切换）先出方案不落地，自动编辑模式能直接读写文件。项目根目录的 CLAUDE.md 是它每次会话自动加载的"长期记忆"，写清楚技术栈、禁止事项和约定，AI 就不会反复犯同一个错。Skills 则是把常用操作（比如"生成公众号排版并推草稿箱"）做成可复用脚本，放进 `~/.claude/skills/` 后用一句话触发，团队还能用 Git 共享。收费上基础对话免费，本质是把已有能力用对，而非额外花钱。

#### 解决什么

它解决的是 AI 编程里最隐蔽的三类损耗。第一是"上下文干扰"：单一长会话里你追加的新任务会污染正在进行的工作，导致两个任务互相串味，这是所有长上下文 Agent 的通病。第二是"重复纠错"：你每开一次会话就把"用 pnpm 别用 npm""建表必须有 create_time"重说一遍，说漏了就出错。第三是"知识无法沉淀"：一个坑你踩过三次，AI 还是每次从零开始。Anthropic 内部的解法是：多开 3 到 5 个 git worktree，每个开一个独立会话，互不干扰；复杂任务先开 plan mode 让一个 Claude 写计划、另一个当幕僚审查；每次纠错完都加一句"更新你的 CLAUDE.md，别再犯同样的错"，反复迭代到错误率明显下降；把一天做两次以上的事做成 Skills 提交到 Git 复用。实测这些习惯能让调试与重构的返工显著减少，新成员进项目也能立刻写出符合规范的代码。

#### 原理拆解

理解这套打法，要抓住四个机理。其一，git worktree 提供"并行不冲突的隔离工作区"——每个 worktree 是同一仓库的独立检出，Agent 在隔离区随便改架构、重构、试新方案，搞砸了直接删掉，主工作区毫发无损，这把"让 Agent 大胆试"变成零成本操作。其二，plan mode 把"规划"和"执行"两个阶段切开，AI 先只产出方案供你拍板，避免一上来就动刀。其三，CLAUDE.md 是持久化上下文，错误后追加的教训会沉淀进文件，下个会话自动继承，相当于 AI 的"错题本"。其四，Skills 和子代理（subagents）把重复劳动和重算力任务外包出去，主代理的上下文窗口保持干净，不会被长任务撑爆。语音输入（macOS 连按两次 fn）比打字快三倍，提示词也更详细，是容易被忽略的提效开关。

#### 动手验证

以"同时推进一个 Bug 修复和一个重构实验，且互不干扰"为例：

```
# Step 1 在主工作区启动 Claude Code，先开 plan mode 列方案
claude            # 进入后按 Shift+Tab 切到计划模式
# 在计划里写："修复登录接口 401 的 Bug，影响 5 个文件"

# Step 2 另开一个隔离 worktree 跑重构实验，不碰主分支
git worktree add ../refactor-exp -b refactor/cleanup
cd ../refactor-exp
claude           # 在这个目录单独会话里让 AI 试重构

# Step 3 主工作区修复完成后，把教训写进 CLAUDE.md
echo "- 登录接口必须用 Bearer Token，禁止在 query 里带凭证" >> CLAUDE.md

# Step 4 把"提交前自动跑 lint"做成 Skill 复用
mkdir -p ~/.claude/skills/precommit && cat > ~/.claude/skills/precommit/SKILL.md <<'EOF'
name: precommit
description: 提交前运行 lint 与测试
# 触发后执行: npm run lint && npm test
EOF

# Step 5 用 /statusline 查看上下文用量与 git 分支，一个任务一个标签页
```

验收标准：重构实验的改动只存在于 `refactor-exp` 目录，主工作区代码完全不受影响；新开会话后 AI 自动遵守 CLAUDE.md 里写的凭证规则；Skill 一句话即可触发。若某次纠正后 AI 又犯，多半是 CLAUDE.md 没提交或描述太模糊，把规则写成明确禁令即可。

#### 对比选型

### 2. 【GitHub Copilot 2026：Sessions 并行会话与 /worktree 隔离工作区实战】

> 📍 **导语**：2026 年 8 月 GitHub 给 Copilot 推了一波被开发者称为"工作操作系统"的更新：CLI 里新增 Sessions 侧边栏、VS Code 加上 /btw 侧聊、CLI 实验性 /worktree 隔离工作区、/rewind 一键回退、以及把多模态语音听写搬到设备端。这些功能单看都不炫技，连起来却精准命中 AI 编程的真实痛点——一个 Agent 正在改跨五个文件的 Bug，你突然想问个命名规范，过去只能打断它，上下文一乱就可能忘了改到第几个文件；现在 /btw 开个侧聊，主任务纹丝不动。它值得今天升级体验，因为"不打断"正是 2026 下半年 AI 编程工具竞争的核心，Copilot 已经把这些人类协作的基础设施搬到了人机协作层。

#### 它是什么

GitHub Copilot 早已不只是编辑器里的补全插件，而是横跨 Copilot 桌面 App、CLI 和 VS Code 的 Agent 协作层。2026 年 8 月这波更新里，最核心的是三件套：Sessions 让你在 CLI 按左箭头弹出侧边栏，用 `n` 新建、`x` 关闭、方向键切换，同时挂着好几个互不干扰的 Agent 会话；/worktree 基于 Git worktree 创建隔离工作区，让 Agent 在副本里随便试，搞砸了删掉即可，主代码库毫发无损；/rewind 能恢复对话状态和 Copilot 改过的文件，即便没开 Git 也能回退。同期还有 /btw 侧聊、元素级标注（在 VS Code 内置浏览器框选页面元素发给 Agent）、默认设备端运行的 multilingual 语音听写，以及代码审查 effort levels 的 Lite/Balanced 正式可用和 ROI 看板。

#### 解决什么

它解决的是"人和多个 Agent 协作"时最磨人的四类问题。第一是"上下文干扰"：你让 Agent A 修 Bug、Agent B 做优化，传统单一会话里两者会串味，Sessions 把每个任务做成独立会话，像 Git 分支一样并行不冲突。第二是"不敢打断"：/btw 让你在不中断主任务的前提下问侧边问题，Agent 不会忘记自己在修 Bug。第三是"不敢让 Agent 直接改生产代码"：/worktree 提供零成本的试错沙盒，方案跑通再合并。第四是"可逆性焦虑"：/rewind 让任何改动都能一键回退。此外，VS Code 元素标注把"这个按钮颜色不对"从纯文字描述升级为"指给你看"的多模态输入，设备端听写则解决了代码讨论语音上云的合规红线。

#### 原理拆解

把这三个功能连起来看，Copilot 的产品哲学呼之欲出：让开发者与 AI 协作的方式，接近人与人的协作方式。Sessions 的本质是"把 Git 的分支思想搬到 AI 协作层"——分支让代码并行开发不冲突，Sessions 让 AI 并行协作不串味。/worktree 则是把文件系统的隔离提前：两个 Agent 各自有独立检出，避免了互相改同一文件导致假设失效。/rewind 的机理是持续记录对话与文件变更快照，即使没有 Git 历史也能还原到任意时间点。设备端听写依赖端侧 NLP 模型，音频不离开本地，合规问题解决得干净利落。代码审查的 Lite/Balanced 分级，则是把"审查深度"从团队统一偏好变成可按风险选择的策略：文档类用 Lite，涉及鉴权支付的敏感 PR 用 Balanced。

#### 动手验证

以"并行修一个 Bug 和做一个独立调查，且互不污染"为例：

```
# Step 1 在 Copilot CLI 里按左箭头打开 Sessions 侧边栏
# 用 n 新建一个主会话修 Bug，再新建第二个会话做独立调查

# Step 2 给第二个会话开隔离工作区，避免改动主分支
/worktree
# 系统创建独立 worktree，在该隔离区里让 Agent 跑测试生成或依赖调查

# Step 3 主会话正在改代码时，用 /btw 问一个不相关的命名问题
/btw 这个函数命名是否该用新的 ESLint 规则？
# 主任务不受影响，侧聊单独回答

# Step 4 若隔离区的实验失败，直接放弃该 worktree，主区无影响
# 若成功，审阅 diff 后合并回主分支

# Step 5 万一改乱了，用 /rewind 还原对话与文件
/rewind
```

验收标准：两个会话的上下文完全独立，互不串味；/btw 的提问没有让主任务"失忆"；隔离 worktree 的改动不出现在主分支的 git status 里；/rewind 后文件回到改动前状态。若发现两个 Agent 都去改同一个迁移文件或公共 API，应明确约定其中一个只读，避免重叠冲突。

#### 对比选型

| 适合任务 | 多 Agent 并行、企业流 | 终端长任务编排 | 编辑器内实时补全 |
| 不适合 | 纯离线无云环境 | 重度图形化偏好 | 超长 CLI 批处理 |
| 隔离机制 | /worktree+Sessions | git worktree | 多规则域 |
| 价格 | 订阅 GitHub | 订阅 Anthropic | 订阅 Cursor |

### 3. 【带引用的答案引擎：Perplexity AI 的 Focus 与 Spaces 用法】

> 📍 **导语**：很多人查资料还在重复一个碎片化流程——打开五六个 Google 标签页，在密密麻麻的网页里逐一比对数，最后自己手动整合。2026 年的 Perplexity AI 把这个繁琐过程压缩进同一个对话框：你输入一个问题，它实时检索网络、综合多个来源，直接吐出一段带编号引用的结构化答案，每句话旁边都能点开原始出处。它和 ChatGPT 的根本差异在于——ChatGPT 从训练数据生成文本，Perplexity 默认就联网，把大模型当"写手"而非"事实来源"，因此事实类查询的幻觉更少、且自带可溯源的审计链。它今天值得用作 Google 的替代品，尤其是写报告、做竞品分析、查最新资讯这类"本来要开十個标签页"的任务。

#### 它是什么

Perplexity AI 被官方定义为"答案引擎"，由前 Google 和 OpenAI 工程师创立，核心能力是实时网络检索加大型语言模型加逐句引用。免费版立刻可用，每天有若干次 Pro Search 额度、完整访问 Comet 浏览器；Pro 版每月 20 美元，解锁无限 Pro Search、GPT-5/Claude Sonnet/Sonar 等模型任选、文件分析、Spaces 与 API 额度。它的 Focus 模式告诉引擎去网络的哪个角落找答案：Web 是默认全量检索，Academic 锁定同行评审论文与预印本，Social 拉取 Reddit 和 X 的真实讨论，Video 索引 YouTube，Writing 关掉搜索直接用模型起草，Math 跑计算与证明，Finance 在 Pro 下拉取实时行情。Spaces 则是围绕主题组织研究、保存对话、上传文件并设定固定指令的协作空间。

#### 解决什么

它解决的是查资料的三重痛苦。第一是"标签页疲劳"：过去要自己开多个分页、逐个比对，Perplexity 把初步整合前移，工具替你完成。第二是"幻觉不可信"：普通对话模型凭训练记忆答公司制度会胡编，Perplexity 每个句子都连到即时网页，并给出来源链接，重要结论可点进去复核。第三是"研究无法累积"：Spaces 让同一主题的脉络沉淀在同一空间，后续搜索自动带入先前框架，不用每次重述背景。Slash 命令（Pro/Max 可用 /gpt、/claude 等）把搜索框变成"网页的命令行"，安全研究者能自建 /audit 把任意配置丢进加固提示词查漏洞。Model Council 还能让 GPT 与 Claude 同时答同一题，标出分歧点供人工复核。

#### 原理拆解

Perplexity 的运转逻辑是"检索优先、生成在后"：你提问后，它先把问题发给搜索索引，抓取最相关页面，再喂给前沿模型（GPT-5、Claude Sonnet 4.5 或自研 Sonar）综合成带脚注的答案。关键机理是"模型是写手而非事实源"——每段落都扎根于开放网络上的某篇内容，因此事实查询幻觉更少、且自带审计链。Focus 模式的本质是"约束来源混合"：选 Academic 后，SEO 优化博客被过滤，只留实证数据，对高 stakes 场景至关重要。Spaces 的机理是"固定指令自动套用"：你在 Space 里写"所有答案引用同行评审论文"，该空间内每次搜索都自动遵循，相当于给研究装上持久偏好。Slash 命令则把"切换模型/聚焦模式"封装成可复用快捷键。

#### 动手验证

以"做一次关于边缘计算监控方案的可信调研"为例：

```
Step 1 打开 perplexity.ai 注册登录（Google/Apple/邮箱，免信用卡）
       在搜索框下点开 Focus，选 Academic，锁定论文与期刊来源

Step 2 输入一句"简报式"长问句（比关键词更有效）：
       "2026 年边缘服务器监控方案，对比 VictoriaMetrics 与 Thanos，
        约束：5 台边缘服务器、要 pros/cons 列表、Markdown 表格输出"

Step 3 对重要问题点亮 Pro Search（每天免费额度留给真正要深挖的查询），
       它会多轮追问澄清意图，再综合更多来源给出更深答案

Step 4 建立专属 Space：点 Spaces → 新建"边缘监控调研"，
       固定指令写"所有结论必须附同行评审或厂商文档出处"，
       之后该主题所有搜索自动继承此约束

Step 5 用 /claude 或 /gpt 切换底层模型复核关键结论；
       最终一键生成可分享的研究页面（Pages）发给团队
```

验收标准：答案每段都带可点击编号引用；切到 Academic 后来源确实为论文而非博客；Space 内后续搜索自动带入固定指令；重要数字点进来源能确认。若某条引用格式正确但内容存疑，仍要点进去核实——引用是线索不是免检章。

#### 对比选型

| 决策维度 | Perplexity AI | ChatGPT | 传统 Google |
|---------|--------------|---------|------------|
| 适合任务 | 带引用的事实查询 | 创作/对话/头脑风暴 | 自由探索链接 |
| 不适合 | 纯创意写作 | 需逐句溯源 | 要快速整合多源 |
| 来源可信 | 逐句引用可查 | 默认不联网 | 需自看原文 |
| 价格 | 免费+Pro $20/月 | 免费+订阅 | 免费 |

### 4. 【私有硬件跑编码代理：Ollama 本地大模型部署实战】

> 📍 **导语**：很多团队想用 AI 编程 Agent，却卡在两个顾虑上：一是敏感代码每敲一个字都发往第三方 API，安全部门直接否决；二是按量计费，长任务跑起来账单吓人。2026 年 8 月 Ollama 连发 v0.32.7、v0.32.8、v0.32.11 三个版本，把"在自己硬件上跑 Agent"变得前所未有的简单——它已是自托管圈运行大模型的事实标准，单个二进制或容器就能拉取、服务并管理 Llama、Qwen、DeepSeek 等模型，新版本还让 `ollama launch` 直接拉起 Claude Code、Codex、Pi、Muse Code 等编码代理，并给 OpenAI 兼容的 Responses 接口加上联网搜索。它值得今天试，因为数据不出本机、零 API 费用、断网也能跑。

#### 它是什么

Ollama 是采用 MIT 许可的开源本地 AI 运行时，让你在个人或公司硬件上直接跑大模型，无需持续联网、也无需触碰 Python 虚拟环境。它支持 Llama、Qwen、DeepSeek、Gemma、Mistral 等大量模型，GitHub 星标已超 17.8 万，成为其他工具构建其上的本地推理层。2026 年 8 月的关键进展：v0.32.7 首发对 Meta 新 30B 多模态智能体模型 Muse Glimmer 的支持（先用 MLX 引擎面向 Apple Silicon）；v0.32.8 把 Muse Glimmer 扩展到 NVIDIA、AMD 等全平台，并带来 VS Code 64k 上下文配置与视觉 OCR 测试；v0.32.11 则让 `ollama launch` 原生支持 DeepSeek Harness（dsh）与 Meta 的 Muse Code，并给 Responses API 加上网页搜索工具。安装脚本一条命令：`curl -fsSL https://ollama.com/install.sh | sh`。

#### 解决什么

它解决的是云端 AI 编程的三道门槛。第一是"数据隐私"：所有推理在本地完成，敏感代码、内部文档从不离开你的机器，合规部门不再有理由否决。第二是"成本与依赖"：不按 token 计费、不依赖第三方 API 可用性，断网环境下仍能干活，特别适合内网、车间、出海弱网场景。第三是"Agent 落地难"：过去想让 Claude Code 类工具跑在本地模型上，要自己拼一堆胶水代码；现在 `ollama launch claude --model muse-glimmer` 一行命令就把真实 Agent 工具指到本地模型，配合 Responses API 的联网搜索，本地助手也能拿到最新信息而非只靠模型权重。对 Apple Silicon 用户，MLX 引擎的 DFlash 加速让 30B 模型跑出"当前最佳"的本地性能。

#### 原理拆解

理解 Ollama，把它想成"介于'我有一块显卡'和'我有一个能用的本地 AI 助手'之间的那一层"。它的核心是一个本地服务（默认 `http://localhost:11434`），对外暴露 OpenAI 兼容接口，应用或 Agent 通过 HTTP 调用即可，无需关心模型加载细节。`ollama launch` 的机理是"内置启动器"——它知道如何把 Claude Code、Codex、Pi、Muse Code 等编码代理 harness 指向你本地服务的模型，从而把同一套本地部署变成 Agentic 编程环境，无需单独安装、无需 API Key、无云端往返。MLX 引擎针对 Apple Silicon 做了图像输入与 DFlash 生成加速；Responses API 的网页搜索则是把"检索增强"作为工具直接挂到兼容接口上，省掉外部检索层。

#### 动手验证

以"在 Apple Silicon Mac 上用本地模型跑一个编码代理"为例：


### 5. 【文本生成完整歌曲：Suno AI 的 Custom 模式与声音克隆实战】

> 📍 **导语**：做短视频、播客、公众号配乐的人常卡在一个现实门槛：不会乐器、进不起录音棚、买商用音乐又怕侵权。2026 年的 Suno AI 把这件事压成"打一句话"——你描述想要的风格、情绪、主题，它在一分钟内产出带人声、带伴奏、带制作的完整歌曲，免费用户每天约 50 积分可生成十首左右。更关键的是 2026 年 3 月推出的 v5.5 模型：音质比 V3 提升 30% 以上、跑调与错词概率降超 60%，并带来声音克隆、自定义模型和商用授权。它今天值得深耕，因为掌握 Custom 模式的分段写词与声音克隆，你就能稳定产出"像自己唱的、可商用"的原创配乐，而不只是随机抽卡。

#### 它是什么

Suno AI 是 2023 年成立的文本生成音乐平台，在浏览器里运行、无需下载，用 Google、Apple、Discord 或邮箱注册即可。免费版每天约 50 积分（约十首歌），Pro 版约 8 到 10 美元/月解锁商用授权、声音克隆与 WAV 分轨导出。创作有三档模式：Simple 模式一个文本框描述歌曲，AI 自动写词写曲；Custom 模式把"风格"和"歌词"拆成两个独立字段，并对歌词用 `[Verse]`、`[Chorus]`、`[Bridge]` 等结构标签精确控制段落；Studio 模式（Premier 计划）提供时间线编辑、速度标记与多轨编排。v5.5 带来的三件套——Voices 声音克隆（录一段你的唱腔生成私有声模）、Custom Models 自定义模型（上传你的曲目微调出专属音色）、My Taste（全员可用、按收听偏好个性化推荐）——把"像你"这件事做到了模型层。

#### 解决什么

它解决的是非音乐人做配乐的三道坎。第一是"零基础门槛"：过去要会乐理、会演奏、会录音，Suno 把这些都内化进模型，你只管描述意图。第二是"商用侵权焦虑"：免费版生成的音乐不能商用，而 Pro/Premier 用户拿到明确商用授权，短视频博主、独立音乐人可放心用作背景乐与品牌曲，解决了传统素材库的版权痛点。第三是"随机抽卡不可控"：Simple 模式出的歌常跑偏，Custom 模式把"风格描述（6 到 10 个制作术语而非情绪形容词）"与"你自己的歌词"分离，再用结构标签锁段落，出歌成功率大幅提升。Studio 的时间线编辑和 WAV 分轨导出，则让生成的歌能进 DAW 做专业混音，而不只是个 MP3 成品。

#### 原理拆解

Suno 的机理是"描述进、成品出"的生成式管线，而非传统数字音频工作站——你描述、模型决策，你不能直接拖动单个音符。Simple 模式里，模型同时写词、编曲并演唱，一次生成两个版本供你挑。Custom 模式的机理是"信号分离"：Style 字段专管声音（流派、子流派、制作特征、速度、声部类型），Lyrics 字段放你的词加概率性结构标签，模型把标签当段落线索大概率遵循；留空歌词并加 `instrumental, no vocals` 即得纯音乐。v5.5 的声音克隆是先验证你的一段口语录音匹配声纹，再据此训练私有声模，之后生成的歌用你的声音而非合成音；自定义模型则是用你已有曲目微调，让新生成向你的既定风格聚拢。My Taste 在后台学习你的收听信号，个性化自动补全建议。

### 6. 【Midjourney 2026 提示词：六要素公式加 --sref/--cref 锁定风格与角色】

> 📍 **导语**：很多人用 Midjourney 出的图总"不对味"——输入"一只猫"得四张图，输入两百字小作文还是得四张"四不像"。问题不在工具，在提示词。2026 年 Midjourney 已迭代到 V7 与 Niji 7，对提示词的理解发生了根本变化：短信号优于长段落，参考图权重大幅提升。掌握一套"六要素公式"（主体+场景+风格+光线+构图+参数）再配合 `--sref` 锁风格、`--cref` 锁角色，出图成功率能从一半提升到九成。它今天值得深耕，因为对做公众号配图、电商海报、小说封面的内容人来说，可控的系列化产出比随机抽卡重要得多，而这两组参数正是 2026 年工作流里最大的杠杆。

#### 它是什么

Midjourney 是头部 AI 绘画生成器，2026 年的主模型是 V7（默认），二次元走 Niji 7。它的提示词遵循一条稳定的六要素结构：主体（谁/什么，含具体特征）、场景（在哪里、在做什么）、风格（艺术家/媒介参考）、构图（景别、角度、距离）、光线（光源与质感）、参数（技术指令如 `--ar 16:9`、`--style raw`、`--v 7`）。V7 的核心变化是"短信号为王"——偏爱几个核心关键词的组合而非长篇描述，且对人物或品牌有严格要求时必须用 `--oref`/`--cref` 传参考图、用 `--ow`/`--cw` 控权重。新增的 `--draft` 草稿模式先用低质量快速出图筛选创意，选中后再用完整质量重生成，大幅省时。它跑在 Discord 与网页端，输入文本加可选参数即可。

#### 解决什么

它解决的是"抽卡不可控"的三类翻车。第一是"含糊出糊图"：只写"做一张好看的图"，模型没有足够约束，结果发散；六要素把主体、光线、构图、风格一次写清，AI 认知偏差显著降低。第二是"风格乱飘"：同一系列配图每次抽卡调性不一，用 `--sref` 传一张风格锚图（配 `--sw` 权重）就能让后续所有图模仿其光影与配色，品牌方甚至建 5 到 10 张风格锚图库反复复用。第三是"角色不一致"：做 AI 虚拟人/连续角色时，用 `--cref` 锁身份（`--cw 100` 保脸发包、`--cw 0` 只锁脸），跨图保持同一张脸。此外，`--style raw` 关掉默认美颜让照片更真实，Vary Region 局部重绘解决了"手画歪了"的老大难，Remix 则在不丢构图的前提下改灯光换衣服。

#### 原理拆解

理解 V7 的提示词机理，要抓住"短信号"和"参考图权重"两条主线。短信号优于长段落，是因为模型对超过 60 到 75 词的长提示注意力显著下降，所以要把最重要的主体与风格放在前 20 词，次级氛围放接下来 20 词，技术参数放末尾。`--sref` 的机理是"风格迁移而非内容复制"——传入一张图 URL，Midjourney 模仿其光影、色板、情绪与构图样式，但不照搬内容；`--sw` 控强度（0 到 1000，默认 100）。`--cref` 则是"身份锁定"，让生成图沿用参考图人物的脸与发型。`--style raw` 关闭默认美化滤镜，对摄影类提示词几乎是必加项。多提示词加权用 `::` 分隔并赋相对权重，`{}` 花括号做排列组合一次出多版，都是精准控制优先级的手段。

#### 动手验证

以"做一组品牌一致的科技博主头像，并修正一只画歪的手"为例：

```
Step 1 写六要素提示词（前 20 词放主体+风格）：
       "Asian woman in red trench coat, cyberpunk Tokyo street at night,
        medium shot from behind, neon backlight with fog,
        photorealistic editorial, kodak portra 400 grain --ar 9:16 --style raw --v 7"

Step 2 锁风格：先生成一张满意的作为风格锚，之后所有图加：
       --sref https://你的锚图.url --sw 100
       保证整组光影配色一致

Step 3 锁角色：若要做同一人物的多场景，加：
       --cref https://人脸参考.url --cw 100
       跨图保持同一张脸与发型

Step 4 局部修正：生成后若手画歪，用 Vary Region 框选手部单独重绘；
       想换灯光/衣服不丢姿势，用 Remix 改提示词保留构图

Step 5 快速筛选：先用 --draft 低质出 4 张挑创意，选中后再完整质量重生成
```

验收标准：六要素齐全的图主体明确、无畸形多余肢体；加 `--sref` 后整组风格统一；加 `--cref` 后跨图人脸一致；Vary Region 修好的手不再扭曲。省钱技巧：竖屏封面用 `--ar 9:16`、横幅用 `--ar 16:9`；永远加 `--no blur, text, watermark, deformed hands` 作默认防护；避免"photorealistic anime watercolor"这类互相打架的风格堆砌。

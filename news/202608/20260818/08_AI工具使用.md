### 1. 【Cursor 项目规则固化：用 .cursor/rules 把团队编码规范写进 AI 上下文】

> 📍 **导语**：用 AI 写代码最磨人的不是它写不出，而是它每次都"失忆"——你上周费劲纠正过的"我们项目禁止用 Lombok""建表必须有 create_time"，新开一个会话它就全忘了，又给你写出一套违规代码。问题根源在于项目的隐性知识（技术栈、命名约定、禁止事项）只存在你脑子里和散落的文档里，AI 根本看不到。2026 年 Cursor 主推的 `.cursor/rules/` 目录机制，正是把这套隐性知识变成显性的配置文件，让 AI 每次对话自动加载，团队还能用 Git 共享。它值得今天就用，因为配置一次，所有会话永久生效，新人进项目也能立刻写出符合规范的代码。

**▌ 它是什么（工具速览）**

Cursor 是当下最主流的 AI 编程编辑器之一，截至 2026 年初日活已超过 100 万、服务 5 万家企业。它提供的"项目规则"能力，不再是一个塞满所有指令的 `.cursorrules` 单文件（该旧格式在 Agent 模式下会被静默忽略），而是 `.cursor/rules/` 目录下多个 `.mdc` 文件，每个文件用 YAML frontmatter 控制"什么时候生效"。规则分三层作用域：User Rules（全局个人偏好，跟随账号）、Project Rules（项目级，跟 Git 走，团队共享）、Team Rules（企业级，Team/Enterprise 计划可用）。此外还有 AGENTS.md 这种纯 Markdown 的轻量替代。收费上基础编辑免费，规则能力本身不额外收费，属于"把已有能力用对"的技巧。

**▌ 它解决了什么问题（场景化拆解）**

它解决的是 AI 编程里最隐蔽的三类损耗。第一是"重复纠正"：你每开一次会话就要把"用 pnpm 别用 npm""TypeScript 严格模式"重说一遍，说漏了就出错。第二是"上下文污染"：旧版单个大文件会把前端规范也塞进写后端的对话，白白消耗 token。第三是"团队不一致"：十个开发者十个写法，Code Review 全耗在风格争论上。三条对应的解法分别是：用 Always Apply 固化无条件适用的安全底线、用 globs 精准投递只匹配相关文件的规范、用 Git 提交规则让全员共享同一套约束。实测数据表明，结构良好的规则层级能让调试与重构节省 20%–25% 时间，规范得当的团队合并 PR 数量提升约 39%。

**▌ 原理拆解（实战工作流）**

理解 `.mdc` 文件，抓住 frontmatter 的三个字段：`description`（AI 判断何时加载 Agent Requested 规则的语义钩子）、`alwaysApply`（布尔，true 则每轮都注入）、`globs`（数组，匹配的文类自动附加）。由此衍生四种激活模式：Always Apply 放通用风格与安全底线，控制在 200 行内；Auto-attached 用 globs 精准投递（如 `src/main/java/**/*.java` 配 Java 规范）；Agent-decided 靠写清楚的 description 让 AI 自主判断（如"涉及建表、写 SQL、数据库迁移时使用"）；Manual 仅在对话里 `@rules/xxx` 手动引用。关键机理是"按需加载"——只有相关规则进入上下文，既保住规范又不浪费 token。优先级上 Project Rules 高于 User Rules，冲突时后加载的覆盖先加载的，团队契约永远压过个人口味。

**▌ 动手验证**

以"给一个 Spring Boot + React 全栈项目固化规范"为例，完整走一遍：

```bash
# Step 1 在仓库根目录创建规则目录
mkdir -p .cursor/rules

# Step 2 写一条 Always Apply 的通用底线（general.mdc）
cat > .cursor/rules/general.mdc <<'EOF'
---
description: 核心项目标准——技术栈、安全与 git 工作流
alwaysApply: true
---
# 项目标准
- 包管理器使用 pnpm（绝不写 npm 或 yarn）
- 语言为 TypeScript strict 模式，禁止无注释的 any
- 安全底线：绝不打印密钥，绝不提交 .env，用 process.env 加校验
- git：小而聚焦的提交，禁止一次性大杂烩
EOF

# Step 3 写一条 Auto-attached 的 Java 后端规范
cat > .cursor/rules/java-backend.mdc <<'EOF'
---
description: Java Spring Boot 后端开发规范，写 .java 或 pom.xml 时生效
globs: ["src/main/java/**/*.java", "pom.xml"]
alwaysApply: false
---
# Spring Boot 规范
- Controller 只做参数校验与调用 Service
- 禁止在 Controller 写业务逻辑、禁止 System.out.println
- 建表必须有 id / create_time / update_time / is_deleted
- 禁止 SELECT *
EOF

# Step 4 在 Cursor 命令面板（Cmd/Ctrl+Shift+P）输入 New Cursor Rule 也可图形化创建
# Step 5 把 .cursor/rules/ 提交到 Git，团队成员自动受益
git add .cursor/rules && git commit -m "chore: 固化项目 AI 编码规则"
```

验收标准：新开一个空会话，让 AI 写一个 `.java` 文件，确认它自动遵守了"禁 SELECT *"且没用 npm；写前端时确认 Java 规范没有被误加载。若某条规则总不触发，多半是 globs 写错或 description 太模糊——把 description 从"数据库规则"改成明确语义句即可。

**▌ 对比选型**

| 决策维度 | .cursor/rules | 旧 .cursorrules | AGENTS.md |
|---------|--------------|----------------|-----------|
| 适合任务 | 多技术栈团队协作 | 单框架小项目 | 个人/快速上手 |

| 学习成本 | 需学 frontmatter | 几乎为零 | 零 |

### 2. 【n8n AI 工作流自动化：用可视化节点把重复任务串成自动流水线】

> 📍 **导语**：很多团队的重复劳动藏在日常里：每天把表单提交写进数据库、收到客户消息先查知识库再回、定时把报表发到群里。这些事单看都不难，合在一起却占据大量人力。传统做法是雇人盯着，或写一堆脚本但没人维护就烂尾。2026 年 n8n 已成为低代码自动化编排的首选开源工具，它用"拖节点、连线"的方式把这些重复任务串成可自动运行的流水线，并原生内置 AI Agent 节点，让你不写复杂代码就能让工作流具备推理、调用工具和记忆能力。它值得今天试用，是因为社区版免费自托管、420+ 集成、1700+ 模板，半小时就能跑通第一个能干的 AI 助手。

**▌ 它是什么（工具速览）**

n8n 是一个开源的低代码工作流自动化平台，既支持自托管（npm 装、本地起、用 ngrok 暴露 HTTPS 便于接收 Webhook），也提供 n8n Cloud 托管版。它的核心画布由"触发器节点 + 处理节点 + 输出节点"组成，每个节点默认对输入的每一项数据执行一次，无需手写循环。2026 年它把 AI 能力做成原生节点：AI Agent 节点负责推理，下面挂 Chat Model（连接 OpenAI、Anthropic、DeepSeek、Gemini 等任意大模型）、Memory（记忆）、Tools（工具调用）三类子节点，构成经典的 ReAct（推理+行动）循环。模型无关是它的最大卖点——换个 API Key 就能在成本与质量间切换，不被单一厂商锁定。对小企业而言，GPT-4o-mini 已能覆盖客服、FAQ、线索筛选等多数场景。

**▌ 它解决了什么问题（场景化拆解）**

它解决的是"执行缺口"：工具够聪明，但没人把聪明落到具体流程里。第一是响应延迟——客户半夜提问没人答，工作流可以 7×24 自动接。第二是跨系统搬运——查 CRM、搜知识库、发邮件这类动作手动做极碎，n8n 用 420+ 预置集成一次连好。第三是上下文丢失——普通聊天机器人每轮独立，n8n 的 Memory 节点（Simple/Window Buffer/Postgres/Redis）让助手记住上周的对话。第四是可靠性——Error Trigger 节点能捕获任意节点失败并返回干净报错，而非静默崩溃。它把"AI 会思考"和"n8n 会执行"彻底分开：模型管决策，平台管干活，你是在画流程而不是写编排代码。

**▌ 原理拆解（实战工作流）**

典型 AI 工作流遵循固定的四段结构：Chat Trigger（入口，捕获用户消息或 Webhook）→ AI Agent（推理中枢，用 System Message 定义身份与边界）→ Chat Model + Memory + Tools（子节点提供能力）→ Output（回聊天框、写 Google Sheet、发 Slack 等）。ReAct 循环在这里体现为：Agent 收到问题后，自己决定要不要调用工具（例如搜知识库、算运费、建工单），n8n 可靠地执行这些工具操作，再把结果交回模型综合成答复。关键设计是 System Message 必须写清"你不能做什么"——例如客服 Agent 要明确"没有工具提供的数据不许编造账户信息"，否则它会幻觉。另一个要点是 items 范式：每个节点对数组里每项自动执行，所以你几乎不用写循环，连 IF 分支都是拖一个节点按条件路由到 True/False 两路。

**▌ 动手验证**

以"搭一个会查知识库、记不住就转人工的支持助手"为例：

```bash
# Step 1 安装并启动（自托管）
npm install -g n8n
n8n start
# 浏览器打开 http://localhost:5678，新建一个空白工作流

# Step 2 添加 Chat Trigger 节点（自带测试聊天窗，无需外部 Webhook）
# Step 3 添加 AI Agent 节点，System Message 写入：
#   "你是 TaskFlow 的客服。规则：1) 先用知识库工具查产品问题；
#    2) 查不到就说'转人工'；3) 不许编造功能或价格；4) 回复 2-3 句。"

# Step 4 给 AI Agent 挂子节点
#   - Chat Model：选 OpenAI Chat Model，模型 gpt-4o-mini，温度 0.3
#   - Memory：Window Buffer Memory，上下文窗口 10，Session ID 用 {{ $json.sessionId }}
#   - Tools：Vector Store QA（接你的 Pinecone/Qdrant 知识库）
#     或 HTTP Request 工具 POST 到工单系统

# Step 5 点 Chat 按钮实测：问"怎么重置密码"应直接答；
#     问"我的订单到哪了"且知识库无账户数据时应回"转人工"
```

验收标准：连续两轮对话后，第三轮问"刚才那个问题"助手仍能接住（说明 Memory 生效）；问知识库外的问题不出现编造。若 Agent 反复搜索不收敛，是 System Message 没说清"何时停止搜索"，补一句停止条件即可。

**▌ 对比选型**

| 决策维度 | n8n AI Agent | 纯对话机器人 | 自写 Python 脚本 |
|---------|-------------|------------|----------------|
| 适合任务 | 跨系统自动流水线 | 单次问答 | 极致定制逻辑 |
| 不适合 | 超轻量一次性任务 | 需执行真实动作 | 不想维护的团队 |
| 集成成本 | 420+ 原生集成 | 几乎为零 | 每个接口自己写 |
| 价格 | 社区版免费自托管 | 多数免费 | 仅算力成本 |

### 3. 【Coze 扣子知识库问答：零代码把私有文档变成可对话助手】

> 📍 **导语**：你电脑里堆着几百份产品手册、报销制度、FAQ 文档，想找一条信息时翻文件夹翻到崩溃，问通用大模型它却说"我不知道"——因为你从没把文档喂给它。过去做知识库问答要写 RAG 代码、装向量库、调模型 API，门槛高到劝退普通人。2026 年字节跳动的 Coze（扣子）把这条路压成零代码：上传 PDF/Word/Excel，平台自动切块向量化，再配一段人设提示词，一个能基于你私有文档准确作答的助手就做好了，还能一键发布到飞书、公众号、企业微信。它今天就该试——不写一行代码、不需要服务器，十分钟让公司制度"活"起来。

**▌ 它是什么（工具速览）**

Coze（扣子）是字节跳动推出的零代码 AI 应用平台，官网 coze.cn 国内直连、免费、中文友好。它的核心对象叫 Bot（智能体），不是简单聊天机器人，而是可以挂载知识库、运行工作流、对接多渠道的完整体。知识库支持 PDF、Word、Markdown、TXT、Excel 甚至网页链接，上传后 Coze 自动做文本分块与向量化存储。底层大模型可选豆包、通义千问、智谱等。Bot 创建有"单 Agent"和"多 Agent"模式，新手用单 Agent 即可。整个配置是图形化拖拽，没有一行代码，非技术人员十分钟能跑通。发布渠道覆盖飞书、微信公众号、企业微信，做出来的助手直接进团队日常工具链。

**▌ 它解决了什么问题（场景化拆解）**

它解决的是企业/个人知识的"最后一公里"可问答化。第一是"文档找不到"：几百份资料人工检索靠记忆，Coze 让"我们产品退款政策是什么"这类问题秒回准确数字。第二是"答案不可信"：通用大模型靠训练记忆答公司制度会胡编，RAG 模式让答案锚定在你的文档上、有据可查。第三是"重复答疑"：客户、新人天天问同一批问题，助手 24 小时自动答，人只处理例外。常见坑也有解法：答案太笼统→在分块时加章节标题等上下文并让 Bot 引用来源；超出知识库→配兜底模板说清能力边界；关键词搜不到→开启"混合检索（关键词+向量）"。这些都不需要写代码，在界面里勾选即可。

**▌ 原理拆解（实战工作流）**

Coze 知识库问答本质是检索增强生成（RAG），跑通分四步：第一步知识库构建，上传文档后平台自动分块并向量化，你也可手动用 `###` 标识知识块做"自定义分段"提升切分质量；第二步智能体创建，在画布里把"知识库检索节点"与大模型生成节点串联；第三步 Prompt 优化，写清楚角色、风格与边界，例如"你是报销制度助手，只依据知识库作答，引用具体条款，超出范围就说不知道"；第四步多渠道发布。一个隐藏强项是"AI 创建"——输入一句话如"搭建入库单知识问答智能体，不使用任何插件"，系统自动生成含角色设定与回复逻辑的框架，你再删掉冗余插件即可。关务、物流等非技术人群沙龙实测 15 人全部跑通，说明门槛确实足够低。

**▌ 动手验证**

以"把公司《差旅报销制度》变成可问答助手"为例：

```
Step 1 打开 coze.cn，手机号注册登录；左侧点 Bot → 右上角"创建 Bot"
       选"单 Agent"模式，命名为"报销小助手"

Step 2 进入"知识库" → 创建知识库 → 上传《差旅报销制度.pdf》

Step 3 回到 Bot，进入"人设与回复逻辑"，写：
       "你是公司差旅报销助手，只依据知识库回答。
        用户问住宿/交通标准，给出具体金额与适用条件并标注出处条款；
        知识库没有的内容，回答'该问题请联系财务'，不要编造。"

Step 4 把刚建的知识库关联到这个 Bot（添加知识库 → 选中）

Step 5 右侧预览区测试："出差住酒店标准多少？"
       → 应返回带条款的具体金额；再问"怎么考雅思" → 应回答转人工/不知道
       确认无误后点"发布" → 选飞书或企业微信渠道
```

**提示**：上传 Excel 当知识库时，订单号等列不能有合并单元格，否则整行失效；高频异常话术（如"还没收到货怎么回"）需手写规则，AI 无法从表格自动归纳。

### 4. 【可灵图生视频：用一张静图加运镜提示词生成短视频】

> 📍 **导语**：你手头有一张产品图、一张封面图，甚至一张老照片，想让它"动起来"做电商详情页、小红书种草或公众号推文——过去这要么靠剪辑软件手K关键帧，要么得学 3D 建模，门槛高到放弃。2026 年快手旗下的可灵 AI 把这件事变成上传即动：给一张图，写一句"缓慢推进、发丝随风轻扬"，几秒到十几秒的短视频就出来了，不用剪辑、不用建模。它今天值得用，是因为相比文生视频，图生视频在人物、构图、光线上可控三倍以上，且有首尾帧、镜头轨迹等专业控制，普通创作者也能产出电影感的动态素材。

**▌ 它是什么（工具速览）**

可灵 AI 是快手推出的视频生成模型，网页端 klingai.kuaishou.com、App 端"可灵AI"均可使用，支持手机号或微信登录。它的图生视频功能提供三种方式：网页端高精度模式（深度估计+语义分割双引擎，材质反光、人物关节更稳）、App 端模板化一键生成（预置 12 种动作逻辑）、首尾帧驱动（锁定起止状态由 AI 推演中间动作）。核心模型推荐选"可灵 1.6"，对产品、美食、人像适配最佳。时长可选 5 秒、12 秒等，画幅支持 9:16 与 16:9。免费用户有基础额度，付费档位提升清晰度与速度。它的差异化在于物理动态真实与镜头轨迹可手绘——你在画布拖动关键帧就能定义推拉摇移路径，这是很多竞品不具备的。

**▌ 它解决了什么问题（场景化拆解）**

它解决的是"静态素材动态化"的三类痛点。第一是电商详情页：一张商品静图想展示"酱汁微微晃动、蒸汽升腾"，过去要拍视频或 3D 渲染，可灵上传即动。第二是老照片/封面活化：一张海报想让背景光斑旋转、桌面反光渐变，写句提示词即可。第三是分镜预演：短片、广告先出静帧再用图生视频验证运镜，比直接文生视频更可控。关键提醒有三个：创意度拉满会偏离原图，建议保持 5 以下保角色一致；运动强度 10 配表演模式会让人脸崩，二者择其一；直接文生视频不如图生视频可控。超过 10 秒的复杂动作，应拆成几段独立生成再用剪映缝合，靠首尾帧像素级对齐保连贯。

**▌ 原理拆解（实战工作流）**

图生视频的工作逻辑是"首帧理解 + 运动推理 + 镜头合成"。你上传的图先被解析为深度与语义结构，提示词里的镜头动作（推近/环绕/平移）、主体反应（晃动/轻扬）、环境反馈（光斑/反光）三部分被分别编码，模型据此生成中间帧并施加你设定的镜头轨迹。参数面板的四个旋钮决定成品：创意度（0–10，越高越艺术但越偏离原图）、运动强度（1–10，控幅度速度）、相关性（1–10，与原图贴合度）、镜头轨迹（手动拖关键帧定路径）。首尾帧模式则用两张图锁死起止构图，AI 只推演中间物理变化，适合产品拆箱、开合动画。理解这条链路后，最有效的优化是"结构化提示词"——先写镜头、再写主体、后补环境，避免"看起来很美"这类无效描述。

```

Step 2 把主体清晰的图片拖入中央虚线框（JPG/PNG，分辨率≥1280×720，主体居中）
Step 3 右侧参数：模型选"可灵 1.6"，时长 12 秒，画幅 9:16（小红书竖屏）
Step 4 提示词框输入结构化指令：
       "镜头缓慢推进，酱汁微微晃动，发丝随风轻扬，
        背景光斑旋转，桌面反光渐变，电影级打光，8K 质感"
       （避免"looks beautiful"等无效词；运动强度保持中等防主体抖）
Step 5 点生成，单镜约 3–10 分钟；生成 3–5 次挑运动最顺的一条
Step 6 若主体变形过大 → 降运动强度或加"保持主体清晰"约束
       若特效不够 → 加强动态描述；下载 MP4 进剪映混剪加转场音效
```

验收标准：主体在 12 秒内未发生明显畸变、运镜方向与你写的提示词一致、光影自然不闪烁。若首尾需要更长叙事，用"前一段尾帧直接作后一段首帧"的像素级交接法，再在剪映用 0.4 秒溶解转场缝合。

### 5. 【WPS AI 办公实战：用智能助手做总结、改写与表格处理】

> 📍 **导语**：很多人装了五六年 WPS，日常却只有三招：双击打开、疯狂敲字、Ctrl+S 保命，剩下的功能栏像地铁线路图一样复杂于是假装看不见。写周报卡壳就盯着空白页发呆，几百页 PDF 合同手动翻，表格里拆手机号还在背 LEFT/MID/RIGHT 函数。2026 年 WPS AI 已经深度嵌进文字、表格、演示、PDF 各组件，用大白话就能让助手写文案、做总结、改文档、分析数据。它今天该用起来，是因为它就在你天天开的办公软件里，不用来回切平台，且对国内办公场景的中文适配最好，十分钟就能把"打字员"变成"偷懒员"。

**▌ 它是什么（工具速览）**

WPS AI 是 WPS 365 内置的 AI 办公助手，入口在每个组件的工具栏右侧：文字里有"AI 伴写"和"AI 帮我写/改"，表格里有"AI 分析"，演示里有"生成 PPT"，PDF 右侧有"AI 阅读"。核心功能分四块：AI 写作（边写边续、一句话生成、智能优化选中文本）、AI 问答与阅读（侧边栏问操作、长文档提取摘要与要点）、AI 数据分析（选中区域说人话做透视表、趋势图）、AI 生成 PPT（一句话出大纲配图版式）。快捷键方面，呼出 AI 助手默认 Alt+Shift+A，接受建议 Tab、拒绝 Esc。收费上基础编辑免费，AI 智能功能需联网使用，部分高级能力随 WPS 365 订阅。它的最大便利是"嵌入式"——你不用离开文档就能完成从写作到排版的全流程。

**▌ 它解决了什么问题（场景化拆解）**

它解决办公里最磨人的三类低效。第一是"从空白页开始"的启动焦虑：周报、通知、方案，不用再对着白屏发呆，给 AI 说"写 Q2 销售周报，正式语气，含数据问题计划"十秒出初稿，你只改数字——但切记 AI 编的数字必须换成你自己的真实数据。第二是"长文档读不动"：几百页合同点"AI 全文总结"，核心条款、违约金额、双方义务哗啦拉成 bullet points，还能追问"违约金那条在哪一页"直接定位。第三是"表格劝退"：怕 VLOOKUP 的人，点 AI 分析说"把考勤出勤天数匹配到工资表"，它自己写公式；看不懂就点"公式解读"用大白话解释。Ctrl+E 智能填充更能免函数拆列。它把"人话"变成"操作"，打工人终于不用在知乎搜"VLOOKUP 为什么报 N/A"。

**▌ 原理拆解（实战工作流）**

WPS AI 的四条主线对应四种"人话→动作"的映射。写作线靠上下文感知：AI 伴写在光标处实时续写，你输入开头它给建议，Tab 接受；AI 帮我写则把一句话需求翻译成完整段落。阅读线靠文档理解：AI 阅读对打开的 PDF/文档做摘要、要点、问答，底层是长文本抽取与问答。分析线靠自然语言转公式：你说"计算 A 列总销售额"，它生成并填充公式，再可调图表样式。PPT 线靠主题生成：输入"2026 新品推广方案，12 页，商务蓝"，大纲配图版式一次吐出。机理核心是"指令越具体结果越准"——限定写给谁、多长、什么风格，比泛泛一句"写个方案"好得多；长文档分段使用 AI 也比整篇喂进去更稳，避免理解偏差。

### 6. 【即梦 AI 绘画：国产文生图工具的提示词与风格控制】

> 📍 **导语**：很多人装了即梦 AI，出的图却总"不对味"——想要中国奶奶包饺子，出来个金发碧眼外国人；想要赛博朋克，结果是一团霓虹糊图。问题不在工具，在提示词。即梦是字节跳动出品、背靠 Seedream 大模型的国产文生图工具，最大杀招是中文理解力极强（实测中文提示词精准度约 92%），还内置"世界知识"懂榫卯结构、水往低处流，甚至支持联网检索生图。它今天值得深耕，是因为掌握一套提示词公式后，出图成功率能从一半提升到九成，且对做公众号配图、短视频封面、课件设计的内容人极其友好，免费额度每天 60–100 积分够日常使用。

**▌ 它是什么（工具速览）**

即梦 AI 是字节跳动的 AI 创作平台（jimeng.jianying.com），提供 AI 作图、AI 视频、数字人等能力，背后是 Seedream 系列模型（已从 3.0 演进到 5.0 lite）。它最突出的差异化：第一，中文原生理解，写"穿红棉袄的奶奶在灶台前包饺子"能准确还原中国式场景；第二，有"世界知识"，懂基础物理与常识；第三，新增联网搜索生图，写"2026 高考加油海报"会自动检索最新视觉元素。功能上支持文生图、图生图（参考图锁定风格/构图/角色一致）、局部重绘、无限画布的跨画布风格继承。每天登录赠送 60–100 积分，普通文生图约 2–5 积分一张。它与剪映、抖音生态打通，生成的图一键进剪映编辑，且内置无版权素材库，自媒体使用更安心。

**▌ 它解决了什么问题（场景化拆解）**

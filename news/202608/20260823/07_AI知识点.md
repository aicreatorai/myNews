# AI知识点

### 1. 【MCP协议：让AI Agent用统一标准即插即用地调用外部工具】

> 📍 **导语**：Model Context Protocol（MCP）由 Anthropic 于 2024 年 11 月开源，2025 年 12 月捐给 Linux 基金会旗下的 Agentic AI Foundation（获 Google、Microsoft、AWS、Cloudflare、Bloomberg 支持）。2026-07-28 发布史上最大规格修订，围绕 Tasks 与 MCP Apps 构建无状态核心。其月 SDK 下载量接近 5 亿次，活跃公开服务器超 1.1 万个。它要解决的，是"每个 AI 应用都得为每套外部系统重写一遍对接代码"的碎片化痛点——如今任何支持 MCP 的客户端都能即插即用地调用任意 MCP Server 暴露的能力。

---

**🧠 深度解析**

**▌ 它是什么？**
MCP 是连接 AI 模型与外部工具、数据源的开放标准协议，可以类比为"AI 世界的 USB-C 接口"。它不是一个搜索引擎，而是一个让模型在对话过程中按需发现并实时调用外部工具（如读文件、查 CRM、发消息、写回状态）的通信协议。常见误区是把它和 RAG 当成竞争关系，其实两者常共存于同一个 Agent 栈：RAG 检索提前建好的文档库，MCP 调用当下才发生的实时动作。它的适用边界很清晰——需要"当下数据"或"写回动作"的场景用 MCP，纯静态知识问答用 RAG 更省。

**▌ 它解决了什么问题？**
Before：每个 SaaS 集成都是一次性胶水代码，Cursor 要接 GitHub、Claude 要接日历、VS Code 要接数据库，团队反复造轮子，维护成本极高。After：只要目标系统实现了 MCP Server，任意支持 MCP 的客户端（Claude、Cursor、VS Code、ChatGPT、Gemini）即可即插即用，无需为每个组合重写对接。一项 2025 年论文发现，把 MCP 的工具目录当作 RAG 的文档索引来处理（先检索再调用），LLM 选对工具的正确率提升超过 3 倍；Anthropic 自身生产数据印证了相近结论。某电商用 MCP 编排退款与客服流程，处理时长缩短了 60%，并释放出一名全职支持人力去做更高价值的工作。

**▌ 核心原理三阶拆解**
**第一层：直觉理解**——把 MCP 想成公司前台：模型是老板，前台（MCP Client）清楚公司有哪些部门（MCP Server）能办什么事，老板随口说"查下这个客户"，前台就跑去对应部门把结果带回来，全程在同一轮对话里完成。

**第二层：技术流程拆解**——输入对话→1) 客户端连接一个或多个 Server；2) Server 向客户端声明自己暴露哪些 tools / resources；3) 模型在对话中判断需要某工具；4) 客户端经 Server 调用，结果直接回到同一轮对话；5) 2026-07-28 修订引入无状态核心 + Tasks 扩展 + MCP Apps 正式扩展，能力以按需协商的 opt-in 扩展形式加载。

**第三层：公式与核心机制**——Server 用结构化 schema 描述每个工具的输入参数，模型按 schema 填参，避免自由格式带来的解析错误。但这套"无签名、无鉴权、无沙箱"的早期现状，正是近期约 20 个 CVE 集中爆发的根因（缓存投毒、提示注入、认证绕过等），说明协议层必须叠加鉴权与沙箱才可靠。

**▌ 动手验证**
```python
# 用官方 MCP Python SDK 声明一个工具（示意）
from mcp.server import Server
app = Server("demo")
@app.list_tools()
async def tools():
    return [{"name": "add", "inputSchema": {"type": "object",
            "properties": {"a": {"type": "number"}, "b": {"type": "number"}}}}]
@app.call_tool()
async def call(name, args):
    if name == "add":
        return [str(args["a"] + args["b"])]
# 客户端连接后，模型即可调用 add(2, 3) 得到 "5"
```
注意：必须在 host 应用中注册 Server 并启用鉴权，避免未授权调用；近期 MCP-2026 系列 CVE 多因缺失鉴权与沙箱导致。

**▌ 对比与选型**
| 维度 | MCP | RAG | 函数调用 |
|------|------|-----|---------|
| 核心思想 | 实时工具标准 | 提前建索引检索 | 模型原生调用 |
| 适用场景 | 实时/写回动作 | 静态知识问答 | 单轮结构化 |
| 数据新鲜度 | 当下数据 | 取决于索引 | 当下数据 |
| 生态成熟度 | 高(5亿下载/月) | 高 | 中 |

### 2. 【RAG检索增强生成：把大模型接上可溯源的私有知识库】

> 📍 **导语**：RAG（Retrieval-Augmented Generation）是 2026 年企业落地大模型最主流的架构。多数业务工作流偏好 RAG，因为它比微调更易维护、可治理、且无需每次数据变动就重训。其核心思路是"先检索、再生成"——把模型原本不知道的外部知识在回答前检索进来，让模型基于证据作答，而不是凭训练记忆编造。在合规与可审计要求越来越高的今天，RAG 几乎是接入企业内部文档、最新法规与私有数据的默认选项。

---

**🧠 深度解析**

**▌ 它是什么？**
RAG 是一种"先检索、再生成"的架构范式，可类比为开卷考试——考试时允许你翻书，而不是直接背答案。它不是一个具体模型，而是一套把向量数据库、检索器、生成模型串起来的流水线。常见误区是以为 RAG 等于"把文档丢给模型"，没有分块、嵌入、重排的检索质量，模型照样会幻觉。边界是：知识频繁变化、需可审计、需保持时效的场景首选 RAG；而教模型稳定的风格或推理模式才考虑微调。很多生产系统两者结合——微调管行为，RAG 管知识。

**▌ 它解决了什么问题？**
Before：纯大模型只凭训练记忆作答，遇到企业内部文档、最新法规、私有数据便"一本正经胡说"，且无法引用来源，出了问题无法追责。After：RAG 把问题相关的文档片段注入上下文，答案有出处、可溯源。检索在毫秒级完成，后台持续抓取、归一化、分块、重嵌入，源内容一变知识库即更新。电商客服接入 RAG 后，可实时引用最新退款政策，避免编造不存在的条款——现实中曾有客服机器人凭空编政策，被仲裁庭裁定"未采取合理措施确保信息准确性"。

**▌ 核心原理三阶拆解**
**第一层：直觉理解**——像写作文前先翻资料库。你问"今年差旅报销上限"，系统先去资料库找出相关章节，再把章节和你的提问一起交给"写手"整合成答案，而不是让写手凭印象乱写。

**第二层：技术流程拆解**——输入问题→1) 文档切分 chunk；2) 用 Embedding 模型转成向量存入向量库；3) 提问时把问题同样嵌入；4) 向量库做最近邻检索取 top-k；5) 拼进 prompt 交给 LLM 生成；6) 可选 Reranker 对片段再排序提升精度。后台 ingest 流程随源内容变化持续重嵌入。

**第三层：公式与核心机制**——检索质量决定答案上限。关键设计是"相似度阈值"：低于阈值的检索结果直接返回空而非强塞，避免"没有好匹配也硬给五个片段让模型编答案"。配合引用标注，让人能一眼发现错配，这正是 RAG 产品化时把"检索质量当成产品指标"的核心原因。

**▌ 动手验证**
```python
from langchain.vectorstores import FAISS
from langchain.embeddings import OpenAIEmbeddings
vs = FAISS.from_texts(["报销上限5000元/次"], OpenAIEmbeddings())
docs = vs.similarity_search("差旅报销上限是多少", k=1)
print(docs[0].page_content)  # 输出：报销上限5000元/次
```
注意：生产环境应加相似度下限过滤与来源引用，避免"自信地检索错误内容"导致的幻觉。

**▌ 对比与选型**
| 维度 | RAG | 微调 | 长上下文 |
|------|------|------|---------|
| 核心思想 | 外部检索注入 | 改权重学知识 | 全量塞窗口 |
| 更新成本 | 低(更新文档) | 高(重训) | 高(重传) |
| 可审计性 | 强(有出处) | 弱 | 中 |
| 时效 | 实时 | 滞后 | 实时 |

### 3. 【GraphRAG：用知识图谱补足传统RAG的多跳关系推理】

> 📍 **导语**：传统 RAG 擅长"片段级"检索，却答不好"谁影响了谁""A 和 B 什么关系"这类需要全局推理的问题。微软提出的 GraphRAG 在检索前先抽取实体与关系、构建知识图谱，再用图结构做社区摘要式检索，显著提升多跳问答与全局归纳能力。当企业文档量庞大、实体关系错综复杂时，普通向量检索容易"只见树木不见森林"，GraphRAG 正是为这种场景而生。

---

**🧠 深度解析**

**▌ 它是什么？**
GraphRAG 是把"知识图谱 + 检索增强生成"结合的方法，可理解为给 RAG 装上一本"人物关系字典"。它不是替换向量检索，而是在向量检索之外增加一层图结构索引。常见误区是以为 GraphRAG 等于"上图数据库"，其核心其实是先用 LLM 从文档抽取实体-关系三元组，再聚类成社区做摘要。边界：文档实体关系稀疏、只需片段问答时，普通 RAG 更划算；涉及跨文档多跳推理、全局总结（如"这份报告的主要风险有哪些"）才值得上 GraphRAG。

**▌ 它解决了什么问题？**
Before：普通 RAG 把问题向量化后只取最相似的几段，模型看不到文档全局，遇到"总结全部并购事件的因果链"只能拼凑片段，容易漏掉关键节点。After：GraphRAG 先建图，把"公司A—收购→公司B—位于→地区C"这样的关系连起来，检索时可沿图遍历，回答多跳与全局归纳问题更完整。在需要跨文档连接的复杂查询上，答案的覆盖率与可追溯性明显优于纯向量 RAG，特别适合合规审查、情报分析、科研综述等场景。

**▌ 核心原理三阶拆解**
**第一层：直觉理解**——普通 RAG 像只给你几页书，GraphRAG 先帮你画好全书的人物关系图，问"谁和谁是盟友"时直接看图回答，不用逐页翻找。

**第二层：技术流程拆解**——输入文档→1) 用 LLM 抽取实体与关系三元组；2) 构建带属性的知识图谱；3) 用图社区检测（如 Leiden 算法）把图分成若干社区；4) 对每个社区生成摘要；5) 查询时先做社区级摘要检索，再做细粒度实体检索，二者融合进 prompt 交给 LLM。

**第三层：公式与核心机制**——图社区摘要是 GraphRAG 的灵魂：它把"局部片段"升维成"局部主题概述"，让模型在没检索到具体段落时，仍能从社区摘要获得全局线索。代价是索引阶段 LLM 调用多、成本高，需要在收益与开销间权衡，通常先小样本验证再全量。

**▌ 动手验证**
```python
# 使用微软 graphrag 库（示意）
import graphrag
index = graphrag.index(input="docs/")              # 抽取实体关系建图
result = graphrag.query("报告中主要风险有哪些？", method="global")
print(result.response)  # 基于社区摘要的全局归纳答案
```
注意：建图阶段 LLM 调用较多，建议先在小样本验证收益，再决定是否全量索引。

**▌ 对比与选型**
| 维度 | GraphRAG | 普通RAG | 微调 |
|------|---------|---------|------|
| 核心思想 | 图+社区摘要 | 向量片段 | 改权重 |
| 多跳推理 | 强 | 弱 | 中 |
| 建索引成本 | 高 | 低 | 高 |
| 适用规模 | 大量文档 | 中小 | 固定 |

### 4. 【视觉语言模型VLM：让AI真正看懂图片里的世界】

> 📍 **导语**：VLM（Vision-Language Model）是连接"看见"与"理解/表达"的多模态模型，从让机器人按语言指令抓物，到辅助医生读片，正快速渗透各行业。2026 年 8 月的 VLM 研究集中于更强推理、降幻觉、提效率：GOTS 方法把视觉 token 压到 5%–20% 仍保留 96% 以上性能；One Anchor for All 仅用 0.03% 参数做跨语言安全对齐。效率与安全的双重突破，正把 VLM 推向端侧与实时场景。

---

**🧠 深度解析**

**▌ 它是什么？**
VLM 是能同时处理图像（或视频）与文本的模型，可回答"图里发生了什么""按这句话描述去操作"等问题。它并非单一架构，常见做法是"视觉编码器（如 ViT）+ 投影层 + 语言模型"三段式。误区是以为 VLM 等于图像分类器，它输出的是自然语言而非标签。边界是精度要求极高的专业诊断仍需人类把关——研究揭示前沿 VLM 会在无图时仅凭人口统计文本"臆造"诊断。2026 趋势从"看得清"转向"能行动、能记忆"：HumanCLAW 测 VLM 能否通过身体行动，GST-Bench 测全局空间理解。

**▌ 它解决了什么问题？**
Before：纯语言模型看不见图，纯视觉模型说不清图，看图问答、图文检索、机器人与 GUI 操作长期割裂。After：VLM 统一了"看"与"说"，一次前向即可图文联合推理。效率上，GOTS（贪心正交 token 选择）把高分辨率 VLM 的视觉 token 降到 5%–20%，性能保留超 96%；MedARC 对 3D 医学影像做免训练冗余压缩，在保诊断性能的同时缩短推理时间。这让端侧、实时 VLM 成为可能，也降低了显存与延迟门槛。

**▌ 核心原理三阶拆解**
**第一层：直觉理解**——把 VLM 想成"戴眼镜的翻译官"：眼镜（视觉编码器）把画面转成内部记号，翻译官（语言模型）把记号连同你的问题翻成自然语言答案。

**第二层：技术流程拆解**——输入图像+问题→1) 图像过视觉编码器得视觉特征；2) 投影层把特征映射进 LLM 词嵌入空间，变成若干"视觉 token"；3) 视觉 token 与文本 token 拼接；4) LLM 自回归生成回答。免训练方法（如 GOTS）在步骤 2 后按残差能量筛选少量关键 token。

**第三层：公式与核心机制**——视觉 token 数量直接决定算力与上下文占用，冗余视觉 token 多会拖垮长上下文与高清图。GOTS 用"与已保留集合正交、残差能量最大"的标准挑 token，既去冗余又保信息，是 2026 年 VLM 效率研究的核心抓手；而 One Anchor for All 证明只需定位极少数"多语言安全神经元"即可跨语言迁移安全对齐，大幅降低对齐成本。

**▌ 动手验证**
```python
from transformers import LlavaForConditionalGeneration, AutoProcessor
model = LlavaForConditionalGeneration.from_pretrained("llava-hf/llava-1.5-7b")
proc  = AutoProcessor.from_pretrained("llava-hf/llava-1.5-7b")
inputs = proc(images=img, text="图里有什么?", return_tensors="pt")
out = model.generate(**inputs, max_new_tokens=50)
print(proc.decode(out[0], skip_special_tokens=True))
```
注意：不同 VLM 的 processor 接口略有差异，需对齐视觉编码器与 LLM 的版本，否则投影层维度会不匹配。

**▌ 对比与选型**
| 维度 | VLM | 纯视觉模型 | LLM |
|------|------|-----------|-----|
| 核心思想 | 图文联合 | 仅视觉特征 | 仅文本 |
| 输出形式 | 自然语言 | 标签/框 | 文本 |
| 理解深度 | 强(可推理) | 中 | 无图 |
| 计算开销 | 高 | 低 | 中 |

### 5. 【世界模型：让AI在"脑内"模拟下一步会发生什么】

> 📍 **导语**：世界模型（World Model）让 AI 不只预测"下一个词"，而是模拟"下一步世界会怎样"——是具身智能、自动驾驶、机器人规划的关键能力。2026 年 8 月研究密集爆发：ELWM 把能量/动量写进潜状态，导航成功率从 81.3% 升至 89.7%、碰撞率从 12.1% 降到 5.8%；WorldSimProbe 提出"可观察模拟器契约"，严格检验动作与状态的真实对应。世界模型正从"画面像不像"走向"物理准不准"。

---

**🧠 深度解析**

**▌ 它是什么？**
世界模型是一类学会"环境动态"的内部模拟器——给定当前状态与动作，预测下一刻状态。类比：你脑中下棋时预演几步，世界模型就是 AI 的"预演引擎"。它不是生成式视频（尽管常共用扩散架构），目标是精准的物理/状态转移而非好看的画面。误区是以为世界模型等于世界模拟器成品，它其实是供规划、策略评估、数据生成的"可微分预言机"。边界：动作空间离散且规律明确的任务收益大；完全开放、长程不可预测场景仍需结合真实交互。

**▌ 它解决了什么问题？**
Before：强化学习智能体只能靠大量真实试错学策略，机器人撞了才知道撞，数据又贵又危险，样本效率极低。After：世界模型让 Agent 在"脑内"海量 rehearsal——EnvACE 用内部 rehearsal 模块替代昂贵真实交互来学工具使用，并迁移到未见基准；WorldDiT 用统一扩散架构同时建模世界与动作，在 LIBERO 四个套件达帕累托前沿且参数低于十亿。ELWM 把显式物理结构嵌进潜空间，把导航碰撞率从 12.1% 降到 5.8%，把 0.8 秒运动预测 NRMSE 从 0.36 降到 0.29。

**▌ 核心原理三阶拆解**
**第一层：直觉理解**——像开车前在脑中模拟"我打方向盘→车往左偏→会不会蹭到护栏"。世界模型把这套内部模拟交给神经网络，让 Agent 先想后动，减少真实世界里的昂贵失误。

**第二层：技术流程拆解**（以动作条件世界模型 ACWM 为例）——输入观测→1) 编码当前观测为潜状态 z；2) 输入动作 a，模型预测下一潜状态 z' 与观测 x'；3) 规划器在模型内多次 rollout 选最优动作序列；4) 把最优动作发给真实环境执行；5) 用真实反馈校正模型，形成"想象—执行—校正"闭环。

**第三层：公式与核心机制**——WorldSimProbe 指出，以往评测只看画面像不像，忽视了"动作是否真导致对应运动"。它提出可观察模拟器契约：给动作必须产生对应运动、环境响应须基于该运动。这把"像"升级为"准"，是 2026 年世界模型走向可信规划的核心标尺，避免模型输出" plausible 却不可执行"的幻觉式预测。

**▌ 动手验证**
```python
# 以 Dreamer 风格世界模型示意（伪代码）
z = encoder.observe(x)                       # 观测编码为潜状态
z_next, reward = world_model.predict(z, action)  # 预测下一步
plan = planner.rollout(world_model, z, horizon=10)  # 模型内规划
action = plan[0]; env.step(action)           # 执行首步并校正
```
注意：世界模型需用真实交互数据持续校正，纯模拟会随时间漂移，导致规划失真。

| 维度 | 世界模型 | 端到端RL | 仿真器 |
|------|---------|---------|-------|
| 核心思想 | 学动态预测 | 直接学策略 | 物理规则 |

| 可迁移性 | 强 | 弱 | 强 |

### 6. 【Prompt工程CoT与DSPy：把提示词从"手写咒语"变成可优化程序】

> 📍 **导语**：Prompt 工程正从"手写咒语"走向"可优化程序"。Chain-of-Thought（CoT）用"让我们一步步思考"激发大模型推理；DSPy 则把提示词与管线声明为可编译、可自动调优的代码模块。2026 年 OWASP 连续第三年把提示注入列为 LLM 头号风险，提示工程也因此兼管安全——既要让模型答得好，也要让它不被恶意指令劫持。

---

**🧠 深度解析**

**▌ 它是什么？**
Prompt 工程是设计输入文本以引导模型行为的技术集合。CoT 是一种具体技巧——在问句后加"让我们一步步思考"，让模型先输出推理链再给答案。DSPy 是一个框架，把"提示词模板、检索器、模型调用"声明为带类型签名的模块，用优化器（如 BootstrapFewShot）自动搜索最佳示例与指令。误区是以为提示词越长越灵，研究指出正确的 300 token 胜过 10 万噪声 token。边界：单轮事实问答无需 CoT，复杂推理、数学、代码任务才显著受益。

**▌ 它解决了什么问题？**
Before：复杂问题直接问，模型常跳步、算错、答非所问；且不同模型要手写不同提示，迁移成本高、难维护。After：CoT 让模型显式推理，数学与逻辑题准确率大幅上升（Wei 等 2022 NeurIPS 奠基工作）。DSPy 进一步把"调提示"变成"编译程序"——改模型或任务只需重跑优化器，无需手工改词。某工程实践把系统提示词从冗长清单精简，反而提升 Coding Agent 表现，印证"少而精"原则；同时结构化分隔符（XML 标签）能把外部内容标记为不可信数据，显著降低间接注入风险。

**▌ 核心原理三阶拆解**
**第一层：直觉理解**——CoT 像考试要求"写出计算过程"，逼模型把脑子里的步骤摊开，减少跳步错误；DSPy 则像把提示词写成函数，编译器自动调参找出最优版本，而不是人肉试错。

**第二层：技术流程拆解**（DSPy）——输入需求→1) 用 @dspy.signature 声明输入/输出字段；2) 用 ChainOfThought 等模块组合成管线；3) 准备少量带标注的训练样本；4) 选优化器对示例与指令做 bootstrap；5) 编译出最优提示与 few-shot 组合；6) 投入推理。换模型时只需重跑编译。

**第三层：公式与核心机制**——DSPy 的核心是"把提示词当作可搜索的程序"：优化器在"能提升验证集指标"的方向上搜索提示与示例空间，而非人肉试错。这与"把 Prompt 当代码"（arXiv:2507.03620）的理念一脉相承，把提示工程从经验手艺升级为可复现的工程方法。

**▌ 动手验证**
```python
import dspy
lm = dspy.LM("openai/gpt-4o"); dspy.configure(lm)
class QA(dspy.Signature):
    question: str -> answer: str
prog = dspy.ChainOfThought(QA)                 # 自带 CoT
prog = dspy.BootstrapFewShot(metric=acc).compile(prog, trainset=examples)
print(prog(question="1+1=?").answer)
```
注意：需准备带标注的 trainset 供编译，且不同 LM 的编译结果不可直接混用。

**▌ 对比与选型**
| 维度 | DSPy | 手写CoT | 微调 |
|------|------|--------|------|
| 核心思想 | 程序化编译 | 人工模板 | 改权重 |
| 跨模型迁移 | 强(重编译) | 弱 | 中 |
| 自动化程度 | 高 | 低 | 中 |
| 上手成本 | 中 | 低 | 高 |

### 1. 【Muon优化器：用矩阵正交化改写大模型预训练的更新方向】

> 📍 **导语**（80-100字）: 大模型预训练十年来几乎被 AdamW 一家垄断，换优化器被认为是吃力不讨好的事。Muon 打破了这个惯例：它不再把权重当成一堆孤立的标量，而是当成矩阵，用牛顿-舒尔茨迭代把动量"正交化"后再更新。月之暗面在 Moonlight 与 Kimi K2 上把它推到万亿参数规模，同样算力下训练效率接近翻倍，让"优化器还能不能进步"重新成为热题。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
Muon 是 MomentUm Orthogonalized by Newton-schulz 的缩写，一种专门服务于神经网络二维权重矩阵的优化器。它的核心动作只有一步：先像 SGD 那样累积动量，再对动量矩阵做一次近似正交化，用正交化后的方向去更新权重。它不是 AdamW 的补丁，也不是学习率调度技巧，而是换了一套"什么才是好更新方向"的假设。它的适用边界很清楚——只管隐藏层里的二维矩阵，嵌入层、输出头、归一化层的一维参数仍旧交给 AdamW。历史脉络上，它承接了 Shampoo、SOAP 这一支矩阵型二阶优化器的思路，却把昂贵的矩阵求逆换成了几轮矩阵乘法，因而第一次在大规模预训练里跑得起。

**▌ 它解决了什么问题？**（120-180字）
AdamW 用逐元素的二阶矩缩放梯度，等于默认每个权重彼此独立，结果是更新矩阵常常被少数几个奇异值主导，方向高度"扁平"，模型有效学习的维度被浪费。以前的对策只能是加大数据量、拉长训练步数。Muon 让更新矩阵的奇异值趋于一致，等于强迫每个方向都出力。月之暗面在 Moonlight（16B 总参、2.4B 激活的 MoE）上报告，在相同数据下达到同等性能只需约 52% 的训练算力；随后 Kimi K2 用改进版 MuonClip 在 15.5 万亿 token 上完成万亿参数 MoE 的预训练，全程未出现损失尖峰。这把"换优化器"从论文玩具变成了工业级选项。

**▌ 核心原理三阶拆解**（350-500字）
第一层：直觉理解。想象你带团队推一辆卡在泥里的车，AdamW 的做法是每个人各自使劲、谁喊得响谁多用力，结果大家方向乱七八糟，合力被抵消；Muon 则先把所有人的用力方向摊平成一个"各方向均匀"的合力，谁也不许独大，于是同样的力气推得更远。

第二层：技术流程拆解。①对二维权重 W 计算梯度 G；②按 SGD-momentum 更新动量 M ← μM + G；③对 M 做正交化，得到 O = NewtonSchulz5(M)；④按 W ← W − η·O 更新。第三步是全部秘密所在：牛顿-舒尔茨迭代用形如 X ← aX + b(XXᵀ)X + c(XXᵀ)²X 的多项式，迭代五次左右就能把 M 的所有奇异值挤到 1 附近，且全程只有矩阵乘法，可在 bf16 上跑，额外开销通常低于总训练时间的百分之一。

第三层：公式与核心机制。数学上，正交化等价于对 M 做奇异值分解 M = UΣVᵀ 后丢掉 Σ，直接取 UVᵀ。这是在谱范数信任域约束下的最速下降方向，几何含义是"步子的最大拉伸倍数被限死"。规模化的两个关键补丁：一是权重衰减必须显式加回，否则大模型后期权重范数会失控；二是按 √(fan-out) 之类的形状因子重缩放更新幅度，使 Muon 能直接沿用 AdamW 已调好的学习率。MuonClip 则在此之上对注意力的 Q、K 投影做 qk-clip，从源头压住 logit 爆炸。

**▌ 动手验证**（100-150字）
用 PyTorch 实现核心的正交化步骤：

```python
import torch
def newton_schulz5(G, steps=5, eps=1e-7):
    a, b, c = 3.4445, -4.7750, 2.0315      # 论文给出的五次多项式系数
    X = G.bfloat16() / (G.norm() + eps)    # 先归一化，保证迭代收敛
    if X.size(0) > X.size(1): X = X.T      # 保证行数不大于列数
    for _ in range(steps):
        A = X @ X.T
        X = a * X + (b * A + c * A @ A) @ X
    return X                                # 奇异值被压到 1 附近
M = torch.randn(512, 1024)                  # 这里用动量矩阵代入
print(torch.linalg.svdvals(newton_schulz5(M).float())[:5])
```
注意：只对隐藏层二维矩阵使用，嵌入与输出头仍走 AdamW，否则收敛会变差。

### 2. 【稀疏自编码器SAE：把大模型神经元拆成人能读懂的特征】

> 📍 **导语**（80-100字）: 大模型内部到底在想什么，长期是个黑箱：一个神经元同时对"金门大桥""代码缩进""法语"起反应，根本没法解释。稀疏自编码器（SAE）用字典学习把纠缠的激活拆成成千上万个单一含义的特征，让研究者第一次能给模型"贴标签"，甚至直接扭动某个特征改变输出。它已成为 2026 年可解释性与模型审计的主力工具。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
稀疏自编码器是一个结构极简的两层网络：把语言模型某一层的残差流激活向量升维到远大于原维度的稀疏空间，再压回原维度重建。训练目标只有两项——重建误差要小、被激活的隐藏单元要少。它不是模型压缩工具，恰恰相反，它把维度放大了几十上百倍；它也不是探针分类器，因为不需要任何人工标注。它的适用边界是"分析已有模型"，不改变原模型权重。历史脉络上，它源自神经科学的稀疏编码与压缩感知，2023 年被 Anthropic 用于小模型后迅速放大到前沿模型，成为机制可解释性从"看单个神经元"转向"看特征字典"的转折点。

**▌ 它解决了什么问题？**（120-180字）
没有 SAE 之前，可解释性研究卡在"叠加现象"上：模型要表示的概念数量远超神经元数量，只能把多个概念挤进同一个方向，导致神经元多义、无法解释。研究者只能靠人工翻激活样本，效率极低。Anthropic 在 Claude 3 Sonnet 上训练出约 3400 万个特征，找到了会对文本、图片乃至"提及旧金山"都统一响应的"金门大桥特征"，把它人为放大后模型会执着地把话题拽向金门大桥；OpenAI 在 GPT-4 上把规模推到 1600 万特征，并给出稀疏度与重建质量的缩放规律；DeepMind 的 Gemma Scope 则一次性开源覆盖 Gemma 2 各层的 400 多个 SAE，让学术界不必自己烧算力就能做实验。

**▌ 核心原理三阶拆解**（350-500字）
第一层：直觉理解。把模型的激活想成一段混音——鼓、吉他、人声全叠在一条音轨里，你听得见却分不开。SAE 就是一台自动分轨机：它假设任何一秒钟真正发声的乐器其实很少，于是准备一个上万件乐器的清单，每次只挑几件来复原这段声音。挑出的那几件，就是这一刻模型真正在"想"的概念。

第二层：技术流程拆解。①从目标模型某层抓取大量激活向量 x（维度 d）；②编码 f = ReLU(W_enc(x − b_dec) + b_enc)，隐藏维度取 8d 到 64d；③解码 x̂ = W_dec·f + b_dec；④损失为 ‖x − x̂‖² + λ‖f‖₁，L1 项负责逼出稀疏；⑤训练完成后，对每个特征取激活最强的若干文本片段，交给另一个大模型自动生成"这个特征代表什么"的解释；⑥用因果干预验证——强行把某特征置零或放大，看输出是否按预期变化。

第三层：公式与核心机制。L1 惩罚会同时压低本该很大的激活值，造成"收缩偏差"。OpenAI 的 TopK SAE 干脆去掉 L1，改为每次只保留激活值最大的 k 个单元，稀疏度成了可直接设定的旋钮；DeepMind 的 JumpReLU 则给激活加一个可学习阈值，低于阈值直接归零，兼顾稀疏与保真。评价一个 SAE 好不好，通常看三条：重建后替换回原模型的交叉熵损失涨了多少、平均激活特征数 L0 是多少、以及有多少特征是"死"的（长期不激活）。

**▌ 动手验证**（100-150字）
最小可运行的 SAE 训练骨架：

```python
import torch, torch.nn as nn
class SAE(nn.Module):
    def __init__(self, d_in, expansion=16):
        super().__init__()
        d_h = d_in * expansion            # 升维成过完备字典
        self.enc = nn.Linear(d_in, d_h)
        self.dec = nn.Linear(d_h, d_in, bias=True)
    def forward(self, x):
        f = torch.relu(self.enc(x - self.dec.bias))
        return self.dec(f), f
x = torch.randn(256, 768)                 # 从某层残差流采集的激活
sae = SAE(768)
xhat, f = sae(x)
loss = (x - xhat).pow(2).sum(-1).mean() + 5e-3 * f.abs().sum(-1).mean()
print(loss.item(), "平均激活特征数L0:", (f > 0).float().sum(-1).mean().item())
```
可直接用 SAELens 或 Gemma Scope 的预训练权重跳过训练环节。

### 3. 【约束解码：用有限状态机逼大模型只吐合法JSON】

> 📍 **导语**（80-100字）: 让大模型返回 JSON，最常见的翻车方式是多一个逗号、少一个花括号，整条链路当场崩掉。很多团队的解法是重试三次加正则修补，既慢又不可靠。约束解码换了个思路：在采样那一刻就把非法 token 的概率直接抹成零，让模型物理上不可能输出错误格式。它是 Agent 与工具调用能稳定跑起来的隐形地基。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
约束解码，又称引导生成、结构化生成，是一类在自回归采样每一步动态屏蔽非法候选 token 的技术。它把目标格式（JSON Schema、正则、上下文无关文法）编译成一台状态机，生成过程中随时查询"当前状态下允许接哪些 token"，把其余 token 的 logits 置为负无穷。它不是提示词技巧，也不是事后校验——提示词只能"请求"模型守规矩，约束解码是从采样空间层面剥夺违规的可能。它的边界也很明确：只能保证语法合法，不保证内容正确，模型照样可以填出格式完美但事实错误的字段。这一路线由 Outlines 于 2023 年系统化，如今已被 vLLM、SGLang、llama.cpp 内置。

**▌ 它解决了什么问题？**（120-180字）
在没有约束解码的年代，工程上普遍采用"生成—解析—失败—重试"的循环，一次工具调用可能触发三到五次模型请求，延迟和成本成倍上涨，且长 Schema 越复杂失败率越高。OpenAI 在推出 Structured Outputs 时给出的评测显示，未加约束的旧模型在复杂 JSON Schema 上的完全符合率不足四成，而开启约束后达到百分之百。开源侧，XGrammar 通过把文法预处理成上下文无关与上下文相关两类 token 分开处理，把每步掩码的开销压到接近零，端到端结构化生成较早期实现有数量级提升。对 Agent 而言，这意味着工具调用参数、函数签名、状态机指令都能一次成型。

**▌ 核心原理三阶拆解**（350-500字）
第一层：直觉理解。想象填一张纸质表单，格子外面有硬塑料挡板：你想在"出生日期"栏写字母也写不进去，笔尖会被卡住。约束解码就是给模型的输出加一圈挡板——不是提醒它别写错，而是让写错这个动作根本无法发生。

第二层：技术流程拆解。①把 JSON Schema 转成等价的正则或上下文无关文法；②把文法编译成有限状态机或下推自动机；③做一次离线预计算，为每个状态构建"允许 token 集合"的位掩码，键是状态、值是词表长度的布尔向量；④生成时维护当前状态，取出对应掩码，对 logits 做 masked_fill(-inf) 后再 softmax 采样；⑤根据采出的 token 推进状态机，直到到达接受状态。关键在于第三步的预计算：如果每步都实时遍历十几万词表做匹配，开销会吃掉全部收益。

第三层：公式与核心机制。设第 t 步的原始分布为 p(v|x)，允许集合为 A_t，则约束后的分布是 p′(v|x) = p(v|x)·1[v∈A_t] / Σ_{u∈A_t} p(u|x)，本质是把原分布截断到合法子集再重新归一化。工程上的两个难点：一是 token 边界与文法符号边界不对齐，一个 token 可能跨越两个文法单元，需要按字节级 trie 展开；二是掩码缓存爆炸，XGrammar 的做法是把大部分与上下文无关的 token 提前静态判定，只对少量上下文相关 token 运行时校验，并用持久化执行栈支持文法分支回溯。

**▌ 动手验证**（100-150字）
用 Outlines 强制模型输出符合 Pydantic 模型的 JSON：

```python
from pydantic import BaseModel
import outlines
class Ticket(BaseModel):        # 目标结构
    title: str
    priority: int
    resolved: bool
model = outlines.from_transformers("Qwen/Qwen2.5-0.5B-Instruct")
gen = outlines.Generator(model, Ticket)      # Schema 被编译成状态机
print(gen("把这句话转成工单：登录页面在夜间模式下按钮看不清，很急"))
# 输出必定是可被 Ticket 解析的合法 JSON，不会出现缺引号/多逗号
```
注意：只保证格式合法，字段内容仍需业务校验；文法越复杂，首次编译耗时越长，建议进程内缓存。

### 4. 【语义熵：用意义层面的不确定性抓出大模型胡编乱造】

> 📍 **导语**（80-100字）: 大模型编造答案时往往语气笃定，靠自我报告的置信度根本抓不住。语义熵换了个角度：让模型对同一问题多答几次，如果这些回答在"意思"上五花八门，说明它其实不知道。这项发表于《自然》的方法把幻觉检测从字面概率推进到语义层面，2026 年又被延伸为按置信度动态分配推理算力的调度依据。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
语义熵是一种衡量大模型回答不确定性的指标：先对同一问题采样多条回答，再按语义等价关系把它们聚成若干簇，最后在"语义簇"这一层级而不是在 token 序列层级上计算熵。熵高说明模型在不同意义之间摇摆，回答很可能是编的；熵低说明模型稳定地指向同一含义。它不是事实核查，不需要外部知识库或标注数据，因此可以零样本用在任意模型、任意领域。它主要针对的是"虚构性幻觉"——模型对同一问题每次给出不同的随意答案，而不是因训练数据本身错误导致的系统性偏差，后者语义熵反而会显示为低熵。

**▌ 它解决了什么问题？**（120-180字）
以前最直接的做法是看输出序列的对数概率，但同一个意思有无数种说法："巴黎""在巴黎""法国首都巴黎"会被判为三个不同序列，熵被人为抬高，导致把稳定正确的回答误判成不确定。语义熵通过先聚类再算熵消除了这种表述冗余。牛津团队发表于《自然》的工作显示，该方法在问答、生传记等多个数据集与多个模型家族上，识别虚构性幻觉的表现稳定优于基于朴素熵与自评置信度的基线，且无需为新任务重新训练。2026 年 7 月的 C3RL 工作进一步把校准做进强化学习奖励，并据此提出置信度自适应的测试时扩展，在保持准确率的同时把推理预算最多压掉一个数量级。

**▌ 核心原理三阶拆解**（350-500字）
第一层：直觉理解。你问一位同学同一道题五遍，他第一次说"选 A"，第二次说"应该是 C"，第三次说"我觉得 B 吧"——你立刻明白他在蒙。反过来，如果他五次都说 A，只是措辞不同，那他多半真会。语义熵就是把这个日常判断变成可计算的数。

第二层：技术流程拆解。①对同一问题以非零温度采样 N 条回答（论文常取 10 条左右）；②用一个自然语言推理模型两两判断双向蕴含——A 能推出 B 且 B 能推出 A，则判为语义等价；③按等价关系把 N 条回答划成若干语义簇；④每个簇的概率取其中所有序列的概率之和；⑤在簇的概率分布上算香农熵，得到语义熵；⑥与阈值比较，超过阈值就标记为可能幻觉，交人工复核或触发检索。

第三层：公式与核心机制。朴素熵是 H = −Σ_s p(s)log p(s)，其中 s 是 token 序列；语义熵先做映射 c = cluster(s)，得到 H_sem = −Σ_c p(c)log p(c)，p(c) = Σ_{s∈c} p(s)。关键在于这一步求和：把同义表述的概率质量合并回同一个"意义"上，熵才真正反映语义层面的分歧。由于采样多条回答开销较大，后续研究提出语义熵探针，直接从模型隐藏状态回归出语义熵值，一次前向即可估计；而 C3RL 走的是另一条路，用正确性、校准度、参考准确率三重奖励把"如实报告置信度"训进模型，再按置信度决定这道题要不要多想几遍。

**▌ 动手验证**（100-150字）
语义熵的最小实现骨架：

```python
import math
from collections import defaultdict
def semantic_entropy(answers, logprobs, equivalent):
    clusters = []                       # equivalent(a,b) 用NLI模型双向蕴含判定
    for a, lp in zip(answers, logprobs):
        for c in clusters:
            if equivalent(a, c["rep"]): c["p"] += math.exp(lp); break
        else:
            clusters.append({"rep": a, "p": math.exp(lp)})
    Z = sum(c["p"] for c in clusters)   # 归一化到语义簇分布
    return -sum((c["p"]/Z) * math.log(c["p"]/Z) for c in clusters)
# 实操：temperature=1.0 采样10条，NLI 用 microsoft/deberta-large-mnli
```
注意：采样条数太少（<5）会显著低估熵；阈值需在自己的验证集上标定。

| 对比维度 | 语义熵 | 序列对数概率 | 让模型自评置信 |
|---------|--------|---------|-----------|
| 核心思想 | 语义簇上算熵 | 看token概率 | 直接问模型有多确定 |
| 表述冗余影响 | 已消除 | 严重 | 无 |
| 额外成本 | 高（需多次采样） | 极低 | 低 |
| 是否需训练 | 否 | 否 | 需校准才可靠 |

### 5. 【模型合并Model Merging：不重训就把多个微调模型缝成一个】

> 📍 **导语**（80-100字）: 你手上有三个从同一底座微调出来的模型——一个会写代码、一个数学好、一个中文强，要合成一个全能选手，常规做法是重新收集数据再训一遍，代价高昂。模型合并给出另一条路：直接在权重空间里做加减法，几分钟、零 GPU 训练就能得到融合模型。开源榜单上大量高分模型正是这么"缝"出来的。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
模型合并是一族在参数空间直接组合多个模型权重、从而融合其能力的技术，不需要任何梯度更新，也不需要原始训练数据。前提条件是这些模型必须"同源"——来自同一个预训练底座、结构完全一致，否则权重不可比。它不是集成学习：集成要同时加载多个模型分别推理再投票，显存与延迟翻倍；合并的结果仍是一个模型，推理成本不变。它也不是蒸馏，不存在教师学生。它的理论前提是线性模式连通性——同源微调模型往往落在损失曲面上同一个低损失盆地内，因此中间的插值点也不至于崩坏。

**▌ 它解决了什么问题？**（120-180字）
过去要让模型同时具备多种专长，只能把各领域数据混在一起做多任务微调，既要反复调配比，又容易出现能力互相拖后腿；想撤销某个不良行为，更是只能重训。任务向量的提出让这些操作变成了向量算术：加法融合能力、减法遗忘能力、类比推理迁移能力，全部在权重上完成。TIES-Merging 指出简单相加会因参数符号冲突而互相抵消，先剪枝再按符号投票后融合可显著改善；DARE 更进一步，发现把微调增量随机丢弃九成以上再等比放大，能力几乎不损失，说明增量高度冗余。工具层面，MergeKit 把这些算法工程化，在消费级机器上几分钟即可完成合并，这也是开源社区高分模型层出不穷的直接原因。

**▌ 核心原理三阶拆解**（350-500字）
第一层：直觉理解。把预训练底座看作一张空白性格底稿，每次微调相当于在底稿上叠一层描图纸——代码那张画了编程习惯，数学那张画了推导偏好。模型合并就是把几张描图纸叠在同一张底稿上；难点在于两张纸的线条在同一处画反了方向，叠起来会互相涂花，所以要先决定这一笔到底听谁的。

第二层：技术流程拆解。①对每个微调模型计算任务向量 τ_i = θ_i − θ_base，即相对底座的权重增量；②可选的稀疏化：按幅值只保留每个任务向量中最大的若干比例参数，其余置零（TIES 的 trim 步）；③解决冲突：对每个参数位统计各任务向量的符号，取总幅值占优的方向，把与之相反的分量丢弃（sign election）；④按权重求和 θ_merged = θ_base + Σ λ_i·τ_i；⑤在小规模验证集上搜索系数 λ，通常用进化算法自动调。

第三层：公式与核心机制。最朴素的 Task Arithmetic 就是上式取 λ 为常数，减号则用于能力擦除，比如 θ_base − λ·τ_toxic 可以削弱毒性输出。DARE 的做法是先以概率 p 随机把 τ 的元素置零，再把剩余元素除以 (1−p) 保持期望不变，p 取 0.9 甚至 0.99 时性能依旧稳定。另一支路线 SLERP 不做加法而在两个权重之间做球面线性插值，保留权重范数与方向特性，常用于只合并两个模型的场景。核心限制始终是同源性：跨底座、跨结构合并目前仍无可靠方案。

**▌ 动手验证**（100-150字）
用 MergeKit 的配置做一次 TIES 合并：

```yaml

  - model: Qwen/Qwen2.5-7B-Instruct
    parameters: {weight: 0.5, density: 0.5}   # density=保留50%幅值最大的增量
  - model: your-org/Qwen2.5-7B-math-sft
    parameters: {weight: 0.5, density: 0.5}

```
```bash

```
注意：base_model 必须真的是二者共同祖先；合并后务必跑一遍基准，能力抵消常常悄无声息。

**▌ 对比与选型**（必填表格）
| 对比维度 | 模型合并 | 多任务微调 | 集成推理 |
|---------|--------|---------|-----------|
| 核心思想 | 权重空间做加减 | 混合数据重训 | 多模型分别推理投票 |
| 训练成本 | 近乎为零 | 高 | 无（但需先各自训） |

| 是否需原数据 | 否 | 是 | 否 |

### 6. 【上下文工程：把Agent的有限注意力预算当资源来调度】

> 📍 **导语**（80-100字）: 上下文窗口涨到百万 token 后，很多人以为把资料一股脑塞进去就行，结果 Agent 跑到第二十步开始前后矛盾、忘记指令。真实情况是：可用长度和有效长度不是一回事，token 越多模型表现反而下滑。上下文工程把提示词优化升级成一门资源调度学问，成为 2026 年 Agent 能不能长时间稳定作业的分水岭。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
上下文工程是指围绕"在每一轮推理时，究竟该往有限的上下文窗口里放哪些 token"所做的一整套系统设计，涵盖系统提示、工具定义、检索结果、历史消息、外部记忆的组织、压缩与淘汰策略。它不是提示词工程的同义词：提示词工程关注一次性怎么把话说好，上下文工程关注在几十上百轮循环中怎么持续维护一个信息状态。它也不是简单的"上下文越长越好"。它的核心假设是：注意力是有限且会衰减的预算，每多放一个无关 token，都在稀释模型对关键信息的关注。这一概念随 Agent 从单轮问答走向长程任务而在 2025 至 2026 年迅速成为工程主线。

**▌ 它解决了什么问题？**（120-180字）
过去的做法是把所有历史消息一路追加，直到撞上窗口上限再粗暴截断，副作用是早期的关键约束最先被砍掉。Chroma 的技术报告在 18 个主流模型上做了系统实验，发现随着输入 token 增加，即便任务本身难度不变，模型表现也会持续、非均匀地退化，他们称之为"上下文腐烂"，直接推翻了"长窗口等于长记忆"的直觉。Anthropic 在工程博客中给出的对策是把上下文当稀缺资源经营：只在必要时加载信息、用结构化笔记外置长期状态、接近窗口上限时做压缩式交接。其多智能体研究系统的实践显示，把子任务分派给独立上下文的子 Agent，再由主 Agent 汇总，能显著提升复杂检索任务的完成质量。

**▌ 核心原理三阶拆解**（350-500字）
第一层：直觉理解。把上下文窗口想成一张办公桌。桌子再大，同时摊开三十份文件你也找不到要用的那份。高效的人会只留当前任务的两三份在桌面，其余归档到抽屉，需要时再取。上下文工程做的就是给 Agent 配一个称职的桌面管理员。

第二层：技术流程拆解。①分层组织：系统提示与不可变约束固定在最前，工具定义次之，检索片段与历史消息放在可变区；②按需检索：不预先灌入全部文档，而是给 Agent 一个搜索工具，用到时才拉取，即"即时检索"；③压缩：当占用逼近阈值（常取窗口的七到八成）时，让模型自己把历史总结成结构化摘要，保留决策、待办与关键事实，丢弃中间过程；④外置记忆：把长期状态写进文件或数据库，上下文里只留索引；⑤子代理隔离：把探索性、消耗大的子任务丢给独立上下文的子 Agent，只把结论回传主线。

第三层：公式与核心机制。可以把每一轮看作在预算 B 下的选择问题：最大化 Σ v_i·x_i，约束 Σ c_i·x_i ≤ B，其中 c_i 是候选信息块的 token 成本、v_i 是它对当前决策的边际价值——本质是一个背包问题，而检索打分、重排序、摘要都是在估计 v_i。工程上有两个反直觉的经验：一是工具描述要少而正交，工具集重叠会让模型选择困难；二是"最小充分信息"优于"尽可能全"，因为无关内容不只是浪费预算，还会通过注意力稀释主动损害判断。

**▌ 动手验证**（100-150字）
一个可直接套用的上下文预算管理器：

```python
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")
def ntok(s): return len(enc.encode(s))
def build_context(system, tools, memory_note, history, budget=120_000, ratio=0.75):
    fixed = [system, tools, memory_note]                 # 不可淘汰区
    used = sum(ntok(x) for x in fixed)
    kept = []
    for msg in reversed(history):                        # 从最近往前保留
        if used + ntok(msg) > budget * ratio: break      # 触发压缩阈值
        kept.append(msg); used += ntok(msg)
    return fixed + list(reversed(kept)), used
```
超过阈值时，把被淘汰的历史交给模型生成结构化摘要写回 memory_note，实现无损交接。

|---------|--------|---------|-----------|
| 核心思想 | 按预算调度信息 | 有多长填多长 | 打磨单轮措辞 |
| 长程任务表现 | 稳定 | 逐步退化 | 不适用 |
| Token成本 | 可控 | 高 | 低 |
| 实现复杂度 | 中高 | 极低 | 低 |

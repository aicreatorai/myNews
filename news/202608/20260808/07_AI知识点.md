### 1. 【分词器与BBPE：为什么同一句话中文比英文更贵三倍】

> 📍 **导语**: 几乎所有人接触大模型的第一天就会遇到"token"这个计量单位，但很少有人追问一句：凭什么"苹果"是一个 token，而"pineapple"可能被拆成三个？为什么同一份合同，翻译成中文喂给某些模型，账单会比英文版贵出两三倍？为什么模型算不对"9.11 和 9.9 谁大"，罪魁祸首其实不在推理能力，而在切词那一步？分词器是整条大模型流水线上最靠前、最不起眼，也最无法回头修改的一环——它在预训练开始前就被冻结，此后模型一生都只能透过这副"眼镜"看世界。2026 年国内主流开源模型的词表已经从 6.4 万膨胀到 15 万以上，OpenAI 把 cl100k_base 换成了 o200k_base，Llama 从 3.2 万一跃到 12.8 万，这些数字背后是一场关于成本、多语言公平与数学能力的隐形军备竞赛。

---

**🧠 深度解析**

**▌ 它是什么**

分词器（Tokenizer）是一个把原始文本双向映射为整数序列的确定性转换层，它独立于模型本体，由一张词表和一套合并规则组成。目前主流大模型几乎全部使用**子词**粒度，即切分单位介于单个字符和完整单词之间，其中最普及的算法是 BPE（Byte-Pair Encoding，字节对编码）及其字节级变体 BBPE。它**不是**传统 NLP 里那种基于词典和语言学规则的中文分词工具——jieba 会努力把"研究生命起源"切成语义正确的词，而 BPE 完全不关心语义，它只统计频率，切出来的碎片可能毫无语言学意义，只要能高效压缩语料即可。它也**不是**可以中途替换的组件：分词器一旦确定，Embedding 层的形状、模型见过的所有 token 分布就都锁死了，换分词器等同于重新预训练。历史脉络上，BPE 原本是 1994 年的一种数据压缩算法，2016 年 Sennrich 等人把它引入神经机器翻译来处理罕见词，2019 年 GPT-2 把基础字母表从 Unicode 字符换成 256 个字节，得到 BBPE，从此彻底消灭了未登录词（OOV）问题；同期 Google 的 SentencePiece 走了另一条路，把空格当作普通符号（记为 ▁）直接在原始文本上训练，天然适配中日泰这类不用空格分词的语言。与当前热点的关联很直接：2026 年 Agent 场景下上下文动辄几十万 token，分词器的压缩率直接决定了同样一份资料能不能塞进窗口、以及每次调用要付多少钱。

**▌ 它解决了什么问题**

没有子词分词之前，工程上只有两个糟糕的选项。一是词级切分：词表要开到几十万甚至上百万才能覆盖真实语料，Embedding 层参数量爆炸，而且永远会遇到没见过的新词、拼写错误、专有名词，只能统统映射成 `[UNK]`，信息直接丢失。二是字符级切分：词表只要几千，永不 OOV，但同样一句话的序列长度会拉长四到五倍，注意力是平方复杂度，代价难以承受。BPE 用"让数据决定切分粒度"这一招同时解决了两头：高频词整体保留为一个 token，低频词退化为若干子词甚至字节，最坏情况才落到字符级。落到具体数字上，2026 年主流模型的中文压缩率（每 token 平均承载的汉字数）差异相当可观：Qwen2.5 以 151,936/152,064 的大词表做到约 1.5–1.8 字/token，DeepSeek-V3 用 129,280 词表约 1.5，GLM-4 的 151,552 词表约 1.45，InternLM2 的 103,168 词表约 1.42，Yi-1.5 的 6.4 万词表则只有约 1.36。而 Llama 2 时代 3.2 万的 SentencePiece 词表处理中文时，一个汉字经常要吃掉 2–3 个 token（UTF-8 编码下一个汉字占 3 字节），这就是"中文更贵"的技术根源——同一段内容，词表小的模型算出来的 token 数可能是词表大的模型的两三倍，成本、延迟、上下文占用全部按这个倍数放大。OpenAI 从 cl100k_base（约 10 万）升级到 o200k_base（约 20 万）后，代码和非英文文本的 token 数下降约 10%–20%，本质上就是花 Embedding 参数换推理成本。

**▌ 原理拆解**

**第一层：直觉理解。** 把 BPE 想象成整理一间堆满乐高散件的房间。一开始你手上只有 256 种最基本的颗粒（对应 256 个字节）。你观察发现"c 后面跟 h"这个组合出现了几万次，于是你把它们粘成一块新的预制件"ch"，登记进目录；接着发现"ch"后面常跟"a"，再粘成"cha"……如此重复几万次，目录里就自然长出了 the、ing、tion 这类高频零件，以及"人工智能"这样的中文常用词。用户给你一段新文本时，你按照登记的先后顺序，把能粘的都粘起来，剩下粘不上的就以最小颗粒交付。整个过程没有任何人告诉过你什么是"单词"。

**第二层：技术流程拆解。** 训练阶段：① 准备语料并做 Unicode 标准化；② 用一段正则做**预切分**（pre-tokenization），把文本粗切成"字母串/数字串/标点串/空格串"等块，这一步至关重要——它保证后续合并永远不会跨越词边界，否则模型会学出"结尾的一个词 + 开头的下一个词"这种毫无意义的 token；③ 在每个块内部统计所有相邻符号对的频次，取最高频的一对合并为新符号，记录进有序的 merges 表；④ 重复第 ③ 步 k 次，最终词表大小 |V| = 256 + k + 特殊 token 数。推理阶段只需按 merges 表的顺序依次应用，得到确定性的切分。这里有两个常被忽略的关键参数：一是**数字编码策略**，Qwen、DeepSeek、Baichuan2、Yi 均采用 single-digit 拆分（"123" → ["1","2","3"]），代价是数字序列变长，收益是数值比较和多位数运算的泛化性显著改善；Llama 3 采用三位一组编码，短数字高效但长数字容易退化成奇怪的切法，这正是很多"小数比大小"翻车案例的底层原因。二是**词表大小的对齐**，Qwen 的 152,064 可被 256 整除、151,936 可被 128 整除，这是为了让 Embedding 矩阵的最后一维对齐 GPU 的 tensor core 分块，纯粹是硬件优化考虑。

**第三层：核心机制。** BPE 与它的两个亲戚在"选哪一对来合并"这个打分函数上分道扬镳。BPE 的准则是**纯频率**：选出现次数最多的相邻对。WordPiece（BERT 使用）改为**似然增益**：选合并后最能提升语料在 unigram 语言模型下似然的那一对，等价于按互信息 count(AB)/(count(A)×count(B)) 排序，倾向于挑"真正互相依赖"而非"单纯都很常见"的组合。Unigram（T5、Gemma 使用）方向完全相反：先构造一个超大候选词表，然后反复计算"删掉某个 token 会让语料整体损失上升多少"，剪掉影响最小的那批，直到收敛到目标大小。方向差异带来一个实用的性质：BPE 是确定性的，同一个词永远切成同一种形式；Unigram 是概率性的，同一个词存在多种切法及其概率，训练时可以随机采样不同切法作为数据增强，这就是子词正则化（subword regularization），BPE 原生做不到。SentencePiece 常被误认为是第四种算法，其实它只是一个**库**，内部既能跑 BPE 也能跑 Unigram，它真正的独特之处是不假设空格分词、直接在字节流上训练。

**▌ 动手验证**

```python
# pip install transformers
from transformers import AutoTokenizer

text_cn = "人工智能正在重塑软件工程的每一个环节。"
text_en = "Artificial intelligence is reshaping every part of software engineering."

for name in ["Qwen/Qwen2.5-7B-Instruct", "meta-llama/Llama-2-7b-hf"]:
    tok = AutoTokenizer.from_pretrained(name, trust_remote_code=True)
    n_cn, n_en = len(tok.encode(text_cn)), len(tok.encode(text_en))
    # 压缩率 = 汉字数 / token 数，越高说明中文越"便宜"
    print(f"{name:32s} 中文={n_cn:3d} 英文={n_en:3d} 中文压缩率={19/n_cn:.2f}")

# 观察数字切法差异，这直接影响数学能力
print(AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B-Instruct").tokenize("9.11 vs 9.9"))
```

预期结果：Qwen2.5 的中文 token 数明显少于 Llama 2，压缩率接近 1.5 以上；Llama 2 会把多数汉字拆成 2–3 个字节片段。注意 Llama 系列需要在 HuggingFace 上先申请授权，否则会报 401；若无网络可改用本地已下载的任意两个词表规模差异较大的模型对比。

### 2. 【RoPE与YaRN：模型靠旋转角度记住词序，又靠插值撑开上下文】

> 📍 **导语**: 注意力机制有一个反直觉的先天缺陷——它本质上是个"词袋"。把"狗咬人"和"人咬狗"喂进去，如果不额外做点什么，自注意力算出来的结果完全一样，因为加权求和天然对顺序不敏感。位置编码就是补上这块短板的零件。而在 2026 年，这个零件的重要性远超"记住词序"本身：几乎所有把上下文从 8K 撑到 128K 乃至百万 token 的方案，动的都是位置编码。你在 config.json 里见过的 `rope_scaling` 字段、社区里流传的"改一下 base 就能延长上下文"的偏方、以及 YaRN、NTK-aware、Dynamic NTK 这一串名词，全都源自同一个数学对象：旋转位置编码 RoPE。搞懂它，你才能理解为什么长上下文模型会在超出训练长度后突然"胡言乱语"，以及社区那些外推技巧到底在动什么手脚。

---

**🧠 深度解析**

**▌ 它是什么**

RoPE（Rotary Position Embedding，旋转位置编码）由苏剑林等人在 2021 年的 RoFormer 中提出，做法是：不给词向量加上一个位置向量，而是**把词向量在若干个二维平面上旋转一个与位置成正比的角度**。位置 m 的 query 转 mθ 度，位置 n 的 key 转 nθ 度，两者做内积时旋转角相减，结果只与 (m−n) 有关。于是绝对位置的编码方式，自动产生了相对位置的注意力行为。它**不是**加在输入层的一次性操作——正弦绝对位置编码只在 embedding 阶段加一次，RoPE 则在**每一层**的 q、k 上都要重新施加，它是注意力计算的一部分，而不是输入的一部分。它也**不是**"能无限外推"的银弹：RoPE 的相对性只在训练见过的角度范围内可靠，超出后模型会遇到从未见过的旋转相位，注意力分布迅速崩坏。适用边界上，RoPE 已成为 Llama、Qwen、DeepSeek、Mistral、GLM 等绝大多数开源模型的默认选择，但在需要极端长度泛化且能接受表达力损失的场景，ALiBi 这类线性偏置方案仍有一席之地。与当前热点的关联在于：2026 年的百万 token 上下文竞赛中，位置编码外推是与稀疏注意力并列的两大技术支柱之一，前者解决"位置认不认得出"，后者解决"算不算得起"。

**▌ 它解决了什么问题**

Transformer 原始论文用的是正弦绝对位置编码，把一组不同频率的 sin/cos 值加到输入向量上。问题有两个：第一，它编码的是绝对位置，而语言中大量规律是相对的——"形容词修饰它后面第一个名词"这条规则与句子起点无关，模型必须从绝对位置里费劲地反推相对关系；第二，位置信息在第一层加进去后，会随着层数加深被残差和 FFN 不断稀释。后来的可学习绝对位置编码（BERT、GPT-2 使用）表达力更强，但把最大长度写死在了参数表里，超一个 token 都不行。RoPE 的收益是三重的：相对位置天然内建、每层重新注入不会稀释、且**没有任何新增参数**。更实际的收益在长上下文上：由于 RoPE 的相对性是通过角度算出来的而非查表得到的，它给"事后延长上下文"留下了操作空间。业界的典型路径是——一个在 4K 上训练的模型，通过位置插值加上几十亿到几百亿 token 的少量续训，就能稳定工作在 32K 甚至 128K，成本相比从头用长序列预训练低一到两个数量级。今天你能用上的大部分长上下文开源模型，走的都是这条路。

**▌ 原理拆解**

**第一层：直觉理解。** 想象每个词向量被拆成很多组，每组两个数，构成一个平面上的箭头。位置越靠后，这个箭头就被逆时针多转一点。两个词做注意力时，模型实际感知到的是它们箭头之间的**夹角差**——夹角差只取决于两个词隔了多远，与它们在整句话的绝对坐标无关。更妙的是，不同组用的旋转速度不同：有的组转得飞快（高频），几个 token 就转满一圈，专门负责分辨"紧挨着"这种近距离关系；有的组转得极慢（低频），几万个 token 才转一圈，负责"这段话在文档的前半部分还是后半部分"这种粗粒度信息。整个向量就像一组不同齿比的钟表指针，共同表示位置。

**第二层：技术流程拆解。** 输入 → 算出 q、k → 对 q、k 施加旋转 → 做注意力。旋转的具体做法：把 d 维向量按相邻两维分成 d/2 组，第 i 组的旋转频率为 θᵢ = base^(−2i/d)，其中 base 通常取 10000。位置 m 处，第 i 组的两个分量 (x, y) 变成 (x·cos(mθᵢ) − y·sin(mθᵢ), x·sin(mθᵢ) + y·cos(mθᵢ))。工程实现上没人真去构造旋转矩阵，都是用两个预先算好的 cos/sin 缓存做逐元素乘加，开销可以忽略。外推方案就是在这个公式上动手脚：**位置插值 PI**（Chen 等 2023）最粗暴，把位置索引 m 整体乘以 L_train/L_target 压缩回训练区间，代价是高频分量被压得过密，短距离分辨率下降，模型对局部语序变迟钝；**NTK-aware scaling** 换个思路，不动位置索引而是放大 base，让低频转得更慢从而覆盖更长范围，同时高频几乎不受影响；**YaRN**（Peng 等 2023）则做了分频段的精细处理——按每组的波长把维度分成三档，波长远小于上下文的高频组完全不插值以保住局部分辨率，波长超过上下文的低频组按 PI 方式插值，中间档做线性混合过渡，此外还引入一个注意力温度缩放系数来补偿长序列下注意力熵的漂移。

**第三层：核心机制。** 用自然语言翻译 RoPE 的核心等式：施加旋转后的 q 与 k 的内积，等于把原始 q、k 相对旋转 (m−n)θ 之后再做内积。这一条恒等式就是 RoPE 全部魔力的来源——**用绝对位置的操作换来相对位置的效果**。理解外推失效的机制也要回到这里：训练时模型只见过 (m−n) 落在 [0, L_train) 区间的旋转相位，对低频组来说这甚至不到一整圈；推理时若 (m−n) 突然远超这个范围，低频分量进入完全陌生的相位区，注意力打分失去校准，表现为"越到后面越语无伦次"。所有外推方法的共同目标都是：让推理时的相位分布尽量落回训练时见过的区间，同时尽可能少损失近距离的分辨能力——PI 牺牲了高频，NTK 保住了高频，YaRN 则做了分频段的显式取舍。

**▌ 动手验证**

```python
import torch, math

def rope(x, pos, base=10000.0):
    """x: (seq, dim)  返回旋转后的向量"""
    d = x.shape[-1]
    idx = torch.arange(0, d, 2).float()
    theta = base ** (-idx / d)                 # 每组的旋转频率
    ang = pos[:, None] * theta[None, :]        # (seq, d/2)
    c, s = ang.cos(), ang.sin()
    x1, x2 = x[..., 0::2], x[..., 1::2]
    return torch.stack([x1 * c - x2 * s, x1 * s + x2 * c], -1).flatten(-2)

q = torch.randn(1, 64)
# 关键验证：位置(5,3)与位置(105,103)的内积应当几乎相同——只依赖相对距离
a = (rope(q, torch.tensor([5.])) * rope(q, torch.tensor([3.]))).sum()
b = (rope(q, torch.tensor([105.])) * rope(q, torch.tensor([103.]))).sum()
print(float(a), float(b))   # 两个数值应高度接近
```

预期输出两个几乎相等的浮点数，误差在 1e-5 量级，这就直接证实了"绝对旋转、相对生效"。若想验证外推，把 base 从 10000 改到 500000 再跑一遍，会看到低频组的角度显著变小。

### 3. 【稀疏注意力：把百万Token长文的单位算力成本砍到二十分之一】

> 📍 **导语**: Transformer 卡了整个行业八年的那道坎，是注意力的 O(n²) 复杂度。上下文从几百 token 涨到一百万，计算量不是涨一千倍而是涨一百万倍。过去大家还能忍，因为长文本是偶发需求；但 2026 年 Agent 成为主流形态后，一个任务动辄几十轮工具调用、几十万 token 的历史轨迹，推理成本从"阶段性支出"变成了"持续性黑洞"。于是这一年出现了一个非常明确的转向：从"把模型做大"转向"把注意力做稀疏"。MiniMax 用自研 MSA 把百万字长文的单位 token 成本压到全注意力的约二十分之一，美团 LongCat-2.0 用 LSA 在五万卡国产集群上跑通万亿参数，蚂蚁 Ling-3.0-flash 干脆从预训练第一天就用混合线性注意力。稀疏注意力已经不是论文里的可选优化，而是新一代模型的出厂配置。

---

**🧠 深度解析**

**▌ 它是什么**

稀疏注意力（Sparse Attention）指的是：不让每个 query 去看序列里的全部 key，而是按某种规则只看其中一小部分，从而把注意力的计算量和显存占用从与序列长度平方成正比，降到接近线性。规则可以是**静态**的（滑动窗口、膨胀窗口、固定的全局锚点 token），也可以是**动态**的（先用低成本方式估算哪些块最相关，再只对这些块做精确注意力）。它**不是**"丢掉一部分上下文"——被跳过的 token 通常仍以某种压缩形式参与（比如通过全局 token 中转、或被折叠进一个固定大小的状态），只是不再逐一精确比对；它也**不是**近似算法的同义词，2026 年的主流做法是把稀疏结构**从预训练阶段就写进架构**，模型是在这个结构下学出来的，而不是训练完再打补丁。适用边界要说清楚：在几千 token 的短上下文上，稀疏注意力带不来收益反而可能因为额外的索引开销更慢；它的价值随序列长度指数放大，通常要到 32K 以上才明显。历史脉络上，2019–2020 年的 Longformer、BigBird 提出了滑窗加全局 token 的静态稀疏范式；2023 年 FlashAttention 从 IO 角度把全注意力的常数项压到极低，一度让稀疏方案显得不划算；而当上下文进入百万级，平方项重新占据主导，稀疏注意力在 2026 年迎来第二春，并与 MoE、线性注意力深度融合。

**▌ 它解决了什么问题**

全注意力的账很好算：序列长度 n=1,000,000 时，注意力打分矩阵有 10¹² 个元素，即使用 FlashAttention 不显式落盘，计算量本身也是天文数字；同时 KV Cache 随长度线性增长，一个百万上下文的请求光缓存就要吃掉几十上百 GB 显存。这带来的直接后果是：长上下文要么贵得没法商用，要么首 token 延迟（TTFT）长到用户放弃。2026 年的公开数据给出了改造后的对比。MiniMax 在新一代文本模型 M3 上落地的 MSA 架构，把百万字长文本的单位 token 计算成本降至传统全注意力的约 1/20，思路类似"精准派单"，只调动最相关的少数模块。美团 7 月 6 日开源的 LongCat-2.0 总参数 1.6 万亿、平均激活约 48B，专为 Agentic Coding 设计，架构上引入 LongCat 稀疏注意力（LSA），通过流感知索引、跨层索引等策略提升百万级长上下文的训练与推理效率，并成为业界首个在五万卡国产算力集群上完成推理的万亿参数模型。蚂蚁 7 月 24 日发布的 Ling-3.0-flash 更激进，总参数 124B、激活仅 5.1B（分别约为上一代 1T 级旗舰的 12.4% 和 8.1%），从预训练伊始就采用原生混合线性注意力架构，5:1 交替堆叠 KDA 与 MLA，配合 1/64 稀疏 MoE 与 SGLang HiCache + Mooncake 分级缓存，**长输入下 TTFT 降低 60% 至 80% 以上**，能力却全方位对标甚至超越前代旗舰。

**▌ 原理拆解**

**第一层：直觉理解。** 全注意力像是开会时每个人都必须和在场的其他所有人单独交谈一遍——十个人还行，一万个人就永远开不完。稀疏注意力是给会议定规矩：你只需要和左右邻座聊（滑动窗口），加上主持人和几位关键嘉宾（全局 token），再加上会前根据议题快速筛出的三五个最相关的人（动态 Top-k）。绝大多数信息通过这几条通路依然能传到，会议时间却从平方级降回线性。而线性注意力走的是另一条路：不再逐个交谈，而是让所有人先把观点浓缩写进一块公共白板（一个固定大小的状态矩阵），后来的人只需读这块白板，无论前面来过多少人，白板大小恒定不变。

**第二层：技术流程拆解。** 以当下最主流的**块稀疏 + 动态选择**为例：① 把长度 n 的序列按 128 token 一块切成 n/128 个块；② 为每个块算一个代表向量（比如 key 的均值池化）；③ 当前 query 块用代表向量与所有历史块做一次极便宜的粗打分；④ 取分数最高的 top-k 个块，外加强制保留的滑动窗口块与序列开头的几个 sink 块；⑤ 只对这批被选中的块做精确的 FlashAttention 计算。关键参数是块大小与 k：块太小索引开销大、块太大召回粒度粗；k 太小会漏掉关键信息、k 太大退化回全注意力。LongCat 的"跨层索引"是一个重要工程细节——相邻层选出的块高度重合，因此不必每层重算索引，可以跨层复用，把索引成本再摊薄。而混合架构如 Ling-3.0-flash 的 5:1 堆叠，则是让五层廉价的线性注意力（KDA，带细粒度对角门控）负责承载长程主干信息，每六层插入一层 MLA 全注意力来做精确的信息召回，兼顾成本与精度。

**第三层：核心机制。** 稀疏注意力真正的设计权衡不在"省多少算力"，而在**信息路径长度**。全注意力的任意两个 token 之间路径长度恒为 1，稀疏结构一旦破坏这一点，远距离信息就需要多跳中转，训练时梯度传递变难。所以静态方案必须保留全局 token（提供 1 跳中转站）与 attention sink（模型天然会把大量注意力质量倾泻在序列开头的少数 token 上，砍掉它们会导致注意力分布崩溃）。线性注意力则用另一种代价换取 O(1) 的 KV：ICLR 2026 一篇状态转移框架的工作（arXiv:2602.01198）指出，一条长 CoT 里真正有用的是"结论性"信息，语法和措辞占了绝大多数 token；于是它把已完成的推理步压进一个固定大小的状态矩阵 S，当前步只需一次 o = q·S 就能取回全部历史，把注意力复杂度从 O(C²) 降到 O(C)、KV cache 从 O(C) 降到 O(1)，代价是历史信息被有损压缩，因此需要额外的动量策略来纠偏。

**▌ 动手验证**

```python
# 需要 PyTorch >= 2.5，FlexAttention 可把任意 mask 编译成块稀疏 kernel
import torch
from torch.nn.attention.flex_attention import flex_attention, create_block_mask

W, SINK = 512, 4          # 滑动窗口宽度 / 保留的开头 sink token 数
def sliding_sink(b, h, q_idx, kv_idx):
    causal = q_idx >= kv_idx
    return causal & ((q_idx - kv_idx < W) | (kv_idx < SINK))

S = 8192
mask = create_block_mask(sliding_sink, B=None, H=None, Q_LEN=S, KV_LEN=S)
q, k, v = (torch.randn(1, 8, S, 64, device="cuda", dtype=torch.bfloat16) for _ in range(3))
out = flex_attention(q, k, v, block_mask=mask)   # 只计算被 mask 命中的块
print(out.shape, f"稀疏度≈{1 - mask.sparsity()/100:.2%}")
```

预期：输出形状与全注意力一致，但实际参与计算的块只占很小比例，序列越长节省越明显。注意 FlexAttention 需要 CUDA 且首次调用会触发 torch.compile 编译，耗时较长属正常现象；CPU 环境请把 device 改为 "cpu" 并缩小 S 以避免超时。

### 4. 【Flow Matching与整流流：把50步扩散采样拉直成4步直线】

> 📍 **导语**: 如果你在 2023 年用过 Stable Diffusion，一定记得那个进度条——生成一张图要跑 50 步去噪，等上十几秒。而今天 FLUX、SD3 这类模型能在几步之内出图，质量还更好。很多人以为这只是"蒸馏"或"更好的采样器"，其实底层换了一整套数学框架：从随机微分方程（SDE）换成了常微分方程（ODE），从"预测噪声"换成了"预测速度"。这套框架叫 Flow Matching（流匹配），配上 Rectified Flow（整流流）的路径拉直技巧，把生成过程从一条在高维空间里蜿蜒摸索的曲线，改造成一条近乎笔直的高速公路。理解它，不仅是理解图像生成，更是理解 2026 年语音、视频、蛋白质结构乃至机器人动作生成为何集体倒向同一条技术路线。

---

**🧠 深度解析**

**▌ 它是什么**

Flow Matching 是一类生成模型的训练框架：它学习一个随时间变化的**速度场** v_θ(x, t)，让样本点沿着这个速度场从简单分布（通常是标准高斯噪声）连续流动到数据分布。生成时只需给定一个噪声起点，用 ODE 求解器沿速度场积分到终点即可。它**不是**扩散模型的竞争对手那么简单——两者在数学上高度相通，扩散模型的 probability flow ODE 形式可以视作 Flow Matching 的一个特例；真正的区别在于 Flow Matching 允许你**自由设计从噪声到数据的路径**，而扩散模型的路径被噪声调度（noise schedule）绑死。它也**不是**"少步数"的同义词：路径是否好走取决于你选的插值方式，只有选择了最优传输意义下的直线路径（并可选地用 reflow 进一步拉直），少步采样才成立。适用边界上，Flow Matching 在连续数据（图像、音频、视频、分子坐标）上表现极佳，在离散数据（文本）上需要额外设计。历史脉络：2022 年 Lipman 等提出 Flow Matching，同年 Liu 等独立提出 Rectified Flow，两条线殊途同归；2024 年 Stable Diffusion 3 与 FLUX.1 把它推向工业界主流，FLUX.1-dev 用 12B 参数的 Diffusion Transformer 配合流匹配，取代了此前的 U-Net + DDPM 组合。

**▌ 它解决了什么问题**

DDPM 时代有三个痛点。第一是**慢**：反向 SDE 每一步都注入随机噪声，轨迹高度曲折，必须用极小的步长才能跟住，典型需要 50 到 1000 步，一张图十几秒起步。第二是**噪声调度玄学**：βₜ 怎么设、用 cosine 还是 linear、要不要 v-prediction，这些超参对结果影响巨大却缺乏原理指引，换个分辨率就要重调。第三是**理论偏差**：前向加噪过程在有限步后并不严格等于标准高斯，反向过程从一个"不完全正确"的先验出发，引入了系统性偏差。Flow Matching 把这三点一并解决：训练目标退化成一个极其朴素的均方误差——预测的速度场要逼近"终点减起点"这个向量；没有噪声调度需要调，时间 t 在 [0,1] 上均匀采样即可；起点严格就是标准高斯，无偏差。收益是量化的：DDPM 需要 50–1000 步，普通 Flow Matching 只需 10–50 步，推理提速 2–10 倍；而经过 reflow 拉直的整流流模型，公开资料显示只需 4 到 8 步即可产出高质量图像。这就是为什么今天的图生图、实时视频生成能做到接近交互式的响应速度。

**▌ 原理拆解**

**第一层：直觉理解。** 想象一片撒满沙粒的桌面，沙粒按标准高斯分布散开，你要把它们推成一幅蒙娜丽莎的形状。扩散模型的做法像是让每颗沙粒做随机游走，每一步都掷骰子决定往哪挪一点点，靠成千上万次微小的随机纠偏最终成型——走的是布朗运动式的曲折路径。Flow Matching 则是先规定好每颗沙粒的**目的地**，然后在桌面上建立一个风场：任何时刻站在任何位置的沙粒，只要顺着当地的风走，就能准时抵达。既然是直线运输，你完全可以只在中途停 4 次而不是 50 次。

**第二层：技术流程拆解。** 训练：① 从数据集采一个真实样本 x₁，从高斯采一个噪声 x₀；② 从 [0,1] 均匀采一个时间 t；③ 用线性插值构造中间点 xₜ = (1−t)·x₀ + t·x₁；④ 该点上的**条件速度**就是 x₁ − x₀（对线性路径求导，是个常量）；⑤ 让网络吃进 (xₜ, t)，输出预测速度，与 x₁ − x₀ 做 MSE。整个训练循环没有任何噪声调度参数。采样：① 从标准高斯采 x₀；② 用 Euler 法迭代 x ← x + Δt·v_θ(x, t)，跑 N 步到 t=1；③ 想要更少步数更高质量，可换二阶的 Heun 求解器，每步多算一次速度取平均，用 20 步达到 Euler 50 步的效果。工程上还有一个关键：文生图场景要在速度场网络里通过 cross-attention 注入文本条件，SD3 与 FLUX 都用 DiT（Diffusion Transformer）替代 U-Net 来承载这个网络。

**第三层：核心机制。** 有两个关键点需要用自然语言翻译。其一是**条件流匹配（CFM）为什么成立**。理想目标是让网络拟合"边缘速度场"，但那个东西需要对全体数据求期望，根本算不出来。CFM 的洞见是：如果改为拟合"给定一对 (x₀, x₁) 的条件速度场"，两个损失函数的梯度完全相同，只差一个与参数无关的常数。也就是说，网络虽然每次只看到一对样本的连线方向，充分训练后学到的却正好是那个不可计算的边缘速度场——这一条等价性是整个方法能落地的理论基石。其二是 **reflow 为什么能拉直路径**。虽然每一对 (x₀, x₁) 的条件路径是直线，但不同样本对的连线会在空间中交叉，网络在交叉点只能输出平均方向，于是学到的边缘轨迹依然是弯的。Rectified Flow 的做法是：用训练好的模型跑一遍完整采样，得到大量"噪声—生成结果"的**配对**，再用这些新配对重训一个流模型。由于配对来自同一条 ODE 轨迹，它们天然不交叉，新模型的路径曲率显著下降；重复一两轮后路径接近直线，此时用极少的积分步数也不会累积明显误差。

**▌ 动手验证**

```python
import torch, torch.nn as nn
# 玩具实验：把二维高斯流成一个圆环
net = nn.Sequential(nn.Linear(3, 128), nn.SiLU(), nn.Linear(128, 128), nn.SiLU(), nn.Linear(128, 2))
opt = torch.optim.Adam(net.parameters(), 1e-3)

def sample_ring(n):
    a = torch.rand(n) * 6.2832
    return torch.stack([a.cos(), a.sin()], 1) * 2.0

for step in range(3000):
    x1 = sample_ring(512)                      # 数据
    x0 = torch.randn_like(x1)                  # 噪声
    t = torch.rand(512, 1)
    xt = (1 - t) * x0 + t * x1                 # 线性插值路径
    loss = ((net(torch.cat([xt, t], 1)) - (x1 - x0)) ** 2).mean()  # 目标=终点减起点
    opt.zero_grad(); loss.backward(); opt.step()

x = torch.randn(1000, 2)                       # 采样：Euler 积分，只用 8 步
for i in range(8):
    t = torch.full((1000, 1), i / 8)
    x = x + (1 / 8) * net(torch.cat([x, t], 1))
print(x.norm(dim=1).mean())                    # 应接近 2.0，说明点落到了半径为2的圆环上
```

预期输出接近 2.0（误差 0.1 以内）。注意即使只用 8 步 Euler 积分也能收敛，这正是直线路径的价值；若把插值改成扩散式的曲线调度，同样 8 步会明显发散。

**▌ 对比选型**

| 对比维度 | Flow Matching | DDPM 扩散 | Rectified Flow |
|---------|--------------|----------|---------------|
| 核心方程 | ODE，预测速度 | SDE，预测噪声 | ODE + reflow 拉直 |
| 典型步数 | 10–50 步 | 50–1000 步 | 4–8 步 |
| 调参负担 | 无噪声调度 | βₜ 调度敏感 | 多一轮重训成本 |
| 生态成熟度 | SD3/FLUX 主流 | 存量模型最多 | 蒸馏加速首选 |

### 5. 【有效阶ED：给神经网络的简单性偏置装上一把可优化的标尺】

> 📍 **导语**: 我们有几百个 benchmark 能告诉你一个模型答得准不准，却几乎没有工具能回答一个更根本的问题：它到底学到了可迁移的规律，还是用一种极其复杂的方式"背下"了训练数据？这个区别在刷榜时看不出来，在模型遇到分布外场景时会瞬间暴露。深度学习理论界几十年来有一个共识性猜想——神经网络之所以能泛化，是因为它天然偏好"简单"的解，这被称为简单性偏置（simplicity bias）。但"简单"长期停留在哲学层面，无法计算、无法比较、更无法优化。2026 年 8 月 6 日，千诀科技联合清华大学团队公开的"有效阶"（Effective Degree, ED）把这个抽象概念第一次变成了可以在真实规模模型上算出来的数字，而且能直接写进损失函数参与训练。更耐人寻味的是，图灵奖得主 Yann LeCun 团队今年 5 月关于世界模型的论文，与这条研究路线在方法论上高度呼应。

---

**🧠 深度解析**

**▌ 它是什么**

有效阶 ED 是一个刻画"神经网络所实现的函数有多复杂"的标量指标，其核心思路是把网络在输入空间上实现的函数，投影到一组**正交函数基**上做谱分解，再看能量分布在低阶项还是高阶项上。低阶项占主导 → 函数接近线性或低次多项式 → 简单；高阶项占主导 → 函数高度非线性、锯齿密布 → 复杂。它**不是**参数量、也不是权重范数这类"模型有多大"的度量——一个 700 亿参数的模型完全可以实现一个极其平滑的低阶函数，而一个小 MLP 也可以拟合出高频抖动的复杂映射；ED 度量的是**行为复杂度**而非**容量**。它也**不是**纯理论玩具：论文的关键突破正在于把这个指标做到可在真实规模模型上计算、比较，并作为正则项直接参与训练。适用边界上，ED 面向"泛化能力诊断"这类问题——筛选预训练模型、判断微调是否过拟合、评估模型在新数据新环境下的稳健性；它不告诉你模型在某个具体任务上的分数，也不能替代常规评测。历史脉络上，简单性偏置的思想可上溯到 Occam 剃刀与最小描述长度原则，深度学习时代则有频率原则（F-Principle，网络优先拟合低频分量）等经验发现，但一直缺少一个能在大模型上落地的可计算量。

**▌ 它解决了什么问题**

在 ED 之前，判断"这个模型学到了规律还是背了答案"，工程上只有间接手段：留出集分数、分布外测试集、对抗样本鲁棒性。这些方法的共同问题是**依赖于你恰好准备了对的测试集**——如果测试集与训练集同分布，背答案的模型照样满分；如果你没想到某类分布偏移，就永远发现不了问题。ED 提供的是一个**不依赖测试集的内在度量**：直接看函数本身长什么样。这带来三类实际用途。其一，筛选预训练模型：面对多个候选 backbone，在下游数据都还没标注的阶段就能比较它们的函数复杂度，倾向选择在同等训练损失下 ED 更低的那个。其二，诊断微调过拟合：微调过程中如果训练损失在降、ED 却在快速攀升，这是模型正在用高阶震荡去拟合噪声的明确信号，比等验证集掉点更早预警。其三，直接参与训练：把 ED 作为正则项加进损失，主动压制高阶分量，据报道该方法有望改善视觉、语言、强化学习以及世界模型在面对新数据、新环境时的表现。研究团队所在的路线还有一个值得注意的时间线细节：清华大学自动化系陈峰教授与千诀科技的联合团队（第一作者章天任）在 ICML 2025 论文《When Do Neural Networks Learn World Models?》中就已采用了相近的方法论视角，比 LeCun 团队 2026 年 5 月的《When Does LeJEPA Learn a World Model?》约早一年。

**▌ 原理拆解**

**第一层：直觉理解。** 想象你要描述一条穿过一堆散点的曲线。你可以用一条直线（一阶），也可以用抛物线（二阶），还可以用一条穿过每一个点、上下剧烈抖动的一百阶多项式。三条曲线在训练点上的误差可能后者最小，但只要来一个新点，一百阶那条大概率错得离谱。"有效阶"就是在问：如果把神经网络看成这样一条曲线，它实质上相当于几阶？关键词是"实质上"——网络的参数量可能对应到极高的阶数上限，但真正被用起来的阶数往往低得多，这个"真正被用起来的阶数"就是 ED。

**第二层：技术流程拆解。** 做法可以概括为四步：① **选基**——挑一组与输入空间匹配的正交函数基。离散布尔型输入用 Fourier-Walsh 基（即 Walsh-Hadamard 变换），此时"阶"就是每个基函数依赖的输入比特个数；连续高斯型输入用 Hermite 多项式基，"阶"就是多项式次数。② **投影**——把网络函数在这组基上展开，得到每个基函数的系数。真实规模模型不可能穷举全部基，实践中用蒙特卡洛采样估计各阶能量。③ **聚合**——按阶数把系数平方求和得到能量谱，再用能量加权平均等方式压成一个标量，就是 ED。④ **优化**——把这个标量当作可微的正则项加进损失反向传播，或者只作为监控指标记录。整套流程的关键工程参数是采样规模与阶数截断点：采样太少方差大，截断太低会漏掉真正的高阶行为。

**第三层：核心机制。** 这里最值得体会的是两个团队用不同数学工具得到的相同结论。千诀-清华团队研究多任务学习设定下具有低阶偏好的网络，用 Fourier-Walsh 变换分析离散布尔世界；LeCun 与 Klindt、Balestriero 研究 LeJEPA 与带平稳动力学的高斯世界，用 Hermite 多项式做谱分解，其结论是：非线性阶数越高的分量，在 LeJEPA 的 alignment 目标下受到的惩罚越强，因此"线性恢复真实隐变量"成为最优解。两者共同指向的洞见是——**把"学习世界模型"形式化为对数据生成隐变量的恢复（可辨识性）问题**，而网络在解空间中的低阶偏置，正是让真实隐变量变得可辨识的关键机制。换句话说，模型之所以能学到世界的结构而不是数据的表象，不是因为它足够强大，恰恰是因为它足够"懒"——优化过程天然优先选择低阶解，而低阶解在合适的条件下唯一对应着真实的生成因子。ED 的价值就在于把这个"懒"的程度变成了一个可以测量和调节的旋钮。

**▌ 动手验证**

```python
import numpy as np
from scipy.linalg import hadamard

# 玩具实验：对一个布尔函数做 Fourier-Walsh 分解，看能量落在几阶
n = 10                                   # 10 个输入比特，共 1024 种输入
H = hadamard(2 ** n) / (2 ** (n / 2))    # 正交化的 Walsh-Hadamard 变换矩阵

X = ((np.arange(2 ** n)[:, None] >> np.arange(n)) & 1)     # 枚举全部输入
f_low  = (X[:, 0] ^ X[:, 1]).astype(float)                 # 2 阶函数（依赖2个比特）
f_high = X.sum(1) % 2                                      # 10 阶奇偶函数（依赖全部比特）

order = X.sum(1)                                           # 每个基函数的阶数
for name, f in [("低阶XOR", f_low), ("高阶奇偶", f_high)]:
    coef = H @ (1 - 2 * f)                                 # 映射到 ±1 后做变换
    energy = coef ** 2 / (coef ** 2).sum()
    print(f"{name}: 有效阶 = {(energy * order).sum():.2f}")
```

预期输出：低阶 XOR 的有效阶约为 2.00，高阶奇偶函数约为 10.00，与理论完全吻合。把 `f` 换成一个小 MLP 在这 1024 个点上的输出，就能观察训练过程中有效阶如何随过拟合而抬升。注意 `hadamard` 要求维度是 2 的幂，n 不要超过 16 否则内存吃紧。

| 对比维度 | 有效阶 ED | 参数量 / 权重范数 | VC维、Rademacher |
|---------|----------|-----------------|----------------|
| 度量对象 | 函数行为复杂度 | 模型容量 | 假设空间容量 |
| 大模型可算 | 可采样估计 | 直接可得 | 通常不可算 |
| 能否参与训练 | 可作正则项 | 可（权重衰减） | 否 |

### 6. 【RLVR训练预算分配：用树形rollout把有效样本比例从27%拉到61%】

> 📍 **导语**: 强化学习后训练已经成为提升大模型推理能力的主干路线，但它有一个很少被摆到台面上的尴尬：绝大部分算力是白烧的。用 GRPO 训练时，你为每个 prompt 采样一组回答，如果这一组全对或者全错，组内优势归一化后全是零，梯度贡献为零——这次 rollout 的钱等于扔进了水里。在 Agentic 场景下这个浪费被急剧放大，因为一条轨迹意味着模型要反复思考、调用工具、接收环境反馈，单次成本高出数量级。2026 年清华与腾讯混元团队的两项工作给出了同一个思路的两种解法：既然预算有限，就别再平均撒胡椒面，把钱花在最可能产生学习信号的地方。TRACE 用树形分配把 Qwen3-8B 数学任务的有效样本比例从 26.8% 拉到 60.6%，GPS 则用一个小模型预判难度，最多砍掉 69% 的 rollout 成本。

---

**🧠 深度解析**

**▌ 它是什么**

RLVR（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）指的是这样一类后训练方法：不训练主观的奖励模型，而是用可自动判定对错的信号（数学答案是否正确、代码是否通过测试、工具调用是否达成目标）作为奖励来做策略优化。**训练预算分配**则是 RLVR 之上的一层调度问题——在总 rollout 数固定的前提下，决定"哪些 prompt 值得采、每个采几条、从哪个中间状态开始采"。它**不是**算法层面的优化器改进，不动损失函数也不动策略梯度公式，动的是**数据侧的采样策略**，因此可以叠加在 GRPO、PPO、DAPO 等任何算法之上。它也**不是**课程学习的翻版：课程学习关心的是"按什么顺序喂样本"，预算分配关心的是"在当前这一步把有限的采样次数投给谁"，且决策是在线的、随模型能力动态变化的。适用边界上，它的收益与"零梯度样本占比"正相关——如果你的任务难度分布本来就集中在模型的能力边缘，收益有限；如果数据集里混杂了大量过易或过难的题目（这是常态），收益会非常显著。与当前热点的关联在于：2026 年 RL 后训练的算力开销已经逼近甚至超过预训练的某些阶段，任何能省下一半 rollout 的方法都是真金白银。

**▌ 它解决了什么问题**

先看没有预算分配时会发生什么。GRPO 的做法是对每个 prompt 采 G 条回答，用组内奖励的均值和标准差把奖励归一化成优势值。这套设计的软肋在于：当 G 条全部答对，每条的优势都是 0；全部答错，同样全是 0。这类样本在训练日志里看起来"跑了"，但对参数更新毫无贡献。实践中随着模型变强，简单题的全对率快速上升，无效样本占比一路走高，训练后期经常出现七成以上的算力打水漂。清华与腾讯混元团队提出的 **TRACE**（Tree Rollout Allocation for Contrastive Exploration）不再把 rollout 预算平均撒到每个 prompt 上，而是把 Agent 轨迹看成一棵树，主动把预算分配给那些最可能产生"成功/失败对比"的 prompt 根节点和中间前缀节点。实验数据很直接：在 Qwen3-14B 的 Multi-Hop QA 任务上，平均准确率从 GRPO 的 51.2 提升到 54.0；在 Qwen3-8B 的数学任务上，**有效样本比例从 26.8% 提升到 60.6%**——同样的算力，产生学习信号的样本翻了一倍多。另一项发表于 ICML 2026 的工作 **GPS**（Generalizable Predictive Prompt Selection）走的是预测路线：先训练一个小型预测模型，让它预测不同 prompt 在当前模型下的难度，再综合难度与多样性来选训练样本。相比随机采样，训练步数加速达到 1.4–2.0 倍；相比那些需要先真实评估一遍才能选题的基线方法，GPS 最多减少 69% 的 rollout 成本，训练时间减少 28%–47%，而且学到的预测模型还能复用到测试时的计算分配上。

**▌ 原理拆解**

**第一层：直觉理解。** 想象一位老师给学生出练习题，每道题只能批改固定次数。如果他把次数平均分给所有题，那些学生闭着眼都能做对的送分题、和远超学生水平的竞赛题，批改多少遍都学不到东西。聪明的老师会把批改次数集中在"学生有时对、有时错"的那批题上——因为只有对错并存，才能通过对比看出到底哪一步走岔了。TRACE 更进一步：它发现同一道题的不同解法在前几步往往是相同的，真正分岔发生在中间某一步。与其从头重做十遍，不如在那个分岔点上多试几次，这样既省了前缀的重复计算，又精准地把对比集中在真正决定成败的位置。

**第二层：技术流程拆解。** TRACE 的流程可概括为：① 对候选 prompt 先做少量试采，估计其成功率；② 把每条 Agent 轨迹按步骤展开成树，根节点是 prompt，中间节点是"已执行了前 k 步"的状态；③ 为每个节点估算一个"对比价值"，成功率越接近 0.5 的节点价值越高，因为从这里继续采样最可能同时得到成功和失败两种结局；④ 按价值排序，把剩余 rollout 预算优先投给高价值节点，从该节点的前缀继续采样而非从头重跑；⑤ 用得到的成功/失败对比计算优势并更新策略。GPS 的流程更轻量：① 收集一批 (prompt, 当前模型表现) 数据；② 训练一个小型难度预测器；③ 每轮训练前用它对候选池打分，按预测难度落在中等区间、且彼此多样的原则选出本轮样本；④ 训练若干步后用新的真实反馈刷新预测器。两者的关键参数分别是"节点价值阈值与树的展开深度"和"预测器更新频率与多样性权重"。

**第三层：核心机制。** 底层只有一句话：**梯度信号的信息量正比于结果的方差**。对二元奖励而言，一组 rollout 的方差是 p(1−p)，在 p=0.5 时取最大值、在 p 趋于 0 或 1 时归零。所以最优的预算分配策略必然是把采样集中在成功率接近一半的地方。这与主动学习里"选不确定性最高的样本标注"、以及课程学习里"最近发展区"的思想同源，只是被放到了 RL 的 rollout 预算这个具体约束下。TRACE 的额外贡献在于把这个原则从 prompt 粒度**下沉到轨迹前缀粒度**——一个 prompt 整体成功率可能是 0.9 看似没价值，但它内部某个中间状态的后续成功率恰好是 0.5，那里才是真正的信息富矿。GPS 的贡献则在于把"估算成功率"这件事本身的成本也省了：与其花 rollout 去试，不如训一个便宜的模型来猜，猜得够准就等于白拿一半预算。

**▌ 动手验证**

```python
import numpy as np
rng = np.random.default_rng(0)

# 模拟：100 个 prompt，成功率从 0 到 1 均匀分布；每个 prompt 采 G=8 条
P = rng.uniform(0, 1, 100)
G = 8

def effective_ratio(probs, g):
    """一组全对或全错 -> 组内优势全为 0 -> 无效样本"""
    r = rng.random((len(probs), g)) < probs[:, None]
    s = r.sum(1)
    return ((s > 0) & (s < g)).mean()

print("均匀分配   有效样本比例:", f"{effective_ratio(P, G):.1%}")

# TRACE 思路：优先把预算投给成功率接近 0.5 的节点
value = P * (1 - P)                       # 对比价值 = 方差
picked = P[np.argsort(-value)[:40]]       # 只选价值最高的 40 个
print("按方差选题 有效样本比例:", f"{effective_ratio(picked, G):.1%}")
```

预期输出：均匀分配下有效样本比例约 55%–60%（因为这里成功率是均匀分布的理想情形），按方差选题后可升到 95% 以上。真实训练中成功率分布高度偏斜（大量趋近 0 或 1），均匀分配的有效比例会低得多，这也正是论文里 26.8% 这个数字的由来。把 `P` 改成 `rng.beta(0.3, 0.3, 100)` 模拟两极分化分布，差距会更明显。

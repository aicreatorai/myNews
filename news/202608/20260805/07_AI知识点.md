### 1. 【线性注意力与混合架构：把Transformer的二次方成本压成线性】

> 📍 **导语**（80-100字）: 上下文越长，标准注意力越吃不消——序列翻十倍，注意力的计算量翻一百倍。2025 到 2026 年，MiniMax-01、Qwen3-Next、NVIDIA Nemotron-H 这批主力模型不约而同做了同一件事：把大部分层换成线性注意力或状态空间模块，只保留少量全注意力层兜底。混合架构从论文走进旗舰模型，成为今年长上下文降本最确定的一条工程路线。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
线性注意力是一类把 softmax(QKᵀ)V 的计算顺序改掉的注意力变体。标准注意力先算 QKᵀ 得到一个 n×n 的分数矩阵，代价随序列长度平方增长；线性注意力用核函数近似替掉 softmax，先算 KᵀV 得到一个 d×d 的固定状态矩阵，再与 Q 相乘，代价降为一次方。它不是"标准注意力的廉价平替"，纯线性模型在需要精确检索的任务上明显吃亏——大海捞针、逐字复制长串 ID、多跳指代消解，都是它的失分区，这也正是它的适用边界。历史脉络上，从 2020 年的 Linear Transformer、Performer，到 RWKV、RetNet，再到 2023 年 Mamba 用选择性状态空间重做一遍，2024 年 Mamba-2 从数学上证明线性注意力与状态空间模型本属同一族，混合架构才最终成为工业界共同答案。

**▌ 它解决了什么问题？**（120-180字）
**Before**：128K 上下文下，注意力的 KV Cache 与分数矩阵吃掉大部分显存，prefill 阶段注意力算子的耗时占比常常过半，服务商只能靠限流和高价消化长文档请求。**After**：线性层的状态大小固定，与序列长度无关，百万 token 推理的显存不再爆炸。MiniMax-01（4560 亿参数 MoE，每 7 层线性注意力配 1 层 softmax 注意力）把训练上下文推到 100 万 token、推理外推到 400 万；阿里 Qwen3-Next-80B-A3B 采用 3:1 的 Gated DeltaNet 与门控注意力混合，官方给出 32K 以上长上下文吞吐提升约 10 倍；NVIDIA Nemotron-H 只保留约 8% 的注意力层，56B 模型的推理吞吐达到同规模纯 Transformer 的约 3 倍。

**▌ 核心原理三阶拆解**（350-500字）

**第一层：直觉理解。** 标准注意力像每写一个字都要把之前所有笔记从头翻一遍，越写越慢；线性注意力像随身带一块固定大小的记事板，每读一句就把要点更新上去，写新字只看记事板，速度恒定，代价是板子容量有限，细节会被后来的内容覆盖掉。

**第二层：技术流程拆解。** 输入序列 → 每个 token 算出 Q、K、V → 用特征映射 φ 处理 Q 与 K（常用 elu(x)+1 保证非负） → 顺序维护状态 S ← S + φ(kᵢ)vᵢᵀ 与归一化项 z ← z + φ(kᵢ) → 输出 oᵢ = φ(qᵢ)ᵀS ÷ (φ(qᵢ)ᵀz)。训练时不必真的逐 token 扫描，而是走分块并行：块内用二次方注意力保证 GPU 并行度，块间只传递一个状态矩阵，兼顾速度与显存。Mamba 系与 DeltaNet 系在此之上加了门控：S ← αᵢS + βᵢkᵢvᵢᵀ，让状态能按内容主动遗忘旧信息。

**第三层：公式与核心机制。** 关键是认清一件事——注意力本质上就是"一个随序列演化的状态"。softmax 注意力的状态是全部 KV，容量随 n 线性增长，所以能精确回忆任意历史位置；线性注意力把状态压缩成常数大小的 d×d 矩阵，容量固定，信息损失是数学上的必然，不是实现不好。混合架构就是拿这个取舍做工程折中：每隔几层插一层全注意力或滑窗注意力承担精确检索，其余层交给线性模块做上下文的平滑聚合。DeltaNet 的改进在于把状态更新写成 delta 规则——先擦掉旧键的关联再写入新值，而不是无脑累加，这显著提升了长序列上的关联记忆能力。

**▌ 动手验证**（100-150字）
用几行 PyTorch 感受状态矩阵与序列长度无关：

```python
import torch
def linear_attn(q, k, v):                        # q,k,v: [n, d]
    phi = lambda x: torch.nn.functional.elu(x) + 1   # 非负核，替代softmax
    q, k = phi(q), phi(k)
    S = torch.einsum('nd,ne->de', k, v)          # 状态矩阵 d×d，与 n 无关
    z = k.sum(0)                                 # 归一化项
    return (q @ S) / (q @ z).unsqueeze(-1)
n, d = 4096, 64
q, k, v = (torch.randn(n, d) for _ in range(3))
print(linear_attn(q, k, v).shape)                # torch.Size([4096, 64])
```
注意：这是非因果版本才能一次算完；因果版本必须用 cumsum 或分块扫描，否则会偷看未来 token。生产环境建议直接用 flash-linear-attention 库的分块内核。

**▌ 对比与选型**（必填表格）
| 对比维度 | 线性/混合注意力 | 标准Softmax注意力 | 滑窗注意力 |
|---------|--------|-------|---------|
| 核心思想 | 固定状态递推 | 全对全打分 | 只看邻近窗口 |
| 时间复杂度 | O(n) | O(n²) | O(n·w) |
| 精确检索 | 靠混合层补 | 强 | 窗口外丢失 |
| KV显存 | 常数状态 | 随n线性增长 | 窗口内常数 |
| 生态成熟度 | 2026快速上量 | 事实标准 | 广泛使用 |

### 2. 【扩散语言模型dLLM：让文本像图像一样并行去噪生成】

> 📍 **导语**（80-100字）: 一次只吐一个 token，是所有主流大模型的生成方式，也是延迟的根源。扩散语言模型换了一条路：先把整段文本打成掩码噪声，再并行"去噪"若干轮，每轮同时确定多个词。2025 年 LLaDA 首次证明 8B 规模的扩散模型能与 LLaMA3-8B 掰手腕，Gemini Diffusion 与 Mercury 把速度推到每秒上千 token，2026 年它已是最被看好的替代范式。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
扩散语言模型是把图像扩散的"加噪—去噪"思路搬到离散文本上的生成模型。训练时随机把一部分 token 替换成掩码符，让模型一次性预测所有被掩位置；推理时从全掩码序列出发反复迭代，每轮把置信度高的位置"定稿"、其余重新掩上，若干轮后得到完整文本。它不是 BERT 那样的掩码语言模型——BERT 的掩码比例固定且只服务于理解任务，dLLM 的掩码比例在 0 到 1 之间连续采样，并有完整的似然下界推导，因此能做纯生成。它也不等于"更快的大模型"，因为迭代轮数与生成质量直接挂钩，砍轮数就是在拿质量换速度。适用边界很清楚：结构化输出、代码填空、可控编辑、低延迟交互占优；超长上下文与流式输出仍是短板。历史脉络是 Diffusion-LM（2022）、D3PM 离散扩散、SEDD 分数熵，直到 LLaDA 把规模推到 8B 并做出指令微调版本。

**▌ 它解决了什么问题？**（120-180字）
**Before**：自回归解码严格串行，生成 1000 个 token 就要做 1000 次前向，GPU 大部分时间在等显存搬运，单请求速度被内存带宽死死锁住；更麻烦的是"一步错、步步错"，模型无法回头修改已经写出的词。**After**：dLLM 每轮可同时确定几十个 token，且后续轮次能覆写前面填错的位置。Inception Labs 的 Mercury Coder 在 H100 上报告超过 1000 tokens/s 的生成速度，约为同档自回归模型的 5–10 倍；Google 在 2025 年 I/O 上演示的 Gemini Diffusion 报告平均 1479 tokens/s、首 token 延迟约 0.8 秒。质量上，LLaDA-8B 在 MMLU、GSM8K 等基准与 LLaMA3-8B 处于同一水平，并在"逆向诗句补全"这类反转任务上超过 GPT-4o，说明它天然绕开了自回归的单向诅咒。

**▌ 核心原理三阶拆解**（350-500字）

**第一层：直觉理解。** 自回归像用打字机逐字敲，敲错了不能改；扩散像雕塑家先摆出一块粗坯，再一遍遍打磨，每轮把最确定的部分定下来，模糊的部分留到下一轮继续修，整体轮廓从一开始就在。

**第二层：技术流程拆解。** 输入提示词加一串掩码符 → 模型一次前向输出每个掩码位置的词分布 → 按重掩策略保留一部分预测、把其余位置重新掩码 → 重复 T 轮 → 输出全文。关键参数有三个：生成长度 L、迭代步数 T、重掩策略。重掩策略主流有三种：低置信度重掩（保留概率最高的若干位置）、随机重掩、以及半自回归分块（把序列切成块，块内并行、块间从左到右）。T 等于 L 时退化成逐位确定，等价于一个慢速自回归；T 越小越快但质量下降，工程上 T 取 L/4 到 L/8 是常见折中。

**第三层：公式与核心机制。** 训练目标是负对数似然的一个上界：随机采样掩码比例 t∈(0,1]，把被掩位置的交叉熵求和后除以 t，再对 t 取期望。"除以 t"这一步是全部数学的关键——它把不同噪声水平下的损失重新加权，使目标成为真正的似然下界，而不是 BERT 那种固定比例的判别式训练，这也是 dLLM 能做生成而 BERT 不能的根本原因。两个核心设计决策：一是使用双向注意力、没有因果掩码，模型天然能利用右侧上下文，但代价是无法直接复用 KV Cache，工程上要靠块级缓存近似弥补；二是重掩策略决定了并行度与质量的平衡点，半自回归分块目前被证明最稳，因为它既保留了块内并行，又维持了整体的从左到右一致性。

### 3. 【RLVR可验证奖励强化学习：用自动判分把推理能力练出来】

> 📍 **导语**（80-100字）: 2025 年起推理模型能力暴涨，关键不是更多人类偏好标注，而是把奖励换成一台能自动判分的机器——数学答案对不对、代码测试过不过。这就是 RLVR（可验证奖励强化学习）。DeepSeek-R1 用它证明纯 RL 就能让长思维链自发涌现，Tulu 3、ProRL 把配方开源，2026 年它已是后训练的默认组件，也是 Agent 训练的地基。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
RLVR 指用"可程序化验证的结果"作为奖励信号做强化学习后训练。奖励不来自一个训练出来的偏好打分模型，而来自一个确定性的验证器：数学题比对标准答案，代码跑单元测试，格式检查用正则匹配，通过给 1、不通过给 0。它不是 RLHF 换个名字——RLHF 的奖励来自人类偏好数据训练的奖励模型，主观且可被套利；RLVR 的奖励客观、不可被"讨好"。它也不是万能钥匙：只适用于答案能被自动判定的领域，写作、共情、开放式建议这类任务仍得靠奖励模型或 LLM-as-Judge。历史脉络上，它承接 AlphaGo 式的结果奖励思路，AI2 在 Tulu 3 中正式提出并命名 RLVR，DeepSeek-R1-Zero 则把它推到极致——完全跳过监督微调，只用规则奖励从基座模型直接训练。

**▌ 它解决了什么问题？**（120-180字）
**Before**：靠 RLHF 提升推理能力效率极低。奖励模型对长推理链的打分噪声很大，模型学到的是"看起来像在推理"的表面模式，还会奖励作弊——把答案写得又长又自信来骗过评分器。人工标注一条高质量数学推理链的成本可达数美元，规模化无从谈起。**After**：验证器几乎零成本、可无限扩展，训练信号只认最终结果。DeepSeek-R1-Zero 在 AIME 2024 上的 pass@1 从 15.6% 提升到 71.0%，多数投票下达到 86.7%，逼近 OpenAI o1-0912；训练过程中模型自发把平均思考长度从几百 token 增长到数千 token，并出现"等一下，我需要重新检查一下"这类自我反思行为——这不是人写进模板的，是奖励压出来的。

**▌ 核心原理三阶拆解**（350-500字）

**第一层：直觉理解。** RLHF 像请一位品味评委给作文打分，评委容易被文采和篇幅迷惑；RLVR 像做数学考试直接对答案，写得再漂亮，答案错就是零分，模型除了真把题做对没有别的捷径可走。

**第二层：技术流程拆解。** 输入一批可验证的问题 → 当前策略对每题采样 G 条完整回答（常用 8 或 16 条） → 验证器逐条打 0/1，可再叠加一个格式奖励 → 计算优势：组内奖励减去均值再除以标准差 → 用带 KL 惩罚的策略梯度更新参数 → 重复。DeepSeek 采用的 GRPO 省掉了 PPO 的价值网络，用"组内相对比较"替代 Critic，显存占用和实现复杂度都大幅下降。关键超参是组大小 G、采样温度、KL 系数 β、每题重复轮数。

**第三层：公式与核心机制。** 优势写作 Aᵢ =（rᵢ − mean(r)）÷ std(r)，目标是最大化 Σ min(ratio·A, clip(ratio, 1±ε)·A) − β·KL。这里藏着一个漂亮的洞察：全对或全错的那些题，组内奖励方差为零、优势全为零、梯度也为零——训练会自动聚焦到"有时对有时错"的临界难度题上，这恰恰是课程学习想做却难以精确做到的事。三个主要坑必须知道：一是熵坍缩，训练后期采样多样性消失，需要熵正则或动态采样过滤掉全对全错的题；二是奖励作弊，模型可能猜出验证器的匹配规则，比如只输出一个数字骗过宽松的正则；三是学界仍在争论 RLVR 究竟是激发了新能力还是只把基座已有能力的采样分布调尖——arXiv:2504.13837 用 pass@k 曲线指出 k 很大时 RL 模型反而不如基座，NVIDIA 的 ProRL 则用更长训练周期给出了相反证据。

**▌ 动手验证**（100-150字）
TRL 已内置 GRPO，把验证器写成奖励函数即可跑通：

```python
from trl import GRPOConfig, GRPOTrainer
def reward_fn(completions, **kw):            # 换成你的验证器
    return [1.0 if "\\boxed{" in c else 0.0 for c in completions]
cfg = GRPOConfig(output_dir="out", num_generations=8,   # 组内采样条数G
                 max_completion_length=1024, beta=0.04) # beta为KL系数
GRPOTrainer(model="Qwen/Qwen2.5-1.5B-Instruct",
            reward_funcs=reward_fn, args=cfg,
            train_dataset=ds).train()
```
注意：num_generations 必须能整除有效批大小，否则直接报错；小模型跑数学 RLVR 建议先用 GSM8K 这类短答案数据，验证器务必做数值比对而不是字符串相等。

### 4. 【FP8与FP4低精度训练：把预训练算力成本砍到四比特】

> 📍 **导语**（80-100字）: 把推理量化到 4 比特早已是常识，但训练一直守在 BF16 这条线上。2025 年防线被推倒：DeepSeek-V3 用 FP8 完成 671B 模型的全程预训练，NVIDIA 随后给出 NVFP4 预训练 120 亿参数模型、10 万亿 token 的完整证据。Blackwell 一代硬件把 FP4 张量核算力做到 FP8 的两倍，2026 年低精度预训练正从论文变成新的成本基线。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
低精度训练指在前向、反向乃至通信中，用 8 比特或 4 比特浮点替代 BF16/FP32 来存储和计算。FP8 有 E4M3 与 E5M2 两种格式，前者精度高用于前向激活与权重，后者动态范围大用于梯度；FP4 常用的 NVFP4 是 E2M1，只有 16 个可表示数值，必须配合微块缩放才勉强可用。它不是推理量化——推理量化是训练完再压，误差只影响一次前向；训练量化的误差会被优化器一步步累积放大，稍有不慎损失曲线就发散。它也不是"整个网络都用 4 比特"：嵌入层、输出头、注意力 logits、归一化层必须保留高精度，主权重仍以 FP32 或 BF16 的主副本形式存在。历史脉络是 FP16 混合精度（2017）→ BF16 成为默认 → Hopper 引入 FP8 张量核（2022）→ OCP 发布 MX 微缩放格式标准（2023-09）→ Blackwell 原生支持 NVFP4（2024）。

**▌ 它解决了什么问题？**（120-180字）
**Before**：BF16 预训练下，一个 671B 的 MoE 模型算力账单以亿元计，显存占用与跨卡通信量同样按 16 比特计费，集群规模被迫无脑堆大。**After**：DeepSeek-V3 用细粒度 FP8 把 14.8 万亿 token 的预训练压到 278.8 万 H800 GPU 小时、约 557 万美元，且训练全程与 BF16 基线的相对损失误差始终低于 0.25%。NVIDIA 在 NVFP4 论文中报告，一个 120 亿参数的 Mamba-Transformer 混合模型用 NVFP4 训练 10 万亿 token，验证损失与 FP8 基线几乎重合，下游任务差距约 1 到 1.5 个百分点，同时矩阵乘吞吐提升到 FP8 的 2 到 3 倍、权重显存直接减半。换算下来，同一个集群一个季度能多跑一到两轮完整预训练。

**▌ 核心原理三阶拆解**（350-500字）

**第一层：直觉理解。** 低精度像换一把刻度更粗的尺子——读数快了，但小数点后面全没了。真正的解法不是换尺子，而是"分段量"：把布料剪成一小段一小段，每段单独选一个合适的刻度基准，这样每段内部的相对精度就够用。这就是微块缩放的全部直觉。

**第二层：技术流程拆解。** ①主权重以 BF16 或 FP32 保存不动；②前向计算前，把权重与激活按小块切分（NVFP4 是每 16 个元素一块），求块内最大绝对值算出缩放因子，除以该因子后转成 FP4/FP8；③在张量核上执行低精度矩阵乘，累加器保持 FP32；④输出再乘回缩放因子还原量纲；⑤反向同理，但梯度对异常值更敏感，常用随机取整避免系统性偏置；⑥优化器始终在高精度主权重上更新，量化只发生在计算路径上。

**第三层：公式与核心机制。** 量化本身很简单：x̂ = round(x ÷ s) × s，全部技巧都在怎么选缩放因子 s。传统做法是整张量共用一个 s，只要出现一个异常大的激活值，其余数值全被压成 0。DeepSeek-V3 的做法是激活按 1×128 的 tile、权重按 128×128 的 block 各自确定 s，并把 GEMM 的部分和每隔 128 步搬到 CUDA Core 上做一次 FP32 累加，弥补 Hopper 张量核累加位宽不足带来的误差。NVFP4 更进一步用两级缩放：块内 16 个元素共享一个 FP8(E4M3) 缩放因子，整张量再套一个 FP32 全局因子，等于给每 16 个数配一把量身定制的尺子。另外两个关键决策：靠近输出的部分层保留 BF16（NVIDIA 建议最后约 15% 的线性层不量化），以及用 Hadamard 随机变换把异常值能量摊平到各个维度之后再量化。

**▌ 动手验证**（100-150字）
单卡即可体验 FP8 训练，Transformer Engine 提供了现成的上下文管理器：

```python
import torch, transformer_engine.pytorch as te
from transformer_engine.common.recipe import Format, DelayedScaling
layer = te.Linear(4096, 4096, bias=True).cuda()       # TE版线性层
recipe = DelayedScaling(fp8_format=Format.HYBRID,     # 前向E4M3/反向E5M2
                        amax_history_len=16)          # 用历史极值定缩放
x = torch.randn(8, 512, 4096, device="cuda", dtype=torch.bfloat16)
with te.fp8_autocast(enabled=True, fp8_recipe=recipe):
    y = layer(x)                                       # 张量核走FP8
y.sum().backward()
```
注意：需要 Hopper 及以上 GPU；张量维度建议为 16 的倍数，否则内核会静默回落到 BF16，你会看不到任何加速。

**▌ 对比与选型**（必填表格）
| 对比维度 | NVFP4训练 | FP8训练 | BF16训练 |
|---------|--------|-------|---------|
| 表示位宽 | 4比特加两级缩放 | 8比特E4M3/E5M2 | 16比特 |
| 硬件要求 | Blackwell | Hopper及以上 | 通用 |
| 相对吞吐 | 约FP8的2-3倍 | 约BF16的2倍 | 基线 |
| 稳定性风险 | 需层级混合精度 | 需细粒度缩放 | 最稳 |

### 5. 【推测解码：用小模型起草大模型验证把生成提速两三倍】

> 📍 **导语**（80-100字）: 大模型生成慢，不是算力不够，而是每吐一个 token 都要把几百 GB 权重从显存搬进计算单元一次，GPU 算力利用率常常不到 5%。推测解码用"小模型起草、大模型批量验证"把这笔搬运费摊到多个 token 上，输出分布还与原模型严格一致。EAGLE-3 把平均接受长度推过 6 个 token，vLLM、TensorRT-LLM、SGLang 全部内置，这是 2026 年最没争议的免费加速。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
推测解码是一种无损的解码加速算法。它让一个廉价的草稿源——小模型、模型自身的浅层预测头、或 n-gram 缓存——先猜出接下来的 γ 个 token，再把这 γ+1 个位置一次性喂给大模型做单次前向验证，用接受-拒绝采样决定保留几个。它不是量化或蒸馏那种"用质量换速度"的方案，数学上可以证明输出分布与大模型逐个采样完全相同；它也不是提升吞吐的万灵药——在批量很大、GPU 已经算满的场景下，额外的草稿与验证开销可能反而拖慢整体吞吐。适用边界是低延迟、小批量、单用户交互式场景，以及代码补全这类高度可预测的文本。历史脉络上，Google 与 DeepMind 在 2022 年底几乎同时提出该方法，2024 年 Medusa 用多头并行草稿去掉了独立小模型，EAGLE 系列改在特征层做自回归草稿，成为当下事实上的最强方案。

**▌ 它解决了什么问题？**（120-180字）
**Before**：自回归解码是内存带宽瓶颈而非算力瓶颈。一个 70B 模型 FP16 权重约 140GB，H100 的 HBM 带宽约 3.35TB/s，理论上每秒最多把权重读 24 遍，也就是单用户最多约 24 tokens/s，算力再强也突破不了这条线。开发者只能靠量化和换小模型硬扛。**After**：验证 5 个 token 与生成 1 个 token 的权重搬运量几乎一样，只要草稿命中率够高，等于白捡数倍速度。原始论文在 T5-XXL 上报告 2 到 3 倍加速；Medusa 报告约 2.2 到 3.6 倍；EAGLE-3 在 LLaMA-3.1-8B 上把平均接受长度提到 6.5 以上、加速比达到 5 到 6.5 倍。DeepSeek-V3 干脆把训练时的多 token 预测模块留到推理阶段当草稿头，第二个 token 的接受率约 85% 到 90%。

**▌ 核心原理三阶拆解**（350-500字）

**第一层：直觉理解。** 像老师批改作业。学生（小模型）飞快写出五步解法，老师（大模型）扫一眼就能同时判断这五步从哪一步开始错——检查比自己从头写快得多。前面对的直接采纳，从第一个错处开始由老师亲自重写一步。

**第二层：技术流程拆解。** ①草稿阶段：小模型自回归生成 γ 个 token 及其概率分布 q；②验证阶段：大模型对这 γ+1 个位置做一次前向，拿到每个位置的概率分布 p；③逐位置接受：以 min(1, p(x)÷q(x)) 的概率接受草稿 token；④一旦某位被拒绝，就从修正分布 norm(max(0, p−q)) 重采样一个 token，并丢弃后面所有草稿；⑤若 γ 个全部接受，还能白送一个由大模型自己产生的 token，所以一轮最多前进 γ+1 步。

**第三层：公式与核心机制。** 接受-拒绝那一步是全部数学的核心。可以严格证明，"以 p÷q 的概率接受、否则从 max(0, p−q) 归一化后重采样"这套组合，其边际分布恰好等于 p，因此加速是无损的，温度、top-p 等采样设置都不受影响。工程上有三条演进主线：一是树形草稿，用精心设计的注意力掩码在单次前向里同时验证多条候选分支而非一条链，接受长度显著提高；二是自草稿，Medusa 加若干并行预测头，EAGLE 在倒数第二层特征上做自回归并把已采样 token 的嵌入回灌，解决了纯特征预测的不确定性问题；三是 EAGLE-3 去掉特征回归损失、改用多层特征融合与训练时的测试模拟，让草稿头的收益能随训练数据继续增长。核心权衡参数是草稿长度 γ：太短收益小，太长则累计拒绝概率上升、草稿算力被浪费，实践中按批大小动态调整比固定值更稳。

**▌ 动手验证**（100-150字）
vLLM 一段配置即可开启，无需改动业务代码：

```python
from vllm import LLM, SamplingParams
llm = LLM(model="meta-llama/Llama-3.1-70B-Instruct",
          tensor_parallel_size=4,
          speculative_config={
              "model": "meta-llama/Llama-3.2-1B-Instruct",
              "num_speculative_tokens": 5})      # 草稿长度γ
out = llm.generate(["用三句话解释推测解码"],
                   SamplingParams(temperature=0.0))
print(out[0].outputs[0].text)
```
注意：草稿模型必须与目标模型使用同一词表，否则直接报错；并发批量超过 32 后收益会明显衰减，务必先在真实流量下压测再决定是否长期开启。

**▌ 对比与选型**（必填表格）
| 对比维度 | 推测解码 | 权重量化(INT4) | 模型蒸馏 |
|---------|--------|-------|---------|
| 是否无损 | 输出分布不变 | 有精度损失 | 能力有损 |
| 加速来源 | 摊薄显存搬运 | 减少搬运字节 | 直接换小模型 |
| 额外成本 | 草稿模型显存 | 量化校准 | 完整重训练 |
| 大批量收益 | 明显衰减 | 稳定 | 稳定 |
| 落地难度 | 引擎一键开启 | 需校准调优 | 最高 |

### 6. 【评测数据污染：榜单分数为何失真与动态评测的解法】

> 📍 **导语**（80-100字）: 一个新模型刷爆 MMLU 与 GSM8K，第二天在你的真实任务上却表现平平——这几乎成了 2026 年的日常。原因之一是评测数据污染：题目和答案早就混进了预训练语料，模型不是在推理，而是在背诵。Scale AI 用一套全新出的小学数学题测出部分模型掉分高达 13 个百分点，动态评测与污染检测因此成为选型时必须补上的一课。

---

**🧠 深度解析**

**▌ 它是什么？**（120-180字）
评测数据污染指评测集的样本、答案或其高度相似的变体出现在模型训练数据中，导致分数无法反映真实泛化能力。它至少分三类：直接污染（原题原答案进了语料）、间接污染（题目被博客、论文、GitHub 转述后进语料）、以及更隐蔽的过拟合式污染（团队反复拿测试集调参和调数据配比）。它不是一句简单的"作弊"指控——互联网抓取规模到了万亿 token 量级，污染在很大程度上是不可避免的工程事实；它也不意味着分数全无意义，只是必须配合更强的验证手段一起看。历史脉络上，GPT-3 论文就已附带专门的污染分析章节，2023 年后随着榜单商业价值飙升问题急剧放大，催生了 LiveBench、LiveCodeBench、GSM1k 这类"活体评测"，以及 n-gram 重叠、困惑度对比、成员推断等一整套检测方法。

**▌ 它解决了什么问题？**（120-180字）
**Before**：选型只看排行榜，团队按分数采购模型，上线后发现真实场景效果与榜单严重脱节，返工成本极高；研究侧更糟，一篇论文声称的提升可能全部来自污染，别人根本复现不了。**After**：有了污染量化手段与滚动更新的评测集，分数第一次变得可审计。Scale AI 在 2024 年重新人工出题构造 GSM1k（与 GSM8K 同分布的 1250 道全新题），发现部分模型家族相对 GSM8K 掉分最高达 13 个百分点，而 Gemini、Claude、GPT 系列的差距接近于零——这直接把"谁在背题"摆上了台面。LiveBench 采用每月更新题目、答案可客观判定的机制；LiveCodeBench 只取模型训练截止日之后新发布的竞赛题，从根本上关掉了污染窗口。

**▌ 核心原理三阶拆解**（350-500字）

**第一层：直觉理解。** 污染就像考试前有人把真题发给了部分考生。你无法从分数上区分"真会"和"背过"，唯一可靠的办法要么是现场出一套全新的题，要么是去翻一翻这些考生的复习资料里有没有夹着原题。

**第二层：技术流程拆解（检测侧）。** ①字符串与 n-gram 重叠检测：对每条测试样本，在训练语料里查是否存在 13-gram 以上的连续重合，这是 GPT-3 与 LLaMA 采用的经典做法，缺点是必须能访问训练语料；②黑盒行为检测：不看语料只看模型，比较模型对原题与改写题的困惑度差异，或用引导式提示让模型补全测试样本的后半段，若能逐字复现即高度可疑；③成员推断，典型如 Min-K% Prob，取每个 token 概率里最低的 K% 求均值，训练时见过的文本很少出现极低概率 token；④顺序敏感性检验，把选择题选项打乱后重测，准确率暴跌说明模型记的是答案位置而不是内容。

**第三层：机制与关键设计决策。** 治理侧有三条路。一是活体评测，只用模型训练截止日之后产生的新数据，LiveCodeBench 的竞赛题与 LiveBench 的月更题都是这个思路；二是私有留出集，题目永不公开、只提供提交接口，如 ARC-AGI 的半私有集与 SWE-bench 的验证服务；三是把评测从"选择题"改造成"可执行验证"，代码跑测试、数学比对答案、Agent 任务看环境最终状态，让死记硬背无法直接兑换成分数。还有一个常被忽略的细节：污染检测本身存在假阳性——一道经典物理题的表述在网上出现过一万次，重合并不等于模型见过标准答案，因此结论应当以"污染风险等级"给出，而不是简单的是或否。

**▌ 动手验证**（100-150字）
用 LM Evaluation Harness 跑一次"标准题 vs 更难改写版"的对照，是最省事的自查：


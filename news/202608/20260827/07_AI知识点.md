### 1. 【混合专家MoE路由：每个token只唤醒少数专家子网络】

> 📍 **导语**：当大模型越做越大，"每次推理都要算完所有参数"成了算力黑洞。2024 年 Mixtral 8×7B 用 460 亿总参数却只激活 130 亿，效果追平 700 亿密集模型；2025 年 DeepSeek-V3 以 6710 亿参数、每 token 仅激活 370 亿，把训练成本压到 280 万 H800 卡时。背后的功臣就是稀疏混合专家（MoE）。理解它，你就看懂了当代旗舰模型"又大又省"的工程密码。

---

**导语**：混合专家（Mixture of Experts, MoE）是一种"把模型做大、把每次计算做小"的神经网络架构。它在 Transformer 的每一层用多个并行的"专家"前馈网络（FFN）替换原本唯一的 FFN，再由一个轻量的"路由器"为每个 token 动态挑选少数几个专家来算，其余专家整轮休眠。它不是把模型拆成几个独立小模型各管一摊，而是在同一层里让不同 token 走不同的子网络。常见误区是以为 MoE 能省显存——其实它"总参数"和密集模型一样大，省的是"每 token 的计算量"（FLOPs）和推理延迟，权重显存几乎不减。适用边界：MoE 在预训练与推理吞吐上极划算，但路由不均、分布式通信复杂、微调易过拟合单一专家，是它的代价。历史脉络：2017 年 Shazeer 提出 Sparsely-Gated MoE，2023 年 Mixtral 首次把高质量开放权重 MoE 做进主流推理栈，2024–2026 年 DeepSeek-V3、Llama 4、Qwen3-235B、Kimi K2 纷纷采用，使其成旗舰标配。

**它是什么**：MoE 层的工作方式可以一句话讲清：对每个 token，路由器打分→选 Top-k 个专家→只算被选中的专家→把结果按分数加权求和。以 Mixtral 8×7B 为例，每层有 8 个专家 FFN，路由器对每 token 选出分数最高的 2 个（top-2），于是每层只跑 2/8 的专家，总参数 46.7B 但每 token 激活约 12.9B。关键约束：路由器必须足够"均衡"，否则会出现"专家坍塌"——少数专家被反复选中、其余闲置。解决之道是训练时加"负载均衡损失"，鼓励各专家接到的 token 流量接近均匀。DeepSeek-V3 更进一步用"无辅助损失的负载均衡"：给每个专家配一个不参与反向传播的可学习偏置，高负载专家降偏置、空闲专家升偏置，既均衡又不干扰主任务梯度。此外它引入"共享专家"（每个 token 必走的通用 FFN）+"细粒度路由专家"（256 个里激活 8 个），把通用知识与专业分工彻底分开，参数利用率从传统 MoE 的约 60% 提到 85% 以上。

**解决什么**：Before：密集模型每个 token 都要过全部参数，70B 模型一次前向就是 70B 级 FLOPs，推理又慢又贵；想提升质量只能整体放大，算力线性飙升。After：MoE 把"容量"和"每 token 算力"解耦——总参数决定知识上限，激活参数决定推理成本。量化上，Mixtral 8×7B 在 FLOPs 匹配 13B 密集模型的预算下，多项基准超过 Llama-2 70B，推理快约 6 倍；DeepSeek-V3 每 token 激活 37B，却以 671B 的总容量在 MMLU、代码、数学上逼近闭源旗舰，且全程训练零不可恢复 loss spike。近期 Qwen3-235B、Kimi K2 都沿用"共享专家+细粒度路由+无辅助损失均衡"的组合，证明这是 2026 年最稳的扩展路线。对部署方，这意味着同样一张卡能服务更多并发、同样预算能养更大的模型。

**原理拆解**：
**第一层：直觉理解**——把 MoE 想成一家有 8 个工位的工作坊，但每次只点亮 2 盏灯：每个任务（token）进来，组长（路由器）看一眼就指派 2 个最对口的人干活，其余 6 人原地待命不耗电费。模型总"人力"很雄厚（8 人都在册），但每件活只动用 2 人，所以既专业又省钱。难点在于组长不能老是点同一两个人，否则另 6 人闲置、那 2 人过劳——这就是负载均衡要解决的问题。

**第二层：技术流程拆解**——① 输入 token 的隐藏向量 h 进入 MoE 层；② 路由器（一个线性层 W_r）算每个专家的得分 g_i = softmax(h·W_r)_i；③ 取分数最高的 k 个（top-k，Mixtral 用 2，DeepSeek 用 8）；④ 只调用这 k 个专家 FFN 算出各自输出 E_i(h)；⑤ 层输出 y = Σ_{i∈topk} g_i · E_i(h)。训练时额外加负载均衡损失 L_balance = N·Σ f_i·p_i（f_i 为第 i 专家实际接到的 token 比例，p_i 为其平均路由概率），最小化它即鼓励均匀分配。

**第三层：公式与核心机制**——路由打分 g(h)=softmax(TopK(h·W_r))，其中 TopK 把非选中专家分数置 −∞。注意：专家总数 N 决定"可达参数"，激活数 k 决定"每 token 算力"，二者独立——这正是 MoE 把模型"做大"又不"算爆"的根本。DeepSeek 的无辅助损失偏置做法是：在路由打分时给专家 i 加偏置 b_i（b_i 只参与路由、不参与输出与梯度），动态把 token 引向空闲专家，实现零性能损耗的均衡。容量因子（capacity factor）则给每专家设 token 上限，超量 token 走残差直连下一层，防单点拥堵。

**动手验证**：用一个最小的 numpy 路由演示（无需大模型即可理解 top-k 门控）：
```python
import numpy as np

def router(tokens, W_r, n_experts=8, top_k=2):
    # tokens: (B, d) 隐藏向量; W_r: (d, n_experts) 路由权重
    logits = tokens @ W_r                 # (B, n_experts)
    # top-k 门控：非选中置 -inf
    thr = np.sort(logits, axis=-1)[:, -top_k-1:-top_k]
    masked = np.where(logits >= thr, logits, -1e9)
    gates = np.exp(masked) / np.exp(masked).sum(-1, keepdims=True)
    return gates                         # 每个 token 在选中专家上的权重(其余为0)
np.random.seed(0)
h = np.random.randn(4, 16)
W_r = np.random.randn(16, 8)
print(router(h, W_r).round(2))
```
注意：真实专家 FFN 需用 PyTorch 实现并在分布式上跑；top_k 太小会掉点、太大失去稀疏收益，常见 k=2（Mixtral）或 k=8（DeepSeek-V3）。预期输出每行为 2 个非零权重、和为 1，印证"每 token 只激活少数专家"。

**对比与选型**：
| 对比维度 | MoE稀疏专家 | 密集模型Dense | 模型并行切分 |
|---------|--------|-------|-------|
| 核心思想 | 每token激活少数专家 | 全参数参与 | 按层切到多卡 |
| 适用场景 | 旗舰预训练/推理 | 中小模型 | 超大规模训练 |
| 性能表现 | 同算力更强 | 训练简单 | 通信开销大 |
| 学习成本 | 中（路由/均衡） | 低 | 高 |
| 生态成熟度 | DeepSeek/Qwen/Kimi | 主流 | 主流 |

### 2. 【LoRA与QLoRA参数高效微调：用低秩适配给大模型打补丁】

> 📍 **导语**：全量微调一个 70B 模型需要数百 GB 显存和多卡集群，对个人和小团队是天价门槛。2021 年提出的 LoRA 只训练不到 1% 的参数就能逼近全量微调效果；2023 年的 QLoRA 再把底座压成 4-bit，让 65B 模型在单张 48GB 显卡上微调。今天 Hugging Face PEFT、Axolotl 让"用自己的数据改模型"成为人人可做的工程。

---

**导语**：LoRA（Low-Rank Adaptation，低秩适配）是一种参数高效微调（PEFT）技术：冻结预训练模型全部原始权重，只在每层注入一对可训练的低秩矩阵（A、B），用极少的参数学着"任务增量"。QLoRA 是 LoRA 的升级，把被冻结的底座量化到 4-bit（NF4），进一步把显存砍掉约 75%，同时用"双重量化"和"分页优化器"稳住训练。它不是重新训练一个模型，而是给大模型贴一组"可插拔补丁"——补丁小到几十 MB，可随时合并回底座或换任务卸载。常见误区：以为 LoRA 只能做"轻量玩具"。实际上多数业务微调场景 LoRA 能达到全量微调 95–99% 的效果，且多适配器并存让一个底座服务多个任务。适用边界：极端追求基准上限或改动模型底层表征时，全量微调仍更优；LoRA 对"风格/领域适配"最划算。历史脉络：2021 年微软提出 LoRA，2023 年 QLoRA（arXiv:2305.14314）把 4-bit 量化与 LoRA 结合，2024 年后 PEFT 库成为事实标准，Llama、Mistral、Qwen 全系列支持。

**它是什么**：标准微调要更新所有权重 ΔW，参数量等于原模型。LoRA 的核心洞察是：权重更新 ΔW 往往是"低秩"的——可以用两个瘦矩阵的乘积近似：ΔW ≈ B·A，其中 B∈ℝ^{d×r}、A∈ℝ^{r×k}，秩 r 远小于 d（常取 8–64）。于是可训练参数从 d×k 降到 r×(d+k)，通常是原模型的 0.1%–1%。训练时原权重 W 冻结、梯度不流过它，只有 A、B 更新；推理时可直接把 B·A 加回 W 合并部署，也可保持分离、按需切换。QLoRA 在此外再叠三层：① 4-bit NormalFloat（NF4）量化底座，专为神经网络权重的正态分布优化；② 双重量化（量化"量化常数"本身）再省 0.4 bit/参数；③ 分页优化器用 CUDA 分页防止梯度检查点时的显存尖峰。配置上，秩 r 常取 8–16、缩放 α 取 2×r、目标模块瞄准 q_proj/v_proj，dropout 0.05–0.1。

**解决什么**：Before：全量微调 7B 模型约需 16GB 显存、70B 约需 140GB，且每换一个任务就要存一份完整权重副本，存储与切换成本爆炸。After：LoRA 把 7B 微调显存降到约 6GB、70B 在单张 48GB 卡上可行，适配器文件仅几十 MB，可版本化、可共享。量化上，QLoRA 论文实测：4-bit 底座微调在多个基准上匹配 16-bit 全精度 LoRA，70B 模型单卡微调质量无损；对企业这意味着用消费级显卡（如 24GB 的 4090）就能定制 13B 级领域模型，把"模型定制"从云厂商专属变成团队日常。近期 Qwen、Llama 的开源生态几乎默认用 LoRA/QLoRA 做指令微调与领域适配，Axolotl 一行配置即可启动。

**原理拆解**：
**第一层：直觉理解**——全量微调像把整幅油画重画一遍；LoRA 像只调整"光影和笔触"两层半透明贴纸。原画（底座）不动，贴纸（A、B 矩阵）学会让画更贴合新主题，改起来便宜、揭下来也不伤原画。QLoRA 则是先把原画用压缩格式存档（4-bit），只在需要落笔时临时解压，省下大量存放空间。

**第二层：技术流程拆解**——① 加载底座并冻结，配置 BitsAndBytesConfig(load_in_4bit=True, nf4, double_quant)；② prepare_model_for_kbit_training 让 Layernorm 等以高精度跑；③ 用 LoraConfig(r, alpha, target_modules=["q_proj","v_proj"]) 通过 get_peft_model 注入适配器；④ 标准 Trainer 训练，梯度只更新 A、B；⑤ 训练后 model.save_pretrained 存适配器，或 merge_and_unload 合并回底座。关键是"底座永远冻结"，省下的不仅是显存，还有反向传播的计算图。

**第三层：公式与核心机制**——前向变为 h = W·x + (B·A)·x，其中 ΔW=B·A 的秩为 r。缩放因子 α/r 控制适配器对输出的影响幅度（α 越大，新任务权重越高）。NF4 的关键：神经网络权重近似零均值正态分布，NF4 在该分布上均匀分配量化区间，比普通 INT4 信息损失更小。双重量化把"量化所用的缩放常数"也量化一次，进一步压缩常数量。梯度经冻结权重"流过"到 A、B，因此底座虽不更新，却能指导学生适配器学到任务特定的增量。

**动手验证**：用 Hugging Face PEFT 做最小 QLoRA（需 `pip install peft bitsandbytes transformers accelerate`）：
```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype="auto")
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b-hf",
                                              quantization_config=bnb, device_map="auto")
model = get_peft_model(model, LoraConfig(
    r=8, lora_alpha=16, target_modules=["q_proj","v_proj"],
    lora_dropout=0.05, task_type="CAUSAL_LM"))
model.print_trainable_parameters()   # 通常可训练参数 <1%
```
注意：4-bit 需 bitsandbytes 与 CUDA；r 太小易欠拟合、太大近全量；训练后可用 merge_and_unload 合并部署。预期打印"trainable params: 0.08%"量级，证明只训极小补丁。

**对比与选型**：
| 对比维度 | QLoRA(4bit) | LoRA(16bit) | 全量微调 |
|---------|--------|-------|-------|
| 核心思想 | 4bit底座+低秩适配 | 16bit底座+低秩适配 | 更新全部权重 |
| 适用场景 | 显存紧张/大模型 | 24GB+显卡 | 极限质量 |
| 性能表现 | 匹配16bit | 95-99%全量 | 基准 |
| 学习成本 | 低(PEFT) | 低 | 高(多卡) |
| 生态成熟度 | PEFT主流 | PEFT主流 | 原生 |

### 3. 【知识蒸馏软标签：用teacher的概率分布训练student】

> 📍 **导语**：2015 年 Hinton 提出知识蒸馏，让小模型模仿大模型的"软标签"而非死记硬背正确答案；到 2025 年 DeepSeek-R1 把 671B 推理模型的能力蒸馏进 1.5B–70B 小模型，数学基准暴涨数十倍。蒸馏已成为大模型时代"以小搏大"最核心的工程能力——理解它，就看懂了为什么手机端也能跑出强推理。

---

**导语**：知识蒸馏（Knowledge Distillation）用一个高性能"教师模型"指导轻量"学生模型"：学生不只学标准答案（硬标签），更学教师输出的完整概率分布（软标签）。它是什么：在分类任务里，教师说"猫 0.7、狗 0.2、狐狸 0.1"，这串"暗知识"（dark knowledge）透露了类别间的相似性结构，比 one-hot 硬标签信息丰富得多。常见误区：以为蒸馏只是"压缩变小、必然变差"。事实是，同等结构的学生用蒸馏常比从头训练更强——因为软标签提供了更平滑、更稳定的监督信号。适用边界：蒸馏最擅长迁移"风格与模式"（如推理链、语气），不直接保证事实准确性；黑盒蒸馏（只靠 API 输出）会损失内部状态信息。历史脉络：2015 Hinton《Distilling the Knowledge in a Neural Network》奠基；CV 时代以 DistilBERT、TinyBERT 为代表；LLM 时代 DeepSeek-R1（2025）用约 80 万条思维链数据 SFT 出 6 个蒸馏模型，证明"蒸馏 > 小模型直接 RL"。

**它是什么**： distill 的核心损失是温度加权的 KL 散度加硬标签交叉熵：L = α·CE(y, y_S) + (1−α)·T²·KL(σ(z_T/T) ‖ σ(z_S/T))。其中 z_T、z_S 为师生 logits，T 是"温度"——T 越大，softmax 越平滑，非目标类的相对置信度越凸显，暗知识越清晰（典型 T=2~5，α=0.1~0.5，T² 用于恢复梯度量级）。蒸馏分四类：① 响应级（匹配输出概率，最经典，DistilBERT 即用）；② 特征级（匹配中间隐藏层，TinyBERT 对齐注意力与隐藏态）；③ 注意力级（MiniLM 对齐注意力图）；④ 关系级（匹配样本间相似结构）。按能否访问教师内部状态，又分白盒（可拿 logits/中间层，精度高）、黑盒（仅 API 文本，靠合成数据训练，Alpaca/Vicuna 即用）、灰盒（部分状态，如 on-policy、DPO 蒸馏）。LLM 时代的范式变迁：闭源 teacher 只能黑盒蒸馏——用 teacher 生成 (指令, 回答) 或 (问题, 思维链, 答案) 数据做 SFT，DeepSeek R1 即此类。

**解决什么**：Before：小模型从头训练或直接在少量数据上微调，既缺知识又易过拟合；让小模型自己强化学习探索推理，往往因"知识储备不足"而效率极低（R1 实验：Qwen2.5-7B 直接 RL 在 AIME 2024 仅 18.3 分）。After：蒸馏把大模型已发现的推理模式"直接灌输"给学生。量化上，R1-Distill-Qwen-7B 在 AIME 2024 达 55.5 分，比基座 9.2 分提升 46 分，比直接 RL 的 18.3 分高出近 3 倍；MATH-500 从 72.0 升到 92.8。与量化叠加后，典型部署管线是"大模型→蒸馏小 5–10 倍学生→int4/int8 量化"，端到端成本降 30–100× 而质量回退仅个位数百分比。近期 1.5B 的 R1 蒸馏模型数学推理碾压同尺寸 RL 模型，证明推理能力可迁移而非必须从头探索。

**原理拆解**：
**第一层：直觉理解**——教授（教师）解题不仅给最终答案，还会在草稿上写"这题像 A 类、不太像 B 类"。学生抄这份带批注的草稿，比只背标准答案学得透。蒸馏就是把教授的"解题直觉分布"喂给学生，让他连"错法之间的差别"都学到。

**第二层：技术流程拆解**——① 教师对一批输入产出软化分布（高温 T 的 softmax）；② 学生用同温度 softmax 输出，计算与教师分布的 KL 散度；③ 同时用真实硬标签算交叉熵；④ 加权求和得总损失反传（只更新学生）；⑤ LLM 黑盒场景改为：教师生成推理数据→学生 SFT。DeepSeek R1 流水线：R1 生成约 80 万条 (题, 思维链, 答案)→严格过滤（格式/长度/正确性/去重）→对 Qwen2.5/Llama3 基座做标准 SFT（不做 RL）→在 AIME、MATH-500、GPQA 等评测。

**第三层：公式与核心机制**——温度软化 q_i = exp(z_i/T)/Σexp(z_j/T)：T=1 即普通 softmax，T 大则分布平坦、暗知识显形。KL 项前的 T² 是因为软化后梯度被 T 缩放、需乘回以保持量级。关键直觉：硬标签只说"对/错"，软标签说"对多少、错法之间多像"，后者提供正则化，使学生训练更稳、泛化更好——这正是蒸馏学生常超同尺寸从零训练模型的原因。灰盒 on-policy 蒸馏让学生自己生成、教师打分修正，比纯黑盒少"暴露偏差"。

**动手验证**：用 Transformers 实现一个最小蒸馏损失（需 `pip install torch transformers`）：
```python
import torch, torch.nn.functional as F

def distill_loss(student_logits, teacher_logits, hard_labels, T=4.0, alpha=0.7):
    soft_s = F.log_softmax(student_logits / T, dim=-1)
    soft_t = F.softmax(teacher_logits / T, dim=-1)
    kd = F.kl_div(soft_s, soft_t, reduction="batchmean") * (T * T)
    ce = F.cross_entropy(student_logits, hard_labels)
    return alpha * ce + (1 - alpha) * kd

# student/logits 与 teacher_logits 同形; 训练时教师冻结
loss = distill_loss(student_logits, teacher_logits, labels)
loss.backward()
```
注意：教师需冻结、不参与梯度；T 与 α 需调参（常 T=2~5）；黑盒场景无 logits 时改用 SFT 合成数据。预期 KL 项随训练下降，学生分布逼近教师。

**对比与选型**：
| 对比维度 | 黑盒蒸馏(SFT) | 白盒logit蒸馏 | 直接RL训练 |
|---------|--------|-------|-------|
| 核心思想 | 教师合成数据训练 | 匹配输出分布 | 奖励探索 |
| 适用场景 | 闭源teacher | 开源teacher | 小模型难奏效 |
| 性能表现 | 强(如R1蒸馏) | 精度最高 | 小模型弱 |
| 学习成本 | 低(调API) | 中(需权重) | 高(调奖励) |
| 生态成熟度 | Alpaca/R1 | DistilBERT | PPO/GRPO |

### 4. 【模型剪枝：砍掉冗余连接把大模型瘦下来】

> 📍 **导语**：你正在为大量"不工作"的参数付电费——研究显示 VGG-16 中 90% 的权重可移除而不掉点。当 175B 模型重新训练一次要数百万美元，2023 年的 SparseGPT 与 2024 年的 Wanda 实现了"免训练一次性剪枝"，几小时内砍掉 50–60% 参数、困惑度几乎不变。剪枝是大模型落地的"瘦身刀"。

---

**导语**：模型剪枝（Pruning）是对已训练好的网络"动减法"：识别并移除对输出影响小的权重、通道、注意力头甚至整个层，缩小规模与计算量、尽量保住性能。它不是重新训练模型，而是"在训练好的肌肉上做减脂"。两类基本形态：非结构化剪枝逐个删权重，可到 90%+ 稀疏度，但产生不规则稀疏矩阵、需专门硬件才能真加速；结构化剪枝删整通道/头/层，模型真变小、在标准硬件上直接提速 2–5 倍，但压缩率较低（常 30–70%）。常见误区：以为"剪掉 90% 权重就一定快 10 倍"。非结构化剪枝在标准 GPU 上不会自动加速，需 2:4 稀疏或稀疏核支持。适用边界：模型已较大、有部署成本压力时最划算；医疗/安全等关键场景不容许任何掉点则慎用。历史脉络：2015 Han 等 Deep Compression 获 ICLR 最佳论文；2019 Lottery Ticket Hypothesis 揭示"中奖子网络"；2023 SparseGPT、2024 Wanda 把免训练剪枝带入百亿参数时代；NVIDIA Minitron 用结构化剪枝+蒸馏从 15B 派生 8B/4B。

**它是什么**：剪枝的核心是"重要性评估 + 掩码置零"。幅度剪枝最简单：权重绝对值越小越不重要，直接归零。但大模型时代发现：权重大不等于重要——Wanda 的关键洞察是一个"权重小但对应输入激活很大"的连接可能很关键，于是用"权重绝对值 × 输入激活的 ℓ2 范数"作为重要性得分，比纯幅度剪枝在 LLaMA-7B 上 50% 稀疏度困惑度从 17.29 降到 7.26。SparseGPT 则把剪枝建模为每层稀疏回归问题，用近似 OBS 求解器一次性重构，OPT-175B 4.5 小时剪 60% 而困惑度几乎不变。结构化方法（LLM-Pruner、Shortened LLaMA、SliceGPT）依梯度或损失删"结构单元"，删后常需轻量 LoRA 微调恢复。剪枝常与量化、蒸馏叠成"压缩三件套"，综合可达 35–49× 压缩比。

**解决什么**：Before：部署 70B 密集模型要整卡常驻全部参数，每次前向算全部权重，推理贵、并发低、无法上端侧。After：结构化剪枝让模型文件真变小、在标准硬件提速 2–5.5×，非结构化配合稀疏硬件能耗最高降 90%。量化上，SparseGPT 在 OPT-175B、BLOOM-176B 实现 50–60% 稀疏度、零样本任务近原模型；Wanda 速度比 SparseGPT 快 300 倍；NVIDIA Minitron 从 15B 结构化剪出 8B 与 4B，训练 token 仅从头训练的 1/40、MMLU 反升 16%。对企业，这意味同一张 A100 可服务 2–5 倍请求量、更小模型可上手机/IoT 离线推理。近期 LLM 压缩综述（ACL 2024）把剪枝列为与量化、蒸馏并列的三大支柱。

**原理拆解**：
**第一层：直觉理解**——剪枝像给一台堆满工具的机器"收掉用不上的扳手"。你不必重造机器，只要确认某把扳手从没被用到、拔掉也不影响产出，就把它拿走。难点是判断"哪把真的没用"：看重量（幅度）太粗，得看它实际经手过多少活（激活）才准——这正是 Wanda 的思路。

**第二层：技术流程拆解**——① 准备少量校准数据（如 C4 若干样本）；② 前向收集每层输入激活统计量（Wanda 用其 ℓ2 范数）；③ 计算重要性得分（Wanda：|W| × ‖输入激活‖）；④ 在每层按预定稀疏比 S% 把最不重要的权重置零（生成二值掩码）；⑤ 可选：轻量微调/LoRA 恢复精度。SparseGPT 额外做逐层近似重构，迭代更新权重以最小化"剪前/剪后输出差"。结构化剪枝则先算结构单元重要性（梯度或损失敏感度），整体删通道/头/层。

**第三层：公式与核心机制**——非结构化重要性（Wanda）评分 s_j = |w_j| · ‖x_j‖₂，其中 x_j 是连接到该权重的输入特征范数；得分最低的 S% 置零。稀疏度 S 与精度呈非线性权衡：50% 几乎无感，>90% 后精度可能陡降，每模型"甜点"不同需实验。结构化剪枝的局部重建目标为 min_{M,Ŵ} ‖WₗXₗ − (M⊙Ŵ)Xₗ‖₂²（M 为二值掩码），SparseGPT 用 Hessian 近似求解。关键提醒：非结构化稀疏需硬件/库支持（如 NVIDIA 2:4 稀疏）才能转化为墙钟加速，否则只是"省了存储、没省时间"。

**动手验证**：用 PyTorch 内置 API 做结构化通道剪枝演示（需 `pip install torch`）：
```python
import torch.nn as nn
import torch.nn.utils.prune as prune

conv = nn.Conv2d(3, 16, 3)            # 示例层
# 按 L1 范数结构化剪掉 30% 的输出通道
prune.l1_unstructured(conv, name="weight", amount=0.3)
prune.remove(conv, "weight")          # 固化掩码为真实0
print((conv.weight == 0).sum().item(), "个权重被剪")
```
注意：以上是 CV 演示；LLM 实际用 SparseGPT/Wanda 库（locuslab/wanda）做免训练剪枝，需校准数据；结构化剪枝删通道后形状改变，常配合 LoRA 微调恢复。预期打印约 30% 权重归零。

**对比与选型**：
| 对比维度 | 非结构化剪枝 | 结构化剪枝 | 量化 |
|---------|--------|-------|-------|
| 核心思想 | 删单个权重 | 删通道/头/层 | 降数值精度 |
| 适用场景 | 有稀疏硬件 | 标准硬件提速 | 省显存 |
| 性能表现 | 90%+稀疏 | 2-5.5x加速 | 4x压缩 |
| 学习成本 | 中(SparseGPT) | 中(需微调) | 低 |
| 生态成熟度 | Wanda/SparseGPT | LLM-Pruner | GPTQ/AWQ |

### 5. 【测试时计算TTC：推理阶段多想一会儿反而更准】

> 📍 **导语**：过去"让模型变强"等于"训更大的模型"。2024 年 OpenAI o1 颠覆了这一假设：不换权重，只在回答前让模型多想几千 token，数学、代码、科学推理准确率就随"思考预算"上升。2025–2026 年 o3、DeepSeek-R1、Claude 扩展思考、Gemini Thinking 全部跟进。测试时计算（TTC）成了与参数量并列的能力杠杆。

---

**导语**：测试时计算（Test-Time Compute，也叫推理时缩放 Inference-Time Scaling）指在推理阶段为单个问题投入更多算力——让模型"想更久"，而非只在训练时堆参数。它不是新训练一个模型，而是给已有的模型在答题时开"额外思考预算"：生成长链思维、采样多条候选、做搜索或自我验证，再汇总择优。常见误区：以为"多想总更好、也更贵"。实际 TTC 对数学/代码/逻辑这类"答案可验证"的难题收益最大，对简单事实问答只是白烧 token 和延迟；且存在边际递减，曲线会 flatten。适用边界：任务须有可检查的"对错标准"（单元测试、形式验证、多数投票）才能高效挑出好答案；开放式创作受益有限。历史脉络：2024 OpenAI o1 首次把显式长链思维做成推理模型；2025 DeepSeek-R1 用 RL 训练推理模型；2026 年 TTC 成前沿模型标配，reasoning_effort 成为可调节旋钮。

**它是什么**：TTC 有两个维度。一是"并行缩放"：同一问题采样 N 条不同思维链（非零温度），用自一致性（self-consistency，直接多数投票）或 best-of-N（用验证器/奖励模型或单元测试挑最优）汇总。二是"顺序缩放"：对足够难的问题，改用束搜索或树搜索（Tree-of-Thought）在推理步骤上展开、回溯、剪枝。具体技术包括：扩展思维链（生成数百到数千推理 token 再答）、自我验证循环（模型自查并修订）、工具增强推理（跑测试套件）。OpenAI 的 o1/o3 通过 reasoning_effort 参数（low/medium/high）分配内部思考算力，思考过程对用户隐藏；非推理模型可手动多次采样投票模拟。关键是"难问题多花钱、易问题一笔过"，把固定训练成本变成按查询可变的成本。

**解决什么**：Before：难问题一次前向就给答案，模型"第一反应"常错；想提升只能训更大模型（数月、数亿美元），已发布的权重改不了。After：TTC 让同一权重在难题上多算 N 倍，准确率随思考预算上升。量化上，计算最优研究指出：许多问题上"小模型 + 更多测试时算力"可匹配甚至超过"大 10 倍的模型只答一次"，且总成本低；o1 在竞赛数学、代码上显著超过同训练算力的非推理模型。经济上，训练前沿模型是数亿美元固定成本，TTC 是每次查询的可变成本——难题花 $0.5 思考、易题花 $0.001，使"按题付费的智能"更灵活。近期代理系统（Agent）靠 TTC 分配更多思考给难步骤、快速过易步骤，让多步任务首次变得可靠。

**原理拆解**：
**第一层：直觉理解**——考试时你有两种变强方式：要么天生更聪明（更大模型），要么多给时间和草稿纸、自己验算（TTC）。对难题，多时间+能检查往往胜过纯天赋。TTC 就是给模型发"草稿纸和更多考试时间"，并教它怎么用。

**第二层：技术流程拆解**——① 生成多条推理路径：同问题采样 N 次（温度>0），每条走不同思维链；② 评分/验证：best-of-N 用验证器或单测给每条打分，self-consistency 直接从各路径抽最终答案；③ 汇总：多数投票（self-consistency）或选验证器最高分（best-of-N），让分散错误相互抵消、共识答案胜出；④ 难题加深：flat 采样失败时切顺序缩放，对推理步做树/束搜索，扩展有希望的分支直到准确率曲线 flatten。预算即旋钮——只在需要的问题上多花。

**第三层：公式与核心机制**——自一致性目标：Â = majority_vote{a₁…a_N}，其中 a_i 为第 i 条路径抽取的答案；当各路径错误分散、正确路径一致时，多数投票以高概率收敛到正确答案。Best-of-N 用验证器得分 s(a_i) 选 argmax_i s(a_i)。核心权衡是"思考预算 N"与"准确率"呈对数上升、最终饱和（diminishing returns），故实践上监测曲线、在 flatten 前停止以省算力。o1/o3 的 reasoning_effort 本质是把这一预算内部化到模型行为（学会何时多想、何时回溯），比外部 prompt "think step by step" 更高效。

**动手验证**：用 OpenAI o1 的推理预算接口做 TTC（需 `pip install openai` 与 API key）：
```python
from openai import OpenAI
client = OpenAI()
resp = client.chat.completions.create(
    model="o1",                         # 或 o3-mini
    messages=[{"role": "user", "content": "证明有无穷多个形如4k+3的素数"}],
    reasoning_effort="high"            # low/medium/high 分配内部思考算力
)
print(resp.choices[0].message.content) # 输出最终答案(思考过程隐藏)
```
注意：TTC 仅 o1/o3 等推理模型原生支持，靠 reasoning_effort 而非 max_tokens（后者只控长度不控思考深度）；非推理模型可手动多次采样+投票模拟。预期 high 档在难题上明显更准，但 token 成本约 2–4×。

**对比与选型**：
| 对比维度 | 测试时计算TTC | 更大训练模型 | 普通单次推理 |
|---------|--------|-------|-------|
| 核心思想 | 推理多算多想 | 堆参数数据 | 一次前向 |
| 适用场景 | 数学/代码/逻辑 | 全面提升 | 简单问答 |
| 性能表现 | 难问题大幅涨 | 固定上限 | 基准 |
| 学习成本 | 低(调预算) | 极高(数月) | 无 |
| 生态成熟度 | o1/R1/Gemini | 训练标配 | 通用 |

### 6. 【Agent记忆：让智能体跨会话记住长期上下文】

> 📍 **导语**：大模型的上下文窗口是有限的"RAM"，会话一结束对话就清零。2023 年 MemGPT 把操作系统的内存管理搬进 Agent：把上下文当寄存器、外部存储当硬盘，让 Agent 自己"换页"存取记忆。如今它演进为 Letta，2025–2026 年 Mem0、LangMem、Hindsight 等把"长期记忆"做成生产级组件。理解它，就看懂了为什么 AI 助手能"越用越懂你"。

---

**导语**：Agent 记忆解决的是"如何让智能体跨会话、跨任务保留并调用知识"。它不是一个单一模块，而是一套分层存储与检索机制。最经典的 MemGPT/Letta 把操作系统内存层级映射到大模型：上下文窗口=CPU 寄存器/L1（最贵、最直接），核心记忆（Core Memory）=RAM（常驻上下文的小块标签记忆），归档记忆（Archival）与回忆记忆（Recall）=磁盘（无限、需检索才调入）。它不是把全部历史硬塞进 prompt（那样又贵又溢出），而是让 Agent 通过函数调用自主决定"记什么、忘什么、何时调出"。常见误区：以为"记忆=把聊天记录全存数据库"。真问题是检索质量与成本控制——无差别存会让噪声淹没信号、每次调用都烧 token。适用边界：长期助手、个人助理、多步项目、多 Agent 共享知识最受益；一次性问答无需记忆系统。历史脉络：2023 MemGPT（arXiv:2310.08560）提出 OS 隐喻；2024 Letta 成立并成参考实现；2025 LangMem、2026 Mem0（arXiv:2504.19413）与 Hindsight 把多策略检索、知识图谱、sleep-time 整理做成标准。

**它是什么**：生产共识是三层记忆架构。① 上下文工作记忆：当前会话的原始消息缓冲、工具调用、活动状态，会话结束即清。② 会话级压缩记忆：本会话抽取/总结的事实，按需读取。③ 长期持久记忆：跨会话的用户偏好、学到的流程，存于"向量库+图"混合存储。Letta 的落地最清晰：核心记忆（默认 2–4KB，含 persona/human/task 区块，永远在上下文）像 RAM；归档记忆是无上限外部向量库，用 archival_memory_insert/search 写入检索；回忆记忆是完整对话日志，用 conversation_search 按内容或时间翻找。关键创新是"LLM 自管分页"——Agent 自己调用 core_memory_replace、archival_memory_search 等工具决定存取，像 OS 虚拟内存一样把信息换入换出。衍生概念 Sleep-time Compute：Agent 在空闲时由异步"睡眠 Agent"整理记忆、抽象模式、消解矛盾，把"在线要快"与"整理要认真"解耦。

**解决什么**：Before：无记忆的 Agent 每次对话从零开始，反复问同样偏好、忘了上周定的方案；把全历史塞进 prompt 则随会话变长迅速溢出窗口、成本飙升且噪声干扰。After：分层记忆让 Agent 在有限窗口里始终装着"最精炼的知识"，完整历史与海量外部数据按需检索。量化上，Mem0 论文（2026）称其混合检索比纯全上下文方法响应准确率高 26%、成本降约 10×；Hindsight 用"语义+关键词+图+时间"四路并行检索 + 交叉编码器重排，在 LongMemEval 长程记忆基准达 94.6%。近期框架还引入"按重要度遗忘"——每周清理低于阈值的记忆，类人睡眠整理；多 Agent 间可在权限控制下共享记忆，像团队共同记忆。这让个人助理真正"越用越懂你"、长期项目 Agent 不丢上下文。

**原理拆解**：
**第一层：直觉理解**——把 Agent 想成用电脑的人：手边桌面（上下文窗口）只放正在用的几份文件，书柜（归档记忆）里存所有资料，日记本（回忆记忆）记每次聊了啥。人不会把整座图书馆摊在桌上，而是需要时用检索调取——Agent 也一样，关键是谁来决定"桌上放什么"。MemGPT 的答案是：让 Agent 自己决定。

**第二层：技术流程拆解**——① 写入：对话中 Agent 学到新事实，调用 core_memory_append（写入常驻小块）或 archival_memory_insert（写入外部库）或 recall 自动记日志；② 检索：每次 LLM 调用前，用用户最新消息/任务描述做查询，对归档库做嵌入相似度检索，把相关记忆注入上下文；③ 分页：超出窗口的旧消息被逐出，经递归摘要压成精简表示留在上下文；④ 整理：空闲时 Sleep-time Agent 抽象模式、消解矛盾。Letta 全靠 LLM 函数调用驱动这三层，给 Agent 完全自主权决定记得什么、忘什么。

**第三层：公式与核心机制**——检索质量决定记忆可用性：查询 q 对归档记忆的相似度用余弦 sim(q, m_i)=q·m_i/(|q||m_i|)，top-k 取回；多策略检索（Hindsight）并行跑语义/关键词/图/时间四路，用互惠排序融合（RRF）合并、再用 cross-encoder 重排。核心权衡：核心记忆每 token 计入每次请求（贵但快），归档/回忆需检索（便宜但多一次调用与延迟）。LLM 自管记忆的代价是"每次记忆操作都烧推理 token"，高频交互需权衡；系统提取式（如 Hindsight 被动抽取）则不占用主 Agent 推理、但丧失模型自主判断的灵活度。

**动手验证**：用 Letta SDK 创建带长期记忆的 Agent（需 `pip install letta` 并启动服务）：
```python
from letta import LLMConfig, EmbeddingConfig, create_client

client = create_client()
agent = client.create_agent(
    name="assistant",
    memory_blocks=[{"label": "human", "value": "用户偏好用Python写后端"}],
)
# 对话中 Agent 可调用 core_memory_replace / archival_memory_insert 自我更新
resp = client.send_message(agent_id=agent.id, message="记住：我下周要交季度报告")
print(resp)
```
注意：Letta 是完整 Agent 运行时（含记忆/工具/状态），非单纯记忆库；若只想要记忆层可接 Hindsight（MCP 原生）。预期 Agent 把"季度报告"写入对应记忆块，下会话可直接回忆，印证跨会话持久化。

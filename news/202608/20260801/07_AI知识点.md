### 【注意力分数与 QKV 投影：从零推导 Self-Attention 矩阵的计算全过程】

**导语**：今天几乎所有大模型（GPT、Claude、Gemini、Llama）的骨架都是 Transformer，而 Transformer 的灵魂只有一句话——用自注意力让每个词一眼看全整句话。理解缩放点积注意力与多头机制，是读懂现代 AI 的第一把钥匙。

**它是什么**：自注意力（Self-Attention）是一种让序列中每个位置都能直接「回看」所有其他位置并加权聚合信息的机制。它把输入向量通过三组可学习矩阵投影成查询（Query, Q）、键（Key, K）、值（Value, V），再用 Q 与所有 K 做点积衡量相关性，softmax 归一化后得到注意力权重，最后对 V 做加权求和。多头注意力（Multi-Head Attention）则是把 Q/K/V 切成若干低维子空间，并行跑多份自注意力，各自捕捉不同类型的依赖（如主谓一致、指代消解、局部词序），再把结果拼接并线性投影。它完全抛弃了 RNN 的串行递推，使任意两个位置的关联只需常数级运算即可建立。

**解决什么**：在 Transformer 之前，RNN/LSTM 必须沿时间步逐个处理 token，前一步的隐状态是后一步的输入，这种串行特性既阻塞了训练并行化，也导致早期信息在长程传递中衰减（梯度消失），远距离依赖难以学习。卷积虽能并行，但关联两个任意距离位置所需的操作数随距离线性或对数增长。自注意力把「任意两位置的关系」压成一步矩阵乘法，运算量恒定、可完全并行，从而在长文本、长序列上兼顾质量与效率。多头则弥补了单次注意力因平均而损失分辨率的问题，让模型从多个表示子空间同时提取关系。

**原理拆解**：设输入序列组成矩阵 X∈R^{N×d}，先线性投影得到 Q=XW_Q、K=XW_K、V=XW_V。缩放点积注意力定义为 Attention(Q,K,V)=softmax(QK^T/√d_k)·V，其中除以 √d_k 是为防止点积数值过大导致 softmax 梯度消失。softmax 行的每项是「当前 token 对第 j 个 token 的关注度」，再用它给 V 加权，得到融合了全局上下文的新表示。多头时把 d 维切成 h 个头（每头 d/h 维），各自独立计算 head_i=Attention(QW_Q^i, KW_K^i, VW_V^i)，拼接后乘 W_O。由于注意力对输入置换不变（本身不知道词序），还需叠加位置编码（正弦或 RoPE）注入顺序信息。复杂度 O(N²·d)，N 为序列长度，所以长上下文会催生后续 KV Cache、稀疏注意力等优化。

**动手验证**：用 numpy 跑一个最小自注意力，直观感受「看全整句」：
```python
import numpy as np
np.random.seed(0)
N, d = 5, 8                      # 5 个 token，维度 8
X = np.random.randn(N, d)
Wq = np.random.randn(d, d); Wk = np.random.randn(d, d); Wv = np.random.randn(d, d)
Q, K, V = X@Wq, X@Wk, X@Wv
scores = Q @ K.T / np.sqrt(d)   # (N,N) 注意力分数
A = np.exp(scores) / np.exp(scores).sum(-1, keepdims=True)  # softmax 按行
out = A @ V                     # 加权聚合
print("注意力矩阵(每行和=1):\n", A.round(2))
print("输出形状:", out.shape)
```
把 N 改到 1000，观察 A 仍每行归一化；再打印某个 query 行，看它对哪些 key 权重高，即可验证「每个词关注全句」。进阶可加 `np.random.randn(h, d, d//h)` 实现多头拼接。

**对比选型**：RNN/LSTM 串行、易并行差、长程弱；卷积并行好但远程关联成本高；自注意力并行且远程 O(1) 关联，代价是 O(N²) 显存，因此超长文本要配稀疏/线性注意力（如 FlashAttention、线性 RNN 流派）。单头注意力表达力有限且平均掉细节，多头以少量额外参数换取多视角表征，是默认选择。位置编码上，绝对正弦编码简单但外推差，RoPE 旋转编码外推更强（见本条所在模块另一篇）。实践里，编码器-解码器用交叉注意力对齐两端，解码器用因果掩码防止「偷看未来」。

### 【RLHF 与 DPO 偏好对齐：从人类反馈强化学习到直接偏好优化的进阶】

**导语**：模型在海量文本上「学会说话」后，并不等于「说人话、守规矩」。把能力强大的基座模型调教成有用、无害、诚实的助手，靠的是偏好对齐。本文串起从 RLHF 到 DPO 的方法演进，帮你搞懂这条大模型后训练主线。

**它是什么**：偏好对齐（Preference Alignment）是用「人类更喜欢哪条回答」的对比数据来微调模型，使其行为符合人类期望。RLHF（基于人类反馈的强化学习）是经典流程：先收集人类对同一问题多份回答的偏好排序，训一个奖励模型（Reward Model）拟合人类偏好（Bradley-Terry 模型），再用强化学习（如 PPO）在最大化奖励的同时用 KL 散度约束不让策略偏离原模型太远。DPO（Direct Preference Optimization，Rafailov et al., 2023）则是更巧妙的进阶：它发现 KL 正则化的 RLHF 最优策略可写成「参考策略 × exp(奖励/β)」的解析闭式，反解后奖励可被表示为策略与参考策略的对数概率比，于是奖励模型被「吸收」进语言模型自身，只需在偏好对 (x, y_w, y_l) 上做二元交叉熵，无需显式奖励模型、无需 PPO 采样。

**解决什么**：无监督预训练的数据来自全网，包含大量不可取的目标（编造、偏见、危险指令）。单纯最大似然只能让模型「像训练语料」，无法精确控制行为。RLHF 用人类偏好把模型推向「更有帮助、更无害」的区域；但它流程复杂、PPO 对超参敏感、训练中要不断从策略采样（慢且吃显存），容易奖励黑客或崩溃。DPO 把「先训奖励模型、再强化学习」的两阶段压缩成单阶段最大似然，训练稳定、算力轻、易实现，成为开源模型（Llama-3-Instruct、Qwen、Zephyr 等）后训练的事实标准。

**原理拆解**：RLHF 目标为 max_π E[r(x,y)] − β·KL(π∥π_ref)，最优策略 π*(y|x) ∝ π_ref(y|x)·exp(r(x,y)/β)。DPO 把奖励反解为 r(x,y)=β·log(π_θ(y|x)/π_ref(y|x))+常数，代入 Bradley-Terry 偏好似然后，常数在成对比较中抵消，得到 DPO 损失：L=−E[log σ(β·log(π_θ(y_w|x)/π_ref(y_w|x)) − β·log(π_θ(y_l|x)/π_ref(y_l|x)))]。β 控制偏离参考策略的幅度。训练时同时加载可训策略 π_θ 与冻结参考 π_ref，对每个 prompt 算「好答/坏答」的对数概率比，只做普通前向+反向，不需要价值网络、不需要 rollout 采样。

**动手验证**：用 Hugging Face TRL 跑一个最小 DPO（需先有 SFT 模型）：
```python
from trl import DPOConfig, DPOTrainer
from datasets import load_dataset
dataset = load_dataset("trl-lib/ultrafeedback_binned", split="train")
training_args = DPOConfig(output_dir="./dpo", per_device_train_batch_size=4,
                          max_length=512, beta=0.1, num_train_epochs=1)
trainer = DPOTrainer(model="your-sft-model", ref_model="your-sft-model",
                     args=training_args, train_dataset=dataset)
trainer.train()
```
关键超参：β 越大越贴近参考（保守），越小越偏向偏好数据（激进但易跑偏）；数据集需成对 (chosen/rejected)。观察验证集上「好答对数概率比坏答更高」即为收敛信号。

**对比选型**：RLHF(PPO) 表达力强、支持在线学习与多轮目标，但工程重、不稳；DPO 简洁稳定、单阶段，适合一次性偏好微调，缺点是离线、依赖偏好数据质量且可能长度偏置（偏好长回答）。其变体 IPO（去概率假设）、KTO（接受非成对反馈）、SimPO（去参考模型更省显存）、Zephyr/ORPO（加 SFT 正则）进一步补短板。实践建议：资源有限或开源复现时首选 DPO/ORPO；需要复杂奖励或在线探索时保留 PPO/RLHF。从数据视角看，RLHF 依赖人类标注的成对偏好，成本高且标注一致性难保证；DPO 同样需要偏好对，但训练阶段省去了奖励模型带来的额外标注与微调成本。实践中常见的混合策略是先用 SFT 让模型学会基本指令遵循，再用 DPO 做一轮偏好微调，最后以少量 PPO 在线纠偏处理长尾风险。值得提醒的是，DPO 并非 RLHF 的终结者：在需要可验证奖励（如代码执行、数学判分）的在线强化学习场景，PPO/GRPO 仍不可替代；而 DPO 类方法胜在稳定、可复现、对小团队友好。选择依据可以归纳为三点：是否具备在线采样算力、偏好数据是否充足且质量可控、是否需要对齐多轮或工具调用等复杂目标。

### 【扩散模型 DDPM 去噪原理：一步步把噪声还原成图像的数学】

**导语**：GAN 统治图像生成八年，直到 2020 年一篇 DDPM 把它拉下马。它的思路反直觉——不去「直接画图像」，而是训练一个网络学会「把噪声一步步擦掉」。本文拆解这条点燃 Stable Diffusion、Sora 的生成主线。

**它是什么**：DDPM（Denoising Diffusion Probabilistic Models，Ho et al., 2020）是一类潜变量生成模型，灵感来自非平衡热力学。它定义两条马尔可夫链：前向过程（扩散）按固定方差 schedule β_t 逐步往数据 x_0 上加高斯噪声，约 1000 步后变成纯噪声 x_T~N(0,I)；反向过程（去噪）训练神经网络 ε_θ 预测每一步加的噪声，从随机噪声出发迭代去噪，最终还原出样本。与 GAN「一个网络直接生成」不同，扩散模型把生成拆成上千步的精细化去噪，训练稳定、模式覆盖好、不易崩塌。

**解决什么**：2020 年前生成式模型各有硬伤：GAN 训练如走钢丝（模式崩溃、梯度爆炸、无似然）；VAE 稳定但样本模糊；自回归逐像素太慢；流模型受可逆雅可比约束表达力受限。扩散模型用「可证明的变分下界 + 噪声预测」把训练变成普通的回归监督，稳定性媲美 VAE，质量超越 GAN（CIFAR-10 上 FID 3.17 首超 BigGAN-deep），且天然支持可控生成、图像编辑、超分。代价是采样慢（千步），后续引出 DDIM、潜在扩散（Stable Diffusion 在 latent 空间跑）、一致性模型等加速方案。

**原理拆解**：前向 q(x_t|x_{t−1})=N(√{1−β_t}·x_{t−1}, β_t·I)，可解析地一步采样任意 x_t=√{ᾱ_t}·x_0+√{1−ᾱ_t}·ε（ᾱ_t=∏(1−β_t)）。反向 p_θ(x_{t−1}|x_t)=N(μ_θ(x_t,t), Σ_θ)。Ho 等人的关键工程改写：让网络预测噪声 ε 而非均值，并把变分下界简化为 L_simple=E_{t,x_0,ε}[‖ε−ε_θ(√{ᾱ_t}x_0+√{1−ᾱ_t}ε, t)‖²]。训练时随机取 t、采噪声、加噪得到 x_t，网络预测 ε；推理时从 N(0,I) 采 x_T，反复 x_{t−1}=(x_t−(1−ᾱ_t)/√{1−ᾱ_t}·ε_θ(x_t,t))/√{ᾱ_t}+σ_t z 直至 x_0。U-Net（含残差与自注意力）是常用骨干。从损失视角看，DDPM 实际是在优化一个加权的变分下界（ELBO），Ho 等人证明预测噪声的简化目标等价于对得分匹配（score matching）的离散化，因此扩散模型与基于分数的生成模型（Song & Ermon 的 SDE 框架）在数学上同源。训练时随机抽步 t 是关键技巧：模型不能只学最后一步，而要能对任意噪声水平去噪，这让它具备逐步精修的能力。推理步数 T 是质量-速度的核心旋钮，理论上 T 越大越接近真实反向方差，但边际收益递减。此后 Nichol & Dhariwal 提出余弦噪声 schedule 改善信噪比，DDPM++、EDM 等进一步细化采样与预条件，奠定了后续 Stable Diffusion 的工程基础。

**动手验证**：用 diffusers 跑最小文生图管线，体会「噪声→图」：
```python
from diffusers import DDPMPipeline
pipe = DDPMPipeline.from_pretrained("google/ddpm-cifar10-32")
image = pipe(num_inference_steps=1000).images[0]   # 从纯噪声去噪 1000 步
image.save("sample.png")
```
想看去噪中间态，可逐 t 调用 `pipe.scheduler` 的 step；自己实现训练则按 L_simple：随机 t、采样 ε、构造 x_t、MSE 回归 ε_θ。把 num_inference_steps 调到 50（配 DDIMScheduler）能大幅提速且质量尚可，直观对比「步数 vs 速度/质量」。

**对比选型**：GAN 快但训练不稳、易模式崩溃；VAE 稳但模糊；自回归质量高但慢；扩散质量与覆盖最佳、训练最稳，但原生采样慢（千步）。加速路线：DDIM/DPM-Solver 少步采样、潜在扩散（先压缩到隐空间再扩散，省 8–16 倍算力）、一致性模型/蒸馏到 1–4 步。文本条件靠交叉注意力把 prompt 注入 U-Net（即 Stable Diffusion）。一句话：要质量与可控性选扩散，要实时选蒸馏/潜在扩散。若从采样效率看，原始 DDPM 的千步是最大短板，DDIM 用非马尔可夫确定性桥接把步数压到 50 步内且质量几乎不降；潜在扩散（Latent Diffusion）先把图像用自编码器压到隐空间，再在隐空间跑扩散，显存与算力省下数倍，是文生图产品的主力；一致性模型与扩散蒸馏则把多步浓缩到 1–4 步，逼近自回归速度。综上，扩散模型用「慢而稳」换来了 GAN 难以企及的训练稳定性与模式覆盖，而它的加速变体已经把速度短板补齐，这也是它能在视觉生成领域全面取代 GAN 的根本原因。

### 【知识蒸馏 Teacher-Student：用 Logits 与特征蒸馏把大模型教给小模型】

**导语**：大模型效果好却跑不动，小模型快却不够聪明。知识蒸馏给出解法——让小「学生」模仿大「老师」的「暗知识」，常能逼近老师水平却只需零头算力。本文讲清软标签、温度、特征蒸馏三条主线。

**它是什么**：知识蒸馏（Knowledge Distillation，Hinton et al., 2015）是一种模型压缩范式：用大而强但笨重的教师模型（常是集成或超大网络）指导小而快的学生模型，使学生不仅学真实标签，还学教师输出的完整概率分布。核心洞察是「暗知识」（dark knowledge）——教师给错误类别的相对概率（如一张「2」更像「3」而非「7」）蕴含泛化结构，硬标签丢弃了它。温度蒸馏把 logits 除以 T>1 再做 softmax，软化分布、暴露类间相似性；极限 T→∞ 退化为直接 logits 匹配。特征蒸馏（FitNets, Romero et al., 2014）更进一步：让学生中间层特征对齐教师中间层（用 hint/回归器），传递的是「怎么想」而非仅「答什么」。

**解决什么**：训练可用大集成换取质量，但部署受延迟、显存、能耗、并发约束，不能每次请求都跑一堆大模型。传统做法是手工剪枝或从头训小模型，但小模型从硬标签学得的信息远少于教师。蒸馏把「部署模型」与「训练模型」解耦：训练期放开用笨重模型，部署期压成单个小模型，既保质量又降成本。它已成为 BERT 压缩、LLM 合成监督、端侧模型、少步扩散采样的事实语法——学生学的不仅是老师答对的，更是老师「犯错的模式」，从而泛化更好。

**原理拆解**：总损失 = α·T²·KL(softmax(z_s/T)∥softmax(z_t/T)) + (1−α)·CE(softmax(z_s), y)。第一项为软目标（同温 T 下师生概率的 KL 散度），乘 T² 是因为软目标梯度随 1/T² 缩小，需补偿以平衡两项；第二项为硬标签交叉熵锚定真值（老师也会错）。T 越大分布越软、露出的暗知识越多，原文用 T∈[1,20]。特征蒸馏则在某层加回归器把学生特征映射到教师特征空间，用 MSE 对齐（hint loss），并可在此基础上再做软标签蒸馏，形成「特征+Logits」两阶段。学生容量不足时，软目标提供的正则能显著提点（MNIST 上 2×800 学生错误从 146 降到 74，逼近 2×1200 教师 67）。

**动手验证**：用 PyTorch 写最小蒸馏（MNIST 分类为例）：
```python
import torch, torch.nn as nn, torch.nn.functional as F
def kd_loss(logits_s, logits_t, labels, T=4.0, alpha=0.7):
    soft = F.kl_div(F.log_softmax(logits_s/T, 1), F.softmax(logits_t/T, 1), reduction="batchmean") * T*T
    hard = F.cross_entropy(logits_s, labels)
    return alpha*soft + (1-alpha)*hard
# 训练循环：教师(冻结)产出 logits_t，学生前向得 logits_s，反向 kd_loss
optimizer.zero_grad(); loss = kd_loss(student(x), teacher(x).detach(), y); loss.backward(); optimizer.step()
```
调 T 看暗知识暴露程度（T 大更软），调 α 权衡软/硬目标；特征蒸馏额外加 `F.mse_loss(project(student_feat), teacher_feat)`。对比「仅硬标签训学生」与「蒸馏训学生」的测试精度即可验证增益。

**对比选型**：剪枝/量化只改结构不改知识来源，蒸馏迁移的是函数行为；与从零训小模型比，蒸馏用教师信号显著提升小模型上限。Logits 蒸馏实现简单、最常用；特征蒸馏需对齐中间层、信息更丰富但工程更重；关系蒸馏（样本间相似性）进一步细化。局限：学生容量远小于老师时收益递减，且依赖教师质量（老师错学生也错）。大模型时代，自蒸馏、在线蒸馏、用强模型生成「合成数据」监督弱模型已成主流压缩与对齐手段。此外，蒸馏与量化、剪枝并不互斥，工业界常组合使用：先蒸馏得到强小模型，再做 INT8 量化上端侧；而大模型时代的「自蒸馏」（用自身生成的软标签训练下一版）与「教师集成蒸馏」则进一步降低了获取强教师模型的成本门槛。

### 【专家路由与辅助负载损失：MoE 如何在稀疏激活下训稳万亿参数】

**导语**：要让模型更强，一个思路是「堆参数」；但全激活意味着算力同比例暴涨。混合专家（MoE）的妙处是「参数很多、每次只激活一小撮」——靠路由网络调度专家。本文讲清路由、负载均衡损失与溢出这三大工程要点。

**它是什么**：混合专家（Mixture of Experts, MoE）在 Transformer 的逐位置前馈层（FFN）处替换为「N 个并行专家 FFN + 一个门控/路由网络」。门控网络对每 token 输出各专家得分，按 Top-K（如 Top-1 或 Top-2）选出少数专家处理该 token，其余专家不激活。于是总参数量可达万亿级，但单 token 计算只走 K 个专家，推理/训练算力近似稠密模型的 K/N。Shazeer 2017 的稀疏门控 MoE 是奠基；Fedus 2021 的 Switch Transformer 用 Top-1「硬路由」把 T5 扩到 1.6T 参数、同算力下预训练提速数倍；GShard 2020 给出专家并行与容量管理等分布式方案。

**解决什么**：稠密模型每增能力都按比例增加每次前向的算力，边际成本高。MoE 把「总容量」与「单次计算」解耦：参数多带来表达与知识容量，稀疏激活保持单次成本低，从而在固定算力预算下显著扩大模型规模（GLaM 用约 1/3 GPT-3 能耗在 29 个基准上超越它）。它让「万亿参数」从纸面走向可训练。代价是训练工程更复杂：路由易「赢家通吃」导致多数专家饿死、分布式通信（All-to-All）开销、微调易过拟合，需要专门机制稳住。除规模优势外，MoE 还带来模块化潜力：不同专家可能在训练中自发分化为不同语言、领域或任务专长，这为「按需激活」的可解释与可插拔模型打开想象空间；同时稀疏激活使单位算力下的知识容量更高，契合「参数多但推理省」的部署诉求。

**原理拆解**：门控 g(x)=softmax(W_g·x)，取 Top-K 得分对应的专家；token 表示 h=Σ_{i∈topk} g_i·E_i(x)。核心难题是负载失衡：若某些专家初期略优，被更多选中→获更多梯度→更优→更被选中，形成正反馈，最终只有少数专家被训练（路由坍塌）。解决办法一是辅助负载均衡损失 L_aux（GShard 形式）：用门控均值与分配占比的点积惩罚不均衡，理想时每个专家接收 1/N token、门控均值 1/N，系数通常约 0.01 以免压过主任务损失；二是专家容量（capacity）：每专家每批最多处理 M 个 token，超量者「溢出」（overflow）丢弃或转投次选，牺牲极少数据换计算均衡；三是噪声 Top-K 门控（Shazeer）加高斯噪声促探索；Switch 还加 router z-loss 正则防门控概率过尖。

**动手验证**：用 PyTorch 写最小 MoE 层，观察负载均衡损失如何拉平专家使用：
```python
import torch, torch.nn as nn, torch.nn.functional as F
class MoE(nn.Module):
    def __init__(self, d, n_experts=4, k=2):
        super().__init__(); self.experts = nn.ModuleList([nn.Linear(d, d) for _ in range(n_experts)])
        self.gate = nn.Linear(d, n_experts)
    def forward(self, x):  # x: (B, d)
        logits = self.gate(x); w = F.softmax(logits, -1)
        topw, idx = w.topk(2, -1)                   # Top-2 路由
        out = torch.zeros_like(x)
        for j in range(2):
            e = idx[:, j]; out += topw[:, j:j+1] * torch.stack([self.experts[e[b]](x[b:b+1])[0] for b in range(x.size(0))])
        # 辅助负载损失：门控均值 vs 实际选中占比
        freq = (F.one_hot(idx, num_classes=4).float().mean(0)).mean(0)
        aux = (w.mean(0) * freq).sum()             # 越小越均衡
        return out, aux
```
打印各专家被选中频率，加 aux 训练后频率应趋近均匀；把容量上限 M 设小，观察溢出 token 比例。

**对比选型**：稠密 FFN 简单稳定但每次全算；MoE 参数/算力解耦、规模性价比高，但训练不稳、通信重、微调易过拟合（ST-MoE 建议只微调非 MoE/FFN 部分）。路由上 Top-1（Switch）最省、Top-2（GShard）更稳；负载手段从辅助损失演进到「无辅助损失负载均衡」（DeepSeek 用可微偏置项调专家偏置，避免 aux loss 干扰主任务）。专家并行需 All-to-All 通信，故常配合张量/数据并行。结论：追求极致规模与性价比用 MoE，追求简单部署用稠密。在专家数量选择上，过少则退化为稠密、丧失稀疏收益，过多则通信与负载均衡压力陡增；GShard 实证数千专家仍可稳定训练。容量因子（capacity factor）是另一关键旋钮：设 1.0 过严会丢 token，设 1.25–2.0 更稳但浪费算力，需按批内长度分布权衡。对于端侧或中小团队，若无法负担 All-to-All 通信，稠密模型反而更省心；MoE 的真正甜区在超大规模预训练与需要「参数扩容不增推理成本」的场景。

### 【位置插值 Position Interpolation 与 NTK 缩放：RoPE 外推扩展上下文长度】

**导语**：模型训练时只见过 4K token，你却塞给它 3 万字的合同——它立刻「抽风」。这不是显存不够，而是位置编码遇到了没见过的旋转角度。本文讲清 RoPE 为何会爆，以及位置插值、NTK-aware 如何低成本把上下文窗口拉长。

**它是什么**：现代 LLM 普遍用 RoPE（Rotary Position Embedding, Su et al., 2021）编码位置：把 query/key 按位置 m 旋转一个角度 θ_m，因注意力是两只旋转向量的点积，留下的是相对偏移，优雅且外推友好。但旋转角只在训练长度内被校准过。位置插值（Position Interpolation, PI；Chen et al. 2023 / kaiokendev 同期）把位置索引整体乘以 λ=L_train/L_target（如 8K→32K 则 λ=1/4），把超长位置「压」回训练区间；NTK-aware 缩放（bloc97, 2023-06 Reddit）不改位置、改基频 b→b·s^{d/(d−2)}，让高频维近乎不动、只插值低频维，被 Peng 等 formalized 为 YaRN。三者都是「把新位置折回训练见过的位置范围」，区别在折得均不均。

**解决什么**：直接外推（不做任何处理）时，超过训练长度的位置产生模型从未见过的旋转角，注意力分数上界比插值时大约 600 倍，softmax 直接被冲垮、输出崩坏——这不是显存问题而是位置泛化问题。PI 用约 1000 步微调即可把 LLaMA 拉到 32K；但它均匀压缩所有维度，会压糊高频维（负责相邻词序），约 4× 后局部分辨力骤降。NTK-aware 改为不均匀插值：高频维保留原分辨率（外推）、低频维插值，常在无需微调时即接近 PI 效果；YaRN 再叠加「按维分段 NTK + 注意力温度缩放」，用约 1/10 数据、1/2.5 步数达到更长窗口，成为开源扩窗事实方案（LLaMA 2→64K~128K）。

**原理拆解**：RoPE 中第 d 维波长 λ_d=2π·b^{2d/D}。PI 令 m→λm，所有维波长同比例缩小、相邻角差被压小，远处 token 难区分。NTK-aware 改基频 b'=b·s^{D/(D−2)}（s 为扩展倍数），等价于不改变位置、只让低频维（大 d、长波长）插值、高频维（小 d）几乎保持外推——因为 b 增大对高频维影响小、对低频维影响大，恰好把「挤压」集中到有余量的低频维，保住局部语序。YaRN 进一步对维分三档处理（NTK-by-parts）并下调注意力温度补偿高频能量。实现上往往只改 RoPE 的 base（如 10000→超 10 万）或加缩放系数，即可生效。值得注意的是，RoPE 的「相对位置由旋转点积保留」这一性质，是它能平滑外推的前提；一旦改变基频或位置缩放，等价于改变了模型对「距离」的感知尺度。YaRN 的「按维分段」正是利用不同维承载不同频率尺度这一事实：低频维负责远距离粗略位置、高频维负责相邻精细顺序，分段处理可在拉长窗口的同时保住局部语序，这也是它优于均匀 PI 的本质原因。

**动手验证**：用 Hugging Face 在加载时改 RoPE 基频，做最小扩窗实验：
```python
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-2-7b",
            rope_scaling={"type": "linear", "factor": 4.0},   # 位置插值 PI
            # rope_scaling={"type": "ntk_scaled", "factor": 4.0},  # NTK-aware
            )
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-2-7b")
txt = "把以下3万字合同逐段总结：" + "..."   # 超训练长度输入
out = model.generate(**tok(txt, return_tensors="pt"), max_new_tokens=512)
```
对比 type="linear"(PI) 与 "ntk_scaled"：在 4× 内 PI 通常够用；超过 4× 时观察 NTK 在长程/局部任务上的优势。用长文档困惑度（perplexity）评估扩窗是否「真有效」而非仅不崩。

**对比选型**：外推（什么都不做）会崩，排除；PI 实现一行、稳但均匀压糊局部序，约 4× 封顶；NTK-aware 不均匀插值、常免微调、长程更好；YaRN 质量/步数最优、扩到 128K 标配，但需少量微调；另有 Dynamically RoPE、Self-Extend、注意力Sink（attention sink）补强「中间遗忘」与长程聚焦。注意「标称窗口≠有效窗口」（RULER 显示不少号称 32K 的模型实际撑不住）。结论：轻量扩窗用 NTK-aware，最佳实践用 YaRN/分段缩放 + 少量长文本微调。在评估上，不能只信标称长度：RULER、LongBench 等长上下文基准显示，不少号称 32K/128K 的模型在「中间信息检索」「跨长距离聚合」任务上明显掉点，即「lost in the middle」现象——模型更关注首尾、忽略中段。因此扩窗后务必用长上下文基准实测有效长度，而非仅看是否不崩。工程落地上，扩窗通常配合 KV Cache 量化、分页注意力（PagedAttention）与分块预填充，才能真正把长上下文跑得既准又省。
